# Пакет содержимого атласа נוסחאון 97002 — инструкция поставщику

Схема: `linguistpro.atlas-content-pack.1.0.0`. Этот архив — всё, что нужно, чтобы подготовить и
самостоятельно проверить пакет содержимого: исходный пакет страниц, схемы, проверка (валидатор),
вычислительное ядро и эталон.

## 1. Роли

- **LinguistPro (разработка)** выдаёт исходный пакет: ID объектов, номера страниц, координаты,
  сырой текст, вырезки рисунков и формул, изображения страниц. Это опора, по которой проверяется
  ваша работа.
- **Вы (поставщик содержимого)** присылаете пакет содержимого: исправленный по изображению иврит,
  огласовки, транслитерацию, перевод, термины, подписи рисунков, таблицы, формулы, шаги примеров,
  предложения опечаток и отчёт о расхождениях.
- **Владелец** — единственный, кто подтверждает (`owner_*`) — в программе, не в файле.

Нельзя: ставить `owner_status`, `owner_reviewed`, `math_review`; придумывать свои ID для объектов,
которые уже есть в исходном пакете; менять привязку символа, которую поставил экстрактор.

## 2. Состав архива

| Путь | Что это |
|---|---|
| `TASK.ru.md` | что именно сдать в этой поставке |
| `source-pack/manifest.json`, `source-pack/pages.jsonl` | исходный пакет: по объекту на строку |
| `source-pack/assets/*.png` | изображения страниц (150 dpi), вырезки рисунков и формул (200 dpi); имя = SHA-256 |
| `source-pack/contact-sheet.png` | все страницы с рамками разметки: серые — блоки текста, бирюзовые — формулы, оранжевые — рисунки, фиолетовые — символы |
| `schemas/*.schema.json` | JSON Schema исходного пакета и пакета содержимого |
| `tools/atlas_validate.py` | проверка (Python ≥ 3.10, только стандартная библиотека) |
| `reference/reference-content.jsonl` | эталон: стр. 7 и 197 полностью, фрагменты 282 и 287–289 |

## 3. Формат

UTF-8 JSONL: один JSON-объект на строку. Первая строка — `header`:

```json
{"type":"header","schema":"linguistpro.atlas-content-pack.1.0.0","atlas_id":"a97002",
 "source_pack_sha256":"<SHA-256 файла source-pack/pages.jsonl, окончания строк LF>",
 "producer":"dots","produced_at":"2026-10-31T09:00:00Z","pages":[7,197,282,284,287,288,289,485]}
```

`pages` — страницы, которые поставка покрывает полностью: для них проверяется, что каждый ивритский
блок переведён. Дальше — объекты типов `block, formula, symbol, figure, region, table, term, example,
erratum, report` в любом порядке. Поля и обязательность — в `schemas/content-pack.schema.json`.
Значение `source_pack_sha256` для этого архива — в `TASK.ru.md`.

## 4. ID

- Объекты из исходного пакета (`block`, `formula`, `symbol`, `figure`, `example`) — **только их ID** из `pages.jsonl`:
  `a97002:p197:b002`, `a97002:p197:f01`, `a97002:p7:st1:s03` (символ таблицы обозначений `st1`), `a97002:p197:fig79`,
  пример с заголовком «דוגמה» — `a97002:p283:ex1`.
- Новые объекты (`region`, `table`, `erratum`, пример без заголовка `example`) — **временный ID**
  `new:<ID родителя>:<метка>`; родитель — страница (`a97002:p282`) или рисунок (`a97002:p197:fig79`);
  метка — строчная латиница, цифры, дефис: `shkiv-small`, `center-distance`. Метка уникальна у родителя.
  Постоянный ID программа даст сама по метке (`a97002:p197:fig79:r-shkiv-small`).
- Термины — `a97002:term:<slug>`, ссылка на смысл — `a97002:term:<slug>#<sense>`.

## 5. Координаты

Страница = номер страницы PDF с 1 (совпадает с печатным). bbox = `[x0, y0, x1, y1]` в **пунктах
страницы PDF** (страница 595 × 842), начало — левый верхний угол, y вниз. Не в пикселях вырезки!
Пересчёт из пикселей вырезки рисунка (200 dpi): `pt = bbox_рисунка.x0 + px · 72 / 200` (так же для y
с `bbox_рисунка.y0`). Область рисунка должна лежать внутри bbox рисунка.

## 6. Текст

- `he` — иврит **как напечатан**, но исправленный по изображению страницы: порядок слов, скобки,
  пробелы, пунктуация (сырой `he_raw` ломает RTL: зеркальные скобки, слитые слова, точка в начале).
  Слова не добавлять и не выбрасывать. Если по изображению текст отличается от `he_raw` по буквам
  или порядку — поле `he_fix_note` с объяснением.
- `he_niqqud` — тот же текст с огласовками (дефективное написание допускается).
- `translit` — латиницей, как в эталоне; `translit_ru` — кириллицей (желательно).
- `ru` — технический перевод по русской инженерной традиции. Все числа из оригинала — в переводе
  (запятая или точка — неважно). Сноски-цифры тоже сохранять.
- Опечатку оригинала в `he`/`ru` **не исправлять**: текст остаётся как в книге, исправление —
  отдельным объектом `erratum`.
- `kind`: `heading | prose | list_item | caption | formula_label | symbol_row | example_heading |
  example_text | table_note | other`.
- `terms` — ссылки на смыслы терминов, которые встречаются в блоке.

## 7. Термины

`term`: `lemma_he`, `niqqud`, `translit`, `senses[] {sense, ru, context}`. Правило: **одно значение —
один перевод**. Разные значения одного слова — разные `sense`. На каждый смысл должен ссылаться
хотя бы один блок, символ или область.

## 8. Формулы и символы

- `display_latex` — для показа. `compute` — выражение для расчёта в грамматике ядра:
  `+ - * / ^`, скобки, унарный минус; константы `pi, e`; функции `sqrt abs exp ln log10 pow min max
  sin cos tan asin acos atan atan2`. LaTeX — не расчёт.
- Переменные `compute` — это `var` символов: символов таблицы обозначений, привязанных к формуле
  (экстрактором или списком `symbols`), либо собственных `local_vars` формулы — когда расшифровки на
  этой странице нет. Левая часть формулы — `result_var` (не входит в `compute`).
- Тригонометрия — обязательно `angle_unit: "deg"` или `"rad"`.
- Имена `e` и `pi` заняты константами грамматики: переменную, которая в книге обозначена `e` (например,
  граничный коэффициент подшипника `e = 0.24` на стр. 289), называйте иначе — `e_lim`; в `symbol_latex` остаётся `e`.
- Если формулу нельзя честно выразить (выбор из таблицы, кусочная зависимость, неравенство,
  итерация) — `"compute": null` и `compute_absent_reason`. **Не подгонять** формулу под грамматику.
- Символ (`symbol`): `symbol_latex`, `var` (латинский идентификатор), `description_he`, `description_ru`,
  `unit`. Если экстрактор не привязал символ к формуле (`formula_id: null`), привязку можно
  предложить полем `formula_id` — уйдёт владельцу на просмотр.
- `ambiguity_note` — где соглашение источника отличается от привычного (например, `i = n_out/n_in`).

## 9. Рисунки, области, таблицы

- `figure`: `caption_he`, `caption_ru`.
- `region`: подпись или деталь на рисунке: `parent` (рисунок), `bbox`, `label_he`, `label_ru`,
  `links` (символы, формулы, термины). Статус `recognition: ocr_high | ocr_low` — ваша уверенность.
- `table`: растровая таблица (стр. 282, 284, 288) или таблица данных: `parent`, `bbox`, `cells[]`
  `{row, col, rowspan, colspan, he, ru, unit?, note?, bbox?}`.

## 10. Примеры и опечатки

- `example`: шаги `steps[] {block?, compute, bindings{}, angle_unit?, printed, note?}` — по одному на
  каждое арифметическое действие решения, с подстановками **как напечатаны**. Ядро пересчитает:
  `F_CORE_VERIFIED` — сошлось, `F_CORE_MISMATCH` — кандидат в опечатку. Это находка, не ошибка.
- `erratum`: `page`, `target` (ID блока/формулы/примера), `as_printed`, `proposed`, `explanation_ru`.
  Только предложение — подтверждает владелец.
- `report`: `discrepancies[] {ref, note}` — всё, в чём вы не уверены.

## 11. Статусы

Четыре оси: `recognition`, `language_review`, `math_review`, `owner_status`. Вы ставите только
`recognition: ocr_high | ocr_low` (у областей и таблиц, не у блоков с текстовым слоем) и
`language_review: unreviewed | producer_checked`. Остальное ставят ядро и владелец.

## 12. Проверка

```
python tools/atlas_validate.py --source source-pack --content a97002-content-pilot-v1.jsonl
```

Выход 0 — ошибок нет. Файл — UTF-8 (не UTF-16). Коды:

| Код | Что значит |
|---|---|
| `E_PARSE`, `E_SCHEMA`, `E_HEADER` | не JSON / не по схеме / нет заголовка |
| `E_SOURCE_MISMATCH` | пакет сделан не по этому исходному пакету (хэш) |
| `E_UNKNOWN_ID`, `E_DUPLICATE_ID`, `E_NEW_ID` | неизвестный, повторный или неверный временный ID |
| `E_BBOX_OUTSIDE` | bbox вне рисунка/страницы — проверьте пункты, а не пиксели |
| `E_STATUS_OWNER`, `E_STATUS_RECOGNITION` | статус, который ставить нельзя |
| `E_COVERAGE` | ивритский блок страницы из `pages` не переведён |
| `E_HEBREW_LETTERS` | в `he` потеряно или добавлено слово (по сравнению с `he_raw`) |
| `E_HEBREW_ORDER` | буквы те же, но порядок другой — слова переставлены |
| `E_NIQQUD_BASE` | `he_niqqud` без огласовок не совпадает с `he` |
| `E_NUMBERS` | число из оригинала отсутствует в переводе |
| `E_REF`, `E_TERM` | ссылка в никуда; дубль термина или смысла |
| `E_COMPUTE` | `compute` не разбирается, переменная не объявлена, нет `angle_unit` или причины, переменная названа `e`/`pi` |
| `E_SYMBOL_BINDING` | попытка изменить привязку символа, поставленную экстрактором |
| `W_*` | предупреждения — разберите, но пакет принимается |
| `F_CORE_VERIFIED`, `F_CORE_MISMATCH` | результат пересчёта шагов примера |
| `F_CORE_UNANCHORED` + `W_PRINTED_UNANCHORED` | подстановки или напечатанный результат шага не найдены в тексте страниц примера (стр. примера и три следующие) — пересчёт не засчитан |

Буквы, порядок, огласовки и числа проверяются у **каждого** присланного блока, даже если его страницы
нет в `pages`; `pages` влияет только на требование полноты (`E_COVERAGE`).

**Валидатор не заменяет смысловую вычитку**: он проверяет структуру, буквы, числа, ссылки и
арифметику. Правильность технического смысла проверяет человек.
