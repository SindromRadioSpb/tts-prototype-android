# Фикстуры субтитров (W2-S5a)

Реальные образцы субтитров для гейта `smoke:captions-parse` слайса **W2-S5a** (видео с
субтитрами → билингвальная таблица + сегмент-караоке). Все файлы получены **живой разведкой
2026-07-27**, не синтезированы.

## Что здесь

| Файл | Что это | Роль |
|---|---|---|
| `ted-hebrew-manual.vtt` | Ручные ивритские субтитры (WebVTT), полный файл, 411 кью | вход парсера, ветка «не катящиеся» |
| `ted-hebrew-manual.json3.json` | Та же дорожка в сериализации `json3` | **независимый оракул** для неё |
| `hebrew-auto-rolling.vtt` | Авто-субтитры (ASR) YouTube, «катящиеся», первые 180 с, 129 кью | вход парсера, ветка разворачивания |
| `hebrew-auto-rolling.json3.json` | Та же дорожка в `json3`, обрезана по тем же 180 с | **независимый оракул** для неё |
| `youtube-panel-en.txt` | Реальная копия панели «Расшифровка видео», английская дорожка | вход парсера вставки |
| `youtube-panel-he.txt` | То же, ивритская дорожка (RTL) | вход парсера вставки, RTL |

**Источник обоих аудио-дорожечных файлов:** YouTube-ролик `iG9CE55wbtY` (TED, Ken Robinson) —
ручная дорожка `iw`; и `lSrPXBgG2T4` — авто-дорожка `iw`. Файлы вставок сняты с `iG9CE55wbtY`
через Selection API в реальном Chrome (то, что физически попадает в буфер обмена).

## Зачем нужен оракул

Гейт сверяет результат разбора `.vtt` с `json3`-сериализацией **той же дорожки**. Это разные
форматы одного источника, поэтому расхождение указывает на ошибку парсера, а не на разночтение
данных — прямое применение принятой в проекте доктрины independent-oracle (гейт не имеет силы,
если пересчитывает тем же кодом, что и продюсер).

Достигнутая на этих фикстурах планка прототипа (2026-07-27): **ручные 411/411 сегментов, текст
100%, старты 100% в пределах 50 мс; катящиеся 65/65 сегментов, текст 100%, старты 100%.**
Гейт должен держать эту планку.

## Краевые случаи, которые эти файлы покрывают

- **Катящиеся авто-субтитры:** 129 кью разворачиваются в 65 реплик. Каждая реплика приходит трижды —
  как «новая» строка с пословными тегами `<00:00:10.280><c>…</c>`, как десятимиллисекундная
  «доводочная» кью и как перенос в следующую кью.
- **Строки тела кью из одного пробела.** Разделять блоки WEBVTT можно **только** по по-настоящему
  пустой строке: `"\n \n"` — это текст кью, а не разделитель. На этом ломается наивный парсер.
- **HTML-сущности:** `&gt;&gt;` в авто-дорожке (смена говорящего). Без декодирования текст
  расходится с оракулом.
- **Cue settings** (`align:start position:100%`) — должны игнорироваться, не попадать в текст.
- **Многострочные реплики** в ручной дорожке (246 из 411) — склеиваются в одну реплику.
- **Названия глав во вставке:** `Introduction`, `Three themes` идут без таймкода и вклиниваются
  **между текстом реплики и следующим таймкодом** (см. `youtube-panel-he.txt`, строка перед `0:44`).
  Их обязательно отбрасывать, иначе они станут фальшивыми сегментами.
- **RTL-иврит** во вставке и в обоих `.vtt`.

Чего эти фикстуры **не** покрывают (дописать при появлении случая): формат `H:MM:SS` во вставке
(оба ролика короче часа), SRT, CRLF, BOM, перекрывающиеся кью, машинно-переведённые дорожки.

## Как перегенерировать

```
node .tmp/vtt-fixture-capture.mjs      # добывает дорожки и печатает анализ
```

⚠ Скрипт-добытчик требует **домашнего (не датацентр) IP**: с прод-хоста YouTube отвечает
ботоловкой и гео-блоком (разведка 2026-07-27, см. дизайн-док). Он одноразовый и лежит в `.tmp/`;
сами фикстуры коммитятся, потому что перегенерация не воспроизводима из CI.

Файлы вставок снимаются вручную: открыть ролик → «Показать текст видео» → выделить панель →
скопировать. Программно то же самое даёт `getSelection().toString()` на
`ytd-transcript-segment-list-renderer`.

## Правила

Фикстуры — **вход тестов, не эталон перевода**. Их нельзя править «чтобы тест позеленел»:
расхождение с оракулом означает ошибку парсера. Если YouTube изменит формат — добавить новый
файл рядом, а не переписать существующий.
