## Контракт адресов

| Сущность | Адрес для обмена | Получатель | Индексация |
| --- | --- | --- | --- |

| Черновик издателя | Существующий приватный preview-контракт | По действующему праву доступа | Не индексировать |

Фрагмент `#room=...` сохраняет временное состояние интерфейса, но не определяет произведение. Кнопки и адресная строка обязаны сохранять ID работы в части URL до `#`. Параметры `from`, `return_to`, `public_snapshot`, фильтры и отслеживание не входят в canonical. Внутренние ссылки Медиатеки остаются обычными `<a href>`: работают средняя кнопка, контекстное меню и копирование. «Полки/Медиатека» в открытом читателе также стали ссылкой, обычный щелчок возвращает в уже прогретый интерфейс.

## Почему это важно для поиска и GEO

До изменения запросы разных работ возвращали одинаковый каркас `library.html` с общим заголовком и без текста произведения. Клиент мог позднее открыть нужный материал, но `#room=benyehuda` сам по себе не служил адресом работы. [Google не рекомендует фрагменты для смены содержимого](https://developers.google.com/search/docs/crawling-indexing/url-structure), а [ссылки с настоящим `href` являются обнаруживаемым маршрутом](https://developers.google.com/search/docs/crawling-indexing/links-crawlable). Теперь сервер отдаёт индексируемую проекцию только для опубликованного и доступного материала. Данные структурной разметки повторяют видимые название, автора и источник; сама разметка не обещает расширенный результат ([правила Google](https://developers.google.com/search/docs/appearance/structured-data/sd-policies)).

Для Google AI Overviews/AI Mode специальных GEO-файлов или разметки не требуется: страница должна быть индексируемой, доступной со сниппетом, полезной и текстовой ([Google Search Central](https://developers.google.com/search/docs/appearance/ai-features)). Bing также рекомендует стабильные canonical URL и понятные страницы для цитирования ([Bing Webmaster Guidelines](https://www.bing.com/webmasters/help/bing-webmaster-guidelines-30fba23a)). `robots.txt` указывает динамический sitemap, который перечисляет только публичные доступные материалы; попадание в sitemap не гарантирует индексирования ([Google о sitemap](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap)).

Проверять после релиза: URL Inspection в Search Console для работы 85 и одного опубликованного материала, выбранный canonical, индексирование, HTML и мобильный рендер; coverage sitemap и 404 после отзыва публикации; в Bing Webmaster Tools — обнаружение URL и цитирование, когда появятся данные. Ни локальный HTTP smoke, ни браузерная проверка не доказывают факт индексации.

## Обмен и ограничения платформы

Опубликованный материал — ссылка на страницу, которую можно передать системным меню или скопировать из карточки Медиатеки. Локальный материал — ZIP с составом и перечнем недоступного аудио. На устройствах с Web Share файлов системное меню передаёт ZIP выбранному приложению. В Chrome без такой возможности Студия предлагает сохранить ZIP и открыть WhatsApp, Telegram или почту; пользователь прикрепляет скачанный файл сам. Веб-страница не может программно вложить ZIP в произвольный мессенджер или `mailto:`. Неудача системного меню не инициирует загрузку без отдельного выбора пользователя.

## Следующая редакционная очередь

Авторские страницы Бен-Иегуды, публичные темы и подборки Медиатеки пока имеют только клиентское представление и общие HTML-метаданные. Их постоянные ID уже существуют, но массовая публикация тонких индексируемых страниц без проверенного описания, прав и доступных материалов ухудшит качество каталога. Следующий выпуск должен дать каждой такой сущности устойчивый URL, редакционное описание, серверный HTML, внутренние ссылки, canonical и выборочное включение в sitemap; затем проверить Search Console на реальном корпусе. Личные подборки, сохранённые фильтры, учебный прогресс, черновики и закрытые группы остаются вне публичной индексации.
