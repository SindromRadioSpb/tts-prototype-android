## 1. Решения владельца (ЗАФИКСИРОВАНО 2026-07-27)

| # | Развилка | Решение |
|---|---|---|
| S5A-TRANSPORT | Как субтитры попадают в приложение | ✅ **Только принесённые пользователем**: файл `.vtt`/`.srt` ИЛИ вставка расшифровки YouTube. Серверная добыча субтитров — **НЕ делаем** (разведка §4: прод-IP забанен ботоловкой и гео) |
| S5A-PLAYER | Воспроизведение и караоке | ✅ **Chromium-премиум с честной деградацией**: локальный медиа-файл (путь S4.2) → YouTube через `<iframe credentialless>` → таблица с таймкодами и переход на YouTube. Никакого молчаливого тупика |
| S5A-PASTE | Вставка расшифровки из панели YouTube | ✅ **В v1**. Единственный путь, дающий «ноль установки» именно для YouTube |
| S5A-EXT | Браузерное расширение | ✅ **Отложено**. Автоматизирует шаг, который вставкой закрывается за два клика; цена — отдельный канал дистрибуции и погоня за селекторами YouTube |
| S5A-GRAIN | Гранулярность строк таблицы | ✅ **Слияние реплик в предложения ≤15 с** (решено 2026-07-27 по ходу реализации, см. §4.5). Реплика субтитров — единица показа, а не языка |

**Уточнение честности по S5A-TRANSPORT.** Отказ от серверной добычи — не «пока не осилили», а
измеренный факт (§4). Пользователю это видно как честная развилка, а не как поломка: Студия
говорит, какие дорожки у ролика есть, и просит их принести. Анти-приоритет пакета «серверный
yt-dlp/ffmpeg» не задет — новых серверных фетчей в слайсе нет вообще.

**Уточнение честности по S5A-PLAYER.** `credentialless` — механизм Chromium; Safari/iOS и Firefox
получают деградацию. Это осознанный размен: альтернатива (снять `COEP: require-corp` с `index.html`)
убила бы cross-origin isolation, на которой стоит wa-sqlite/OPFS-движок.

## 2. Ценность слайса после разведки

S5b-lite уже работает: видео-**файл** транскрибируется через Files API (v3.11.248). S5a добавляет
поверх этого три вещи, которых ASR дать не может:

1. **Ручные субтитры — написанный человеком текст**, а не вывод модели. По R9 это asserted-источник
   там, где ASR даёт derived. Для учебного материала это принципиально другой класс качества.
2. **Точный тайминг бесплатно.** ASR-тайминг проходит валидатор R11 и иногда честно отбрасывается;
   тайминг субтитров монотонен по построению. Плюс экономия ≈$0.13 за 20-минутное видео (R16).
3. **Караоке под самим роликом.** Не под скачанным файлом, а под видео на YouTube.

## 3. Архитектура и поток данных

```
[субтитры] ──┬── файл .vtt / .srt ────────────┐
             └── вставка панели YouTube ──────┤
                                              ▼
                          public/js/captions-parse.js  (pure, dual-export)
                          — детект формата, разворачивание катящихся,
                            декод сущностей, отбрасывание глав
                                              ▼
                            [{ i, start, text }]  ← формат, который УЖЕ
                                              │     принимает конвейер S4
                                              ▼
                    validateSegments(...)  (asr-transcript.js, БЕЗ ИЗМЕНЕНИЙ)
                                              ▼
              /api/translate-table seg-режим  (сервер БЕЗ ИЗМЕНЕНИЙ)
                                              ▼
              buildRowTiming → { v:1, unit:'row', entries:[{o,t}] }
                                              ▼
                       StudioMediaKaraoke  (одна правка: см. §5.4)
                                              ▼
[медиа] ──┬── локальный blob из OPFS (S4.2, есть) ──────── играет как сегодня
          ├── YouTube <iframe credentialless> (новое) ───── играет в Студии, Chromium
          └── нет ни того, ни другого ───────────────────── таймкоды + «открыть на YouTube с M:SS»
```

**Разделение ответственности (R12).** Сервер в этом слайсе **не меняется ни строкой**. Ни нового
эндпоинта, ни нового внешнего фетча, ни новой записи. Поверхность R14 не растёт. Всё — клиент.

## 4. Разведка, на которой стоит дизайн (2026-07-27, живые прогоны)

Разведка проведена ДО дизайна — по правилу de-risk из плана S4 (транспорт-спайк первой задачей).

### 4.1 Добыча субтитров: серверная — NO-GO

| Шаг | Из браузера Студии | С прод-хоста (Hetzner DE) | С домашнего IP |
|---|---|---|---|
| Список дорожек (`watch` / innertube) | ❌ CORS | ❌ 4/5 роликов `LOGIN_REQUIRED «Sign in to confirm you're not a bot»`, 5/5 израильских каналов — гео-блок | ✅ 8/8 |
| Скачать подписанный `timedtext` | ✅ **работает** (200, полное тело) | единственный прошедший ролик отдал URL с `exp=xpe` → **пустое тело** | ✅ |
| Разбор HTML watch-страницы (второй путь) | — | ❌ то же самое, 4/5 ботоловка | ✅ |

Вывод: недостающее звено — **только** «узнать подписанный URL». Ни сервер, ни браузер его получить
не могут; всё остальное в цепочке доступно. Отсюда S5A-TRANSPORT.

### 4.2 Плеер: `credentialless` — GO

Проверено на живом проде поверх действующего `COEP: require-corp`:

| Браузер | Версия | Контекст | Плеер готов | Часы идут | `crossOriginIsolated` после |
|---|---|---|---|---|---|
| Chromium (сборочный) | 148 | desktop + Android-эмуляция | ✅ | ✅ | `true` |
| Chrome (реальный) | 150 | desktop + Android-эмуляция | ✅ | ✅ | `true` |
| Edge (реальный) | 150 | desktop + Android-эмуляция | ✅ | ✅ | `true` |

Контроль: обычный (не-`credentialless`) iframe на той же странице — плеер **не стартует**; та же
проба на странице без COEP — стартует. То есть блокирует именно COEP, и `credentialless` его
снимает, не трогая изоляцию. Дополнительно: плеер отдаёт **список дорожек субтитров**
(`getOption('captions','tracklist')` → `languageCode`, `kind`, `is_default`, `is_translateable`),
но **не отдаёт** ни текст, ни подписанный URL — проверено сканированием объекта дорожки.

### 4.3 Разбор субтитров: валидирован на 100%

Прототип сверен с `json3`-сериализацией **той же дорожки** (independent-oracle):

| Фикстура | Кью на входе | Сегментов | Оракул | Текст | Старты ≤50 мс |
|---|---|---|---|---|---|
| Ручные ивритские (TED) | 411 | 411 | 411 | **100%** | **100%** |
| Авто-ивритские, катящиеся | 129 | 65 | 65 | **100%** | **100%** |

Найденные краевые случаи (все закреплены фикстурами в `scripts/premium/fixtures/captions/`):
катящаяся структура авто-субтитров (каждая реплика приходит трижды); **строки тела кью из одного
пробела** — блоки WEBVTT разделяются только по-настоящему пустой строкой; HTML-сущности (`&gt;&gt;`);
cue settings; многострочные реплики; RTL.

### 4.5 Гранулярность: реплика субтитров ≠ строка таблицы (замер по ходу реализации)

Замер на реальных фикстурах: **≈21 реплика в минуту**. Двадцатиминутный доклад TED даёт 411 реплик
и упирается в кап 400, зеркалящий `ingest/segTable.js` — то есть **всё длиннее ~18 минут не
импортируется вовсе**. Даже внутри капа строка таблицы длиной 2,8 секунды — плохая единица для
обучения: реплика субтитров нарезана под ширину экрана, а не по языковой границе.

Решение владельца: после разбора склеивать соседние реплики до естественной границы (`.`, `?`, `!`,
`…`) либо до 15 секунд. Тот же доклад: 411 → **188 сегментов**, средняя длина 67 символов; в кап
влезает видео минут на 40–45. Порог 15 с выбран не произвольно — ровно его требует ASR-промпт
S4 (`asr-transcript.js:13`), так что обе ветки инжеста дают одинаковую гранулярность, и
`validateSegments`/`buildRowTiming` работают с привычной формой данных.

Честность (R9/R11): старт склеенного сегмента = старт его первой реплики (никакой интерполяции),
исходное и итоговое число реплик попадает в провенанс, слияние не пересекает границу глав.

### 4.4 Вставка панели: формат снят с реального Chrome

Копия панели «Расшифровка видео» даёт строгое чередование: таймкод на своей строке (`M:SS`), следом
одна строка текста. В поток вклиниваются **названия глав без таймкода**, причём между текстом
реплики и следующим таймкодом. Концов реплик нет. Языковое меню панели помечает авто-дорожки прямо
в названии, и для одного языка может быть **две** записи — вторая машинно-переведённая.

## 5. Контракты (точные схемы)

### 5.1 `public/js/captions-parse.js` (новый, pure, dual-export)

```js
CaptionsParse.parse(rawText, { hint, merge = true, mergeMaxSec = 15 }) → {
  ok, format: 'vtt' | 'srt' | 'youtube-panel',
  rolling: boolean,           // катящиеся авто-субтитры развёрнуты
  language: string | null,    // из заголовка VTT `Language:`, иначе null
  kindHint: 'auto' | 'manual' | 'unknown',  // DERIVED, см. §6
  segments: [{ i, start, text }],           // i = позиция в массиве, плотно, с нуля
  cueCount: number,           // реплик ДО слияния (провенанс, §4.5)
  merged: boolean,            // слияние применялось
  droppedHeadings: number,    // отброшенные названия глав (только youtube-panel)
  warnings: string[],
  error_code?: 'CAPTIONS_EMPTY' | 'CAPTIONS_NO_TIMESTAMPS' | 'CAPTIONS_UNPARSEABLE' | 'CAPTIONS_TOO_MANY'
}
```

`merge: false` отключает слияние — этим пользуется гейт, чтобы сверять разбор с оракулом
пореплично (оракул хранит по событию на реплику). Продуктовый путь всегда идёт со слиянием.
Кап 400/2000 проверяется **после** слияния: до него доходит меньше сегментов, и именно это
делает импортируемыми ролики длиннее 18 минут.

Правила разбора, зафиксированные разведкой:

- **Блоки WEBVTT разделяются только по-настоящему пустой строке.** `"\n \n"` — это текст кью.
- **Катящиеся** определяются по доле кью с пословными тегами `<HH:MM:SS.mmm>` / `<c>`
  (порог: ≥20% кью и ≥3 штук). Разворачивание: пропустить кью короче 50 мс; строку с пословными
  тегами считать новым текстом на старте её кью; строку без тегов брать, только если она не равна
  предыдущей выданной (это перенос).
- **Сущности** `&amp; &lt; &gt; &nbsp; &quot; &#39; &lrm; &rlm;` декодируются; прочие теги
  вырезаются. Пословные тайминги **отбрасываются, не используются** (R11: word-level запрещён).
- **Вставка панели:** строки до первого таймкода — названия глав, отбрасываются. Между таймкодами
  первая строка — текст, всё сверх неё — название главы, отбрасывается со счётчиком.
  Конец реплики = старт следующей; у последней конца нет и мы его не выдумываем.
- **Слияние в предложения (§4.5):** соседние реплики склеиваются, пока суммарная длительность
  сегмента ≤ `mergeMaxSec` И предыдущая реплика не оканчивается на `.`/`?`/`!`/`…`/`:`.
  Старт сегмента = старт его ПЕРВОЙ реплики. Слияние не склеивает реплики, между которыми пауза
  больше 2 секунд — это смена говорящего или новая мысль. Ни один символ не теряется:
  конкатенация текстов сегментов равна конкатенации текстов реплик.
- Капы клиента зеркалят серверные: **400 сегментов, 2000 символов** (`ingest/segTable.js:8-9`),
  проверяются **после** слияния. Превышение → `CAPTIONS_TOO_MANY` с честным текстом, а не
  молчаливое усечение.

Новый вид источника `kind: 'captions'`, едет существующим save-путём в `source_meta_json`:

```json
    "format": "vtt" | "srt" | "youtube-panel",
    "kindHint": "manual" | "auto" | "unknown",
```

склеивались и в каком объёме (411 → 188) — слияние это преобразование, а не исходные данные (R9).

### 5.4 Единственная правка караоке-модуля

`studio-media-karaoke.js:76` `ensureRun(blob, entries, rowCount)` — сейчас единственная зависимость
от блоба это `URL.createObjectURL(blob)` + `new Audio(url)` (строки 79-80). Правка: принимать либо

## 6. Как определяется «авто или ручные» (R9: derived ≠ asserted)

Мы **никогда не заявляем** тип субтитров как факт. Есть три уровня свидетельства, и в UI видно, какой сработал:

| Свидетельство | Откуда | Что показываем |
|---|---|---|
| `vtt-rolling` | катящаяся структура + пословные теги | «похоже на авто-субтитры» + канон-формулировка «авто-субтитры, качество не гарантировано» |
| `player-tracklist` | `kind` дорожки от самого плеера | «у ролика: ручные / авто» — но это про **дорожку ролика**, а не про принесённый файл |
| `none` | ничего из перечисленного | «источник субтитров не проверен» |

Отдельная честность: панель YouTube предлагает **машинно-переведённые** дорожки наравне с
настоящими. Ивритский текст, переведённый роботом с английского, — не ивритская речь. Определить
это по вставленному тексту нельзя, поэтому дефолтная формулировка для вставки — «расшифровка
YouTube, тип дорожки не проверен», а `player-tracklist` её лишь уточняет. Пользователь не
опрашивается «это авто?» — заявление пользователя не является свидетельством (R9).

## 7. UI-поток (расширение диалога «Импорт»)

1. **Ссылка на видео.** Пользователь вставляет URL. Классификатор перед `fetchUrl()` (сейчас там
   ноль классификации, `studio-import.js:174`) распознаёт YouTube и уводит на ветку S5a вместо
   бессмысленного `fetch-url` (сегодня такой URL даёт либо `EXTRACT_EMPTY`, либо мусор из шелла).
2. **Плеер.** Если `capability().supported` — встраиваем ролик, показываем `oEmbed`-заголовок
   (проверено: `oEmbed` из браузера доступен). Иначе — честная строка «в этом браузере
   воспроизведение недоступно» без предложения кнопки.
3. **Подсказка про субтитры.** Из `tracklist()`: «у ролика есть ручные субтитры на иврите» /
   «только авто-субтитры» / «субтитров нет → загрузите файл» (живой путь S5b-lite).
4. **Приём субтитров:** поле файла (`.vtt`,`.srt`) и текстовое поле для вставки. Разбор мгновенный,
   локальный, бесплатный; сразу показывается число реплик и длительность покрытия.
5. **Превью** — как в S4: одна строка = одна реплика, редактируемо. Число строк изменилось → тайминг
   честно отбрасывается (`PREVIEW_EDITED`).
6. **«Использовать»** → текст в `#inputText`, паспорт в `window.v3LastImportMeta`. Дальше существующий
   путь «Перевести» → seg-режим → караоке.
7. Все новые строки → `ru/en/he` + bump `CACHE_VERSION` в `public/sw.js` (tt-fallback мёртв).

Мобильная ловушка `button { width: 100% }` — для каждого нового контейнера явное исключение
`#<id> button { width: auto; }`. Перед каждым UI-коммитом — Playwright-скриншот @380×844.

## 8. Обработка ошибок

| Ошибка | Поведение |
|---|---|
| Файл не разбирается | `CAPTIONS_UNPARSEABLE` — честный отказ; НЕ импортировать как простой текст |
| Во вставке нет таймкодов | `CAPTIONS_NO_TIMESTAMPS` + подсказка «нужна расшифровка с таймкодами, не просто текст» |
| Реплик 0 после разбора | `CAPTIONS_EMPTY` — без пустой таблицы |
| Больше 400 реплик / реплика >2000 символов | `CAPTIONS_TOO_MANY` с числом; предложить более короткий фрагмент |
| Ролик запретил встраивание (`onError` 101/150) | плеер убирается, остаются таймкоды и ссылка «открыть на YouTube» |
| `credentialless` не поддержан | кнопка плеера не показывается вовсе (не «показать и сломаться») |
| YouTube IFrame API не загрузился | то же, `reason: 'no-yt-api'` |
| URL не YouTube | ветка S5a не включается, работает существующий `fetch-url` |
| `SEG_MAPPING_LOST` от translate-table | таблица есть, тайминг честно отброшен, warning в провенансе |

## 9. Инварианты программы (перенос в план)

- **R14/R12:** ноль новых серверных эндпоинтов, ноль новых серверных фетчей, `server.js` и
  `ingest/*` не меняются. Анти-приоритет «серверный yt-dlp/ffmpeg» не задет.
- **R11:** только сегмент-уровень. Пословные тайминги из авто-субтитров **отбрасываются**, хотя
  физически присутствуют в файле — соблазн «бесплатного word-level» отвергнут сознательно.
  `HE_RU_PROMPT`/`ANY_HE_PROMPT`, `renderTable` и Зал не тронуты (`smoke:reader-parity` зелёный).
- **R9:** субтитры и таблица — derived; тип дорожки — свидетельство с указанием источника, не факт.
- **R16:** LLM-затрат в добыче субтитров нет вообще; платный шаг только существующий перевод.
- **R15:** новых серверных хранилищ нет; субтитры живут в паспорте текста, как сегодня транскрипт.
- **R4:** ни одного молчаливого тупика — каждая недоступность объяснена и ведёт к рабочему пути.
- **COEP/COOP `index.html` не трогаем.** Изоляция обязана остаться `true` — это проверяется в smoke.

## 10. Тесты и гейты

- **Unit (`node --test`):** `captions-parse.js` — VTT, SRT, вставка панели, катящиеся, сущности,
  пробельные строки тела, главы, капы, все `error_code`; `parseVideoId` (watch/youtu.be/embed/shorts
  + мусор); правка `ensureRun` (адаптер vs блоб).
- **`smoke:captions-parse` (новый) — independent-oracle гейт:** разбор `.vtt` из
  `scripts/premium/fixtures/captions/` **с `merge:false`** сверяется с `json3`-сериализацией той же
  дорожки (оракул хранит по событию на реплику, поэтому сверка идёт до слияния). Планка,
  достигнутая прототипом и обязательная к удержанию: **ручные 411/411 текст 100% старты 100%;
  катящиеся 65/65 текст 100% старты 100%.** Отдельно — инварианты слияния на тех же фикстурах:
  ни один символ не потерян (конкатенация сегментов = конкатенация реплик), старты неубывающие,
  старт сегмента равен старту его первой реплики, число сегментов ≤ числа реплик и ≤ капа.
  Плюс разбор обеих фикстур вставки.
- **Живой smoke плеера (обязателен ДО релиза):** Playwright против прода, реальные Chrome и Edge —
  `credentialless` iframe, `onReady`, `getDuration`, продвижение часов, `crossOriginIsolated === true`
  после встраивания. Скрипт разведки уже написан и переносится в `scripts/premium/`.
- **Регресс:** существующие `smoke:ingest`, `smoke:media-karaoke`, `smoke:reader-parity`,
  `test:api-smoke`, `smoke:i18n` — зелёные.
- **UI:** Playwright-скриншот @380×844 перед каждым UI-коммитом.
- **De-risk порядок:** транспорт-разведка уже выполнена (§4) — это снимает спайк-задачу с плана;
  первой задачей идёт pure-ядро парсера под оракульным гейтом.

## 12. Риски

| Риск | Контрмера |
|---|---|
| YouTube меняет формат панели «Расшифровка видео» | парсер терпимый, при непонятном вводе — честный отказ, а не мусор; фикстура зафиксирована; ломается видимо у пользователя, не молча |
| YouTube ломает совместимость embed с `credentialless` | `capability()` + `onError` → деградация на таймкоды и ссылку; таблица не зависит от плеера |
| Пользователь приносит машинно-переведённую дорожку | формулировка провенанса по умолчанию «тип дорожки не проверен»; уточнение только по свидетельству плеера |
| Авто-субтитры плохого качества как «истина» | бейдж «авто-субтитры, качество не гарантировано»; текст derived, событий памяти не порождает |
| Chrome Android ведёт себя иначе, чем эмуляция | owner-приёмка на реальном телефоне до закрытия слайса |
| Правки превью ломают mapping | существующий контракт «число строк = число сегментов», иначе честный drop |
| Расхождение капов клиент/сервер | капы читаются из одного места и покрыты unit-тестом (урок: конфиг-строка должна совпадать по построению) |
