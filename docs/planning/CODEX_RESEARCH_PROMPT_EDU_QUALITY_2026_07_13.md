ИНВАРИАНТЫ (нарушающее их предложение = брак):
- R1: LLM никогда не утверждает морфологию (лемма/корень/биньян/POS) — только
  резолвер с провенансом; LLM переформулирует поверх.
- R17 «кто учит — не сертифицирует»: память ученика (review_log) пишет ТОЛЬКО
  детерминированный грейдер; всё LLM-порождённое — advisory, вне памяти.
- MNAR: просмотр/объяснение — не учебное событие; неответ информативен.
- Этикет: ни одного LLM-вызова и автооткрытия без явного тапа; честные
  empty-state; провенанс на всём генерируемом; textContent-рендер.
- Privacy классы A–D: личный текст — только за двойным consent, класс D не
  персистится; корпус — общий. Все новые user-данные несут user_id.
- Честность: никаких заглушек, никаких сфабрикованных чисел, деградация
  подписывается; scaffold-изменения никогда молча.
- R16: каждый LLM-сценарий через квоту/леджер; стоимость управляема.

ЗАДАЧИ ИССЛЕДОВАНИЯ (все три — обязательные):

A. АУДИТ ОБРАЗОВАТЕЛЬНОГО КОНТУРА. Пройди путь ученика (первое знакомство →
   ежедневная петля чтение/повторение/диалог → долгосрочный прогресс) по живому
   коду и оцени против науки SLA (comprehensible input i+1, retrieval practice,
   spacing, производство vs рецепция, корректирующая обратная связь, мотивация/
   автономия) и против конкурентов (Duolingo Max, LingQ, Readlang, TalkPal,
   Speak). Где контур рвётся? Что агент ЗНАЕТ о студенте, но не ИСПОЛЬЗУЕТ
   педагогически? Примеры направлений (проверь и расширь): межсессионная
   связность наставника (помнит ли он вчерашний диалог?), диагностика ошибок
   письма → целевые упражнения, прогрессия сложности диалогов, отсутствие
   произношения/аудирования длинных форм, misconception-карта (зачаток есть),
   цели/учебный план недели, а не только дня.

B. ЕЖЕДНЕВНЫЕ АРТЕФАКТЫ КАК ТОПЛИВО. Для каждого потока (review_log,
   srs_projections+channel_stats, agent_ux, nudge_ledger reasons, история
   объяснений, тексты/черновики ученика, llm_usage_ledger) ответь: какие
   педагогические сигналы в нём уже лежат неиспользованными? Предложи контуры
   «данные → детерминированный вывод → действие наставника» (например: паттерн
   ошибок по биньянам из review_log → приоритет конструкции в плане; latency
   как прокси автоматизации навыка; agent_ux dismissed-паттерны → калибровка
   нуджей). Помни: ретроспективный анализ, не RCT-гейты; выводы должны быть
   детерминированными и объяснимыми (анти-циркулярность: LLM не оценивает сам
   себя).

C. ПЕДАГОГИЧЕСКИЙ КАНОН В ДОЛГОВРЕМЕННОЙ ПАМЯТИ АГЕНТА. Спроектируй, как
   загрузить агенту обучающую литературу так, чтобы советы наставника стали
   методически grounded, а не «общими знаниями LLM»: (1) корпус источников —
   составь конкретный список кандидатов по категориям: SLA-классика (Krashen,
   Nation по вокабуляру, retrieval/spacing литература), методика иврита
   (учебники грамматики, частотные списки, ошибки русскоязычных в иврите),
   CEFR-дескрипторы; для КАЖДОГО — лицензионный статус (public domain / открытая
   лицензия / нужна покупка — фильтр обязателен); (2) архитектура: как хранить
   (артефакт-модель «общее» как corpus works? отдельный pedagogy-store? RAG с
   каким индексом?), как агент достаёт (retrieval в context-pack сценариев —
   каких именно?), как цитирует (провенанс «источник: Nation 2001» в мете —
   инвариант честности); (3) чем это ЛУЧШЕ базовых знаний модели — где
   grounding реально меняет совет (дозировка новых слов, выбор упражнения,
   формулировка корректирующей ОС), а где это карго-культ; будь честен.
