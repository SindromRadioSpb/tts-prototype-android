## 0. Итог в трёх строках

1. **Термин по нажатию** — слово, привязанное в данных атласа к термину (`term#sense`), открывает карточку термина:
   огласовка, транслит, значение в этом месте, страницы книги, «в мой словарь». Только данные атласа, без нового разбора.
2. **Морфология любого слова** — та же карточка слова, что в других материалах Зала (корень, биньян, форма, Pealim,
   статус), по заранее выпеченному разбору Dicta; где слово — вычитанный термин, побеждает термин.
3. **Раскраска по узнаваемости** — статус слова из «Моего словаря» (только чтение), по умолчанию выключена; затем на
   этом слое строится тренажёр G6 (снятие перевода по ступеням).

## 2. Требования и анти-цели

Требования: то же поведение карточки слова, что в других материалах (без форка семантики метки/оценки/заметки —
инвариант `morph-host.js`); технические термины атласа — по вычитанному словарю, а не по догадке разборщика; RU/EN/HE,
390/768/1440, RTL, темы, без горизонтальной прокрутки; печать не меняется; поиск и озвучка работают как раньше.

Анти-цели:
- открытие страницы или раскраска пишет что-либо в `word_status`/`review_log` (только явное действие человека);
- инженерный термин получает бытовое значение от Dicta («שן» — зуб колеса, а не зуб человека);
- обёртка каждого слова роняет память или замедляет длинный раздел на телефоне (урок OOM на iPhone, 3.11.760);
- нажатие на слово при открытом плеере непредсказуемо: то читает отсюда, то открывает карточку;
- раскраска включена молча и забивает экран, где уже четыре колонки.

## 3. Решения архитектуры (предлагаемые)

| Решение | Почему |
|---|---|
| Разбиение на слова — при отрисовке только строки иврита (`he_niqqud`, иначе `he`), лениво: раздел целиком не оборачивается сразу, страницы — по мере появления в окне (`IntersectionObserver`) | память и скорость на длинных разделах; печать и поиск видят тот же текст |
| Позиции терминов в блоке — вычисляются при сборке (`build_reader_data.py` или пост-шаг): для каждой ссылки `term#sense` найти слово(а) блока по скелету с проклитиками (тот же разбор, что поиск, `atlas-search.js`); не найдено — ссылка остаётся на уровне блока (чип «термины абзаца») | честно: ссылка без места не выдумывает место |
| Разбор Dicta — выпекается заранее для блоков атласа, как Д8-К4 (локально, ≤ 2 потока, журнал, привязка по хэшу строки), лежит на томе рядом с разделами (`atlas/a97002/parse/<sid>.json`) | один разбор для всех, без согласия и ожидания; правка текста → нет совпадения хэша → нет разбора (не старый) |
| Термин побеждает Dicta на своих словах; Dicta — на остальных | вычитанный инженерный смысл важнее общего разборщика |
| Карточка — `ReaderMorph`/`morph-host` Зала через переходник атласа (§W0 решает, как: временный «несохранённый» текст или регистрация раздела как корпусной работы в локальной базе) | один канон памяти слова в продукте |
| Раскраска — только чтение `word_status` по `lemma_key`, кэш на раздел, перекраска по `onProfileChanged` | без записей при чтении |
| Плеер и слова: при открытом плеере нажатие на слово — «читать отсюда», карточка — долгим нажатием/второй кнопкой; при закрытом — карточка | одно предсказуемое правило (решение E3) |

## 4. Этапы и задачи

Порядок: **W0 → W1 → W2 → W3**, затем тренажёр (отдельный план). Ставить после V5 (озвучка всей книги) и до или
параллельно с печатью всей книги (дизайн §10 п. 4). Каждый этап — красные тесты сначала, отдельный коммит, выпуск по
правилам атласа (данные на том до кода, версии синхронно, проверка на живом сайте).

### W0. Исследование и решения (без выпуска)
- Как работает карточка `ReaderMorph` при `getTextKey() = null` и без `verifyOccurrence`: что доступно (разбор,
  статус, «в мой словарь», заметка), что недоступно, что пишется. Сравнить с вариантом «раздел атласа = корпусная
  работа в локальной базе» (цена: память, синхронизация, удаление).
- Замер на реальных данных: позиции терминов — сколько из 1 821 ссылок находятся в тексте блока по скелету; сколько
  слов в разделах (самый длинный), время обёртки страницы и раздела на телефоне среднего класса (CPU ×4).
- Оценка выпечки Dicta: число строк/слов, время при ≤ 2 потоках, объём файлов на томе.
- Отчёт `docs/research/engineering-atlas/2026-11-xx-word-layer-spike/README.md` + выбор варианта; вопросы E1–E5 владельцу.

### W1. Термин по нажатию
- Сборка: позиции терминов в блоке (поле `term_spans` или пост-шаг), отчёт «ссылка без места».
- Ридер: слова-термины в строке иврита — кнопки (подчёркивание точками, не цвет); карточка термина: лемма с
  огласовкой, транслит, значение в этом месте (`sense`), другие значения, чипы страниц (как в поиске), «▶» (озвучка
  термина — запись из P3, если есть), «в мой словарь» (через `morph-host`, явное действие).
- Блок с терминами без места — чипы «термины абзаца» под переводом (по переключателю «Колонки»).
- Тесты (linkedom), браузерный smoke 390/1440 RU/HE; печать без изменений.

### W2. Морфология любого слова
- Выпечка разбора Dicta для блоков атласа (скрипт по образцу `bake-corpus-place-parse.js`), привязка по хэшу строки,

- **E6:** архив для ИИ-агента собирается скриптом и кладётся на Google Диск, как пакеты dots; кнопки в атласе нет.

## 7. Стоп-лист

- без форка семантики `morph-host.js` (метки, оценки, заметки) и без правок `reader-core.js`;
- никаких записей в `word_status`/`review_log` при открытии, прокрутке, раскраске, озвучке;
- выпечка Dicta — только локально, ≤ 2 потока, с журналом; не с сервера и не из браузера пользователя;
- не править опубликованные JSON разделов руками (правки — `corrections/a97002.json`);
- запись на прод и деплой — по правилам атласа, данные до кода, с резервной копией.
