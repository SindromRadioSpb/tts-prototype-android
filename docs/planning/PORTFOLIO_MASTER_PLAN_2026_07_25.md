## 1. Диагноз: почему казалось, что «нет общего плана»

Два разных явления, которые полезно развести:

**(A) Стратегических фреймов было четыре за 10 дней — но живой один.**

| Фрейм | Дата | Тезис | Решение владельца |
|---|---|---|---|
| North Star | 2026-07-11 | Reading Intelligence → Personal Mentor → Hebrew OS | ❌ PROPOSAL, D1–D7 пусты |
| AI Agent Education Strategy | 2026-07-11 | «least-agentic-sufficient», детерминированное ядро | ❌ PROPOSAL, D1–D17 «DECISION REQUIRED» |
| Edu Quality Agentic | 2026-07-13 | Разрыв = continuity; F1/F2/F3 память/evidence/корпус | ❌ «no implementation authorization» |
| **Hermes Education Scale-up** | **2026-07-21** | Закрыть production speech+writing+SRL через агента Hermes | ✅ **APPROVED, исполняется** (У1–У8, Д5=GO H2, Д6=GO H3) |

Frame 4 **консолидирует** (а не параллелит) три предыдущих: операционализирует ту же мысль
«Reading → Personal Mentor». Frames 1–3 остаются **справочником инвариантов/рисков**, не дорожной картой.
→ Стратегия де-факто **уже пере-сошлась**. Расхождение в основном *документальное* — старые фреймы лежат рядом и шумят.

**(B) Реальное живое напряжение — сдвиг поверхности доставки.**
Активная разработка ушла с «in-app агент (PAS Wave 2, исполнитель Claude)» на «масштабировать личного агента Hermes
(hermes-education-scaleup, исполнитель Codex)». Последние ~15 коммитов — целиком Hermes (C1/C2 voice).
Это оставило пласт in-app Wave 2 в статусе **`ENGINEERING_COMPLETE / EVIDENCE_DEFERRED`** и поставило AI-наставника на паузу.
Это — настоящая развилка (§6), а не путаница.

## 3. Оперативное vs стратегическое

**Оперативные (доделать/поддерживать — решений не требуют):**
- H2.7 Hermes closure-аудит (текущий фронт).
- **Mini App P8.6 security-ops** — firewall на `:8000`, ротация `AUDIO_UPLOAD_TOKEN`, UptimeRobot `disk_warn`. **Must-do независимо от стратегии.**
- BRR-хвост: proclitic Phase-3 rollout, доэнричить 61 работу, каденция бейка/публикации.
- Retention P6 — по календарю (~окт), не по решению.
- Поддержка: Room-continuity, Sync-hardening.

**Стратегические (открытая развилка):**
- Первичная поверхность доставки: in-app агент vs личный Hermes (§6).
- Долг evidence: «построено, но не подтверждено» (F1/F2/CP0/LB2).
- Проблема **N=1**: весь портфель валидирован только на владельце.
- Судьба S4–S7 / F3-M1 / хвоста Mentor.

## 4. Три стратегических факта, на которых держится рекомендация

1. **Evidence-долг — конкретен.** `S3 CP0` (построен, окно не запущено), `F1` (построен, owner-only), `F2` (evidence-run-1 открыт), `LB2` (evidence deferred). Паттерн: код написан, контур «реально работает/помогает?» не замкнут. Долг растёт, потому что новые треки открываются быстрее, чем закрываются доказательства по старым.
2. **N=1.** Mini App — «owner-pilot, не product-validated»; F1/F2 — owner-only; CP0 — окно не запущено; Hermes — личный агент. Ни одна фича не проверена на людях, кроме владельца.
3. **Развилка поверхности** (§6) — усилие уже де-факто ушло на личного Hermes; это конкурирует с in-app доставкой.

## 6. Развилка поверхности: in-app агент vs личный Hermes

| | **A. In-app агент** (PAS + Telegram Mentor) | **B. Личный Hermes** (hermes-education-scaleup) |
|---|---|---|
| Что это | LLM-слой *внутри* LinguistPro (Studio/Зал-компаньоны, объяснения, role-play, writing, next-text, нуджи + бот Mentor) | Внешний always-on агент владельца (WebUI + iPhone «Hermex») по OAuth-MCP; закрывает speech/writing/недельный SRL |
| Достигает | **всех пользователей** (и пилот-учеников) | **владельца** (personal + R&D) |
| Исполнитель | Claude | Codex |
| Плюсы | доставляет ценность конечным юзерам; здесь живёт evidence-долг; **обязателен для пилота**; уже зрелый | высокий *личный* рычаг; быстрая итерация; дешёвый R&D-полигон (C1–C5); стресс-тестит MCP-субстрат |
| Минусы | скован инвариантами/мульти-юзером/i18n/SW; медленнее; cost/юзер на масштабе | **не достигает внешних юзеров** (N=1); риск бесконечного R&D-стока; расширяет разрыв owner↔продукт; координация двух линий |
| Роль | делает **продукт** лучше и **валидируемым** | делает **владельца** и R&D лучше; де-рискует будущее — но не валидация продукта |

**Синтез (рекомендация):** это не «A или B», а назначение ролей:
- **A — первичен** для ценности+валидации: закрыть F1/F2/CP0, пилот на моате.
- **B — ограниченная R&D-полоса** с **exit-гейтом**: добить H2.7, довести C2 до go/no-go, дальше **новые чартеры (C3–C5) только по вопросу «заработал ли результат решение о production-поставке?»** — не по инерции. У R&D должен быть выход.
- **Два исполнителя — преимущество, если у каждой полосы WIP-лимит + записанный exit** (иначе — сегодняшний разброс). Дисциплина: ровно один активный трек на полосу + условие закрытия.
