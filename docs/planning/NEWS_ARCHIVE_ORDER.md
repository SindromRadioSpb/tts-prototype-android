# Архивный добор одной статьи

Редакторский API позволяет дополнить список учебных статей после закрытия
выпуска. Это отдельная публикация одной статьи, не новый выпуск и не пересборка
«Обзора дня». Клиент выбирает ровно один существующий `item_key`, без передачи
URL либо текста в запросе на добор. Сначала проверяйте, нет ли готовой учебной
статьи для той же исходной публикации; если она уже есть, используйте её ссылку.

## Порядок

1. Найдите `item_key` в `candidates.json` исходного закрытого выпуска.
   При открытом выпуске сохраняется обычный путь `/:id/extras`.
2. Вызовите `POST /api/news/editor/editions/:id/archive-order` с
   JSON `{"item_key":"na_…","note_ru":"Причина выбора"}`. Нужны те же
   редакторские права, что для обычного добора (редакторский Bearer либо
   авторизованная сессия с CSRF). Не записывайте ключ ни в архив, ни в журнал.
3. Скачайте выданный ZIP и распакуйте его в отдельную рабочую папку. Сохраните
   `archive-order.json`, имена файлов, оригинальные строки, разбиение на абзацы,
   источник и снимки. Заполните учебные поля, как в обычном пакете.
4. Выполните `node scripts/news/build-pack.js <папка> --check-only`, затем без
   `--check-only` и отправьте ZIP на `POST /api/news/editor/packs` от того же
   редактора. В пакете должен быть лишь один связанный оригинал. Не прикладывайте
   `overview.json`, список отказов, `withdraw` или старый `edition_id`.
5. Проверьте квитанцию публикации и ссылку работы (`items[0].work_id`). Повторная
   отправка того же успешного пакета вернёт дубликат с действующей ссылкой,
   если материал по-прежнему доступен. Повторный запрос добора с теми же полями
   и учётной записью до завершения выдаёт тот же ZIP.

## Ограничения

- Допустим только кандидат из сохранённого `candidates.json` и `overview.json`
  закрытого среза, для которого по-прежнему есть полный, неплатный сохранённый
  текст. Источники не скачиваются заново; адрес, дата, исходный заголовок,
  идентификатор статьи и сюжет должны совпадать. Через 72 часа от среза либо
  по окончании срока хранения кэша текста добор недоступен (`SOURCES_EXPIRED`,
  HTTP 410). Окно готового заказа не больше шести часов и обрезается остатком
  срока хранения исходника.
- Фотографии берутся из кэша либо по сохранённым в парсинге адресам с
  разрешённых HTTPS CDN этого издания, без переходов по редиректам и с
  учётом robots.txt. В заказ входят **все** сохранённые фотографии в рамках
  действующего лимита формата (12). Пропуск, превышение лимита или неудачная
  загрузка блокируют весь заказ (`ARCHIVE_PHOTOS_UNAVAILABLE`), без резервации
  статьи. Это снимок байтов на момент выдачи заказа, не доказательство
  неизменности файла на CDN с момента среза, если фото тогда не было скачано.
- При загрузке сервер проверяет оригинальные Hebrew-строки, их порядок и номера
  абзацев, исходные атрибуты, неизменность фотографий и обязательные учебные
  слои. Публикация уже известной статьи, в т.ч. удалённой или архивной, через
  эту операцию не допускается (`ALREADY_TAKEN`).
- Заказ хранится отдельно от выпусков. Пока он действует, строка не может
  попасть в очередной полный пакет либо в обычный добор, но не удаляется из
  обзора. Успешный результат отображается по той же канонической карточке,
  без изменений старого ZIP, счётчиков, сроков выпуска, текста обзора и
  расписания. Записываются актор, исходный выпуск, ID заказа и ID пакета.
  По истечении срока удаляется только временный архив заказа; опубликованная
  работа, запись происхождения и журнал событий остаются.

## Локальная проверка

`node --test tests/newsArchiveOrders.test.js`: HTTP-заказ и загрузка, 12 фото
Maariv на имитации CDN, сбой одного фото и запрет robots.txt, защита исходника,
права редакторов, повторная публикация, срок хранения, обычный добор и отсутствие
вмешательства в запланированные выпуски. Применяется миграция
`090_news_archive_orders.sql`. Тесты используют изолированные SQLite и HTTP,
фоторесурсы и данные синтетические.
