# 03 — Горизонт 1: исполнительный дизайн (9 слайсов)

«Без кода LinguistPro» ≠ «без инженерной работы»: слайсы H1 меняют Hermes-side артефакты —
skills, `~/.hermes/config.yaml → mcp_servers`, локальные MCP-обёртки, датасеты на диске.
Прод LinguistPro, его схемы и MCP-поверхность в H1 НЕ меняются вообще.

## Общее для всех слайсов

- **Репозитории:** канонические артефакты → LinguistPro-репо `docs/planning/hermes-education-scaleup/2026-07-21/hermes-side/<slice>/` (G:\HERMES_AGENT — не git; там только рабочие копии). В hermes-side/ каждого слайса: артефакт + README (что, как установить, как проверить, как откатить).
- **Установка скиллов:** владелец передаёт текст скилла агенту Hermes (workspace G:\HERMES_AGENT смонтирован в контейнер как /workspace) — Hermes сохраняет в своём skills-store; верификация — попросить агента воспроизвести активную политику своими словами + прогнать пробный сценарий.
- **Установка MCP:** правка `~/.hermes/config.yaml` (внутри volume `hermex-hermes-home`) — аддитивная секция `mcp_servers`; ⚠ listChanged:false → после правки обязателен `docker restart hermes-agent hermes-webui` + НОВАЯ сессия агента, иначе инструменты не появятся.
- **Rollback любого слайса:** удалить секцию из config.yaml / попросить агента деактивировать скилл, рестарт контейнеров. Прод LinguistPro не затронут by construction.
- **Данные наружу (privacy-инвариант H1):** внешним MCP (Sefaria, YouTube, LRCLIB) передаются ТОЛЬКО поисковые запросы (название песни, цитата, слово) — никогда содержимое личных текстов, due-списков или профиля целиком. Фиксируется в trainer policy (H1.0) как правило.
