2. Проверь живое состояние: `git log --oneline -3`, версия в package.json; сверь со STATUS.
3. Определи следующий шаг по правилам:

   - H1.0 CLOSED, скиллы (H1.1–H1.3) не все CLOSED → любой незакрытый из `H1_02`/`H1_03`/`H1_04`
     (параллелизуемы разными сессиями).
   - Скиллы закрыты, интеграции (H1.4–H1.7) не все CLOSED → любой незакрытый из `H1_05`–`H1_08`
     (параллелизуемы; ⚠ все правят один `~/.hermes/config.yaml` — мержить аддитивно).
   - H1.0–H1.7 CLOSED (или SKIPPED с вердиктом) → `H1_09_OWNER_LIVE_AND_CLOSURE.md`.
   - H1 CLOSED → сообщи владельцу: нужен явный go на H2 (Д5, гейт G-H2-START в
     `10_ACCEPTANCE_GATES_AND_CLOSURE.md`); H2-промты BLOCKED до этого go.

5. Если STATUS расходится с реальностью (например, артефакт слайса есть, а статус PLANNED) —
   зафиксируй расхождение в отчёте; STATUS правит только сессия, исполнявшая слайс, либо
   владелец — не «чини» чужие строки молча.
