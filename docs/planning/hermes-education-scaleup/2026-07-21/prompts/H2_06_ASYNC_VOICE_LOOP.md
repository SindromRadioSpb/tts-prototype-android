сессия (скилл H1.1) → отложенный разбор → опц. propose_track_word (H2.3). Контракт — 04 §6.

мелочи inbox-конвенции).

## Инварианты
Transcript preview ОБЯЗАТЕЛЕН до разбора: юзер подтверждает/правит — ASR-ошибка не должна стать
«ошибкой ученика» (правило 13 политики). Raw audio не хранится (Д7 — уже обеспечено H2.5);
транскрипты ephemeral (Д1). ASR умер → петля деградирует в текст, не ломается. Облачный fallback
запрещён. propose_track_word из голосовых — с caveat POSSIBLE_ASR_ERROR где уместно. TTS-ответ —
существующим продуктовым TTS через handoff, НЕ новым каналом.

## Scope / Non-goals
Scope: скилл-текст «Голосовая сессия» (расширение H1.1 состоянием VOICE_INTAKE→TRANSCRIPT_PREVIEW)
+ конвенция voice-inbox (как владелец кладёт файл: путь/формат) + 3 сценария + канон + STATUS.
Non-goals: realtime (H3-C2); произносительный фидбек (H3-C1); хранение аудио/транскриптов;
изменение H1.1-скилла для текстовых сессий (голосовая — надстройка).

## Пошаговая работа
1. Скилл-текст: VOICE_INTAKE (файл в inbox) → transcribe_audio → TRANSCRIPT_PREVIEW (полный
   текст + помеченные неуверенные сегменты + «верно? поправь») → далее машина H1.1 (recasts →
   POST_ANALYSIS → RETRY) с добавкой: в разборе отдельно «где я тебя мог неверно расслышать».
2. Конвенция inbox в README: путь, форматы, «1 сообщение = 1 файл», очистка (H2.5 удаляет сам).
3. Сценарии (транскрипты в `hermes-side/h2.6/ACCEPTANCE_TRANSCRIPTS.md`):
   - A: полный цикл голосовое→preview→сессия→разбор;
   - B: preview с 1 правкой юзера — правленый вариант используется в разборе;
   - C: ASR недоступен (выключи обёртку) — честная деградация в текстовую сессию.
4. Канон: `hermes-side/h2.6/VOICE_SESSION_SKILL.md` + README + транскрипты.
