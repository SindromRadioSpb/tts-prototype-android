# H1 parallel monitoring — короткие запросы к Hermes

Окно: **2026-07-23 — 2026-08-05 включительно**. Запросы можно вставлять в
обычные новые чаты. Hermes только проводит сессию и выдаёт компактный итог;
владелец переносит цифры в H1.8 evidence. Никаких скрытых записей: любое
изменение LinguistPro — только отдельный proposal и подтверждение владельца.

## 1. Реальная польза после любой H1-сессии

```text
Подведи итог только что завершённой реальной учебной сессии: тип петли,
примерные минуты, что помогло, что мешало, retry X/Y и моя оценка пользы 1–5
(спроси её, не придумывай). Не оценивай mastery/уровень и ничего не записывай.
```

## 2. Разговор — выполнить дважды за окно

```text
Проведи conversation skill по моему личному материалу: 8–15 моих реплик на
иврите, recast в потоке, разбор 3–5 повторных ошибок и retry. В конце спроси
оценку 1–5 и выдай: реплики, минуты, retry X/Y, без изменения LinguistPro.
```

## 3. Письмо — выполнить дважды за окно

```text
Проведи полный writing WCF: задание → мой черновик → feedback ровно по 2–3
категориям → моя ревизия → сравнение. В конце спроси оценку 1–5 и выдай минуты,
была ли реальная ревизия и сколько целевых ошибок исправлено. Ничего не сохраняй.
```

## 4. Недельная ретроспектива — один раз в каждую неделю

```text
Проведи weekly SRL по live-данным: факты → ровно два вопроса → до трёх
process-целей → мой выбор → якорь когда/где/что. Спроси оценку 1–5; proposal
создавай только после отдельного явного подтверждения. В итог выдай дату, цель
и X/Y дней исполнения прошлой цели; если данных нет — так и скажи.
```

## 5. Все интеграции вместе — один раз за окно

```text
Разбери выбранную мной песню/видео одним bounded-проходом: YouTube subtitles,
LRCLIB timestamp, Sefaria intertext и Kaikki+wordfreq для максимум двух лемм.
Вызовы делай последовательно; для каждого источника покажи provenance/ошибку,
ничего не выдумывай и не импортируй. В конце спроси общую оценку 1–5.
```

## 6. Safety, consent и стоимость — в начале и в конце окна

```text
Сделай read-only H1 audit: вызови get_agent_connection и покажи status,
consent_version, capability_version и granted_scopes; перечисли write/propose
tool calls этой сессии. Не называй стоимость без billing evidence: отдели
подтверждённые $0, неизвестное и неожиданные расходы. Ничего не меняй.
```

## 7. Решение по каждой петле — день 14

```text
По моему вставленному 14-дневному журналу сделай таблицу H1.1–H1.7:
использований, оценка 1–5, incidents, решение CONTINUE/REPAIR/DISABLE и одна
причина. Не восстанавливай отсутствующие факты и не сертифицируй mastery.
```

## 8. Continuation evidence — день 14

```text
По вставленному журналу проверь ровно критерий: есть ли хотя бы одна петля с
оценкой ≥4/5 и использованием ≥1 раз в каждую из двух недель. Ответь YES/NO,
назови петлю и даты; при нехватке данных ответь NOT_PROVEN. Ничего не записывай.
```

## Stop-сигналы

Немедленно сообщить Codex/владельцу, не ждать day 14, если обнаружены:
unwanted write; новый scope/consent drift; неожиданный metered cost; повторная
галлюцинация/сикофантия; систематический отказ нужной петли.
