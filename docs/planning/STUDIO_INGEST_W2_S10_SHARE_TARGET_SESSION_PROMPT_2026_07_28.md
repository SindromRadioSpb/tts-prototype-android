## Задача слайса

«Поделиться» с телефона (URL / текст / файл) из любого приложения → PWA LinguistPro →
диалог «Импорт» с предзаполненной правильной вкладкой. Множитель для ВСЕХ инжест-сценариев:
ютуб-ролик из приложения YouTube, статья из браузера, аудио из диктофона/файлового менеджера,
.vtt/.srt из мессенджера — всё в two-tap. Фундамент готов и больше не ограничен 20 минутами
(S12); диалог уже имеет три вкладки и авто-классификацию ютуб-ссылок (`fetchUrlOrVideo`).

## Что уже известно (проверить по живому коду, не принимать на веру)

1. **`share_target` в манифесте отсутствует** (инвентарь §2 канона, строка ~50). Найти
   манифест (`public/manifest.json`?), его текущие поля, как SW относится к навигациям.
2. **SW-архитектура:** `public/sw.js`, precache + CACHE_VERSION-механика; ЛЮБАЯ правка sw.js =
   бамп CACHE_VERSION. Для файлового шаринга спека требует `method: POST` +
   `enctype: multipart/form-data` — POST-запрос надо перехватывать в SW (fetch-хендлер,
   стэш в Cache/OPFS, redirect) ИЛИ заводить серверный роут. **Zero-server-growth склоняет к
   SW-перехвату — но это надо разведать живьём**, а не предположить.
3. **COEP/COOP:** приложение отдаётся с `COEP: require-corp` (S5a: `crossOriginIsolated`
   обязан остаться true — на нём wa-sqlite и YouTube-плеер через credentialless). Как ведёт
   себя share_target-навигация (POST c redirect) под этими заголовками — разведать. Это
   главный кандидат на «стену», о которую может разбиться наивный дизайн.
4. **Платформы:** Android Chrome/Edge поддерживают share_target; **iOS Safari — НЕ
   поддерживает вовсе** (и не собирался). У владельца iPhone — т.е. слайс в первую очередь
   для Android-учеников; honest-деградация обязательна (R5 capability-before-offer:
   на iOS фича просто не существует, никаких мёртвых кнопок).
5. **Cold-start:** шаринг чаще открывает PWA с нуля. index.html — 39K строк; данные шаринга
   должны пережить бут и открыть `StudioImport.open()` с предзаполнением. Замерить время
   бута на троттлинге и решить, где живёт стэш (sessionStorage? OPFS? Cache API) и как
   диалог узнаёт о нём (URL-параметр? сообщение от SW?).
6. **Целевые сценарии шаринга — уточнить у владельца ДО дизайна:** из каких приложений
   реально шарят ученики? (YouTube шарит URL; подкаст-приложения обычно шарят URL эпизода,
   НЕ аудиофайл; файлы приходят из файлового менеджера/диктофона/WhatsApp.) От ответа
   зависит, нужен ли вообще POST/multipart-путь в v1 или хватит GET (url+text).

## Замеры/разведка ДО дизайна (R10 measure-before-code — норма проекта)

3. **GET-вариант (url/text/title)** — самый дешёвый путь; проверить, как параметры доезжают

## Развилки, которые надо решить ДО кода (вынести владельцу)

- **Скоуп типов v1:** только URL+текст (GET, простой и надёжный) vs +файлы (POST+multipart+
  SW-перехват, сложнее и рискованнее под COEP). Цена/риск каждого — из разведки.
- **Серверный роут vs SW-перехват** для файлов (если файлы в скоупе): zero-server-growth vs
  надёжность; любой новый серверный вход — через существующие механизмы валидации (R14).
- **iOS:** честный анти-скоуп («фичи нет») vs заменитель-инструкция («открой приложение и
  вставь») где-нибудь в UI шаринга. НЕ городить полумёртвых суррогатов.
- **Поведение при уже открытой PWA** (share в существующее окно: focus + открыть диалог vs
  всегда новая навигация).
- **Провайдер-дыра (из S12, pre-existing S4-эры):** дефолт `#providerSelect` = `google-free`,
  при котором seg-путь (караоке, чанки) не задействуется вообще. Share-флоу сделает это
  заметнее: ученик пошарил подкаст, а караоке нет. Кандидат в скоуп S10 или отдельный
  微-слайс: форсить/подсказывать gemini-провайдер для медиа-импортов. Решение владельца.

## Инварианты (не нарушать)

- **browser-first BYOK**: серверного Gemini-ключа НЕТ; пользователь платит своим.
- **Zero-server-growth по возможности**; новый серверный вход — только через развилку
  владельцу; любой внешний fetch — через `ssrfGuard` (R14).
- **R9 derived≠asserted**: провенанс `origin=share_target` (+исходное приложение, если
  доступно) — в паспорт импорта.
- **R5 capability-before-offer**: iOS не видит несуществующую возможность.
- **COEP/`crossOriginIsolated` должен остаться true** — гейт `smoke:yt-player`/wa-sqlite.
- **Byte-parity**: `renderTable`/reader-core не трогать — `npm run smoke:reader-parity`.
- **SW:** любая правка `sw.js` → бамп `CACHE_VERSION`; **локали**: каждая новая строка →
  ru/en/he СРАЗУ + бамп `?v=` у всех трёх locale-тегов `index.html` И `CACHE_VERSION` одним
  изменением + `node tests/i18n.smoke.js --write-lock` (гейт `smoke:i18n`).
- Мобильная ловушка `button { width: 100% }`; скриншот 380×844 перед каждым UI-коммитом.
- **Git: стейджить ТОЛЬКО явными путями** (никогда `-A`/каталогом — в дереве лежат
  посторонние файлы владельца). Пуш — только в релиз-задаче.

## Уроки прошлых слайсов (S12 добавил новые)

- **Дефекты живут в плане, а не в коде**: числовые фикстуры/константы плана проверять
  РЕАЛЬНЫМИ вызовами до фиксации (S12-T3: фикстуры конфликтовали с константами дыр).
- **Правило формулировать целиком**, не кусками (подсказку о дорожках правили 5 раз).
- **Живой смоук ловит то, что не видят ревью** (S12: молчаливая дыра 31 мин; S5a: paused-лаг
  адаптера). Детерминированный фейк — вместо «нажми и посмотри» в автоматизации;
  `window.confirm` в продукте — стабить в смоуках.
- **Legacy-семантика на границе — главный источник глубоких багов** (S12: односторонняя
  защёлка `timingDropReason` на shared-паспорте пережила два fix-раунда).
- **Ревью кода строк-«копий» UI**: гейт-тест ловит «AI Перевод» даже в КОММЕНТАРИИ.
- **Деплой:** перед релизом проверить диск прода (`df -h /`) — 2026-07-28 был 100%
  (build-кэш 9.1 ГБ вычищен → 85%); зависший/упавший деплой перезапускается пустым
  коммитом; rolling-update даёт транзиентные 404.
