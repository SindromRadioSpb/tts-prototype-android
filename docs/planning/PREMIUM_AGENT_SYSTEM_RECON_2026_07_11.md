## §0 Мандат владельца (записан 2026-07-11)

Владелец **не подтвердил** measurement-first направление стратегических пакетов и задал своё: **премиальная зрелая система агентов в Студии и Зале; масштабирование AI для пользователя; старт owner-only, но артефакт-модель сразу различает личное (тексты/слова/предложения пользователя) и общее (корпус Бен-Иегуды, будущие корпуса); удобная настраиваемость; конкурентные практики топовых AI-приложений.** Уточнено тремя решениями:
- **Волна 1 = все четыре семейства**: читающий компаньон (Зал) · агент-редактор (Студия) · диалог/практика · оркестрация обучения.
- **Фичи-сначала**: owner-only на текущем runtime; полный control-plane/tenancy — отдельной волной позже.
- **Телеметрия лёгкая, не гейтит** шипы; ретроспективный анализ вместо RCT-гейтов.

Из стратегических пакетов переносятся ТОЛЬКО уже-канонические инварианты (§7) — они premium-направление страхуют, не тормозят. Пакеты (`NORTH_STAR_*`, `ai_agent_education_strategy_*`) остаются справочником возможностей/рисков, их sequencing НЕ применяется.

## §3 Личное vs общее (артефакт-модель, готовим мультиюзер малой кровью)

| Класс | Примеры | Доступ агента | Consent |
|---|---|---|---|
| Личное B/C | `learner_artifacts` (тексты), предложения | только через consent-гейтнутые tools (есть) | двойной, fail-closed (есть) |
| Личное производное | learner graph, review_log, channel_stats | read-tools (есть) | покрыто пэйрингом/консентами |
| **Общее** | корпуса (Бен-Иегуда, будущие) | **новый** `get_corpus_sentence_context` + каталог | НЕ нужен (public domain); только лимиты |

Правило на будущее число корпусов: общий артефакт = каталог `corpus-catalog-v<N>` + тела на томе; агент-tool принимает `{corpus_id, work_id, order_index}` — добавление корпуса не меняет агента. Все новые user-таблицы несут `user_id` (авто-GDPR-sweep — инвариант уже структурный).

## §5 ФОРК PAS-F1 — экономика ключей (главное решение владельца)

| Вариант | Суть | За | Против |
|---|---|---|---|
| **(a) Серверные AGENT_* на всё** | премиум-фичи платит сервер, per-user лимиты | «премиально из коробки», путь к подписке, один леджер | стоимость на владельце уже в пилоте; лимиты жёсткие |
| (b) BYOK на тяжёлое | диалог/объёмные фичи на ключе пользователя | масштабируется даром | «premium» с оговоркой «принеси ключ»; ломает UX-планку |
| (c) Гибрид | базовые квоты сервер + BYOK поверх как расширение | лучшее из двух; квота-бар уже есть как паттерн | сложнее объяснить и настроить |

**Рекомендация: (c) гибрид** — серверная базовая квота держит премиальность, BYOK-расширение снимает потолок владельцу-power-user'у сейчас и «продвинутым» пользователям потом.

## §6 Лёгкая телеметрия (не гейтит)

Каждая агент-фича обязана писать: (1) в `llm_usage_ledger` — свой scenario (есть механизм); (2) в `learner_events` — новый закрытый тип `agent_ux` c payload-идентификаторами `{feature, action: offered|accepted|dismissed|abandoned, latency_ms}` (никакого контента). Ничего не блокирует шип; смотрим ретроспективно «что живёт».

## §7 Инварианты (не пересматриваются без владельца)

1. **R1:** LLM никогда не утверждает лемму/корень/биньян/сенс — только resolver-факты с провенансом; переформулировка поверх.
2. **Память ученика:** review_log пишет только детерминированный путь (reviewer); диалог/письмо/вопросы — advisory, вне памяти (v1).
3. **Этикет:** ни одного LLM-вызова и авто-открытия без явного тапа; textContent-рендер; честные empty-state; провенанс-строка «🤖 provider·model» на всём генерируемом.
4. **Privacy:** классы A–D как есть; корпус — общий (без consent), личные тексты — двойной consent; context-pack класса D не персистится; log-hygiene гейт покрывает новые модули (расширить скоуп при добавлении файлов agent/).
5. **R16:** каждый сценарий через reserveLlmCall; kill-switch наследуется; BYOK-ключи никогда не логируются/не персистятся сервером.
6. **Процесс:** спека-дельта слайса → adversarial-критика (малый фронт) → код → гейты с exit-кодами → SW bump (карточка/Зал/Студия — precached) → локали ru/en/he для всех строк Зала → live-verify на прод-профиле.
