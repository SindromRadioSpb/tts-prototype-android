## 2. Требования и анти-цели

Требования: RU/EN/HE интерфейс, 390/768/1440, RTL, обе темы, без горизонтальной прокрутки; офлайн после открытия
раздела; печать, поиск, озвучка и карточка слова — как раньше; новые строки — во все три локали.

Анти-цели:
- открытие страницы, смена ступени, прокрутка, раскраска, упражнение «Найди в книге» или «Что за символ» пишут
  в `word_status`/`review_log` (в журнал памяти идёт только явная оценка термина в тренировке);
- ступень снижается или повышается молча — человек теряет перевод посреди чтения и не понимает почему;
- термин-словосочетание разрезан на слова и учится как два бытовых слова («כוח» + «היקפי» вместо «окружная сила»);
- в упражнении правильный ответ неоднозначен (фрагмент повторяется в книге дословно; два символа с одним смыслом)
  и честный ответ засчитан как ошибка;
- языковая модель выдаёт ответ упражнения: ответы — только из данных атласа (страница блока, строка таблицы обозначений);
- тренажёр подменяет книгу: ошибка не ведёт на страницу оригинала.

### G3. «Найди в книге»

**Файлы:** создать `scripts/atlas/build-train-bank.cjs` (+ тест в `scripts/atlas/tests/`), данные `train/find.json` на томе;
ядро и UI тренажёра; локали; smoke.

**Формат `find.json`** (`linguistpro.atlas-train-find.1.0.0`): `{ schema, atlas_id, built_from: { sections: { <sid>: content_pack_sha256 } },
items: [{ id, sid, page, block, he, formulas: [formulaId…], terms: [termRef…], kind: 'book' | 'exam' }] }`.
`he` — без огласовки, как в книге. Экзаменационные задачи владельца входят тем же файлом с `kind: 'exam'` (формат
приёма — §6).

**Интерфейс ядра:** `pickFind(bank, { sid | null, seen }) → item`; `checkFind(item, answer, index) → { section: bool, page: 'exact' | 'near' | 'wrong', formula: bool | null }`
(`near` — ±1 стр. в том же разделе, Г3); `findStats(history) → { attempts, sectionRate, pageRate, medianMs }`.
История — `localStorage` `room.atlas.find.v1`, последние 500 попыток.

**Шаги:**
- [ ] Тест сборщика: блок, чей текст дословно (без огласовки и пунктуации) встречается в книге ещё раз, — не в банке;
  блоки короче 6 или длиннее 30 слов — не в банке; `page` и `sid` совпадают с данными раздела; сборка на тех же
  данных даёт байт-в-байт тот же файл. FAIL → реализация → PASS.
- [ ] Тест ядра: верный раздел и страница → `exact`; соседняя страница того же раздела → `near`; верная страница чужого
  раздела невозможна; раздел без формулы → `formula: null`.
- [ ] UI: фрагмент крупно, RTL, без перевода; таймер; выбор раздела (оглавление на двух языках), номер страницы,

- [ ] Банк не загружен или устарел (`content_pack_sha256` раздела не совпадает) → вопросы этого раздела не задаются,

### G4. «Что это за символ?»

**Файлы:** ядро и UI тренажёра; локали; smoke.

**Интерфейс ядра:** `symbolQuestions(section, rnd) → [{ formulaId, page, latex, mathml, symbols: [{ latex, answer: { ru, he, unit }, options: { meaning: [4], unit: [4] | null } }] }]`;
`checkSymbol(q, picks) → { meaning: bool, unit: bool | null }`. Подходят формулы с ≥ 2 символами, у которых есть `ru`;
отвлекающие варианты — из таблиц того же раздела, с другим `ru` и другой единицей; символ без единицы — вопрос
только о смысле.

**Шаги:**
- [ ] Тесты: варианты не содержат двух одинаковых смыслов; верный вариант всегда среди четырёх; символы с одинаковым

## 9. Что легко пропустить (проверить на ревью)

1. Раздел без слоя «В контексте (ИИ)» или со строкой, отклонённой при приёме, на ступени 1 — честная строка, не пустота
   и не ошибка (тест в G1).
2. Термин с двумя значениями в разных разделах (`term#sense`) — две разные цели; ответ одного раздела не засчитывается
   другому (тест в G2).
3. Данные раздела пересобраны после правки (`content_pack_sha256` сменился) — вопросы «Найди в книге» этого раздела
   не задаются до пересборки банка (тест в G3).
4. Телефон 390 HE: подстрочник, сегменты ступени и выбор раздела из 42 пунктов — без горизонтальной прокрутки (smoke G1, G3).
5. Профиль без терминов и пустой `review_log` — панель «Тренировать» объясняет, с чего начать, а не показывает нули (тест в G2).
