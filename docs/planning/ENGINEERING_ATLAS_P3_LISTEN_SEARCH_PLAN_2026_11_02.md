## 0. Итог в трёх строках

1. **Поиск** — по всей книге, без сервера: компактный индекс `search.json` собирается вместе с данными ридера,
   ищет по ивритской/русской фразе, термину, обозначению, единице и транслиту; результат открывает нужную страницу и
   подсвечивает найденный объект. Не требует решений владельца — идёт первым.
2. **Озвучка** — заранее записанное аудио (контракт PB2): при чтении ничего не синтезируется, ключ пользователя не нужен,
   подмены голоса на браузерный нет. «▶ Слушать» читает раздел блок за блоком (иврит / русский / иврит → русский),
   «▶ RU / ▶ HE» в карточке формулы читает формулу и её обозначения. Текст для чтения формул строит
   **детерминированный генератор по проверенному словарю**, не языковая модель.
3. Код озвучки можно выпускать до записи аудио: без манифеста кнопок нет. **Запись аудио (платный вызов Google) —
   только после решений владельца D1, D3, D5** (§6).

## 3. Поиск — архитектура

### 3.1 Решения

| Решение | Почему |
|---|---|
| Индекс на клиенте, один файл `DATA_DIR/atlas/a97002/search.json` | Книга маленькая (≈ 0,7 млн символов всех полей); работает без сервера и офлайн; тот же приём «данные на томе», что у разделов. Серверный FTS не нужен. |
| Один общий модуль `public/js/atlas-search.js` (UMD: `window.AtlasSearch` + `module.exports`) для сборки и запроса | Байтовое совпадение нормализации при сборке и запросе — по построению (урок `corpus-fts`). |
| Сборка `scripts/atlas/build-search-index.cjs` (Node) из готовых `sections/*.json` | Индекс строится из **опубликованного** вида данных (после `reader_corrections`), поэтому совпадает с экраном. |
| Нормализация иврита — `CorpusFTS.normalizeToken`, не своя копия | Один канон в проекте. |
| Русская морфология — стеммер Snowball (Russian), JS-реализация в том же модуле, с тестами | Запрос «пружины» находит «пружина», «пружин»; без словаря на клиенте. Лицензию (BSD) указать в заголовке. |
| Обозначения и единицы — по проверенному словарю `atlas/a97002/notation-lexicon.json` (в git) | Греческие имена, индексы, варианты записи единиц — конечный список, его можно вычитать. |

### 3.2 Что индексируется (единица поиска = объект книги)

Каждая запись: `ref` (ID объекта, по которому ридер найдёт `data-ref`), `kind`, `sid`, `page`, поля для поиска и
короткий текст для выдачи (he/ru, ≤ 160 симв.).

| kind | Источник | Поля |
|---|---|---|
| `term` | `sections[].terms` (слить по книге по ID) | лемма, огласовка (снятая), транслит лат./кир., переводы смыслов; список страниц из ссылок блоков `term#sense` |
| `block` | `items[type=block]` | he (скелет), ru (стем), translit, translit_ru; `terms` блока |
| `formula` | `items[type=formula]` | ключи обозначений из `latex`, `result_var`, `vars[].latex/he/ru/unit` |
| `symbol` | `vars[]` формулы | ключ символа, he, ru, единица; `ref` = `vars[].ref`, цель прокрутки — формула |
| `table` | `tables[].cells` | he/ru ячеек; одна запись на таблицу, номер найденной ячейки — в выдаче |
| `figure` | `figures[]` + `regions[]` | подпись «איור N», метки областей he/ru |
| `example` / `erratum` | `examples`, `errata` | заголовок, текст |

Служебные поля поставщика (`editor`, `note`, `source_text`, `he_raw`, «редакционное…») **не индексируются** —
пункт 4.3 стандарта качества. Для выдачи использовать тот же фильтр, что ридер (`cleanMeta`); если он внутри
`factory`, вынести в общую функцию модуля без изменения поведения.

### 3.3 Нормализация и сопоставление

- **Иврит.** `normalizeToken`; плюс: гереш/гершаим (`׳ ' ״ "`) → один вид (аббревиатуры `מ"מ`, `מה"ט`); макаф `־` → пробел.
  Проклитики (ו, ה, ב, כ, ל, מ, ש и их цепочки до 3 букв) — **на запросе**: кандидаты-скелеты сверяются со словарём
  индекса; совпадение через снятие проклитики ранжируется ниже точного и помечается «по форме слова».
  Термины находятся и через ссылки блоков `term#sense` — это не зависит от формы слова в тексте.
- **Русский.** нижний регистр, `ё→е`, стем Snowball; точное совпадение слова выше совпадения по стему.
- **Транслит.** латиница и кириллица транслита — отдельные поля (запрос «kfits», «кфиц» находит קפיץ).
- **Обозначения.** канонический ключ символа: буква + индекс + штрихи. `\sigma_{Lc}`, `σ_Lc`, `σLc`, `sigma_Lc`,
  `сигма Lc` → один ключ; `d₁`, `d_1`, `d1` → один ключ; `\varphi`/`φ`/`ϕ` → один. Регистр значим (D ≠ d): точный
  регистр — первым, другой регистр — ниже с пометкой. Ключи извлекаются из LaTeX небольшим токенизатором по
  подмножеству команд книги (§1); неизвестная команда в формуле → формула всё равно индексируется по `vars`, а команда
  попадает в отчёт сборки.
- **Единицы.** группы равнозначных записей в словаре: `N·mm = N*mm = Н·мм = Нмм`, `mm² = mm^2 = мм²`,
  `rpm = об/мин = 1/min = min⁻¹`, `MPa = МПа`, `N/mm² ` — **отдельно** от `MPa` (физически равны, но это разная запись
  книги; показывать как «связанная единица», не как точное совпадение). Ивритские записи (`מ"מ`, `ניוטון`…) — туда же.
- **Фраза.** в кавычках — точная последовательность слов в одном объекте; без кавычек — все слова в объекте
  (И), иначе — частичное совпадение ниже.

### 3.4 Ранжирование (детерминированное)

Порядок групп в выдаче: **Термины → Обозначения → Формулы → Текст → Таблицы → Рисунки → Примеры/опечатки**.
Внутри группы: точность (точно > стем/проклитика > частично) → вес поля (заголовок > абзац > подпись) → TF-IDF по
объекту → порядок книги. Ничего случайного; одинаковый запрос — одинаковый ответ (тест).

### 3.5 Режим «фрагмент условия» (G5, текстовая часть)

Запрос ≥ 6 ивритских слов (вставка условия задачи) → не «все слова в одном блоке», а **страницы по покрытию терминов**:
термины книги, найденные во фрагменте (по скелету с проклитиками), взвешены IDF; страница/раздел получают сумму весов;
выдача: «Разделы и страницы, где встречаются термины фрагмента» + чипы найденных терминов с переводом + формулы этих
страниц. Фото условия (распознавание) — вне этого этапа.

### 3.6 Экран

- Поле поиска — в панели атласа **и** на странице оглавления. Переключатель области: «Во всей книге» (по умолчанию) /
  «В этом разделе». «В этом разделе» сохраняет нынешнее поведение (подсветка в тексте, Enter / Shift+Enter, счётчик).
- Выдача — список групп (§3.4) с числом в каждой; у результата: иврит и перевод с подсветкой совпадения, «стр. N ·
  раздел», пометка «по форме слова»/«другой регистр» при неточном совпадении. Карточка термина: иврит + огласовка +
  транслит + перевод + чипы страниц («стр. 131, 134, 197 …»). Первые 50 результатов, затем «Показать ещё».
- Нажатие → `openSection(sid, page)` → прокрутка к `[data-ref="<ref>"]` и подсветка; если объекта нет (данные
  перестроены) — открыть страницу и подсветить текст запроса; на экране — «← К результатам (N)».
- История: из открытого результата кнопка «Назад» браузера возвращает к выдаче с тем же запросом и прокруткой;
  перезагрузка адреса выдачи восстанавливает запрос. Для этого `onState` получает необязательный 4-й аргумент
  `{ query, scope }`, а `library-ui.js` хранит его в `anchor` атласа (минимальная правка `renderAtlasCorpus` +
  восстановление в `roomAtlasAnchor`). Проверить, что `roomCommitPresentation` переносит дополнительное поле, тестом.
- Пусто: «Ничего не найдено по «…»» + подсказки (иврит без огласовок, русская основа слова, обозначение `σ_Lc`).
  Индекс не загрузился — «Поиск по книге сейчас недоступен» + доступен поиск в разделе (честно, не «0 результатов»).
- Доступность: `role="search"`, подпись поля, `aria-live` для числа результатов, стрелки по выдаче, Esc очищает;
  цели нажатия ≥ 36 px; 390 px без горизонтальной прокрутки; HE-интерфейс — зеркально.

### 3.7 Бюджеты производительности (проверяются тестом/скриптом)

- `search.json` ≤ 1,5 МБ без сжатия (сервер не сжимает ответы — `compression` не подключён); цель ≈ 1 МБ.
  Сверх бюджета — сначала компактный формат (словарь токенов + массивы номеров объектов), шардинг — только если не
  хватает.
- Загрузка — при первом фокусе поля (и в простое на оглавлении), разбор ≤ 150 мс на телефоне среднего класса.
- Запрос 1–3 слова ≤ 30 мс (p95 на ПК в тесте ≤ 10 мс); фрагмент ≤ 100 мс.
- Индекс несёт `sections_sha256` (SHA-256 каждого файла раздела); `index.json` получает то же поле при сборке.
  Сборка и выгрузка — одним шагом; несовпадение при выгрузке — стоп.

### 3.8 Качество поиска — эталонный набор

`scripts/atlas/search-gold.a97002.json` — ≥ 60 запросов с ожидаемыми `ref`/страницами, составленных **по книге**

## 4. Озвучка — архитектура

### 4.1 Решения

| Решение | Почему |
|---|---|
| Только записанное заранее аудио; при чтении — без синтеза, без ключа, без браузерного голоса | Контракт публичных корпусов PB2: один голос для всех, нулевая цена чтения, никаких «тихих» подмен. Нет записи → нет кнопки. |
| Один модуль текста для чтения `public/js/atlas-speech.js` (UMD) для выпечки и ридера | Ридер сам вычисляет текст и его SHA-256 и играет запись **только при совпадении хэша** с манифестом. Правка текста после выпечки → запись не играет (не звучит устаревшее). |
| Тело аудио — существующий `/api/audio/:assetKey` и `DATA_DIR/audio-cache` | Готово: Range, immutable, ETag; загрузчик `push-canon-audio.js` идемпотентен. Новых маршрутов не нужно. |
| Ключ записи — тот же семантический ключ, что в PB2 (`assetKey(assetType, text, profile)` → `computeAssetKey`) с `assetType` = `atlas_block` / `atlas_formula` | Одна схема ключей в проекте; разные типы не смешиваются. |
| Формулы — детерминированный генератор по словарю чтения | Требование §7 Ф4; анти-цель «символ/число искажены»; ошибка словаря исправляется в одном месте для всей книги. |
| Скорость — `playbackRate` на клиенте (0,75 / 1 / 1,25 / 1,5), запись одна | Не множим записи. |

### 4.2 Что читается

- **Блоки** `heading`, `prose`, `list_item`, `caption`, `example_heading`, `example_text`, `table_note`: иврит — из
  `he_niqqud` (с огласовкой произношение точнее; без огласовки блок **не** выпекается и попадает в отчёт), русский —
  из `ru`. Перед синтезом — та же очистка, что `ttsSpeechText` (кантилляция), NFC, схлопывание пробелов; символы
  внутри прозы (`d₁`, `σ`, индексы Юникода) — через словарь обозначений (§4.3), иначе блок в отчёт «не готов».
- **Не читаются в «Слушать»** (этап 1): таблицы, легенды рисунков, заметки редактора, `other`, `symbol_row`,
  `formula_label`. Формулы в непрерывном чтении — по переключателю «Читать формулы» (по умолчанию вкл.).
- **Формула**: «чтение» + «где …». RU: «C равно F, делённое на f. Где C — жёсткость пружины, ньютон на миллиметр;
  F — сила, ньютон; f — прогиб, миллиметр». HE: «C שָׁוֶה F חֲלָקִי f. כַּאֲשֶׁר C — קְבוּעַ הַקְּפִיץ …» (точный вид — словарь).
  Пояснения берутся из `vars[].ru/he/unit` только если они чистые (без служебных фраз — тот же фильтр `cleanMeta`);
  иначе «где …» опускается, чтение формулы остаётся.

### 4.3 Словарь чтения `atlas/a97002/speech-lexicon.json` (в git, вычитывается)

Разделы: латинские буквы (RU: «эф», «дэ»; HE — ивритской записью с огласовкой: «אֶף», «דִּי», чтобы ивритский голос
не гадал), греческие (`σ` «сигма» / «סִיגְמָה», `π` «пи» / «פַּאי», `φ/ϕ/varphi` — одно), операторы и отношения
(`=` «равно»/«שָׁוֶה», `\frac` «… делённое на …»/«… חֲלָקִי …», `\cdot` «умножить на»/«כָּפוּל», `\sqrt` «корень из»,
`^2` «в квадрате», `^n` «в степени n», `\le`, `\cong`, `\pm` …), функции (`sin`, `cos`, `tan`, `max`, `min`, `ln`),
индексы и штрихи («d один» / «d с индексом один», «φ штрих»), единицы (по всем 40 записям книги: RU и HE),
числа (десятичный разделитель RU «0,05»; HE — цифрами, проверить на пилоте), буквы обоих регистров в одной формуле
(«D большое / d малое», HE «גְּדוֹלָה / קְטַנָּה» — только когда в формуле есть оба), ивритские слова в индексе
(`n_{\text{גזירה}}` → «n גְּזִירָה»).

Генератор (`AtlasSpeech.formula(item, lang, lexicon)`) разбирает LaTeX книги в дерево по подмножеству команд
(§1: ≈ 40) и читает его по правилам: дробь со сложным числителем/знаменателем — «дробь: в числителе …, в знаменателе
…»; скобки — по структуре, а не по символам. **Нет записи в словаре / неизвестная команда / не разобралось → формула
`unavailable` с причиной**, без «приблизительного» чтения. Отчёт покрытия `docs/research/engineering-atlas/
2026-11-xx-speech/coverage.json` (сколько формул читается, по каким причинам нет). Цель ≥ 95 % формул; остаток —
пополнение словаря, не обход.

Проверка словаря (независимость): RU-часть вычитывает владелец, HE-часть — dots (по тому же формату, что пакеты
содержимого); плюс выборка 40 формул разной сложности (по 1–2 на раздел) — текст чтения RU/HE в пакете
`speech-review-pack.md` для владельца/dots. Это ворота V2 (§5). Пометки владельца «отклонено» по отдельной формуле
хранятся в `atlas/a97002/speech-overrides.json` (исключить или задать точный текст) — генератор их применяет.

### 4.4 Манифест аудио

`DATA_DIR/atlas/a97002/audio/<sid>.json` (по разделу; том, не git):

```json
{ "schema": "linguistpro.atlas-audio.1.0.0", "atlas_id": "a97002", "section": "s09-belt",
  "section_sha256": "<sha файла раздела, из которого выпекали>", "speech_contract": "atlas-speech/1",
  "lexicon_sha256": "<sha словаря>", "rights_sha256": "<sha записи о правах>",
  "profiles": { "he": { "id": "…", "voice": "he-IL-…", "rate": 0.8, "pitch": 2.5 }, "ru": { "id": "…", "voice": "ru-RU-…", "rate": 1.0, "pitch": 0 } },
  "items": { "a97002:p197:b004": { "he": { "key": "<64 hex>", "text_sha256": "…", "bytes": 12345, "ms": 4200, "audio_sha256": "…" },
                                   "ru": { … } },
             "a97002:p197:f01":  { "he": { … }, "ru": { … } } },
  "coverage": { "blocks": [412, 430], "formulas": [37, 38] } }
```

Ридер: загружает манифест раздела при открытии (нет файла → нет кнопок, никаких ошибок в консоли); для каждого
объекта вычисляет текст через `AtlasSpeech` и `text_sha256` (SubtleCrypto); совпало → играет `/api/audio/<key>`,
нет → объект пропускается и считается «не озвучен». Порядок выпуска (PB2 п. 8): **сначала тела аудио, потом манифест**.

### 4.5 Экран

- **Карточка формулы**: две маленькие кнопки «▶ RU» «▶ עב» в шапке карточки (есть запись — видна; нет — не
  показывается); повторное нажатие — стоп; играет «чтение + где …». Подсветка играющей формулы.
- **«▶ Слушать»** — кнопка в панели атласа; открывает мини-плеер (на телефоне — закреплён снизу, не перекрывает
  текст: отступ под плеер; на ПК — в панели): ⏮ ⏯ ⏭ блок, режим «Иврит / Русский / Иврит → русский», скорость,
  «Читать формулы», ✕. Начинает с первого видимого блока текущей страницы; играющий блок подсвечен
  (`aria-current`), прокрутка следует за чтением, пока человек сам не прокрутил (тогда пауза следования на 5 с и
  кнопка «К читаемому месту»). Нажатие на блок при открытом плеере — «читать отсюда». Переходит через страницы
  раздела; в конце: «Раздел прослушан · Следующий раздел →». В плеере — «озвучено 412 из 430» (честное покрытие).
- Один звук на весь Зал: старт атласа останавливает аудио карточки слова (`morphHost.stopAudio`) и наоборот —
  через опции `mount` (`audio: { onStart, stopOthers }`), без прямых ссылок модуля на `library-ui`.
- Media Session API: заголовок «стр. N · раздел», кнопки экрана блокировки; продолжение при выключенном экране
  iPhone — проверка на устройстве владельца (отдельный вид доказательства, не заменяется автотестом).
- Настройки (`room.atlas.listen`: режим, скорость, формулы) — `localStorage` в try/catch.
- Печать не меняется; в печатной версии кнопок нет.

### 4.6 Выпечка и выгрузка

`scripts/atlas/atlas-tts.cjs` с командами:
- `inventory` — без сети: собрать тексты из `data/atlas/a97002/sections`, посчитать тарифицируемые символы
  (`ssmlBilledCharacters` из PB2), объём и длительность (оценка), отчёт покрытия; **стоп, если сумма > потолка D5**.
- `bake --sections s09-belt[,…] --lang he,ru` — только при: запись о правах (§6 D1) валидна, профиль утверждён (D3),
  инвентаризация в потолке, ключ/учётные данные — в окружении оператора (`validateSecretGate`). Возобновляемо, по
  ключу содержимого (уже записанное не пишется повторно), конкурентность ≤ 2, повтор с паузой на 429/503.
  Повторно использует `synthesizeRowWithClient`/`assetKey`/`validateTiming` из `materials-pb2-tts.js`; если нужное не
  экспортировано — вынести в `scripts/premium/lib/public-tts-core.js` **без изменения поведения PB2** (его тесты зелёные).
- `verify` — каждое MP3 декодируется, хэши совпадают, манифест ссылается только на существующие тела.
- выгрузка тел — `push-canon-audio.js --dir <out>/audio-cache` (`AUDIO_UPLOAD_TOKEN`), затем манифесты раздела в
  `DATA_DIR/atlas/a97002/audio/` тем же способом, что разделы (skill, шаг 5.2: резервная копия, `chown`, проверка по HTTPS).

Пословные отметки времени (караоке) — **не в первом выпуске**: подсветка по блоку. Если на пилоте окажется, что
отметки `SSML_MARK` не увеличивают оплачиваемый объём существенно, можно включить их для иврита в выпечке заранее
(без экрана) — решение по замеру, записать в отчёт пилота.
