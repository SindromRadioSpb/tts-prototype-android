# Упрощение проектных и глобальных инструкций

Дата: 2026-09-13. Статус: утверждённые изменения реализованы; структурная проверка выполнена.
Исходный commit: `78dd8996`. Область: инструкции, маршрутизация Skills и документация.
Основание: аудит по [статье OpenAI](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra), затем разрешение владельца «Утверждаю. Стартуй» и расширение на глобальные инструкции.
Этот документ — отчёт реализации, не новый набор обязательного вводного чтения.

## Что изменено в репозитории

- [AGENTS.md](../../AGENTS.md) и [CLAUDE.md](../../CLAUDE.md) стали короткими точками входа.
- [Общие правила](../AGENT_WORKFLOW.md) объединяют область задачи, авторизацию, завершение, проверки и защиту данных. Их не нужно повторно читать, если актуальная копия уже в контексте.
- Доменные детали, UI/CSS и production-команды перенесены в `docs/architecture/AGENT_{DOMAIN,UI,OPERATIONS}_GUIDE.md`. Исторические сведения помечены как снимки.
- Убраны универсальный API smoke для документации, обязательный пересказ всего проекта и фиксированный цикл чтения нескольких слоёв памяти.
- R1–R17 применяются по релевантности; исправлена оставшаяся формулировка «все пять». Роли не означают обязательный запуск команды агентов.
- Запрос на результат разрешает необходимые локальные этапы. Ошибка элемента блокирует зависимую операцию; красный release gate блокирует публикацию, сохраняя возможность диагностики и ремонта.
- В двух корпусных Skills шаблон создаётся только для новой программы; существующие spec и evidence переиспользуются. Детальные acceptance-контракты перенесены в references. Проверки применяются к заказанным артефактам.
- Публикация корпуса имеет один канонический Skill в `.agents/skills/`; `.claude/skills/` ссылается на него. Сохранены bodies-first, allowlist, cache/version gates и production-readback. Посторонние dirty-файлы не требуют очистки дерева.
- Условный запрет изменения Studio «до Stage 2» заменён областью задачи: локальная правка Зала остаётся локальной, общий сценарий может требовать общего компонента. Наличие совместного media-host и Studio-потребителей проверено в коде.

Объём общего вводного чтения (LF-нормализованные символы, не токены): прежние AGENTS + CLAUDE + роли — около 42,4 тыс.; новые AGENTS + CLAUDE + общие правила — около 6,7 тыс. Роли и доменные сведения доступны по необходимости. Это уменьшение объёма текста, не измерение скорости модели.

Не все найденные шаблонные Skills представлены активной сессии; наличие файла не выдаётся за факт его загрузки.

## Проверки и границы доказательства

- Проверены YAML/frontmatter изменённых Skills, относительные ссылки проектных файлов и новых workbook references, целостность сохранённых копий.
- Generic `quick_validate.py` проходит для проектных Skills. У части vendor Skills сохранены прежние несовместимости валидатора: `compatibility`, `tools`, регистр имени `Spreadsheets`. Для них проверены корректность YAML, неизменность соответствующих метаданных и идентичная ошибка на исходной версии. Это не заявляется как полный PASS generic-validator.
- Локальный manager патча проверяется на отдельном fixture: check без записи, apply, повторный apply, restore, отказ перезаписать неизвестные правки. Изменение реальных пользовательских документов для проверки не требуется.
- Scoped `git diff --check` выполнен; staged-проверка выполняется перед коммитом. Изменения приложения отсутствуют; API/browser/production-тесты для этого документационного изменения не запускались.
- Сценарии аудита: опечатка в документации; локальный корпус без публикации; одна ячейка spreadsheet; ранее одобренная обработка фотографий; ранее одобренная правка CLAUDE.md. Независимый read-only проход выполнен; выявленные остаточные противоречия исправлены. Проход проверял согласованность инструкций, а не выполнял эти внешние операции.
- Нет A/B-замера времени, стоимости или tool calls в новых сессиях. Ускорение по размеру инструкций не экстраполируется на фактическую производительность.

## Локальная сохранность и применение

Глобальные правки хранятся на этой машине. Каталог `~/.codex/instruction-backups/2026-09-13-astra-audit/` содержит before/after, manifest с SHA-256, инвентарь Skills, validation и `manage-local-patch.py`. Пользовательский README объясняет check/apply/restore. Скрипт проверяет все исходные hashes до записи и отказывается переносить правки поверх незнакомой версии плагина.

Обновление плагина может заменить файлы кэша. Для новой версии нужен проверенный перенос патча; автоматический watcher не установлен. Уже загруженные инструкции текущей сессии не меняются задним числом — новая сессия нужна для загрузки новых описаний и правил.

Проверки целостности исходников, review_log, прав, бюджетов, независимого оракула, PWA release-контракта и различия automated/owner/device acceptance сохранены.
