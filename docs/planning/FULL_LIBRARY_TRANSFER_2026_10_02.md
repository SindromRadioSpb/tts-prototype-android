# Полный перенос личной библиотеки

Утверждено владельцем 2026-10-02 в goal: реализовать ранее описанный сценарий целиком, проверить и опубликовать. Исходная база: `origin/main`, `0bb7bead`, production shell 3.11.717. F0–F6 выполнены: shell 3.11.718, commit `db42438c`, production и изолированный browser roundtrip подтверждены.

## Пользовательский результат

Один сценарий в существующем экспорте библиотеки, использующий канонические writer boundaries Импорт-центра: «Перенести библиотеку». Полный резерв восстанавливает личную библиотеку на другой машине, в том числе у другого пользователя. Исходный профиль не изменяется. Данные получателя не удаляются. Все исключения видны до экспорта и после восстановления.

Два режима: «Перенести мои данные» (заметки, история обучения, прогресс, объяснения включены по умолчанию) и «Передать библиотеку другому человеку» (материалы, структура, ASR, медиа и MP3 включены; личные данные выключены по умолчанию, их можно явно включить). Импорт объяснений в другой аккаунт — отдельная осознанная операция копирования с сохранением происхождения; обычный notebook import сохраняет существующую проверку владельца. Секреты, сессии входа, provider credentials и права доступа аккаунта не переносятся. Данные, существующие только на сервере, не объявляются включёнными в локальный резерв.

## Состав

- Все сохранённые личные тексты, архивные материалы, таблицы, переводы, метаданные и provenance; MP3 строк и текстов.
- Личная структура Медиатеки: категории, коллекции, описания, порядок, настройки представлений и сохранённые ссылки. Публичный каталог не копируется; имеющиеся персональные ссылки/локальные копии остаются персональными данными.
- Все канонические учебные материалы с достижимой immutable историей caption/table revisions, mapping, raw evidence и playback source.
- Самостоятельные неудалённые media/caption workspaces, в том числе текущие draft и история до создания таблицы.
- Локальные медиа, включая используемые подготовленные совместимые копии и зарегистрированные renditions, с дедупликацией по SHA-256.
- По выбору: заметки, закладки, прогресс, review_log и прочие экспортируемые личные learner records, локальные объяснения наставника.

## Выбор медиа

Перед сборкой инвентаризация размера и доступности, без paid provider calls. Для каждого файла: название, размер, использующие материалы, наличие YouTube, доказанность синхронизации, выбор включения. Файл без YouTube включён по умолчанию; его можно исключить вручную. Наличие URL не доказывает тождественность монтажа или таймингов. Только валидная playback source с подтверждённой timing basis допускает массовое исключение «с проверенной YouTube-привязкой». Непроверенная связь не исключается автоматически. Онлайн-зависимость называется явно. MP3 включены независимо от выбора исходных медиа.

Реестр различает `included`, `excluded_by_user`, `external_only`, `missing`, `failed`. Частичный резерв из-за отсутствующих файлов не становится полным из-за пользовательского исключения других файлов. Любой пробел материализации канонических пакетов показан отдельно. Пользователь видит общий размер, экономию, исключения и отсутствующие файлы. Повторить получение имеющихся MP3 можно; повторная платная генерация не запускается автоматически.

## Формат и запись

Версионированный manifest, реестр payload entries с размером и SHA-256; источники, история и привязки сохраняют идентичность. Один payload на SHA. Архив содержит совместимую проекцию library/library.json и канонические пакеты; новые компоненты аддитивны, прежние ZIP остаются импортируемыми. Для медиа потоковая запись/чтение с ограниченным буфером, без целого видео в ArrayBuffer и без whole-archive buffer. Большие архивы требуют безопасной поддержки границ ZIP/ZIP64 либо явно проверяемого multipart transport; переполнение 32-bit полей недопустимо. При отсутствии внешнего streaming save используется OPFS staging с проверкой места и последующей выгрузкой File, без ложного сообщения об успешном сохранении. Прерывание и нехватка места не меняют исходную библиотеку.

## Восстановление

1. Прочитать структуру, проверить безопасные пути, лимиты, дубликаты, manifest, размер и SHA каждого включённого payload; испорченный архив не изменяет библиотеку.
2. Предварительно показать количество, размер, исключения, конфликты материалов/структуры и выбранные личные данные. Проверить свободное место. Явное «Восстановить» — граница записи.
3. Применять через существующие канонические writer/repository boundaries. Повторный импорт идемпотентен. Конфликтующий текст/история не перезаписываются молча. Структура Медиатеки объединяется без потери существующих данных, с явным планом конфликтов.
4. Включённые исходные медиа автоматически связать по SHA с восстановленными package/text bindings. MP3 сохранить локально для воспроизведения после холодного открытия и offline, без обязательной загрузки на сервер. Исключённые файлы остаются `needs-media`; YouTube сохраняет online source и timing/offset. Подключение выбранного позже файла проверяет точный SHA.
5. Итоговый отчёт отдельно показывает тексты, историю, структуру, MP3, исходное медиа, личные данные, конфликты и незавершённые действия. Ошибка одного хранилища не выдаётся за атомарный успех всех хранилищ; успешный повтор завершает недостающие части.

ASR/переводы при восстановлении не генерируются. Скачивание YouTube не выполняется неявно. Согласие на копирование объяснений в другой аккаунт не меняет требования обычного импорта или доступ к исходному аккаунту.

## Этапы и gates

- F0: спецификация, baseline, формат, независимые проверки состава/безопасности; целевой commit/push в feature branch.
- F1: core и потоковый контейнер, план выбора, manifest validation, дедупликация, bounded memory, повреждение/границы размеров.
- F2: экспорт всех компонентов и workspace, структура/learner privacy, медиа/MP3, cancellation и named gaps.
- F3: no-write preview, canonical import, local MP3 persistence, автоматические media bindings, structure merge, foreign-owner copy, retry/conflicts.
- F4: UI в существующем дизайне, RU/EN/HE, клавиатура/фокус/мобильный/RTL, progress и явные результаты.
- F5: изолированные roundtrip и browser gates: чистый профиль другого пользователя, оба режима privacy, MP3/медиа offline, синхронный seek, cold reopen, исключённое медиа/YouTube source, workspace/draft/history, existing-library merge, idempotence, corrupt archive no-write, quota/cancel. Независимый oracle сравнивает исходный и восстановленный состав; state-only PASS недостаточен для playback.
- F6: требуемые repository release gates, обновление shell/module/SW/integrity contract; разрешённая Docker очистка, deployment convergence, повторная live version/health/assets/browser проверка. Owner-data и платные результаты не изменять для тестов.

## Разрешённая очистка перед deployment

Владелец явно разрешил безопасное удаление неиспользуемых и резервных образов перед деплоем. Сначала свежая inventory: контейнеры (включая stopped refs), images, volumes, disk, health. Удалять только точные ID неиспользуемых LinguistPro образов без container references; разрешение распространяется и на старые rollback images. Работающий образ, контейнеры, volumes, файлы резервов и пользовательские данные сохраняются. Не использовать docker system prune. Build-cache cleanup не включать автоматически в разрешение на images. После очистки проверить сохранённые runtime/data и health.
