Статус: LOCAL PASS; целевой релиз 3.11.524, production-проверка ожидается.

## Сигнал владельца и воспроизведение

Владелец начал физическую проверку на iPhone и прислал два снимка: сообщение «Браузер открыл другое хранилище…» в публичной и личной Медиатеке; «Повторить» не восстанавливает доступ. Снимки просмотрены. Они подтверждают срабатывание защиты смены backend, но не раскрывают конкретную низкоуровневую ошибку iPhone.

В отдельном профиле Chromium воспроизведён тот же путь на настоящей SQLite/OPFS: исходная страница удерживает sync handles после освобождения Web Lock, новая страница открывает Медиатеку. До исправления открывается резервная IndexedDB-библиотека, срабатывает `vfsBackendChanged()`. После закрытия исходной страницы «Повторить» не помогает: ожидание исходной карточки заканчивается timeout 15 секунд. Тест не использует личные данные владельца.

## Причина

1. `initDBOnce()` пробовал оба физических хранилища внутри одной попытки. Успешный fallback делал весь boot успешным, поэтому внешние попытки с backoff больше не возвращались к исходному хранилищу.
2. Медиатека вызывала `loadAll()` по «Повторить». `initLocalDB()` возвращался сразу для уже открытого соединения, а sticky-флаг смены хранилища сохранялся до нового документа.
3. Новые переходы Учебный зал ↔ Медиатека и возврат из reader обходили уже существующее graceful close, применённое для перехода в Студию. Это оставляло окно гонки освобождения handles.

Точный тайминг и первичная VFS-ошибка на физическом iPhone не измерялись удалённо; механизм воспроизведён контролируемой реальной конкуренцией за OPFS, а не подменой сообщения в UI.

## Исправление и инварианты

- При сохранённой идентичности хранилища worker открывает только его; временный отказ запускает три настоящих попытки исходного backend. Постоянный отказ даёт ошибку, не новую пустую библиотеку. Первый запуск без preference сохраняет capability fallback. Неизвестная сохранённая identity блокируется явно.
- Локальная кнопка «Повторить» закрывает своё соединение и перезагружает документ с тем же адресом/условиями; сохранённый выбор backend не сбрасывается. Публичный сетевой retry остаётся отдельным.
- Переходы Медиатеки в Зал/Студию и переходы Зала в Медиатеку освобождают соединение до навигации. Modified clicks/new tabs сохраняют обычное поведение. Возврат BFCache в Медиатеку выполняет чистое подключение.
- Для недоступного исходного хранилища добавлена инструкция на RU/EN/HE. Схема БД, материалы, learner state и review_log не менялись; миграции между хранилищами нет.
- R4: рабочее восстановление вместо зацикленного retry. R11/R13: исходная библиотека и журнал сохраняются; альтернативный store не выдаётся за исходный. R12: используются существующий движок и graceful close. R14/R15: тестовые профили изолированы, личное содержимое не публикуется.
