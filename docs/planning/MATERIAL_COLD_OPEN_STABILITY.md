# Стабильное первое открытие материала

Начато 2026-10-23 по поручению владельца «формализируй и стартуй». Исходный код: `9a41a298` (production runtime 3.11.814). Основание: O-124, O-126–O-129 и [замеры предыдущего выпуска](../research/reader-performance/2026-10-23/REPORT.md). Это исполняемая программа небольших проверяемых поставок; перечисленные ниже результаты ещё не объявлены достигнутыми.

## Результат для пользователя

Материал открывается в Зале, Studio Classic и IDE с правильным текстом и сохранённой позицией. Первый экран становится доступен без ожидания обработки всех слов; фоновые слои не заменяют таблицу, не сбрасывают выделение и не возвращают предыдущий материал. Обновление прямой ссылки оставляет пользователя в материале.

## Поставки и порядок

| Этап | Конкретное изменение | Приёмка | Статус |
| --- | --- | --- | --- |
| S1 | Одно согласованное чтение карточки и строк в DB worker вместо нескольких передач OPFS-владения; одинаковый read model для трёх поверхностей | Один RPC, один read snapshot; корректные аудиоссылки, огласовка и identity; нет записи данных/commit чужой транзакции; холодное открытие в браузере | Выпущено и проверено на production 3.11.815, `0e059364` |
| S2 | Один выполняющийся запрос public catalog; прямой маршрут к нужной работе без ожидания посторонних каталогов | Deep link, refresh во время загрузки, retry после ошибки, A→B; проверка актуальной публикации/прав сохраняется | Кандидат 3.11.816 проверен; production ожидает capacity gate |
| S3 | Studio: обновление ячеек транслитерации без полной замены таблицы; независимое появление сохранённого контекста | Classic + IDE: сохранность редактора, пользовательской транслитерации, replay, фокуса, позиции; поздний callback A не изменяет B | Ожидает S1 |
| S4 | Видимые и восстановленные строки получают gloss/morph первыми; остаток обрабатывается с бюджетом времени | Длинные абзацы и 2500 строк; сохранённые AI/manual gloss, отсутствие генерации; scoped refresh без повторного полного прохода | После профиля S1–S3 |
| S5 | Уменьшение объёма первого metadata payload и, при необходимости, DOM | Отдельный контракт обязательных полей media/provenance/editorial; поиск по всему материалу, выделение и редактирование не теряются | Исследование, не условие S1 |

S1 намеренно сохраняет весь `source_meta_json` и `table_model_meta_json`: эти поля могут содержать тайминги медиа и сохранённые учебные доказательства. Исключается только уже исключённый `source_text`. Позиция пока читается существующим каноническим путём. Оптимизация S5 не должна превратить сокращённую UI-проекцию в источник для сохранения карточки.

## Проверка результата

- Изолированные fixtures: короткий текст; 34 длинных абзаца; 499 строк с сохранённым контекстом; 2500 строк. Медиа, огласовка, пользовательская транслитерация и разрывы `order_index` проверяются отдельно.
- Холодный запуск отделяется от повторного открытия: новый документ/worker, готовая локальная БД; новый пустой профиль с импортом корпуса — отдельный сценарий. HTTP/SW cache и backend OPFS/IDB фиксируются в результатах.
- Метрики: от намерения открыть до данных, первого видимого интерактивного слова, восстановленной позиции и готового видимого подстрочника; максимальная main-thread task; число RPC и запросов catalog. `paint`/`ready` сами по себе не доказывают интерактивность.
- Для сравнительного вывода — одинаковые fixtures, viewport, cache policy и последовательные baseline/candidate запуски. Малую выборку публиковать как отдельные наблюдения/медиану с диапазоном; p95 не заявлять по нескольким открытиям.
- Общая цель: первый интерактивный экран ≤1 с после получения данных. Это целевой показатель, а не обещанный результат S1; выпуск S1 должен доказать сокращение DB-операций и отсутствие регрессии поведения. Остаточную задержку фиксировать отдельно.
- Обязательные сценарии: новая вкладка, прямой URL, refresh во время открытия, resume, быстрое A→B→A, закрытие до завершения, несколько вкладок, ошибка чтения и явный retry. Worker read проверяется в autocommit и внутри принадлежащей вызывающему транзакции.
- Owner-профиль: только разрешённые диагностические чтения, без grading/save/paid AI. Отдельно сверять `review_log`; активность владельца в других вкладках не выдавать за неизменность всего профиля.

## Выпуск

Каждая поставка: целевые тесты → браузерные сценарии затронутых поверхностей → согласованные version/module/SW/integrity → свежая инвентаризация deploy и диска → безопасная очистка только разрешённого cache → release → проверка фактически выданных assets, health и сценария в production. Сохраняются runtime/rollback images, volumes, БД и backups. Ошибка gate блокирует выпуск, но не диагностику.

Доказательства и фактический статус этапов дополняются здесь и в `docs/research/reader-performance/2026-10-23/`; незакрытые ограничения остаются в OBSERVATIONS_LOG.

## S1: результаты до выпуска

62 холодных чтения в изолированном Chromium (OPFS и IndexedDB): старый путь делает 3 RPC, новый — 1; хеши возвращённых read models полностью совпадают. OPFS, медианы 3 пар: 40 строк 48.7→22.9 мс; 499 строк 81.1→57.2 мс; 34 длинных абзаца 58.3→35.0 мс; 2477 строк 209.1→189.6 мс. Это время чтения после инициализации БД, не полного запуска страницы.

IDB на большой fixture имеет разброс: первая выборка из 3 пар 162.6→181.7 мс, уточняющая из 7 пар 183.5→166.1 мс. Оснований обещать стабильный процент ускорения IDB нет; единый снимок и уменьшение RPC подтверждены на обоих backend.

Браузерные проверки Classic/IDE/Room, позднего открытия, медиа-lifecycle и resume прошли. Полный Reader smoke на 2500 строках и длинных абзацах прошёл: поиск, ручная транслитерация, replay, сохранённый AI/manual контекст без генерации, мобильный viewport и RTL. Первый интерактивный экран в отдельном desktop-наблюдении 1.37 с от открытия / 1.19 с после данных, longest task 805 мс: общий целевой показатель ≤1 с пока не достигнут (S4/S5 остаются открыты).

## S1: production

Deployment 2929 завершён 2026-10-23 17:20:24 UTC. Версия 3.11.815, 10/10 изменённых assets совпали с Git; оба shell, health, БД и миграции готовы. На фактически опубликованном коде прошли Classic/IDE/Room lifecycle и 16 дополнительных холодных fixture-чтений через OPFS/IDB. В owner-профиле (732 текста, 108996 строк) отдельно сверены полные read models трёх материалов: 499/34/2477 строк; старый и новый путь совпали. Все 11754 записи review_log сохранили исходный хеш. Это проверка чтения на настоящей базе, не новый owner-UI cold benchmark. [Доказательства](../research/reader-performance/2026-10-23/REPORT.md).

Ограничение выпуска: 4.21 GiB available перед cold build оказалось недостаточно для запаса при распаковке — available временно 0 (root free 1.43 GiB). После завершения удалён только build cache, доступно 2.85 GiB. Следующий runtime push блокируется до нового capacity preflight: ориентир ≥6 GiB available для текущего образа и отсутствие активной сборки. Нужен согласованный точный набор старых образов либо расширение диска; произвольное удаление образов/данных не разрешено. Документация выпуска публикуется с `[skip cd]`.

## S2: проверенный кандидат 3.11.816

Прямой `public_corpus` + `public_work` открывает материал после инициализации БД и проверки актуальной публичной публикации/каталога, до ожидания Ben-Yehuda root, полного списка локальных текстов, фонового canon и групп. Одинаковые выполняющиеся запросы публичного каталога объединены; ошибка освобождает запись для повторной попытки. Epoch материала и token навигации запрещают позднее открытие после ухода пользователя. Фоновый canon использует общую очередь импорта; write gate включается только при начале его операции, чтобы не заблокировать уже ожидающий материал.

В изолированном Chromium на публичных GET выполнены: 499 строк «Хаммама» при удерживаемых посторонних ответах; retry после HTTP 503; уход во время загрузки каталога и снимка; переключение A→B (679 строк) с настоящим завершением фонового canon; возврат к родительскому корпусу без повторного catalog fetch; refresh в паузе materialization. Baseline 815 при таком удержании не начинал запрос нужного каталога. Это проверка порядка зависимостей и поведения, не процент ускорения обычного открытия.

2864 unit tests и 233 i18n checks прошли. Отдельный cold-canon smoke подтвердил все 6646 строк/79 текстов, конкурирующую вкладку, rollback и восстановление после прерывания. [Отчёт и воспроизведение](../research/reader-performance/2026-10-23/REPORT.md).

Проверка локальной копии по snapshot и восстановление evidence пока остаются существующими; group и baked Ben-Yehuda resolver не ускорены этим этапом. Owner-профиль и физическое устройство в S2 не использовались. Производственный выпуск ещё не выполнен: preflight 2.85 GiB available, cache 0 B; нужен отдельно согласованный точный набор старых images с сохранением runtime 815 и rollback 814 либо расширение диска.
