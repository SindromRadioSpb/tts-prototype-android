# Ф0 · Замер слоя слов: Dicta + Pealim (А), русские формы (Б), объём Gemini (В)

Дата: 2026-10-11. Канон: [../WORD_LAYER_RESEARCH_AND_PLAN_2026_10_11.md](../WORD_LAYER_RESEARCH_AND_PLAN_2026_10_11.md).
Материал: «До последнего имени: люди с военной базы Шура» — 730 строк, 5649 вхождений.
Второе мнение (НЕ эталон): ручная разметка ChatGPT из `02_Иврит_Подробный_разбор.xlsx`.

## Вердикт

**А пригоден как основа Ф1.** Dicta разбирает текст бесплатно, за 61 запрос и ~20 с на весь текст.
Качество ограничивает не Dicta, а **стыковка Dicta→Pealim**. Её дефекты найдены, классифицированы
и закрыты детерминированными правилами (join v3). Остаток, который правилами не закрывается, —
выбор значения омонима и устойчивые сочетания; это ровно зона варианта **В** (решение D1/D2 в силе).

**Б осуществим без ИИ**: русские формы строятся для 98% глагольных и 93% именных парадигм;
на ручной выборке нет грубых ошибок после исправления трёх классов дефектов.

## 2. Найденные дефекты стыковки и правила join v3

Исходная нестрогая стыковка (v1) давала 95% покрытия, но ~11% неверных парадигм
(רואה → «страшиться», באמת → «подтверждать», רבנים → «властитель»). Правила v3:

1. **Точный согласный ключ сначала**; нестрогий ключ (полное/неполное письмо) — только при сильной
   улике: в парадигме есть клетка с тем же написанием или той же огласовкой.
2. **Глаголы ל״ה**: Dicta пишет лемму с конечной י (ראי = ראה) → пробовать ה.
3. **Хуфъаль/пуаль** = `passive-*` клетки парадигм хифъиль/пиэль в Pealim.
4. **Фильтр по части речи и типу таблицы Pealim**: предлоги и אין хранятся как таблицы суффиксов
   (`P-1s…`), личные местоимения — как набор местоимений (`1s…`). Это же различает омографы:
   את = объектный маркер / «ты (ж.)» / «лопата».
5. **Местоимения**: Dicta сводит лемму всех личных местоимений к אני/הוא → ученику показывать
   само местоимение.
6. **של + суффикс**: Dicta делит שלי как ש+לי (лемма ל = «к») → правило «של».
7. **Голый предлог** — базовая форма, не клетка «мне/мной».
8. **Неразмеченные коды части речи Dicta** (декодер `db/premium/morph/dictaMorphId.js` их не
   называет; смысл выведен по примерам, нужна проверка на контрольных формах):
   12 аббревиатура · 16 междометие · 18 квантор/определитель (כל, איזה, המון) · 19 экзистенциальное
   (יש/אין) · 20 модальное (יכול, צריך, אפשר) · 21 частица (אי) · 26 причастное · 27 связка היה ·
   29 титул (מר, רב). Без фильтра они попадали в глаголы: עוד → «свидетельствовать».
9. **Числительные** — только неизменяемые записи (иначе עשרה → «богатство»).
10. **Поиск по форме** (без леммы) — только при точном совпадении огласовки.

Открытый вопрос для Ф1: рабочий резолвер морф-карточки (`reader-morph.js` / NotesAutoGen) устроен
иначе, чем зонд. Проверить, не повторяет ли он дефекты 1–2 и 4, прежде чем строить слой на нём.

## 3. Вариант Б — русские формы без ИИ (pymorphy3, только зонд)

| Парадигмы | Все клетки построены |
|---|---|
| Глаголы | 98.3% (3396/3453) |
| Существительные | 93.0% (4137/4447) |
| Прилагательные | 79.9% (785/983) |

Ручная проверка 120 случайных клеток ([f0/ru-forms-sample.md](f0/ru-forms-sample.md)):
89 верно, 4 грамматично, но неестественно («вы были приобретёнными»), 1 опечатка в самом Pealim,
26 — честная подпись вместо формы (страдательные формы и совершенный вид в настоящем).
Первый прогон дал 12/120 ошибок трёх классов — исправлены: повелительное 1-го лица («иллюстрируемте»),
значения из нескольких слов («будет быть повреждённым», «перочинные нож»), неверный омоним
pymorphy («том» → «тот», «груш» → «груши»).

Ограничения: перевод формы строится от **первого** значения Pealim, оно не всегда контекстное
(חטיבה «рубка леса», а не «бригада») — контекстное значение даёт В; страдательные клетки
(~26% глагольных) пока только подписаны. Для Ф2 это разовая офлайн-сборка файла
переводов форм; pymorphy3 нужен только при сборке, не в браузере.

## 4. Вариант В — объём Gemini (оценка, не замер API)

Для текста в 5649 слов: ~28 тыс. выходных токенов (контекстная глосса ≈10 символов ≈5 токенов
на слово с обвязкой) и ~33 тыс. входных. Это ≈2.5× колонки русского перевода (2.06 ток/слово по
замеру 2026-08-05). Пересчёт в деньги — по актуальному прайсу при старте Ф3; Batch API даёт −50%.
Калибровка: доля токенов на символ русского текста взята из того замера, а не из `countTokens`.

## 5. Решения для Ф1 (предлагаемые)

1. Слой слов строится при создании таблицы: Dicta (≤2 параллельных запроса, кэш) → join v3 →
   статус каждого вхождения: `ok` / `нет в словаре форм` / `нужна проверка` (подозрение ASR из
   имеющихся отметок никуда).
2. Перенести коды части речи из §2.8 в `dictaMorphId.js` после проверки на контрольных формах.
3. Сочетания до В: засеять список устойчивых выражений из листа «Сочетания» прототипа (92 строки)
   как ручной словарь сочетаний — пометка «сочетание» вместо пословного перевода.
4. Омонимы одной части речи (חלל, עצם, רע…) честно помечать «несколько значений», пока нет В.
