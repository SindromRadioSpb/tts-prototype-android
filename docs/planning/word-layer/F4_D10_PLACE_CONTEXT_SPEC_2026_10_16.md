# Ф4 · Д10 — слово на своём месте: омограф по своему предложению (А + В)

Дата: 2026-10-16. Решение владельца 2026-10-16: «Утверждаю план. А+B» (А — сохранённый разбор Dicta, В — ваше решение для
места), Б (слой ИИ «в контексте») — проба на «Путь от Осло до 7 октября»: включить, если на нём целесообразно.

## Замер до кода (профиль владельца, 721 текст, 798 272 слова, 3.11.776)

- Многозначных вхождений (форма — клетка ≥ 2 статей Pealim, чтение не «точно»): 43 702 (5,5 %), почти все — путь «вероятно».
- С сохранённым разбором Dicta предложения (`sentence_morph`): 9 623 (22 %; разобрано 24 056 из 104 660 строк, 143 текста).
- Правило А однозначно выбирает статью в 5 764, **меняет ключ в 418** (после Д9 Dicta в основном подтверждает ключ).
- Слепой экзаменатор (тот же протокол): А на 150 случайных заменах — правило верно 112, верен прежний ключ 16, неразличимо 22;
  на «Пути от Осло» — 6 : 0 (7 неразличимо). **Б** на «Пути от Осло» — 2 : 4: перевод ИИ не различает часть речи
  (הַנְּכוֹנָה «правильная» → «готовиться», יָפֶה «хорошо, что» → «хорошеть»). **Б не включён.**

## Правило (одно место — `ReaderMorph.resolveCore(..., { place: { sid, off } })`)

1. **В — решение ученика для места** («⚖ Проверить морфологию», `lexical_resolution_events` `manual_correction`; якорь места
   проверен `LexicalResolutionService.projectExactOccurrence`): статья Pealim — она; «это имя» — имя.
2. **А — сохранённый разбор Dicta предложения**: среди кандидатов (статья чтения, её альтернативы, статьи, чья клетка —
   огласованная форма) ровно одна с ТОЧНОЙ частью речи Dicta и леммой Dicta среди цитатных форм (лемма, 3 л. м. р. ед. прош.,
   инфинитив, ед. ч., м. р. ед. ч.) — она. Не трогает «точно», служебные слова; для «вероятно» нужны ≥ 2 кандидата.
3. Иначе — чтение написания (как было).
Место не читается, если слово по этому номеру уже другое (строка правлена).

**Только сохранённые данные решают ключ** — живой запрос Dicta карточки по тапу меняет показ, не ключ (его нет на всех
поверхностях). Хранилище мест: `ReaderMorph.setPlaceLoader` (ставит `MorphHost`: `sentence_morph` + решения по местам),
`ensurePlaces`, `invalidatePlaces` (после «Обогатить» — `refreshDictaLexicon`; после нового решения — `appendLexicalResolution*`).

Поверхности: раскраска (`decorateWords`), тренажёры (`_scanWords`), тап и сохранённый ключ (`resolveWordLight(…, place)` —
`preCtxCard` теперь чтение места), сканер списков и карточек (`scanRows` по `row.id`), карточка слова из списка / тренажёра
(`openWordCard(…, { lemmaKey })` — открывает статью ключа списка). Поколение ключей карточек: `list-keys-scan-v2` + число
`sentence_morph`.

## Д10.2 Отметки идут за словом

`migrateIdentityD9(ldb, { places: true })` — правило Д9.2 (≥ 80 % мест ключа уходят на один ключ — отметка туда; все —
снимается со старого), «до» = ключ написания, «после» = ключ места; флаг `lp.identityMigrationD10_v1(.backup)`.

## Известные ограничения

- Покрытие: только предложения с сохранённым разбором Dicta (22 % многозначных мест). Доразбор остальных — отдельное решение
  владельца (фоновые запросы к Dicta через сервер, ≤ 2 одновременно).
- Тренажёры, пересобирающие ответ по написанию (перевод, пропуски), для слова с ключом места **пропускают** упражнение
  (ключи не совпали) — меньше видов упражнений, никогда не чужое значение или неверная оценка. Проверка набранного ответа
  с приставкой принимает ключ места, если он — альтернатива формы.
