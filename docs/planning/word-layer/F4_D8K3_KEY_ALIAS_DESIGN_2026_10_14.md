# Ф4 · Д8-К3 — одна история слова: соответствие «старый ключ → новый» (реализовано 3.11.770, 2026-10-14)

Решение владельца К-3 (2026-10-14): у слова не должно быть двух историй — старого ключа-написания с расписанием и
новой записи (Pealim после Д7 или Dicta после Д8-К). Принято: «таблица соответствия, которую читают клиент и сервер
наставника; журнал не переписывается; отдельным шагом с проверкой пересчёт-до == пересчёт-после на профиле владельца».

Замер (профиль владельца, 2026-10-14): в `review_log` 4030 ключей вида `…#` (3709 без части речи, многие — словоформы:
אביו, אהבתו) против 1671 ключа `pid:`.

## Уточнение проекта: соответствие — событие журнала, а не отдельная таблица (R12)

Отдельная таблица рядом с журналом = вторая истина (красный флаг R12: «конкурирующая истина рядом с логом»), и её
пришлось бы отдельно синхронизировать и отдельно хранить на сервере. Поэтому соответствие — **событие** того же
журнала, который уже синхронизируется и пересчитывается на обеих сторонах:

```
{ id: "alias:<sha1(old→new)>", item_key: <старый ключ>, kind: "alias", grade: null,
  reviewed_at: <момент решения>, source: "identity", meta_json: { alias_to: <новый ключ> } }
```

- **Только дописывается.** Отмена — новое событие `alias_to = <сам старый ключ>` (позднее побеждает).
- **Правило свёртки (одно, общий модуль `public/js/key-alias-core.js`, его же `require`ит сервер):**
  карта = последнее событие `alias` каждого ключа (по `reviewed_at`, `id`); канонический ключ = проход по цепочке
  (≤ 8 шагов, цикл → остановка). Расписание ключа T = `FSRS.replay` объединения строк всех ключей, чей канонический
  ключ = T, по времени. У поглощённого ключа своей проекции нет. Ручной статус T = последняя отметка (`mark`) среди
  объединённых ключей.
- **Журнал не переписывается**: строки повторений остаются под своими ключами; меняется только свёртка.

## Потребители (что меняется)

| Сторона | Где | Изменение |
|---|---|---|
| Клиент | `appendReviewLog` (валидатор) | принять `kind: alias` (`alias_to` обязателен, ≠ `item_key`, или = для отмены) |
| Клиент | `recomputeSrsFromLog`, `healLocalProjections` | свёртка по каноническому ключу; проекции поглощённых ключей очищаются |
| Клиент | `word_status` | проекция: статус и расписание переходят на новый ключ при пересчёте |
| Сервер | `learnerLogRepo` | `RL_KINDS.alias`, `alias_to` в разрешённых полях |
| Сервер | `learnerProjectionRepo` | `_itemRows` и `distinctItemKeys` по каноническому ключу; пересчёт обоих ключей при приёме `alias` |
| Синхронизация | `cloud-sync` | старый клиент незнакомое событие пропускает (проверено: `refused++`, без «ядовитой страницы»); новый клиент один раз докачивает журнал с начала, чтобы не потерять пропущенные `alias` |

## Производитель соответствий

Кандидаты: ключи, не являющиеся `pid:`, `dl:`, `note:`, `sent:`, у которых есть строки журнала или статус. Цель —
**единственный** ключ, который сейчас (Д7 + лексикон Dicta) получает каждое огласованное место этого написания в
моих текстах (правило Д7.2, обобщённое на `dl:`). Несколько целей или ни одного места — соответствия нет.

1. **Пробный прогон** (ничего не пишет): кандидатов N, будет соответствий M, неоднозначных A, без мест P; примеры;
   инвариант: для каждого ключа вне соответствий пересчёт до == после; для каждого нового ключа
   пересчёт == `replay(объединения)`.
2. **Владелец смотрит отчёт** (R13: dry-run на реальном профиле до боевого включения).
3. **Применение**: события `alias` пачкой; резервная копия; кнопка «Откатить» (события-отмены).

## Гейты

- Юнит: свёртка (цепочка, цикл, отмена, позднее побеждает), валидаторы клиента и сервера, пересчёт на сервере.
- Пробный прогон на профиле владельца: отчёт + инвариант пересчёта.
- После применения: синхронизация с сервером — проекции сервера == проекции клиента по затронутым ключам.

## Реализация (3.11.770)

- `public/js/key-alias-core.js` — правило свёртки (клиент + `require` сервера); `fsrs-core.replay` пропускает `alias`
  (как `mark`/`annul`): событие личности — не память (найдено гейтом D25: без этого откат давал 4 повторения вместо 2).
- Клиент `local-db`: `getAliasMap` / `canonicalKey` / `getReviewLogFolded` / `aliasTouchedKeys` / `applyAliasProjection`;
  `recomputeSrsFromLog` и `lastMarkStatus` — по свёрнутой истории; `cloud-sync` — проекция затронутых ключей до
  продвижения курсора, отметка на поглощённом ключе — на слово, одноразовая докачка журнала (`alias_repull_v1`).
- Сервер `learnerLogRepo`: `kind: alias` (`alias_to`, `alias_reason`), `itemRows` по свёртке (кэш карты на пользователя),
  пересчёт обоих концов и прежней цели; `learnerProjectionRepo.distinctItemKeys` по каноническому ключу.
- Производитель `ReaderMorph.planKeyAliases` / `applyKeyAliases` / `undoKeyAliases`; «Мой словарь» → «Мои слова» →
  блок «Одна история слова»: «Проверить» (пробный прогон), «Объединить (N)», «Откатить объединение».
- Гейты: `keyAliasCore`, `keyAliasServer` (приём, пересчёт, оракул, отмена), dictionary-smoke D25 (план → объединение
  2+1 → 3, отметка → слово; откат → 2/1, журнал цел), server-replay 65/65, learner-ingest 24/24, cloud-sync 32/32.
- **Не сделано:** пробный прогон на профиле владельца (нужна вкладка на 3.11.770) и решение владельца по отчёту.
