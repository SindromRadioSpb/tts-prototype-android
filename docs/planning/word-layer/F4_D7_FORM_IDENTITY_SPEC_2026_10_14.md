# Ф4 · Д7 — форма слова сводится к лемме; отметки переносятся; «Не разобрано» по группам; знакомость среза = ключи списка

Дата: 2026-10-14. Основание: проверка подборки владельца (O-083 в `docs/planning/OBSERVATIONS_LOG.md`). Решения
владельца 2026-10-14: (а) засчитывать форму, если приложение уверенно сводит её к лемме Pealim, отметки переносить
автоматически, **при конфликте выигрывает более поздняя отметка**; (б) группы в «Не разобрано» — делать; (в) знакомость
и список — на одной основе.

## Д7.1 Правило личности слова (а)
Сейчас ключ статуса — от офлайн-разбора `resolveCore`; форма, которую разбор не узнал (`unknown` / `guessed`), получает
ключ-написание (`ילדי#`), хотя обогащение слоя слов (`enrichReading`, шаг 3 «форма без букв-помощниц») находит её
**клеткой ровно одной парадигмы Pealim** (יַלְדֵי = сопряжённое мн. ч. ילד). Карточка по тапу это показывает, список — нет.

Новое правило: если офлайн-разбор не уверен, а обогащение сводит огласованную форму к одной парадигме (канал
`form-canonical`), — это и есть разбор слова: `resolveCore` возвращает его («вероятно», не «точно» — урок архаичного
золота: «точно» там снижало честность 81,8% → 62%). Одно место — значит одинаково везде: раскраска в тексте, долгое
нажатие, карточка, списки Зала и словаря, Студия. Служебные/наречные чтения обогащения (шаги 1–2) на ключ не влияют.
`RESOLVER_REV` → `ctx-r2` (запечённые контекстные сайдкары деградируют к мягким промахам, кэш разборов словаря обновляется).

## Д7.2 Перенос отметок (а)
Один раз на устройстве, в фоне после открытия Зала / Студии / словаря (Web Lock — одна вкладка):
1. Отметки на не-`pid` ключах со статусом.
2. Один проход по строкам моих текстов (страницами): огласованные формы каждого такого написания.
3. Каждая форма → новое правило → ключ. Все формы дали один и тот же `pid:N` → перенос; разные леммы или нет
   огласованных мест → отметка остаётся (честно, без догадки).
4. Перенос каноническим путём (`setWordStatus` — событие отметки в журнал): у леммы нет отметки → получает отметку
   написания; есть — **побеждает более поздняя** (`updated_at`); отметка написания снимается.
5. **Расписание повторения не переносится**: оно — свёртка журнала повторений по ключу (её пересчитывают синхронизация и
   сервер наставника); переписывать журнал нельзя. Повторения слова продолжаются на старом ключе, как раньше.
Итог пишется в консоль и в `localStorage lp.identityMigration_v1` (сколько перенесено / конфликтов / оставлено).

## Д7.3 «Не разобрано» по группам (б)
Группы строит программа из того, что разбор уже знает, без ручной разметки и без ИИ: «Похоже на имя» (подсказка имён
или часть речи «имя собственное»), «Есть догадка» (`guessed`: архаичные и редкие формы), «Нет в словаре» (остальное).

## Д7.4 Знакомость среза = ключи списка (в)
Знакомость и словарик среза считаются тем же оценщиком (`evaluateRecordedFamiliarityV2`) по ключам **списка**:
частоты лемм среза, неразобранные — «неизвестно», имена — вне знаменателя, служебные слова — вне, как и в списке.
Подборка — сумма по текстам; у каждого текста свой процент тем же способом.
**Вне Д7:** проценты на карточках Зала/Студии и каталога корпусов считает конвейер ингредиентов, для корпусов — на
сервере по всему каталогу; перевод его на ключи Зала — отдельный шаг (O-083). Пометка «как в Зале» со словаря снимается.

## Разбор по ролям
- **R11:** одна личность слова на всех поверхностях (одно место — `resolveCore`); журнал не переписывается; перенос —
  каноническими событиями отметки; конфликт — по правилу владельца.
- **R1/R10:** форма засчитывается только при однозначной клетке Pealim; иначе остаётся «не разобрано»; «вероятно», не «точно».
- **R2:** ученик видит в списке лемму, а не форму; отметка на форме теперь отмечает слово.
- **Риски:** часть архаичных написаний свернётся к неверной лемме при совпадении огласовки (ручная выборка шага 3 — ≈93%
  верно); слово с переносом статуса и непереносом расписания — две строки в «Моих словах» до следующего повторения.
