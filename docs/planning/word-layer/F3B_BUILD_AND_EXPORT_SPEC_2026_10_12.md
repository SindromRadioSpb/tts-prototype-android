# Ф3б · ИИ-перевод слов при сборке материала и в экспорте — спецификация (решено)

Дата: 2026-10-12. Статус: **решения владельца приняты 2026-10-12 (§6: 1а, 2а, 3а)**, реализация. Предшественник: [F3_SPEC_2026_10_11.md](F3_SPEC_2026_10_11.md) (3.11.741).

## 1. Запрос владельца

Ф3 поднял качество подписей (≈7% → ≈2% вводящих в заблуждение). Нужно:
1. выбирать «Перевод слов ИИ (Gemini)» **при формировании** учебного материала — с медиа и без;
2. **экспортировать** материал вместе с ИИ-данными подстрочника и ленты слов.

## 2. Что есть сейчас (проверено по коду и на проде)

- Сборка и с медиа, и без идёт одним конвейером `LearningMaterialTask`
  (`public/js/learning-material-task.js` + `-ui.js`; адаптеры в `index.html` ~35046):
  транскрипт → таблица → сохранение → привязка ▶ → доказательство ▶ → пакет (ZIP) → готово.
  Цена согласуется в окне старта и хранится в журнале задачи (`table_quote`).
- Ф3 работает **по отрисованной таблице** (DOM): ключ строки = хэш(слова огласовки + `textContent` ячейки перевода).
  ИИ-подписи лежат в IndexedDB устройства (`lp-word-gloss-ai`) и в серверном кэше; **в экспорт не входят**.
- Экспорт: `TextCardFormat.buildCardPayload` (карточка без медиа), `StudioPortableLearningPackage.exportMaterial`
  (медиа-материал, ZIP), `local-db exportBundle` (библиотека). Образец переносимого производного слоя уже есть —
  `learning_niqqud_layer` (`portable()` при экспорте, `remember()` при импорте, сбой слоя не ломает импорт).

### Дефект, найденный при разборе (живой прод 3.11.741, вкладка Студии)

У медиа-строк в ячейку перевода позже дорисовывается кнопка ▶︎ (`media-host.js renderRowReplay`).
`textContent` ячейки = `"… ▶︎"` — этот символ попадает **в ключ строки, в серверный кэш и в промт Gemini**.
Ключ поэтому зависит от поверхности и момента (до/после появления кнопки, есть ли файл на устройстве):
- та же строка в Зале или на другом устройстве может **оплачиваться повторно**;
- экспорт по ключам из данных карточки не найдёт эти строки.

## 3. Предложение

### 3.1 Опция при сборке
- В окне «Собрать учебный материал» — флажок **«Перевод слов ИИ (Gemini) для подстрочника и ленты»** с ценой
  рядом с ценой таблицы: текст — точное число слов × $0,15/1000; медиа по ссылке — вилка от длительности
  (замер «Шура»: ≈1,75 слова/с). Без ключа Gemini флажок недоступен и ведёт к настройке ключа.
- Согласие и цена пишутся в журнал задачи (`word_gloss_ai: {enabled, quote}`), как `table_quote`: возобновление
  задачи не спрашивает заново.

### 3.2 Новый этап задачи «Перевод слов (ИИ)»
- После сохранения карточки и привязки ▶, **до** упаковки — чтобы ZIP уже содержал слой.
- Строки берутся **из сохранённой карточки (данные, не DOM)**, пакеты по 8, до 3 параллельно, тот же маршрут
  `/api/word-gloss-ctx` и серверный кэш.
- Этап **не валит материал**: итог называется на финальном экране («переведено 712 из 730 строк; 18 — словарный
  перевод»), кнопка «Догрузить» (оплаченные строки повторно бесплатны). Отмена честно останавливает этап.

### 3.3 Единый ключ строки из данных (исправление дефекта §2)
- Ключ v2 = хэш(слова огласовки из `he_niqqud` + перевод строки из данных) — одинаков в Студии, Зале, экспорте, на
  любом устройстве. В DOM-пути перевод читается без кнопок и значков (только текст значения).
- Уже оплаченное не теряется: при поиске сперва v2, затем старый ключ v1; найденное по v1 копируется под v2.

### 3.4 Экспорт и импорт
- Новый переносимый слой `word_gloss_ai_layer` (по образцу `learning_niqqud_layer`):
  `{schema:"word-gloss-ai-layer-v1", rows:[{order_index, key, model, glosses, mwe}]}` — только строки этой карточки.
- Едет в: карточке текста (`text-card-v2`), ZIP медиа-материала, экспорте библиотеки (кроме «облегчённого»).
- Импорт **заново вычисляет ключ из импортированной строки**: запись, чей ключ не совпал (правленый текст, чужая
  карточка, подделка), чьё число подписей ≠ числу слов или чьё сочетание выходит за строку, отбрасывается и
  считается (`{stored, rejected}`); сбой слоя **не ломает** импорт карточки. Отдельный sha256 не нужен: в ZIP
  целостность даёт контрольная сумма манифеста, в остальных форматах — доказательство ключом.
- Провенанс сохраняется: подписи ИИ остаются помеченными «ИИ» и моделью.

### 3.5 Показ
См. решение §6.2: готовые (оплаченные) ИИ-подписи показываются при включённом подстрочнике/ленте; тумблер
«Перевод слов ИИ» отвечает за **дозаказ** новых строк при чтении.

## 4. Не входит
Облачная синхронизация слоя; ИИ-строка в карточке по тапу (отдельный шаг); UI ленты.

## 5. Проверка
Юнит: ключ v2 (паритет «данные = DOM» на строке с кнопкой ▶︎ и без), миграция v1→v2, слой portable/remember
(подделанный sha256, несовпадение слов), круговой экспорт→импорт карточки и ZIP, этап задачи (частичный сбой,
отмена, возобновление без повторного согласия). Смоук `word-gloss-ai-smoke` + живой прогон с реальным ключом на
коротком тексте и коротком видео; на проде — сборка → экспорт → импорт в чистый профиль → подписи «ИИ» без
сетевых запросов к `/api/word-gloss-ctx`.

## 6. Решения владельца

1. **Флажок при сборке по умолчанию** — (а) выключен, запоминается последний выбор на устройстве *(рекомендую)*;
   (б) всегда выключен; (в) повторяет тумблер «Перевод слов ИИ» чтения.
2. **Показ готовых ИИ-подписей** — (а) всегда, когда они есть, тумблер = только дозаказ *(рекомендую: деньги уже
   потрачены, качество выше)*; (б) только при включённом тумблере, как сейчас.
3. **Публикация в публичную Медиатеку** — (а) ИИ-слой едет с опубликованным материалом, все читатели видят подписи
   без своего ключа *(рекомендую для материалов, которые публикуете вы)*; (б) не едет, каждый платит сам.

**Решения приняты 2026-10-12: 1(а), 2(а), 3(а).**

## 7. Реализация (3.11.742)

- Ключ строки v2 и перенос v1: `public/js/word-gloss-ai.js` (`rowPayloadFromData`, `cellValue` без кнопок/значков,
  `legacyKeys` — v1 с ▶︎ и без; найденное по v1 копируется под v2). Машинная огласовка в `meta.niqqud_derived`
  даёт тот же ключ.
- Путь по данным: `ensureDataRows`, `estimateDataRows`, `glossCard` (итог = покрытие строк карточки).
- Слой: `portable(rows)` / `remember(layer, rows)`; подключён в `TextCardFormat` (`word_gloss_ai_layer`),
  `v3TcsBuildCardPayload`, `local-db exportBundle/importBundle` (кроме slim), ZIP медиа-материала —
  несемантический файл `learning/word-gloss-ai.json` (content root материала не меняется; подмена ловится
  контрольной суммой), импорт пакета — `applyVerified` (и для дубликата: слой вне content root).
- Публикация: `publication/materialArchive.js wordGlossLayer` (ограничение формы и размеров, только известные поля)
  кладёт слой в публичный снимок; сводка издателя «ИИ-перевод слов: N строк»; читатель Зала проверяет каждую
  строку при импорте снимка. Уже опубликованные материалы получат слой после повторной публикации архива.
- Сборка: `LearningMaterialTask` — подписанное согласие `word_gloss_ai {enabled, quote{words, usd, basis}}`,
  фаза `glossing` после ▶ и до пакета, сбой → `word_gloss.error`, материал готов; `retryWordGloss` («Догрузить»).
  Окно: флажок с ценой (текст — точно, ссылка — по длительности, 1,75 слова/с), без ключа недоступен, выбор
  помнится (`lmt.wordGlossAi`); живой прогресс «Перевод слов (ИИ): d из n строк»; итог на финале.
- Показ: `WordGloss.apply` — оплаченные подписи видны при включённом подстрочнике/ленте; `ai` = ленивый дозаказ.
- Гейты: npm test 2542/2542 (+16: `wordGlossAiLayer`, `learningMaterialTaskWordGloss`, `wordGlossAiPortable`),
  i18n 233/233, пакеты 70/70 + браузерный, text-card 35/35, reader-parity, reader-morph, studio-morph,
  autogen-parity, sw-update 12/12, word-gloss, word-gloss-ai (A2 под новое правило показа),
  learning-material-task-browser (флажок, цена по длительности, этап, итог, иврит 380 px),
  новый `scripts/premium/word-gloss-ai-material-smoke.js` (карточка → перевод по данным → экспорт карточки и
  библиотеки → стирание → импорт → 14/14 подписей ИИ без запросов; ▶︎ не меняет ключ).
