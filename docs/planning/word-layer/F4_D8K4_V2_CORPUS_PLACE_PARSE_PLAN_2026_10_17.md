### К4.1 Локальная выпечка (компьютер владельца, не прод)

`scripts/premium/bake-corpus-place-parse.js` — по образцу `build-proclitic-overlay.js` / `build-context-overlay.js --enrich`:

- **Источник строк** — те же файлы, что получает ученик: работы каталога Бен-Иегуды (`/data/benyehuda/works/…`, текущий
  каталог, включая учебные издания) и снимки общедоступных корпусов (`/api/public-corpora/<slug>/works/<id>?snapshot=`).
  Только публичные корпуса; личные тексты и групповые корпуса выпечка не видит.
- **Повторное использование:** кэш прежней выпечки (`.tmp/benyehuda/proclitic-overlay-dicta-cache.json`, снимок
  в `Архив/dicta-cache-snapshots/`), ключ — строка `hebrew_plain.trim()`. Строка из кэша не запрашивается заново;
  старые токены без огласовки (`nq` нет) дозапрашиваются (нужны огласовка и биньян).
- **Запросы к Dicta напрямую** тем же провайдером, что сервер (`db/premium/providers/dictaMorph.js`, модель
  `dicta-morph-v2`, жанр `modern` — как разбор своих текстов, чтобы правило А получало одинаковые факты), с IP
  компьютера владельца.
- **Вежливость (урок O-090 и `feedback_bulk_dicta_bake_ratelimit`):** не больше 2 запросов одновременно и пауза
  ≥ 300 мс между запросами; после 503/429 — пауза 2 мин, удвоение до 15 мин, первый запрос после паузы — проба, успех
  сбрасывает; после 3 подряд отказов-проб — остановка прогона с записью в журнал (утром продолжить).
- **Журнал и продолжение:** журнал готовых работ (`.tmp/d8k4/ledger.json`; кэш — атомарная запись + замок, как у прежних
  выпечек); перезапуск продолжает с места. **Повтор неразобранного:** отдельный проход только по строкам, где Dicta
  ответила пусто/ошибкой (не более 3 попыток на строку; оставшиеся перечислены в отчёте прогона).
- Снимок кэша после каждой ночи — в `Архив/dicta-cache-snapshots/` (gzip + контрольная сумма).

### К4.2 Файл раздачи — один на работу, сырые факты, сжатый

```
{ "v": 1, "model": "dicta-morph-v2", "src": { "kind": "by"|"pc", "id": "<работа>", "edition": "<bundle_sha256|snapshot_sha256>" },
  "rows": [ [ "<sha256(hebrew_plain.trim()) 16 hex>", <order_index>, [ [word, lemma, [lemmas…], posDicta, niqqud, binyan, prefix], … ] ], … ],
  "missing": <строк без разбора> }
```

- Только факты Dicta; ни ключа Pealim, ни решения. Строка без разбора в файл не входит (`missing` — счётчик).
- Адрес содержит издание: Бен-Иегуда — `/data/corpus-parse/by/<id>-<bundle_sha16>.json.gz`; Медиатека —
  `/api/public-corpora/<slug>/works/<id>/parse?snapshot=<sha>` **с той же проверкой права чтения**, что и сама работа
  (не статика: права изданий Медиатеки живут на сервере). Неизменяемый адрес → `Cache-Control: immutable`.
- Хранение: том прода (`/app/data/…`), не git, не деплой; загрузка — `push-corpus-place-parse.js` (как
  `push-context-overlay.js`, токен загрузки из окружения, атомарная перезапись, `--dry-run`).
- **Не в кэше PWA:** service worker эти адреса не кладёт в precache и не перехватывает в runtime-кэш; после применения
  разбор живёт в базе устройства — офлайн работает из базы, второй копии нет.

### К4.3 Применение на устройстве

Новый модуль `public/js/corpus-place-parse.js` (Node-тестируемый, зависимости аргументами, как `corpus-materialize.js`):

1. **Когда:** сразу после `ensureBenYehudaWork` / `ensurePublicWork` (импорт новой работы) и при открытии работы корпуса,
   у которой разбора ещё нет (работы, скачанные до выпуска). Одна работа за раз; в фоне, не на пути открытия текста.
2. **Сопоставление:** для каждой строки работы на устройстве (`sentences` по `text_id`) — `sha256(he_plain.trim())`
   (`crypto.subtle`) и `order_index`; строка файла применяется только при совпадении хеша. Затем проверка по номеру
   токена: скелет `word` токена i совпадает со скелетом единицы `ReaderMorph.placeUnits` по тому же выравниванию —
   иначе строка не применяется. Строка, которую ученик правил, не совпадёт по хешу — разбор к ней не попадёт.
3. **Запись:** `saveSentenceMorph(textId, sid, "dicta-morph-v2", tokens, "corpus-dicta")` — токены в форме хранимой
   строки (`{ word, prefix, stem, lemma, lemmas, niqqud, posDicta, binyan }`). **Только туда, где разбора нет:** свой
   разбор (`dicta-morph`) и разбор, пришедший в снимке Медиатеки, не перезаписываются (новая функция
   `saveSentenceMorphIfAbsent`, `INSERT … ON CONFLICT DO NOTHING`).
4. **Память (урок 3.11.760):** файл разжимается потоком (`DecompressionStream`), разбирается один раз; запись — страницами
   по 200 строк в одной транзакции; ни одной структуры на всю библиотеку. После записи — `ReaderMorph.invalidatePlaces`
   для строк работы. Хранилище мест не меняется: `ensurePlaces` по-прежнему держит ≤ 6000 строк, загрузчик читает базу
   порциями по 400.
5. **Лексикон устройства:** `DictaLexicon.refresh` **пропускает** строки `provider = 'corpus-dicta'` (см. «Развилка Р1»).
6. **Синхронизация и экспорт:** строки `corpus-dicta` не едут в облачную синхронизацию (воспроизводимы с сервера; урок
   O-088 о размере), полный экспорт сохраняет `provider` как есть (сейчас `exportBundle` переписывает его в `dicta-morph`).

### К4.5 Свои тексты: общий лимит сервера + медленная фоновая порция

- **Сервер:** один на процесс ограничитель запросов к Dicta (`db/premium/dictaBreaker.js` → `dictaGate`): не больше 2
  одновременных запросов **на весь сервер** (сейчас 2 — на один HTTP-запрос, N учеников = 2N), минимальный интервал
  между запросами, очередь с потолком; переполнение → ответ `rate_limited` с `retry_after_ms` (клиент ждёт). Общий
  с огласовкой (`niqqudGateway`, `nakdanOnDemand`) — бан Dicta на IP, а не на задачу.
- **Клиент (`DictaEnrich.autoEnrich`):** вместо 2000 строк за запуск — капля: 40 строк в запросе, пауза ≥ 20 с между
  запросами, только пока вкладка видима, не больше 600 строк за сеанс; `rate_limited` — остановка до следующего
  сеанса с учётом `retry_after_ms`. 4 633 строки владельца уйдут за ~8 сеансов без всплеска.
- **Вопрос при первом запуске:** один раз каждому, у кого решение не записано (новый ученик и старые ученики без
  согласия). **Когда именно — на утверждение:** рекомендация R4 — не при открытии приложения, а при первом СВОЁМ
  тексте (до него вопрос без предмета), карточкой-предложением, не модальным окном поверх чтения. Текст: что уходит (предложения ваших текстов), куда (Dicta, dicta.org.il, через наш сервер), что остаётся
  (разбор на устройстве, текст на сервере не хранится), как выключить (Настройки). Кнопки «Да, разбирать в фоне»
  (главная, в фокусе) и «Не сейчас»; **ничего не отмечено заранее**. Ответ записывается с версией текста и временем
  (`dictaAutoParseConsent_v1` + `…at`, «Не сейчас» — `…declined_at`); отказ не переспрашивается, включается в настройках.
  Строки — в локалях ru/en/he.

## Развилка Р1 — корпусный разбор и лексикон устройства (рекомендация: А сейчас, Б после замера)

Лексикон устройства складывает все строки `sentence_morph`; первое прочтение написания — ключ навсегда, а «решающее

Бен-Иегуды (архаика) станут ключами слов в своих текстах ученика и перевесят доли Д9 (R11).

- **А (рекомендация для первой поставки):** корпусный разбор работает только через правило места Д10; в лексикон не
  идёт. Омографы корпуса — по контексту сразу; слова корпуса вне Pealim остаются «не разобрано», как сейчас.
- **Б (вторая поставка, отдельное решение):** лексикон с раздельными счётчиками источников — своё прочтение главнее
  корпусного, корпусное даёт ключ только написанию, которого свои тексты не видели, и только из страт, прошедших Г2.
  До решения — замер на профиле владельца (только чтение): сколько написаний своих текстов сменили бы ключ.

## Развилка Р2 — «своя статья» против места (Д10.1, рекомендация: проверить экзаменатором до прогонов)

Замер на корпусе показал два частых класса ошибок правила места: הַיּוֹם «сегодня» → יום и אֱלֹהִים → אלוה. Оба —
слова, у которых есть своя статья Pealim, а Dicta отделяет приставку или даёт другую лемму. Д9 уже защищает такие
слова в чтении написания (A1, «наречие-заголовок не уступает»), но `_atPlace` эту защиту обходит.

- **Предложение Д10.1:** правило А не уводит слово от кандидата, чья цитатная форма = огласованная форма текста
  (своя статья, A1 Д9), кроме причастий (исключение Д9). Правка — в одном месте, действует и на своих текстах.
- **Проверка до решения:** в Г2 добавить страту «своя статья» (места, где А уводит от своей статьи), 60 случаев;
  если экзаменатор подтверждает ошибку в ≥ 70 % — Д10.1 в выпуск вместе с К4.3. Иначе — без Д10.1.
