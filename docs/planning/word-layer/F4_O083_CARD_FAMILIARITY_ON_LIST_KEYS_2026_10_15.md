# O-083 · «Знакомо X%» на карточках своих текстов — по ключам списка (2026-10-15)

Предшественники: `F4_D7_FORM_IDENTITY_SPEC_2026_10_14.md` (Д7.4 — знакомость среза словаря по ключам списка),
`F4_D8K_ROLE_CRITIQUE_2026_10_14.md`, `F4_D8K3_KEY_ALIAS_DESIGN_2026_10_14.md`. Журнал: O-083.

## Что не так (замер на профиле владельца, 2026-10-15, только чтение)

Карточки своих текстов в Зале и Студии считают «знакомо X%» конвейером ингредиентов B7
(`learning-compass-ingredients.js`, воркер): слово → `pid` по формам Pealim, без лексикона Dicta (`dl:`), без
личности формы (Д7), без имён. Словарь считает тот же текст сканом Зала (`ReaderMorph.scanRows`) по ключам своего
списка. Десять текстов владельца (24–198 строк):

| Текст | Зал/Студия | Словарь | Неразобрано: карточка → словарь |
|---|---|---|---|
| טבלאות כרונולוגיות | 12,4 % | 20,9 % | 406/680 → 184/588 |
| קטעי־יומן (רות רבינוב) | 23,1 % | 32,8 % | 520/1437 → 134/1150 |
| בֶּרְל כַּצֶּנֶּלְסוֹן | 26,4 % | 38,5 % | 691/2047 → 115/1576 |
| שְׁנֵינוּ | 28,8 % | 35,6 % | 28/132 → 14/105 |
| לֵילוֹת | 21,7 % | 19,8 % | 46/132 → 29/120 |
| … ещё пять | 17,5–25,2 % | 25,7–33,3 % | |

Карточка занижает знакомость на 4–12 п. п. (9 из 10), а 30–60 % неразобранного делают её «ограниченной»
(`rank_eligible: false`) — такие тексты выпадают из подборок «по знакомости». Один и тот же текст показывает два числа.

Скорость скана (desktop, профиль владельца): ~0,1 мс/строка; 2 477 строк — 725 мс (самая долгая блокировка 316 мс),
684 строки — 101 мс; все 400 своих текстов (72 тыс. строк) ≈ 25 с фоном.

## Решение

1. **Один скан текста по ключам списка** — `public/js/text-key-scan.js` (UMD): слой имён из перевода слоя слов,
   решения «это имя (здесь)», скан `ReaderMorph.scanRows`, ингредиенты по ключам списка. Словарь и карточки зовут
   ОДНУ функцию — число совпадает по построению (не «по той же идее»).
2. **Карточки своих текстов** (Зал «Мои тексты», Студия): ингредиенты = скан. Поле `text_token_count` — все слова
   текста (как считал воркер): по нему время чтения; `total_token_count` остаётся суммой ключей + неразобранное +
   имена (инвариант оценщика).
3. **Версия ключей в кэше**: `resolver_version` описателя = `recorded-familiarity-v2|keys:<поколение>`, поколение =
   версия скана + число строк лексикона Dicta + число событий alias + число решений «имя». Вырос лексикон / объединили
   историю — карточки пересчитываются фоном; текст не трогается. В самих ингредиентах `resolver_version` прежний —
   оценщик тот же.
4. **Калибровка скорости чтения** остаётся на подсчёте воркера (все слова) и больше НЕ пишет кэш своих текстов
   (иначе ингредиенты воркера легли бы под описатель скана).
5. **Корпуса не трогаем**: каталог Бен-Иегуды, Медиатеки и групп ранжирует работы ингредиентами сервера; одна работа
   не должна показывать в каталоге одно число, а скачанная — другое. Их перевод на ключи списка — вместе с разбором
   корпусов Dicta на сервере (Д8-К4, отложено владельцем).

## Разбор по ролям (до кода)

- **R2 (методист)**: служебные слова выходят из знаменателя — как в словаре (Д7.4, решение владельца); процент станет
  выше и честнее: «знакомо» про слова, которые учат. Время чтения считает все слова — иначе оно занижено на ~25 %.
- **R10 (морфолог-оценщик)**: скан не идеален (архаика, «guessed»), но это тот же разбор, что видит ученик на тапе и
  в словаре; неразобранное честно остаётся в знаменателе как «незнакомое».
- **R11 (do-no-harm)**: журнал и проекция не меняются — только одноразовый кэш агрегатов; старые строки кэша по
  другой версии просто не совпадут и будут пересчитаны. Ранжирование идёт внутри одного источника (свои тексты
  между собой) — шкалы не смешиваются.
- **R16 (цена на устройстве)**: пересчёт всех своих текстов ≈ 25 с CPU фоном на desktop, на iPhone оценочно 3–4×;
  повод — только рост лексикона/объединение/решение «имя», не каждое открытие. Скан уступает поток (async) между
  текстами; страница остаётся отзывчивой.
- **R4 (UX)**: на карточке меняется только число; «оценка ограничена» исчезнет у большинства текстов.
- **Риск**: словарь и карточки начинают зависеть от одного модуля — регресс в нём виден сразу в обоих местах (это
  и цель). Гейты: юнит на ингредиенты (инвариант сумм, `text_token_count`), смоук словаря (D-гейты знакомости),
  смоук карточек Зала (room-b7-learning-compass), сверка на профиле владельца: число карточки = число словаря.

## Реализация (3.11.774)

- `public/js/text-key-scan.js`: `scanLens` (лексикон → решения «имя» → слой имён → `scanRows`), `listIngredients`
  (единственная реализация; `DictionaryProgress.scanIngredients` — тонкая обёртка), `textIngredients` (+ `text_token_count`;
  без движка Pealim — `LEXICAL_RESOLVER_UNAVAILABLE`, в кэш не пишется), `generation`.
- Словарь зовёт `scanLens`/`listIngredients`; `LocalTextFamiliarity` (Студия) и Зал (`myCompassDescriptor`,
  `buildAndCacheCompassDescriptor`, счётчик «Готовим подбор») — тот же скан и та же версия кэша.
- `MorphHost.loadDictaLexicon` — общий промис лексикона; колбэк каждого хоста вызывается один раз, кто бы ни начал загрузку.
- Не входит в поколение: слой перевода слов (его «имя:» подсказки) — живёт в своём кэше; изменение подтянется при
  следующем изменении текста или лексикона.
