## 3. Находки, которые нужно закрыть до массовой публикации

- **Н1. Сборщик теряет слой ИИ целиком** (`build-learning-release.py:89`): в `normalized` нет `word_gloss_ai_layer`. Строки собираются по белому списку (стр. 79). `hebrew_niqqud` и `russian` при этом сохраняются байт в байт, поэтому после переноса ключи сойдутся. Нужен приёмочный тест «исходный ZIP → тело → чистый клиент → повторное открытие» с результатом `rejected=0` (Ф3).
- **Н2. Числовые потолки в маршруте Медиатеки** (`materialArchive.js:105`: `glosses.length<=80`, `mwe<=40`). Решение владельца от 2026-10-22: снять или обновить. **Предложение:** вместо чисел ввести структурный инвариант клиента — число глосс равно числу слов строки, а `mwe.from ≤ to < n`. Санитарный лимит 120 символов на одну глоссу оставить: максимум в данных 88. Вместо счётного потолка ввести общий бюджет байтов тела. Каждую отброшенную строку записывать в отчёт с причиной.
- **Н3. Отказы клиента не видны никому.** `local-db.js:6916` и `:7080` вызывают `WordGlossAI.remember()`, но результат `{stored, rejected}` выбрасывают. Его нужно поднимать в итог импорта как отдельный исход: текст сохранён, слой сохранён частично (N из M). Это не ошибка сохранения текста (см. [[feedback_optional_cache_not_canon]]).
- **Н4. Части не связаны.** `book_section` нигде не читается, в каталоге `parts=1`, а `library-ui.js:12169` умеет только подпись «N частей». Оглавления, переходов между частями и сквозного «Продолжить» нет.
- **Н5. Гигантские строки.** В папках 7 и 8 1 760 строк длиннее 80 слов, 305 — длиннее 200, максимум 791 слово. Слой ИИ для них оплачен и верен. Пересегментация сменит ключи и оплату: без причины её не делаем. Нужен только замер открытия и прокрутки на телефоне (Ф6).
- **Н6. Метка эпохи против официального периода.** У неопубликованных `official_period=modern`, а `era/app_era` равен `mandate`, `tehiya`, `unknown` или пусто. Полку Modern строим по официальному периоду, а `era` оставляем фасетом. Это требует подтверждения владельца.
- **Н7. Хранение версий и откат.** Тела лежат на томе прода, каталог — неизменяемые файлы `vN` в git. Откат каталога означает возврат к `v(N-1)`. В Ф1 нужно проверить, что тела старой версии не стираются и том переживает перезапуск.

## 4. Как устроено произведение (без склейки строк)

- **Карточка произведения** в Modern: одна запись каталога `kind:"work"` с манифестом частей `parts[]`. В каждой записи — `part_id`, `section_id`, `order`, дорожка, заголовок, число строк, `edition_id`, `body_sha256` и тело.
- **Часть** = существующее учебное издание (`benyehuda-learning-edition`) со своим телом, `text_key` и `edition_id`. Механизмы `previous_text_keys`, открытия опубликованного и защиты устройства переиспользуются без изменений.
- **Ленивая загрузка:** открытие произведения скачивает манифест и одну нужную часть (`corpus-materialize.js`).
- **Прогресс:** по части — существующий `text_progress.last_row_idx`; по произведению — производное значение (доля прочитанных строк по частям), отдельно не хранится. «Продолжить» = последняя открытая часть и её строка.
- **Переходы:** в конце части — «Следующая часть», в начале — «Предыдущая». Оглавление показывает дорожки (текст / примечания / структура) и пометку «выбранные фрагменты».
- **Единый ZIP для скачивания** = архив с теми же частями и их идентификаторами плюс манифест произведения. Это резервная копия, а не склеенный текст.

## 5. Реестр выпуска (`registry.json`, единственный источник статусов)

Для произведения: `work_id`, автор, заголовок, официальный период, «полное / избранное», список частей, `registry_version`, статус проверки и публикации, ссылка на backup.
Для части: `part_id`, `section_id`, дорожка, `order`, исходный архив + sha256, `library_sha256`, `rows_sha256`, число строк, `source_dump_sha256`, `section_source_sha256`, границы в символах, слой ИИ (строк / покрыто / отказов клиента), выбранная редакция или отвергнутые дубли (с причиной), опубликованное тело + sha256, версия каталога.
Счётчики произведений, частей и ZIP ведутся раздельно. Статус в названии папки — только подсказка: истиной считается реестр.

## 6. Контракт переноса (вход → публичное тело)

Сравниваются поля по каждому классу данных, итог «перенесено / отброшено (причина)» без молчаливых потерь:
- **основные:** `hebrew_plain`, `hebrew_niqqud`, `russian`, `translit`, `translit_ru`, `order_index`, `row_id`, `translation_provider`, `niqqud_authority`;
- **морфология и огласовка:** `meta.niqqud_derived` (публичное подмножество `public_derived`), `meta.*` с позициями в источнике;
- **слой ИИ:** `word_gloss_ai_layer` целиком; для каждой строки — ключ, повторно доказанный клиентским `rowPayloadFromData`;
- **паспорт части:** `book_section`, `text_learning` (без путей и данных сборки);
- **запрещено в публичном пакете:** заметки, прогресс, закладки, SRS, `imported_at` устройства, пути архивов, промты, журналы сборки, Details/Evidence/PDF.

Белый список сборщика пересматриваем по этому контракту, а не только добавляем одно поле.
