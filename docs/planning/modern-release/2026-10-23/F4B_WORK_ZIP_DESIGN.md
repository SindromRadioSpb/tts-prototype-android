# Ф4б — единый ZIP произведения из частей (дизайн, 2026-10-23)

Требование владельца (2026-10-22, п. 1): «Единый ZIP можно добавить позже: внутри те же части и идентификаторы».

## Что получает ученик
На странице произведения (оглавление) кнопка **«Скачать произведение (ZIP)»**. Открывается то же окно «Отправить или сохранить», что у отдельного текста: состав архива, ход подготовки, «Отправить ZIP» / «Сохранить ZIP».

## Из чего собирается
Из **публичных проверенных тел частей** (`works/<id>-<hash32>.json`), не из копии на устройстве:
- каждое тело скачивается тем же путём, что при открытии части, и проверяется по `bundle_sha256` из запечатанного оглавления (`BenYehudaLearningEdition.verifyBytes`) — несовпадение = архив не собирается, сообщение «часть N пришла повреждённой»;
- личных данных нет по построению (заметки, прогресс, закладки живут в базе устройства, а не в публичных телах) — это требование п. 4 «аудит публичного пакета»;
- части, уже лежащие на устройстве, всё равно берутся из публичного тела (кэш браузера/SW отдаёт их без сети, если они уже скачивались); в базу устройства сборка ничего не пишет.

## Формат (совместим с существующим импортом)
```
manifest.json          format: linguistpro-bundle, schema_version 1, text_count = число частей,
                       work: { schema: benyehuda-work-zip-v1, work_id, title, author, catalog_version,
                               toc_sha256, parts: [{ part_id, order, track, parent, text_key,
                               learning_edition_id, bundle_sha256, rows }] }
library/library.json   { schema_version, corpus_meta_version, texts: [тексты всех частей в порядке оглавления],
                         shelves: [], audio_assets: [] }   — тексты байт-в-байт из тел (с word_gloss_ai_layer)
work/toc.json          запечатанное оглавление как опубликовано (байты, sha = card.toc_sha256)
```
- Идентификаторы те же: `text_key`, `learning_edition_id`, `part_id`, `source_meta.public_learning.part` — импорт ZIP на другом устройстве даёт ровно те же тексты, что открытие частей из каталога (прогресс и «Продолжить» сходятся).
- Аудио: у публичных изданий Modern аудио нет → `audio_count 0`, не «частичный» архив.
- Сжатие DEFLATE: самое большое произведение (47169) — 26,7 МБ JSON → ≈5–6 МБ ZIP.

## Память и сеть (телефон)
- Части скачиваются по одной (последовательно), тело разбирается, из него берётся `library.texts[0]`, остальное отпускается. Пик ≈ размер всего JSON (≤ 27 МБ) + ZIP.
- Прогресс «часть k из N», отмена закрытием окна (AbortController уже есть в окне).
- Без сети и без кэша части → честный отказ «нужна сеть», ничего не записано.

## Разбор по ролям (опровержение до кода)
- **R-ученик:** «зачем ZIP, если части открываются?» — для переноса на другое устройство/офлайн-архива и отправки преподавателю; кнопка не главная, во второй строке страницы произведения. ✔
- **R-данные/целостность:** «тела из кэша могут быть старой редакции» — проверка каждого тела по `bundle_sha256` из оглавления, запечатанного каталогом; старая редакция не пройдёт. ✔
- **R-приватность:** «ZIP с устройства утащил бы заметки» — собираем только из публичных тел. ✔
- **R-совместимость:** «импорт не знает про произведения» — и не должен: каждая часть — обычный текст; `work/toc.json` — справка для будущего импорта целиком. Риск: импорт 160 текстов разом. Проверить импортом ZIP 56289 в чистый профиль. ⚠ проверка в приёмке.
- **R-производительность:** «26 МБ JSON на телефоне» — последовательная загрузка, без импорта в базу; замерить пик памяти на 47169. ⚠ проверка в приёмке.
- **R-продукт:** «а единый ZIP в каталоге (без открытия страницы)?» — не нужен: вход только со страницы произведения, там же видно, что это N частей.

## Приёмка
1. 58052 и 56289: ZIP собран, `text_count` = частям, каждый текст байт-в-байт равен тексту из тела, `work/toc.json` sha = `toc_sha256`.
2. Импорт ZIP в чистый профиль: N текстов, слой ИИ сохранён (`rejected 0`), страница произведения показывает части «на устройстве».
3. Испорченное тело → архив не собирается, понятное сообщение.
4. Офлайн без кэша → «нужна сеть»; с кэшем → собирается.
5. ru/en/he, 380 px.
