# Ф4. Произведение из частей в Читальном зале — дизайн

Дата: 2026-10-23. Статус: **ПРОЕКТ, ждёт решений владельца по §9.** Код не написан.
Основа: план `../2026-10-22/README.md` (§4, §8, §11), кандидат выпуска Ф2 (363 произведения, 719 тел).
Код проверен по `origin/main` @ `bf4af1b3`.

## 1. Что нужно (слова владельца)

- одна карточка произведения;
- оглавление с правильным порядком частей;
- переходы «Предыдущая / Следующая часть»;
- кнопка «Продолжить» с последней позиции;
- прогресс по произведению и отдельно по частям;
- загрузка нужной части, а не всей книги.

Склеивать строки в один огромный учебный объект нельзя. Единый ZIP — отдельно и позже (Ф4б): внутри него те же части и идентификаторы.

## 3. Данные

### 3.1 Карточка произведения в каталоге (era-манифест)
У однородного произведения карточка остаётся **точно как сейчас** (`parts: 1`). Это 345 из 363 работ кандидата. Многочастных — 18: 8 исходных (17966, 28023, 28024, 47169, 54845, 56289, 58052, 64596) и 10 крупных однородных, поделённых сборщиком на фрагменты (10290, 10291, 10754, 24374, 29108, 29289, 30738, 34231, 50615, 64365).

У многочастного: `parts: N` (как сейчас), `segments` — сумма строк основной дорожки, `toc_file` + `toc_sha256` — оглавление отдельным неизменяемым файлом, `text_key`/`file` первой части, чтобы старый код, не знающий о частях, открыл хотя бы начало, а не сломался.

### 3.2 Оглавление `works/<id>-<hash16>-toc.json` (ленивое, проверяется по sha256)
```json
{ "schema": "benyehuda-work-toc-v1", "work_id": "64596", "title": "ראשית", "scope": "complete",
  "source_coverage": 0.9995, "about": [{"kind":"byline","text":"…"}],
  "parts": [ { "part_id": "64596-section-01", "order": 1, "track": "text", "title": "ראשית · 01",
               "fragment": null, "rows": 216, "file": "works/64596-….json", "bundle_sha256": "…",
               "text_key": "…", "learning_edition_id": "…", "word_gloss_ai_rows": 216,
               "previous_text_keys": [] } ] }
```
Почему отдельный файл: 56289 имеет 160 частей. Встраивать их в era-манифест значит качать оглавление при каждом просмотре эпохи. Оглавление нужно только при открытии произведения.

### 3.3 Части на устройстве
Каждая часть после первого открытия — обычный локальный текст (как сейчас любое учебное издание). Связь с произведением уже лежит в теле: `source_meta.public_learning.part = { work_id, part_id, track, fragment, title }`, `corpus.byehuda_id`. Этого достаточно для «Продолжить», прогресса и «Прочитанных» **без каталога и без сети**.

## 4. Поведение

### 4.1 Каталог и поиск
Одна карточка. Подпись объёма — «47 частей · 10 119 строк». Если на устройстве есть прогресс — бейдж «часть 3 из 47 · 12%». Нажатие открывает **страницу произведения** (§4.2), а не первую часть.

### 4.2 Страница произведения (новый экран читателя Зала, мобильный в первую очередь)
- Заголовок, автор, «О материале» (как сейчас, плюс объём и состав).
- **Главная кнопка:** «Продолжить: часть 3 · строка 45» при наличии прогресса, иначе «Начать чтение».
- **Прогресс произведения:** «прочитано частей 2 из 47 · 6% строк». Строки считаются только по основной дорожке и только по фактически открытым частям; неоткрытая часть — 0, без догадок.
- **Оглавление:** список частей по порядку Бен-Иегуды. У каждой — номер, название, строки, своё состояние («не открыта» / «45%» / «✓ прочитано»), значок «на устройстве».
  - Дорожки «Примечания» и «Структура» (у 56289 и 58052) — см. §9, вопрос 2.
  - Фрагменты одной части («· 1/4») идут подряд, отступом под своей частью.
- Длинное оглавление (160 строк) — виртуальный список не нужен (160 строк DOM дёшево), но с поиском по названию части и кнопкой «к текущей части».

### 4.3 Читатель части
- **Полоса частей** над таблицей: «‹ Предыдущая · Часть 3 из 47 · Оглавление · Следующая ›». В RTL стрелки и порядок зеркалятся.
- **Финальная карточка:** первым пунктом «Следующая часть: <название> (N строк)», дальше — существующий «что дальше». На последней части: «Произведение прочитано» и предложение отметить его.
- Переход к соседней части загружает только её (тот же `ensureBenYehudaWork` с карточкой части). Следующая часть может подгружаться в фоне, когда читатель дошёл до последних 10% текущей (только при сети и не на экономном трафике).

### 4.4 Полка «Продолжить чтение»
Одна карточка на произведение: название произведения, «часть 3 из 47 · 45%», нажатие открывает именно эту часть на сохранённой строке. Запрос `getContinueReading` добавляет `json_extract(source_meta_json,'$.public_learning.part.work_id')` **один раз на текст** (не на строку — урок iPhone OOM 3.11.760) и группирует в JS по самой свежей части.

### 4.5 «Прочитано»
Часть отмечается как сейчас. Произведение «прочитано», когда все части основной дорожки отмечены или пройдены (≥95%). Отметка «прочитать всё» на странице произведения ставит отметки только на уже открытых частях. Никаких подложных записей прогресса для неоткрытых частей.

### 4.6 Офлайн и загрузка
- Открытая часть доступна офлайн, как любое учебное издание.
- На странице произведения: «На устройстве: 5 из 47 частей». Кнопка «Скачать все части» скачивает их по одной, с прогрессом и продолжением после обрыва (тот же цикл `corpus-materialize` «одна за другой, без остановки на сбое», он уже есть).
- Офлайн без оглавления: если файл оглавления не скачан, страница произведения строится из частей на устройстве и честно говорит «оглавление недоступно без сети». Тупика нет: «Продолжить» работает.

### 4.7 Обновления и откат
- Исправление части = новое издание этой части (новый `edition_id`, новый файл), у части появляются `previous_text_keys`. Механизм сохранения старого издания на устройстве работает по части.
- Новый файл оглавления (новый hash) публикуется вместе с каталогом v(N+1). Откат — возврат каталога v(N), старое оглавление и тела на томе остаются.
- Старые ссылки `?corpus_work=<id>` продолжают работать: они открывают страницу произведения.

## 6. Чего Ф4 НЕ делает
- Не склеивает строки.
- Не меняет однородные произведения и не трогает 688 опубликованных изданий.
- Не делает единый ZIP (Ф4б).
- Не меняет эпохи приложения (см. §9, вопрос 1).

## 7. Опровергающий разбор по ролям (до кода)

Каждая роль пыталась доказать, что дизайн плох. Ниже — возражение и чем оно закрыто.

- **R4 Премиум-UX.**
  - *Возражение:* лишний экран — нажал на книгу, а читать не начал; это хуже, чем сразу открыть часть.
  - *Ответ:* если есть прогресс, главная кнопка страницы произведения — «Продолжить» в зоне большого пальца, это один тап. А с полки «Продолжить чтение» открывается сразу часть, без страницы. Для первого открытия страница с оглавлением нужна: читатель видит, что книга из 47 частей, а не попадает молча в «01».
  - *Возражение 2:* 160 строк оглавления Алона на 380px — свалка.
  - *Ответ:* дорожки свёрнуты (§9.2), есть «к текущей части» и поиск по названию.
- **R8 Graded reading.**
  - *Возражение:* «47 частей» пугает новичка.
  - *Ответ:* прогресс показывает пройденное («2 из 47»), каждая часть — законченный учебный кусок со своим «✓». Страница не обещает «лёгкости», которой нет: объём честный.
- **R6 Куратор-библиотекарь.**
  - *Возражение:* одна запись каталога на книгу из «избранных записей» (Сенеш 28024, 67 фрагментов) выдаёт избранное за книгу.
  - *Ответ:* объём «выбранные фрагменты» и покрытие источника (75%) — в карточке и в «О материале» (§4.2), в формулировке без процентов-догадок.
- **R7 Литературовед.**
  - *Возражение:* порядок «по положению в источнике» ломается у Сенеш: три снимка источника, части из HTML-блоков.
  - *Ответ:* реестр привязал все 67 частей к одному тексту выгрузки, наложений нет (Ф0). Порядок — по этой привязке, а не по номерам архивов.
- **R2 Методист.**
  - *Возражение:* прогресс «% строк» поощряет пролистывание.
  - *Ответ:* это существующая метрика Зала (`continuePercent`), не новая; отметка «прочитано» по-прежнему ставится только при ≥95% строк части.
- **R11 Регрессолог.**
  - *Возражение:* группировка «Продолжить» по `work_id` может спрятать обычный текст, если у двух материалов совпадёт `work_id`.
  - *Ответ:* группируются только тексты с `public_learning.part.work_id`, а это появляется лишь в телах частей Ф2. Однородные и старые издания проходят как сейчас. Тест обязателен на смешанном профиле: старое издание + части + собственный текст.
  - *Возражение 2:* неоткрытые части в прогрессе как «0%» занижают прогресс, а «скачать всё» могло бы ставить ложный прогресс.
  - *Ответ:* прогресс пишется только при чтении; загрузка ничего не пишет в `text_progress`.
- **R5 Продукт / R16 Стоимость.**
  - *Возражение:* фоновая подгрузка следующей части тратит трафик.
  - *Ответ:* только у последних 10% части, только при сети и без режима экономии; отключаемо.
- **R4 + R11, мобильная память.**
  - *Возражение:* тело 4 МБ всё ещё тяжело на iPhone.
  - *Ответ:* это верхняя граница; медиана тела 0,12 МБ, 90-й процентиль 0,96 МБ. Замер открытия самого тяжёлого — обязательная приёмка Ф6.

Неснятых красных флагов нет. Два решения — за владельцем (§9).

## 8. Приёмка Ф4
- 380px LTR (ru) и RTL (he) плюс desktop: каталог, страница произведения, полоса частей, конечная карточка, полка «Продолжить».
- Сценарий в браузере на **непустом** профиле: открыть произведение → часть 1 → дочитать → «Следующая часть» → закрыть → «Продолжить» с полки → та же строка → оглавление → часть 5 → прогресс «2 из N».
- Офлайн: открытые части читаются, страница произведения без оглавления честно говорит об этом.
- Старая ссылка `?corpus_work=` и ссылка на часть.
- `npm test`, `smoke:reader-parity` (правило: правка читателя), `smoke:corpus-room`, `smoke:corpus-nav`.

## 9. Решения владельца

1. **Полка Modern.** В Зале навигация по эпохам приложения; официальный период Бен-Иегуды виден только в «О материале». 688 опубликованных «modern» сейчас лежат в «Подмандатном периоде» (309) и в «Период не определён» (287). Варианты:
   - **А (рекомендую):** отдельная подборка на главной Зала «Современная ивритская литература — по классификации Бен-Иегуды» по официальному периоду. Эпохи приложения не трогаются, работа видна в обоих местах.
   - **Б:** перенести официально-«modern» работы в эпоху «Современная литература». Около 600 работ поменяют место в навигации; старые позиции «эпоха → автор» у читателей изменятся.
   - **В:** ничего не менять.
2. **Дорожки «Примечания» и «Структура»** (только 56289 Алон и 58052 «Рабочий»):
   - **А (рекомендую):** в оглавлении — только основной текст; у главы, где есть примечания и структура, — вложенные пункты «Примечания к главе», «Структура главы», свёрнутые по умолчанию.
   - **Б:** отдельные разделы «Примечания» и «Структура» в конце оглавления.
