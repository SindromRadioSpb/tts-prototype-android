## O-092 · Д8-К4: строка с кавычками (מפא"י, תרפ"ז, כ"כ) теряет разбор корпуса целиком
- **Дата / где:** 2026-10-17, прод 3.11.781, проверка Г5 на чистом профиле; работа Бен-Иегуды 55762 «נפלה ההכרעה»: из 241 строки разбор лёг на 215, 23 отброшены как «не выровненные», 3 без совпадения хеша.
- **Что видно:** устройство делит מפ"ם на «מפ» и «ם» (и оставляет гереш в בקיבוץ׳, ה׳רכיבה׳), а у Dicta это одно слово «מפ"ם» (или «ה» + «רכיבה»). В `ReaderMorph.placeUnits` совпадения нет, доля выровненных слов падает ниже 90 % (`CorpusPlaceParse` MIN_ALIGNED), и строка не получает фактов совсем, вместе со всеми омографами в ней.
- **Масштаб (замер на выпечке, без Dicta, [скрипт](../research/d8k4-corpus-parse/2026-10-17/g5-prod/misalign-measure.js)):** 634 готовые работы, 57 153 строки с разбором; отброшено 2 197 (3,84 %), в них 15 752 слова. 2 179 из 2 197 — строки с `"`/`״`/`׳`/`'` (сокращения, годы по еврейскому счёту, инициалы); оставшиеся 18 — сокращения с точками (ה.ח.צ, א.נ.מ).
- **Почему важно:** правило места не работает в каждой 26-й строке корпуса; чаще всего в публицистике и письмах периода мандата, где сокращений много.
- **Предложение:** чинится на устройстве, без повторной выпечки и без Dicta. Сравнивать в `placeUnits` без кавычек и гереша, а слово Dicta, совпадающее со склейкой соседних единиц устройства (מפ + ם = מפם), считать выровненным с ними; либо не учитывать такие осколки в знаменателе порога. Гейт: тот же скрипт (цель: отброшено < 0,5 %) и `tests/corpusPlaceParse.test.js`. Код — область Д8-К4, править согласованно с её сессией.
- **Исправление (3.11.782):** `placeUnits` сравнивает буквы без кавычек и гереша (ר׳ = ר'); куски сокращения, которое устройство режет по кавычке, а Dicta держит одним словом, считаются выровненными («покрыты»), но токена не получают — осколок не берёт разбор целого слова (R11). Порог в `CorpusPlaceParse.apply` = выровненные + покрытые. Работа, применённая прежним выравниванием, применяется один раз заново (`ALIGN = 2`, список работ в `lp.corpusParse.aligned.v2`): строки с фактами не трогаются, отброшенные получают факты. **Замер** на 690 выпеченных работах / 62 553 строках: отброшено 2404 (3,84 %) → 286 (0,46 %); остаток — цепочки ссылок на стихи (משלי ט"ו י וט"ו), где устройство теряет однобуквенные куски целиком. На 60 029 строках, выровненных и прежде, расхождений 0, плюс 669 слов получили факты (гереш). Тесты: `tests/corpusPlaceParse.test.js` (реальные строки работ 191 и 55, повторное применение).
- **Статус:** закрыто (3.11.782), проверено на проде (работа 191: 39 из 39 строк с кавычками с фактами).

- **Дата / где:** 2026-10-16, прод 3.11.777, доразбор личных текстов владельца в «Моём словаре» (29 324 строки, 262 текста, по 40 строк в запросе `/api/morphology/batch`, запросы последовательно).

Тесты `tests/morphologyBreaker.test.js`, `tests/dictaEnrich.test.js`.
- **Огласовка (2026-10-16, после 3.11.780):** предохранитель вынесен в общий `db/premium/dictaBreaker.js` — бан Dicta на IP, а не на задачу, поэтому один отказ останавливает все три серверных пути: разбор (`morphologyGateway`), пакетную огласовку (`niqqudGateway` → `dictaCloud`, теперь по 2 одновременно вместо 3; после отказа остаток пакета не отправляется, ответ несёт `rate_limited` и `retry_after_ms`) и огласовку по запросу (`nakdanOnDemand`, её 30-секундная пауза после 3 ошибок осталась, сверху — общая). Параллельные отказы одного бана удваивают паузу один раз. `/api/niqqud` и `/api/niqqud/on-demand` (503) говорят `rate_limited`; `reniqqud-fill` помечает работу неудачной, а не «нечего огласовывать». Клиенты (Студия, Зал) и так останавливаются на первой ошибке. Тест `tests/niqqudBreaker.test.js`.
- **Осталось:** доразобрать 4 633 строки, когда Dicta снимет блок (автоматический разбор подхватит их сам, порциями по 2000 при запуске). Попутно: `scripts/premium/nakdan-integration-smoke.js` падает на устаревшей проверке `CACHE_VERSION = "v3.11.237"` (не связано).

- **Что видно:** пока идут обогащение Dicta и «📚 Спряжения (Pealim)», действия с карточкой и интерфейсом заблокированы.
- **Причина (проверена):** после сохранения карточки `v3MorphMaybeAutoEnrich` запускает фоновый проход (код не ждёт его), но прогресс `#v3MorphEnrichProgress` был полноэкранным затемняющим слоем (`position:fixed; inset:0; z-index:100000`). На 798 строках «Голани» это минуты.
- **Статус:** закрыто (3.11.634): прогресс — плашка в углу, клики проходят сквозь хост, `role=status`/`aria-live=polite`. Не проверено: гонки записи морфологии, если человек за это время правит строки той же карточки.

## O-001 · Новая версия не подхватывается обычной перезагрузкой
- **Дата / где:** 2026-09-24 (3.11.626 → 627) и 2026-09-25 (3.11.632 → 633), вкладка Студии владельца.
- **Что видно:** после деплоя две обычные перезагрузки оставляли старую `APP_VERSION`; помогла только `unregister()` регистрации service worker. `registration.update()` + `SKIP_WAITING` не помогали.
- **Почему важно:** обычный пользователь остаётся на старой версии, пока не закроет все вкладки; исправления до него не доходят, а stale-tab guard может блокировать действия.
- **Предполагаемая причина:** не проверена. Кандидаты: waiting worker не активируется (нет обработчика `SKIP_WAITING` или `clients.claim()`), либо `index.html` отдаётся из кэша SW до активации.
- **Новое свидетельство (2026-09-25):** профиль Playwright MCP с прошлых сессий при живой 3.11.635 загрузил `APP_VERSION` **3.11.344** из service worker: отставание на ~290 релизов. Блокирует ценность программы UI-релизов (AUDIT P0-11).
- **Предложение:** воспроизвести на одноразовом профиле: деплой → перезагрузка → какая версия; проверить `sw.js` (install/activate/message); показать «Доступна новая версия — обновить» с надёжной активацией.
- **Итог R0 (2026-09-25):** воспроизведено стендом `npm run smoke:sw-update` (сценарий E: катящийся деплой → новый воркер не ставится → после схождения две обычные перезагрузки дают старую версию). Тост в Студии, Зале и Медиатеке доставляет релиз одним нажатием (A, D, E зелёные). В Медиатеке добавлены проверка обновлений и нажатие по актуальной регистрации. «Перезагрузка приносит релиз» не решено → O-015.
- **Статус:** закрыто частично (R0); остаток — O-015.
