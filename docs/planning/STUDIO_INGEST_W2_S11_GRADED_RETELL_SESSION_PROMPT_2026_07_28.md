## Задача слайса

Кнопка/опция **«Упростить до моего уровня»** для импортированного (и вообще любого) текста:
из оригинала строится **пересказ на иврите уровня ученика** — короче, лексика и грамматика
по силам, смысл сохранён — и приземляется как ОТДЕЛЬНЫЙ текст со своей таблицей (оригинал
не подменяется — R11 do-no-harm). Педагогическая пара к S12: часовой подкаст → 10-минутный
пересказ по уровню; ученик читает пересказ, амбициозный — оригинал с караоке.

## Что уже есть (кирпичи — проверить по живому коду, не принимать на веру)

1. **Уровень ученика локально:** `word_status` (известные слова, OPFS) + `lemma-canon.js`
  (единый кейер) + офлайн-морфословарь (`pealim-infl-v12`, 9279 парадигм) + FSRS
  (`fsrs-core.js`). Из этого локально считается **known-coverage любого текста** (доля
  известных лемм) — измеримая основа «уровня» вместо гадания.
2. **PAS-D «next-text» и «scaffold-advisor»** (премиум-агенты, SHIPPED v3.11.153-167) — уже
  выбирают тексты по уровню и советуют скаффолды. Грепни их код/промты: как они сейчас
  оценивают уровень/сложность; переиспользуй, не изобретай второй способ (config-string-match:
  одно определение уровня на проект).
3. **BYOK-пути к Gemini:** серверный прокси `/api/translate-table`-класса (с кэшем) И прямой
  браузерный вызов `generativelanguage` (паттерн `gemini-files.js`, S4). Пересказ может пойти
  любым — развилка (см. ниже).
4. **Приземление текста:** «текст в поле ввода → AI Перевод → таблица → сохранить» —
  существующий конвейер; пересказ длиной >250 строк сам попадёт под чанк-механику S12.
  Провенанс-паспорт `v3LastGeminiMeta.source` + панель «Происхождение» (R9) — расширяемы.
5. **Graded-reading доктрина:** R8-роль; Зал имеет scaffolded reading console (adaptive
  niqqud, tap-reveal) — пересказ это ДРУГОЕ (переписывание текста), но UX-язык уровней
  должен быть согласован.

## Замеры/разведка ДО дизайна (R10 measure-before-code — норма проекта)

1. **Качество пересказа на реальном материале** (главный риск — R1: выдуманные формы,
   кривой иврит): взять 2-3 реальных текста разной сложности (транскрипт подкаста из
   research-материалов S12, статья, рассказ из корпуса), прогнать 2-3 варианта промта
   (уровень задан по-разному: CEFR-меткой / списком известных лемм / целевой coverage),
   оценить выход R1/R2-линзами. Мини-gold: 10-20 предложений с ручной разметкой
   «форма существует / выдумана». Реальный ключ (`GEMINI_API_KEY` в .env) — есть; квота
   могла восстановиться после 2026-07-28.
2. **Known-coverage движок:** есть ли готовый расчёт coverage текста против word_status
   (next-text PAS-D что-то такое делает?) — грепнуть; замерить скорость на длинном тексте
   (3000+ лемм) на CPU-троттле.
3. **Токены/стоимость/время** пересказа длинного транскрипта (вход 30-40k ток, выход
   ограничен 65 536 — для пересказа обычно ок, но замерить где предел входа, при котором
   качество держится; чанк-пересказ — вероятный анти-скоуп v1).
4. **Промт-инженерия уровня:** что реально работает — «CEFR B1» vs «используй ТОЛЬКО эти
   леммы + до N новых» vs «целевая доля незнакомых слов X%». Замер, не спор.

## Развилки, которые надо решить ДО кода (вынести владельцу)

- **Определение уровня:** (а) данные-driven — целевой % незнакомых лемм из word_status
  (честно, лично, наш моат; требует достаточно прокачанного профиля); (б) CEFR-подобная
  метка, выбранная учеником вручную (просто, работает с пустым профилем); (в) гибрид:
  метка + подсветка coverage до/после. Цена и качество каждого — из замера 4.
- **Транспорт вызова:** серверный эндпоинт с кэшем (paritet с translate-table; +серверный
  код) vs прямой браузерный вызов (zero-server-growth, паттерн S4; кэш только клиентский).
- **Где живёт кнопка:** в превью диалога «Импорт» (до перевода) vs в Студии рядом с
  «AI Перевод» (после приземления) vs обе. R4-мнение + простота v1.
- **Что сохраняется:** пересказ = отдельный текст в Библиотеке со связью с оригиналом в
  провенансе (рекомендация: да — CLG-доктрина «канонические форматы», никакой подмены) —
  как выражается связь и бейдж «упрощено ИИ, уровень X» в UI.
- **Тайминг/караоке пересказа:** пересказ — другой текст, сегмент-привязки к аудио НЕТ —
  честно без караоке (R11: нет соответствия — нет тайминга). Но TTS-озвучка пересказа
  (существующий ttsBake + word-караоке) — работает из коробки. Подтвердить как анти-скоуп/скоуп.
- **Смета/подтверждение (R16):** пересказ длинного текста стоит заметно (вход большой) —
  где показываем $ до траты.

## Инварианты (не нарушать)

- **R11 do-no-harm:** оригинал НИКОГДА не подменяется и не портится; пересказ — отдельная
  сущность с явным бейджем. Никакой интерполяции смысла сверх уровня-упрощения.
- **R1:** ни одной выдуманной ивритской формы в пересказе — это gate-критерий качества,
  не пожелание (аудит-мини-gold в тестах/смоуке).
- **R9 derived≠asserted:** провенанс: оригинал-источник, промт-уровень, модель, дата.
- **R16:** смета до траты; деградация без LLM осмысленная (кнопки нет/disabled с честной
  причиной, не ошибка после клика).
- **browser-first BYOK**: серверного Gemini-ключа НЕТ; новый серверный код — только через
  развилку владельцу; внешние fetch — через `ssrfGuard` (R14).
- **Byte-parity**: `renderTable`/reader-core не трогать (`npm run smoke:reader-parity`).
- **Локали**: каждая новая строка → ru/en/he СРАЗУ + бамп `?v=` всех трёх locale-тегов И
  `CACHE_VERSION` одним изменением + `node tests/i18n.smoke.js --write-lock` (`smoke:i18n`).
- Мобильная ловушка `button { width: 100% }`; скриншот 380×844 перед каждым UI-коммитом.
- **Git: стейджить ТОЛЬКО явными путями**; пуш — только в релиз-задаче. Работать на main.
