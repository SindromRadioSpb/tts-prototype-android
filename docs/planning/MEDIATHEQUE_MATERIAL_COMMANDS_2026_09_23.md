# Медиатека: команды над материалами — спецификация (2026-09-23)

Статус: **SPEC — дизайн утверждён владельцем 2026-09-23, спецификация на проверке.**
Предшественники: [MEDIATHEQUE_EDITORIAL_SCALE_2026_09_22.md](MEDIATHEQUE_EDITORIAL_SCALE_2026_09_22.md),
[ROOM_MEDIATHEQUE_STAGE2_PLAN_2026_09_12.md](ROOM_MEDIATHEQUE_STAGE2_PLAN_2026_09_12.md).

## 1. Зачем

Владелец не может удалить опубликованный материал ««Ворт» — документальное реалити-шоу…» из
«Общедоступных», чтобы импортировать исправленную версию. Команды над темами и подборками уже есть,
команд над **материалом** нет. Нужен релизный набор, а не одна кнопка.

## 2. Решения владельца (дословный смысл)

| # | Решение |
|---|---|
| D1 | Замена версии = два действия: «Удалить материал» (старая версия стирается с сервера), затем обычное «Добавить материал». Раскладка по темам/подборкам и прогресс учеников старой версии не переносятся. |
| D2 | Удаление в «Общедоступных» срабатывает **сразу после подтверждения**, минуя черновик витрины. Ссылки на удалённый материал из черновика убираются автоматически. |
| D3 | В релиз входят: удалить (по одному), удалить выбранные, изменить карточку, скачать архив материала. Журнал действий редактора — следующий этап. |
| D4 | «Мои материалы»: «Удалить из Медиатеки» убирает материал только из Медиатеки; карточка остаётся в Библиотеке. Свои тексты удаляются только из Библиотеки. |
| D5 | Все команды «Общедоступных» — только владелец (редактор). «Мои материалы» — каждый пользователь для своих. |

## 3. Установленные факты (код на 2026-09-23, v3.11.618)

- Витрина (`public/js/mediatheque-core.js`) хранит только **ссылки** `{kind:'public',slug,workId,snapshotHash}`;
  ключ ссылки включает `snapshotHash`.
- Каталог «Общедоступных» (`mediathequeCatalog`, `db/publicationRepo.js:871`) — все элементы текущих
  редакций **всех** опубликованных корпусов с медиа, включая корпуса, ведомые скриптами (песни, физика, PB2).
- «Добавить материал» (`public/js/mediatheque-publisher.js`) скрыто заводит корпус `media-<sha256(тема)[:20]>`
  на тему верхнего уровня, копирует архив в черновик, пишет права, публикует новую редакцию.
- Операции «исключить элемент из черновика корпуса» нет. Отзыв (`withdraw`) действует на корпус целиком.
- Редакция не может быть пустой: `published_corpus_editions.item_count >= 1`.
- Материал физически присутствует: в `snapshot_json` каждой редакции, где он был
  (`published_corpus_edition_items`, `publication_draft_items`); в ZIP-пакете каждой такой редакции
  (`published_corpus_editions.package_path`); в файлах `published_corpus_assets.storage_path`;
  в подготовленном импорте `publication-imports/packages/<sha>.zip`, `publication-imports/media/<sha>`,
  `publication-imports/<token>.json`.
- Откат корпуса (`rollback`) переставляет указатель на любую прежнюю редакцию.
- Опубликованная витрина при чтении уже отбрасывает ссылки на недоступные материалы
  (`getPublicMediatheque`, `reference.forget`).
- «Мои материалы» показывают **все** карточки Библиотеки; понятия «скрыт из Медиатеки» в схеме
  `linguistpro-mediatheque-v1` нет, а `validate` отвергает лишние поля.

## 4. Область действия команд «Общедоступных»

Удаление, изменение карточки и скачивание архива доступны только для материалов корпусов со slug
`media-*` (созданных Медиатекой). Для прочих корпусов действия видны неактивными с объяснением:
«Материал принадлежит собранию <название>; им управляют в Центре публикаций». Так Медиатека не
переписывает корпуса, которые ведутся скриптами.

Права проверяет сервер (`mediathequeOwner`: роль `owner`), интерфейс лишь скрывает кнопки. Каждая
новая точка — `requireStrictSameOriginJson` или эквивалентная проверка происхождения, CSRF, лимит.

## 5. Команды

### 5.1 Удалить материал (Общедоступные)

**Интерфейс.** Меню «⋯» на карточке материала и на странице материала, только в режиме редактора.
Окно подтверждения:
- название материала; где он стоит сейчас (темы, подборки, «На главной» — по опубликованной витрине
  и черновику);
- «Это необратимо: материал и его файлы будут стёрты с сервера. У зрителей он исчезнет сразу.
  Копии, уже сохранённые на устройствах учеников, сервер стереть не может»;
- кнопка «Скачать архив перед удалением» (5.4), если архив есть;
- поле подтверждения не требуется; основная кнопка — «Удалить навсегда» (опасный стиль).

**Сервер.** `POST /api/publication/mediatheque/materials:delete`
`{ items:[{slug, workId}] , expectedMediathequeRevision }` → отчёт по каждому элементу.
Для одного материала (одна транзакция БД на материал, файлы — после коммита):
1. Найти корпус по `slug`; отказ `MATERIAL_NOT_MANAGED` для не-`media-*`; `MATERIAL_NOT_FOUND`, если
   `workId` нет в текущей редакции.
2. Отказ `DRAFT_VERSION_CONFLICT`, если у корпуса есть активный черновик с чужими незавершёнными
   правками (черновик, созданный самой Медиатекой и не отличающийся от текущей редакции, закрывается).
3. Если в текущей редакции есть другие элементы — выпустить новую редакцию без элемента тем же
   конвейером, что `publish` (права остальных элементов переносятся без изменений).
   Если элемент последний — корпус переводится в `ARCHIVED`, `current_edition_id=NULL`.
4. **Вычистка** во всех редакциях и черновиках корпуса, где был `public_work_id`:
   - `snapshot_json` элемента → `{"purged":true}`, `title` → «Удалённый материал», `creator` → NULL
     (хеш `snapshot_sha256` сохраняется как идентификатор истории);
   - такие редакции помечаются вычищенными (новая таблица `published_corpus_edition_purges`
     `(edition_id, public_work_id, purged_at, purged_by)`); `rollback`/`restore` на них отвечают
     `EDITION_PURGED`;
   - их ZIP-пакеты удаляются с диска, `package_complete=0`; выдача пакета отвечает `EDITION_PURGED`.
5. Удаление файлов после коммита: ассеты элемента, на которые не ссылается ни одна невычищенная
   редакция; подготовленный импорт этого архива (`publication-imports/*` по `content_root_sha256` из
   `publication_archive`). Ошибка удаления файла не откатывает удаление материала: она попадает в
   отчёт как `FILE_CLEANUP_PENDING` с путём, и повтор операции дочищает.
6. Витрина: все ссылки на этот `workId` (любой `snapshotHash`) удаляются и из **черновика**
   (одна запись ревизии поверх текущего черновика, прочие правки целы), и из **опубликованной** витрины
   (новая редакция витрины = текущая опубликованная минус эти ссылки; прочие неопубликованные правки
   черновика не публикуются). Иначе правило 5.3 «ссылка следует за текущей версией» вернуло бы
   материал на старые места при повторном импорте с тем же `workId` — вопреки D1.
7. Событие `MATERIAL_DELETED` в `publication_events` (без содержимого материала).

**Отчёт.** `{ deleted:[{slug,workId,title,corpus_archived}], failed:[{slug,workId,title,code}],
cleanup_pending:[...] }`. Интерфейс показывает итог: «Удалено: N. Не удалось: M» со списком причин.

### 5.2 Удалить выбранные (Общедоступные)

Кнопка «Удалить» в панели выделения (рядом с «Распределить», «Теги», «На главную»). Одно подтверждение
со списком выбранных. Тот же эндпоинт; сервер обрабатывает материалы по одному: сбой одного не
останавливает остальные. Не-`media-*` материалы в выделении перечисляются в окне как «будут
пропущены» с причиной. Выделение после операции снимается только с удалённых.

### 5.3 Изменить карточку (Общедоступные)

Меню «⋯» → «Изменить карточку». Поля: название, описание, автор/источник, теги (до 30 по 80 символов),
«Разрешить скачивание». Сохранение:
`POST /api/publication/mediatheque/materials:update` `{slug, workId, expectedSnapshotHash, fields}`.
1. Проверки как 5.1 п.1; `MATERIAL_CHANGED` при несовпадении `expectedSnapshotHash`.
2. Новая редакция корпуса, где у элемента изменены: колонки `title`, `creator`; в снимке
   `library.texts[0].title/topic/tags`; права скачивания — новым фактом прав. Прочие элементы без изменений.
3. `public_work_id` сохраняется; `snapshot_sha256` меняется. Витрина не переписывается при записи.
   Правило чтения: **публичная ссылка следует за текущей версией своего `slug`+`workId`**. Функция ядра
   `followCurrent(structure, catalog)` заменяет в ссылках устаревший `snapshotHash` на текущий, если
   тот же `slug`+`workId` есть в каталоге; ссылки без такого материала отбрасываются (как сейчас).
   Применяется на сервере в `getPublicMediatheque` и при чтении черновика, на клиенте — к личной
   структуре («Мои материалы» хранят сохранённые публичные ссылки) и к ключам прогресса.
   Дубликаты после замены схлопываются.
4. Удалённый материал (5.1) под правило не попадает: его ссылки удалены из обеих витрин (5.1 п.6).

### 5.4 Скачать архив материала (Общедоступные)

Меню «⋯» → «Скачать архив материала». `GET /api/publication/mediatheque/materials/archive?slug=&workId=`
(только владелец) отдаёт `publication-imports/packages/<package_sha256>.zip` из
`source_meta.publication_archive.package_sha256`; при `publication_media` — второй файл медиа отдельной
кнопкой «Скачать медиафайл». Если архива нет (материал опубликован не через импорт архива или до
хранения пакетов) — кнопка неактивна с причиной «Для этого материала исходный архив на сервере
не хранится».

### 5.5 Удалить из Медиатеки / Вернуть (Мои материалы)

- Схема `linguistpro-mediatheque-v1` получает поле `hidden: string[]` (ключи `my/<textKey>`), только
  для личного пространства; `validate` принимает его отсутствие (старые данные) и нормализует в `[]`;
  `publicOnly` отвергает непустое `hidden`. Экспорт/импорт структуры переносят поле.
- Команды ядра `items.hide {keys}` (снимает ключи из тем, подборок, главной, аннотаций остаются) и
  `items.unhide {keys}`.
- Меню «⋯» карточки и панель выделения: «Удалить из Медиатеки». Подтверждение: «Материал исчезнет из
  Медиатеки. В Библиотеке он останется; вернуть можно через фильтр «Скрытые»».
- Фильтр «Скрытые» в «Темы и фильтры»; на скрытых карточках действие «Вернуть в Медиатеку».
- Удаление карточки в Библиотеке не меняется.

## 6. Ошибки и честность

| Код | Когда | Текст (ru) |
|---|---|---|
| `MATERIAL_NOT_MANAGED` | корпус не `media-*` | Материал принадлежит собранию «…»; им управляют в Центре публикаций. |
| `MATERIAL_NOT_FOUND` | уже удалён / нет в текущей редакции | Материал уже удалён или заменён. Обновите страницу. |
| `MATERIAL_CHANGED` | карточку изменили в другой вкладке | Карточку уже изменили. Обновите страницу и повторите. |
| `DRAFT_VERSION_CONFLICT` | у корпуса незавершённый черновик | У собрания есть незавершённые правки. Завершите их в Центре публикаций. |
| `EDITION_PURGED` | откат/пакет вычищенной редакции | Эта редакция содержит удалённый материал и недоступна. |
| `FILE_CLEANUP_PENDING` | файл не удалился | Материал удалён, но часть файлов не стёрта. Повторите удаление, чтобы дочистить. |

Все новые строки — в `public/i18n/locales/{ru,en,he}.js`; версии по правилу lockstep.

## 8. Не входит в релиз

- Журнал действий редактора (экран поверх `publication_events`) — следующий этап.
- Замена версии «на месте» с переносом раскладки — отклонено владельцем (D1).
- Управление корпусами скриптов из Медиатеки.
- Стирание копий на устройствах учеников (невозможно с сервера; сказано в окне подтверждения).
