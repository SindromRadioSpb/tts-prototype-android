## 1. Цель и главный критерий

Цель владельца: зрелый ситуационный курс внутри LinguistPro, а не набор HTML-файлов. Уроки образуют систему:
сквозные жизненные задачи, повторное появление слов и конструкций, переходы между уроками и объяснениями.

**Критерий качества:** через какое-то время человек справляется с **новой** ситуацией.
Красивый интерфейс и повтор знакомого ответа этим критерием не являются.

Из него следуют четыре требования к данным, а не только к интерфейсу:
1. Доказательства разделены по каналам: чтение, слух без текста, письмо на иврите, сборка из карточек, транслитерация, речь, самопроверка. Подсказка и образец отмечаются отдельно.
2. Новизна задания измерима: у каждого задания есть отпечаток (ситуация × параметры × реплика). Повтор знакомого отпечатка не считается переносом.
3. Время между обучением и проверкой фиксируется: «применил после перерыва» — отдельная отметка.
4. Каждая ивритская строка — проверенная пара «огласованная форма + полное письмо». Одну из другой не выводим.

### 2.3 Вывод из сопоставления [суждение]
hebrew240 — **тематико-лексический словник**: 8 слов на тему, 2 строки диалога, перевод на иврит. «Кафе» —
**ситуационный урок**: цель, сцена, разбор, практика, перенос. Механически переносить черновики в формат
«Кафе» нельзя по трём причинам:
- одна ситуация «Кафе» опирается на слова из 7+ разных черновых уроков;
- без прошедшего времени до L141 невозможна цепочка «записаться → перенести → **объяснить причину**»;
- 1 920 заданий одного типа не дают материала для практики со снятием опор.

Полезно сохранить: словник с парами огласовок (как сырьё для проверки), транскрипции, 1 920 контекстных
фраз (как материал для заданий, а не как тесты), темы L1–L60, персонажей.

## 4. Концепция [предложение]

### 4.1 Курс как тип корпуса в Зале
Курс публикуется как корпус Зала, как атлас `atlas:a97002`, например `course:ulpan`. Такой путь атлас уже
прошёл: данные на томе, читалка, тренажёр, словный слой. [проверить: расширяемость реестра корпусов и
формат адреса `#room=…`]. Текст урока становится строками Зала: касание слова открывает морфологическую
карточку, работают статусы «Мой словарь», ▶ у строки, огласовки, транслит и перевод по общим настройкам
Зала. Задания — отдельный модуль курса. Движок прототипа (проверка, учёт попыток, отложенная обратная
связь) переносится туда как компонент, а не как отдельная страница.

### 4.2 Граф курса (данные, а не вёрстка)
- **Единица языка** — слово, устойчивое сочетание, конструкция (`אפשר + N`, `N + בלי + N`), грамматическая точка. ID берётся из словника, где он есть. Пара «огласовка + полное письмо», транскрипция, род и число.
- **Умение (can-do)** — «попросить с условием», «исправить ошибочное подтверждение», «перенести запись».
- **Ситуация** — роли, цель, параметры карточки, возможные сбои.
- **Сюжетная цепочка** — последовательность ситуаций с общими героями и последствиями решений. Пример владельца: записаться на приём → перенести → объяснить причину → подтвердить новое время.
- **Урок** — один полный цикл (§4.3), ссылки на единицы (новые / повторяемые) и на объяснения-предпосылки.
- **Задание** — тип, канал доказательства, отпечаток новизны, допустимые ответы.

Автоматические проверки графа: каждая новая единица встречается ещё минимум в 3 последующих уроках в новых
контекстах; у каждого умения есть перенос; у урока нет неизученных обязательных форм.

### 4.3 Урок — законченный цикл
1. **Цель** — одна фраза «смогу…» и что произойдёт в сцене.
2. **Сцена на слух**: текст скрыт, понимание общего смысла. Открыть текст можно, это отмечается.
3. **Чтение и разбор**: огласованный текст, подсветка новых средств, касание → карточка Зала, микрокарта грамматики на один экран.
4. **Практика со снятием опор**: узнавание → выбор → сборка → свободный ответ.
5. **Сбой**: недопонимание, ошибочное подтверждение, «нет в наличии».
6. **Новая ситуация без готового ответа** — другие параметры, другой собеседник, иногда другая сцена.
7. **Итог по умениям**: самостоятельно / с опорой / нужен повтор. Каналы показаны отдельно.
8. **Отложенное возвращение**: через 1–3 дня новый вариант ситуации, а не тот же текст.

Если не хватает основы, есть ссылка на объяснение или урок-предпосылку.

### 4.4 Библиотека типов заданий
Каждый тип помечен тем, что он доказывает. Ни один тип не считается «умею говорить» сам по себе.

| Тип | Доказывает |
|---|---|
| Понимание на слух: общий смысл и деталь | понимание на слух (только без открытого текста) |
| Минимальные пары на слух: `קטן/גדול`, `עם/בלי`, `יש/אין`, `לשבת/לקחת` | различение звучания |
| Чтение с огласовками / без огласовок | чтение (два разных уровня) |
| Пропуск, трансформация по роду (`רוצה/רוצָה`, `מבין/מבינה`), порядок слов | форма |
| Пары по касанию, сборка из карточек | узнавание, выбор |
| Поиск ошибки в подтверждении, ремонт диалога | понимание с контролем смысла |
| Ветвящийся диалог: собеседник реагирует на выбор ученика | применение в сцене |
| Свободный ответ (письмо на иврите / транслит) | письмо; транслит отдельно |
| Информационный пробел: меню, цена, расписание | применение с подстановкой |
| Произнести реплику (по желанию) | практика речи; распознавание неуверенно → техническая неопределённость |
| Перенос: новая ситуация, без образца, после перерыва | **главный показатель** |

### 4.5 Проверка ответов
- Сохраняем замкнутую смысловую проверку «Кафе» (слоты: напиток, размер, условие…), но строим словарь проверки из проверенных пар и форм (таблицы Pealim уже есть в LinguistPro [проверить]), а не из рукописных списков.
- Ввод с огласовками и без них распознаётся одинаково (дефект H1).
- В закрытой сцене уверенно называем смысловую ошибку, например согласие с неверным подтверждением (H3).
- «Не могу проверить» сразу ведёт к самопроверке и не запирает урок (H2).
- Необязательная оценка ИИ для свободных ответов (BYOK) помечается как отдельный канал «оценка ИИ».
- Для каждого урока — набор трудных ответов-проб, как `checker-probe.mjs` в REVIEW (57 случаев), входит в приёмку.

### 4.6 Огласовки
- В данных всегда проверенная пара. Отображение — через существующие режимы огласовок Зала [проверить].
- Снятие опор по курсу: в начале огласовано всё; затем только новые и неоднозначные слова; затем полное письмо с огласовкой по касанию.
- TTS получает огласованную форму. Это подтверждено замером: WaveNet 16/16 с огласовками против 15/16 без. **Голоса Chirp 3 HD огласовки искажают** (4/16) — для учебного иврита они не годятся.
- Источники проверки: Dicta и Pealim как черновик, решает человек. Огласовки атласа показали, что поверх полного письма они расходятся с формами Pealim примерно в 14 % употреблений [проверить для курса].

### 4.7 Звук
- Реплики озвучиваются по отдельности, сцена склеивается с паузами. Метки слов SSML для подсветки уже есть в `scripts/premium/lib/ttsBake.js`.
- Минимум два голоса (роль = голос). Скорость 1 / 0,85 / 0,75 сохраняется между повторами (дефект H5).
- Ворота выпуска: локальная сверка распознаванием → прослушивание человеком по листу → снятие блокировки.

### 4.8 Прогресс и повторение
- «3 000» показываем как счёт содержания: введено N. Отдельно: узнаёт (чтение), узнаёт (слух), применил сам после перерыва.
- FSRS-6 LinguistPro подходит для слов и устойчивых фраз (узнавание и вспоминание) [проверить: как курс записывает `review_log` и не смешивается ли это с тренировкой Зала; у атласа для терминов отдельный ключ `at1:`].
- Для умений в ситуации нужен новый вид повторения: «ситуационное возвращение» по расписанию, каждый раз на новом варианте карточки. Его придётся разработать.

### 4.9 Каналы и устройства
- Весь маршрут проходим на телефоне без микрофона и клавиатуры иврита: карточки, выбор, транслит, самопроверка — с честной меткой канала.
- Речь — по желанию. На компьютере с Компаньоном распознавание локальное. Неуверенный результат — техническая неопределённость, а не ошибка ученика.

## 5. Черновой маршрут (для обсуждения, не окончательный)

Сквозной сюжет «Первые месяцы в Израиле», герои Дани и Рут из черновиков, ученик — главное действующее лицо.
Параллельно идёт короткая дорожка «Буквы и звуки», она не является барьером на входе.

| Модуль | Ситуации (цепочки) | Ключевая грамматика |
|---|---|---|
| 1. Первые дни | знакомство → **кафе** (эталон) → цена и оплата → магазин у дома (`מכולת`) → телефон и адрес | `יש/אין`, род прилагательных, `אפשר + N/инфинитив`, числа в контексте, род говорящего |
| 2. Город | автобус и проездной → такси → «как пройти» → договориться о встрече и опоздать | настоящее время глаголов движения, время и дни, `צריך/יכול + инф.` |
| 3. Здоровье | записаться в `קופת חולים` → **перенести** → **объяснить причину** → подтвердить → аптека | прошедшее `היה/הייתי`, частые глаголы в прошедшем, `כי`, даты |
| 4. Жильё | смотреть квартиру → поломка → сосед | `של`, местоимения с предлогами, сравнение |
| 5. Ульпан и работа | расписание, просьбы, собеседование | будущее, повелительное, придаточные с `ש` |
| 6. Люди и праздники | приглашение, поздравление, Шабат, праздники | пересказ речи, условие |

Отсюда главный вывод о порядке: прошедшее время нужно примерно к 12–15-му уроку, а не к 141-му.
Абстрактная лексика L221–L240 уходит в продвинутые модули.

## 7. Стандарт «не слабее Кафе» (рубрика приёмки урока)

1. Одна понятная цель-умение и связная сцена с последствием решений.
2. Сцена сначала на слух; минимум 3 задания «только слух» на репликах, которых ученик ещё не читал.
3. Не меньше 6 разных типов заданий из §4.4. Опоры снимаются постепенно.
