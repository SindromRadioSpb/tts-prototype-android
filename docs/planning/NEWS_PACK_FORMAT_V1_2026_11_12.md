## 1. Что это и чего это не делает

Один ZIP = порция новостей (от одной до 1000 статей, любые из 7 изданий). Сервер принимает каждую статью отдельно и выдаёт квитанцию.

Не делает:
- не переносит **текст оригинала** на сервер: исходник нужен только для проверки на дословность и в пакет не попадает (§6);
- не переносит фото из статей (D2), кроме фото со свободной лицензией;
- не пишет в личные данные пользователей и в Медиатеку/Зал.

## 2. Устройство архива

```
2026-11-12T0600_dot_batch.lpnews.zip
├── manifest.json                       обязательно
├── articles/
│   ├── ynet-0001/article.json          обязательно, одна папка = одна статья
│   ├── haaretz-0002/article.json
│   └── walla-0003/
│       ├── article.json
│       ├── b1.word-gloss-ai.json       необязательно: слой «в контексте (ИИ)» для версии B1 (§7)
│       └── image.jpg                   только при image.mode = "licensed"
└── README.txt                          необязательно, сервер игнорирует
```

- Имя файла произвольное, расширение `.lpnews.zip`.
- Кодировка JSON — UTF-8 без BOM. Даты — ISO 8601 с часовым поясом (`2026-11-12T08:15:00+02:00`).
- Имена папок — произвольные латиница/цифры/дефис, только внутри пакета. Идентичность статьи задаётся не именем папки (§5).

## 4. Справочник изданий (на сервере, не в пакете)

Пакет ссылается на `outlet_id`. Названия, домены и цвет метки хранит сервер. Адрес оригинала должен принадлежать доменам издания.

| `outlet_id` | Название (как показываем) | Разрешённые домены оригинала |
|---|---|---|
| `ynet` | ynet · ידיעות אחרונות | `ynet.co.il`, `*.ynet.co.il` |
| `mako` | mako | `mako.co.il`, `*.mako.co.il` |
| `walla` | וואלה | `walla.co.il`, `*.walla.co.il` |
| `maariv` | מעריב | `maariv.co.il`, `*.maariv.co.il` |
| `c14` | עכשיו 14 · ערוץ 14 | `c14.co.il`, `*.c14.co.il`, `now14.co.il` |
| `n12` | N12 · חדשות 12 | `n12.co.il`, `*.n12.co.il`, `mako.co.il/news-*` |
| `haaretz` | הארץ | `haaretz.co.il`, `*.haaretz.co.il` |

Mako и N12 пересекаются: новости канала 12 бывают и на mako. Одна и та же статья по одному `canonical_url` хранится **один раз**. Издание выбирается по пути адреса (`/news-*` → `n12`). Домены проверить на живых ссылках из пробного пакета.

Новое издание добавляется в справочник сервера, формат пакета при этом не меняется.

### 5.2 Поля

**`revision`** (да) — целое ≥ 1. Статья с тем же ключом и большим `revision` заменяет прежнюю. С равным — считается повтором. С меньшим — отклоняется.

**`source`** — откуда статья:

| Поле | Обяз. | Правило |
|---|---|---|
| `outlet_id` | да | Из справочника §4 |
| `url` | да | Как была найдена |
| `canonical_url` | да | `<link rel="canonical">` страницы; иначе `url` без `utm_*`/`fbclid`/`#…`. Сервер нормализует ещё раз (https, нижний регистр хоста, без хвостового `/`) |
| `section_original_he` | да | Рубрика так, как она названа на сайте |
| `section` | да | Общий список: `news`, `politics`, `security`, `world`, `economy`, `consumer`, `sport`, `culture`, `tech`, `health`, `science`, `local`, `opinion`, `lifestyle`, `other` |
| `content_type` | да | `news`, `analysis`, `opinion`, `interview`, `live`, `feature`. Для `opinion` пересказ обязан называть автора («по мнению автора колонки …») |
| `published_at` | да | Время публикации оригинала. Отсюда считаются 3 дня свежести (D4) |
| `updated_at` | нет | Если оригинал обновлялся |
| `retrieved_at` | да | Когда dot прочитал статью |
| `author` | нет | Как подписан на сайте; `null`, если нет |
| `original_title_he` | да | Заголовок оригинала дословно, **не длиннее 160 символов** — короткая цитата для плашки источника и для «разных голосов» |
| `paywalled` | нет | `true` для платных материалов (Haaretz premium и др.) |
| `language` | да | `he` |

**Ключ статьи** (идентичность, защита от повторов) = `outlet_id` + нормализованный `canonical_url`. Его вычисляет сервер.

**`image`** (да) — одно из трёх:

| `mode` | Поля | Как показываем |
|---|---|---|
| `source_link` | `url` (адрес картинки на сайте издания, обычно `og:image`), `credit_he` (подпись автора фото, если есть), `alt_he`, `alt_ru` | Браузер читателя загружает картинку с сайта издания, рядом подпись «Фото: ynet» + `credit_he`. Сервер картинку не скачивает и не хранит |
| `licensed` | `file` (`image.jpg`/`.webp`/`.png`, ≤ 1 МБ), `license` (например `CC BY-SA 4.0`), `author`, `license_source_url`, `alt_*` | Храним, показываем с указанием автора и лицензии |
| `none` | — | Запасная обложка: цвет издания + рубрика |

Если картинка по `source_link` не загрузилась — тоже запасная обложка (D2).

**`learning`** — учебный пересказ:

| Поле | Обяз. | Правило |
|---|---|---|
| `title_he` | да | Собственный заголовок пересказа, не копия оригинального |
| `title_ru` | да | Перевод заголовка; `title_en` и др. — по `ui_languages` |
| `summary_ru` | да | 1–2 предложения «о чём» для карточки ленты |
| `versions[]` | да, ≥ 1 | Уровни одного пересказа. `level` ∈ `A2`, `B1`, `B2`, `C1`. На старте достаточно одного уровня `B1`; 2–3 уровня — по возможности |
| `versions[].rows[]` | да, 3–120 строк | Одна строка = одно предложение. `p` — номер абзаца. `he_plain` (обяз., без огласовки), `ru` (обяз.), `en` (по языкам). `he_niqqud`, `translit`, `translit_ru` — желательны (dot уже делает их для Медиатеки), `field_meta` — как в LPLP (§7) |
| `versions[].word_gloss_ai` | нет, желательно | Имя файла слоя «в контексте (ИИ)» в папке статьи, схема `word-gloss-ai-layer-v1` (§7) |
| `glossary[]` | нет, 5–12 | Ключевые слова и выражения статьи |
| `abbreviations[]` | нет | Аббревиатуры из текста с расшифровкой — для тренажёра газетного иврита |
| `entities[]` | нет | Люди, партии, организации, места: `type` ∈ `person`, `party`, `org`, `place`, `event`; короткая нейтральная справка |
| `questions[]` | нет, 2–5 | Вопросы на понимание: `mc` (с `options_he` и `answer_index`) или `open` (с `answer_ru`) |
| `story_key` | нет, желательно | Ключ сюжета: **один и тот же у статей разных изданий об одном событии**. Формат `ГГГГ-ММ-ДД-короткие-латинские-слова`. Основа для «одно событие — разные голоса» |
| `story_title_ru` | нет | Название сюжета |
| `tags[]` | нет | Свободные теги на иврите |
| `sensitive` | да | `heavy` = `true` для тяжёлых тем; `kinds` ⊂ `war`, `terror`, `violence`, `death`, `abuse`, `disaster` — для фильтра «без тяжёлых тем» |

Требования к пересказу (их же получает dot, приложение А):
- собственные слова и собственный порядок изложения; факты, имена, цифры, даты — как в оригинале;
- не переносить дословно фразы длиннее 6 слов, кроме цитат прямой речи до 15 слов в кавычках с указанием, чья это речь;
- без собственных оценок и выводов; позицию автора (`opinion`) передавать как позицию автора;
- длина: 25–60% объёма оригинала.

**`check`** (да) — материал для проверки на дословность без передачи текста оригинала:
- `source_shingles` — SHA-256 (первые 16 hex-знаков) каждой последовательности из 5 подряд идущих слов оригинала после нормализации (§6);
- `source_word_count` — число слов оригинала.

Собирает это вспомогательная программа упаковки (§8), а не сам dot вручную.

**`prepared`** (да) — кто и как подготовил. Попадает в журнал и в провенанс статьи.

## 6. Проверка на дословность

Нормализация текста (одинаковая у упаковщика и сервера): убрать огласовку и знаки кантилляции, заменить все виды кавычек/гершаимов/тире на один вид, убрать пунктуацию, привести конечные буквы ךםןףץ к обычным, схлопнуть пробелы, разбить по пробелам.

Сервер считает те же 5-словные отпечатки для всех версий пересказа и ищет совпадения с `source_shingles`:
- доля совпавших отпечатков пересказа **> 15%** → статья отклоняется (`VERBATIM_OVERLAP`);
- **8–15%** → публикуется, но помечается в журнале редактора для выборочной проверки;
- отпечатки, целиком лежащие внутри кавычек, не учитываются.

Пороги — стартовые, уточняются по пробному пакету. Самооценка dot не используется: сервер считает сам.

## 7. Совместимость с тем, что dot уже делает, и что сервер досчитывает сам

**Образец dot для Медиатеки** (`Kan-Docu-Children-of-Hebron-context.learning.zip`, 2026-11-10, разобран 2026-11-12): строгий LPLP v2 с `content_root_sha256` и хэшами всех файлов. В строках таблицы `he_plain`, `he_niqqud`, `translit`, `translit_ru`, `ru`, у каждого поля `field_meta` (`authority: "provider"`, `provider: "OpenAI assistant"`). Слой `learning/word-gloss-ai.json` в схеме `word-gloss-ai-layer-v1` (877 строк; у каждой строки `key`, `order_index`, `glosses[]` по словам, `mwe[]`). Плюс `quality/report.json` с честными ограничениями. Вывод: dot справляется со строгим форматом, хэшами и всеми слоями. Поэтому v1 рассчитан на полный набор слоёв, а не на минимум.

Новостной пакет **не вкладывает целый LPLP на каждую статью**. LPLP рассчитан на личный материал с медиа: граф ревизий, дорожки, привязка медиа по SHA. На тысячу текстовых статей в день это лишний объём и лишние проверки. Но тела статей используют **те же имена полей и те же слои**:

- **Строки:** у каждой строки `versions[].rows[]` есть необязательный `field_meta` в форме LPLP (`{"he_niqqud":{"authority":"provider","provider":"dot"}}`). Огласовку и транслитерацию dot **присылать стоит**: так статья сразу открывается полной таблицей.
- **Огласовка от dot = данные поставщика, не проверенные.** Показываем её с пометкой источника. Вторая проверка Dicta — тем же механизмом «второго мнения», что уже работает для учебных материалов (3.11.685–686), и **только при первом открытии статьи**, не массово: Dicta уже банила IP за поток запросов.
- **«В контексте (ИИ)»:** у версии необязательное поле `word_gloss_ai` — файл в той же папке статьи (`b1.word-gloss-ai.json`) в схеме `word-gloss-ai-layer-v1`, ровно как в пакете Медиатеки. `key` и `order_index` строк слоя сервер перепроверяет тем же правилом, что приложение (`word-gloss-ai.js`): строка, чей ключ не совпал с текстом, отбрасывается, остальные принимаются. Нет слоя — карточка работает как обычно.
- **Отчёт о качестве:** необязательное `quality` в `article.json` — та же идея, что `quality/report.json`: `independent_ai_review` (bool), `human_review` (bool), `warnings[]`. Показывается в провенансе.
- **Морфология, статус слов, озвучка** — как у любого учебного материала, по запросу читателя.

Вход: папка с файлами `*.draft.json`. Это тот же `article.json`, но вместо `check` в нём поле `source_text_he` (полный текст оригинала).
Программа:
1. проверяет каждую статью по этой спецификации и печатает понятные ошибки;
2. из `source_text_he` считает `check.source_shingles` и `source_word_count`, сразу проверяет дословность по §6;
3. **удаляет `source_text_he`** и кладёт `article.json` в архив;
4. пишет `manifest.json` с `sha256` и собирает `.lpnews.zip`.

Есть флаг `--check-only` — проверить без сборки.

## 9. Приём на сервере

**Кто загружает.** Роль **«Редактор новостей»** (`news_editor`): свой вход, отзывается владельцем одной кнопкой. Права — только загрузка пакетов, просмотр журнала и квитанций, снятие статей. Доступа к учебным материалам, Медиатеке, Залу, пользовательским данным и настройкам нет. Владелец имеет все права роли.

**Где.** Страница `/news-editor.html`: перетащить архив → прогресс → квитанция. Тот же приём доступен запросом `POST /api/news/packs` (или `/api/news/editor/packs`) с заголовком `Authorization: Bearer <ключ редактора>` и `Content-Type: application/zip` — для запуска из скрипта dot.

**Как.** Разбор идёт по одной статье. Ошибка в статье не останавливает пакет. Итог по каждой статье:

| Итог | Когда |
|---|---|
| `published` | новая, проверки пройдены, свежая (≤ 3 дней от `published_at`) |
| `archived` | новая, проверки пройдены, но старше 3 дней → сразу в архив |
| `revised` | заменила прежнюю версию (`revision` больше) |
| `duplicate` | тот же ключ и тот же `revision` — ничего не изменилось |
| `flagged` | опубликована, но дословность 8–15% (§6) |
| `withdrawn` | снята по `manifest.withdraw` |
| `rejected` | с кодом причины, см. ниже |

Коды отказа: `SCHEMA_INVALID`, `OUTLET_UNKNOWN`, `URL_DOMAIN_MISMATCH`, `DATE_MISSING`, `DATE_IN_FUTURE`, `HEBREW_MISSING`, `TRANSLATION_MISSING`, `ROWS_OUT_OF_RANGE`, `VERBATIM_OVERLAP`, `CHECK_MISSING`, `TITLE_COPIES_ORIGINAL` (`title_he` совпадает с `original_title_he`), `IMAGE_INVALID`, `IMAGE_LICENSE_MISSING`, `REVISION_STALE`, `SHA_MISMATCH`, `TOO_LARGE`.

Квитанция: сводка («опубликовано 412 · в архив 20 · повторов 37 · отклонено 9»), таблица отказов с причинами, ссылка на журнал. Квитанция доступна и в ответе `POST` (JSON) — dot может прочитать её и исправить отклонённые статьи.

**Пределы v1:** архив ≤ 50 МБ, ≤ 1000 статей, `article.json` ≤ 256 КБ, картинка ≤ 1 МБ. Не более 20 пакетов в час с одного входа.

**Публикация** — автоматическая (D3). У владельца на странице редактора: снять статью, снять весь пакет, отозвать вход dot.

## 10. Жизненный цикл статьи

| Этап | Когда | Что видит читатель | Что хранится |
|---|---|---|---|
| Свежая | 0–72 ч от `published_at` | лента издания и рубрики | всё + рассчитанные слои |
| Архив новостей | 3 дня – 6 месяцев | «Архив новостей»: поиск по изданию, дате, рубрике, сюжету | пересказ и все поля пакета; рассчитанные слои (огласовка, морфология) удаляются и считаются заново при открытии |
| Карточка | > 6 месяцев | в архиве как карточка: заголовок пересказа, издание, дата, рубрика, кратко, превью-ссылка, ссылка на оригинал | только эти поля |
| Снята | по команде | ничего | запись в журнале |

- Перевод между этапами — автоматически по расписанию на сервере.
- **Срок «6 месяцев» — моё предложение** (D4 задаёт только «оставлять карточку»).
- Новость сама по себе **не появляется в «Моих материалах»**. Если пользователь сохранил статью, начал её учить или взял из неё слова, у него хранится личная копия пересказа. Для него статья не уходит ни в архив, ни в карточку, и связи слов в «Моём словаре» сохраняются. Снятие статьи владельцем убирает её из ленты и архива, но не из личных копий: там появляется пометка «снята источником LinguistPro».

## 11. Что показывается из провенанса

На каждой статье сверху и внизу: «Учебный пересказ LinguistPro по материалам ynet · 12.11.2026 07:40 · Оригинал ↗». Внизу ещё: автор оригинала, рубрика, «подготовлено: dot · дата», для `opinion` — «мнение автора колонки». Логотипы изданий не используем: только название текстом и нейтральный цвет-метка (D2/§3 мозгового штурма).

## 12. Версии формата

- Новые **необязательные** поля добавляются без смены `schema_version`; сервер игнорирует незнакомые поля и показывает их в квитанции как предупреждение.
- Изменение смысла или обязательности поля → `schema_version: 2`. Сервер принимает v1 и v2 параллельно, пока dot не перейдёт.
- Упрощение по результатам пробного пакета (правило владельца) — обязательные поля, с которыми dot не справился, переводятся в необязательные, и это фиксируется в этом документе.

## 14. «В архив» и «Удалить» (решение владельца 2026-11-13, выпуск 3.11.887)

- **«В архив»** — статья сразу уходит из свежей ленты в архив (по-прежнему ищется и открывается). Обратно — «Вернуть в ленту», пока статье меньше 72 ч.

- Где: во вкладке «Новости» меню «⋯» на карточке (видно только владельцу и вошедшему редактору; после действия — «Отменить»), и на `/news-editor.html` раздел «Статьи»: «В ленте / В архиве / Удалённые», поиск и фильтр по изданию.

- Адреса: `POST /api/news/editor/articles/<id>/archive | unarchive | delete | restore`, список `GET /api/news/editor/articles?view=feed|archive|deleted`.

## 15. Оригиналы один-в-один и фото из статьи (решение владельца 2026-11-14, выпуск 3.11.888)

Основание: раздел фактически читает один человек — владелец. Ограничение «только пересказ» (D1) снято: статья публикуется **текстом оригинала один-в-один**, как и раньше со ссылкой на оригинал и с указанием издания. Фото берутся из самой статьи, у каждого есть подпись автора фото и ссылка на источник. `schema_version` остаётся `1`: всё новое необязательно, старые пакеты принимаются как раньше.

### 15.1 Версия `OR` — текст оригинала

- В `learning.versions[]` появляется уровень **`OR`**. Это тело статьи дословно, в том же порядке, без сокращений и правок. Строки в той же форме, что у пересказа: `p`, `he_plain`, `he_niqqud`, `translit`, `translit_ru`, `ru`, `en`, `field_meta`, слой `word_gloss_ai`.
- Строк у `OR`: **от 1 до 400**. У пересказов по-прежнему от 3 до 120.
- Версия `OR` ставится **первой**: из ленты открывается первая версия. Пересказ `B1` и другие — по желанию, следующими версиями. В Зале над текстом есть переключатель «Версии: Оригинал · B1».
- **Проверка на дословность (§6) к `OR` не применяется**, только к версиям-пересказам.
- **Обратная проверка — «совпадает ли с оригиналом».** Сервер и упаковщик считают, какая доля 5-словных отпечатков `OR` (с цитатами) найдена в `source_text_he`. **< 50%** → отказ `ORIGINAL_MISMATCH` (это не та статья или не её текст). **50–85%** → публикуется, в квитанции предупреждение `FIDELITY_LOW:<процент>` (текст сокращён или правлен). Квитанция и упаковщик печатают процент совпадения.
- Если в статье есть `OR`, `title_he` **может совпадать** с заголовком оригинала, отказа `TITLE_COPIES_ORIGINAL` нет. `original_title_he` — до 300 символов (было 160).
- `prepared.method`: `original`, если в статье только `OR`, или `original+paraphrase`, если есть и пересказ.
- Новые необязательные поля `learning.subtitle_he`, `subtitle_ru`, `subtitle_en` (до 600 символов) — подзаголовок статьи (כותרת משנה). Показываются крупно над таблицей, в строки не входят.

### 15.2 `images[]` — фото из статьи

Почему файлы, а не ссылки: Зал работает с заголовком COEP `require-corp`, и браузер не показывает там картинки с сайтов изданий (они не шлют CORP). Поэтому фото приходят **файлами в пакете**, сервер хранит их у себя (таблица `news_images`) и отдаёт со своего адреса.

```json
"images": [
  { "file": "img-1.jpg", "role": "hero", "source_url": "https://ynet-pic1.yit.co.il/picserver6/…/main.jpg",
    "credit_he": "צילום: רויטרס", "caption_he": "מליאת הכנסת", "caption_ru": "Зал пленарных заседаний Кнессета", "alt_ru": "Депутаты в зале" },
  { "file": "img-2.webp", "role": "inline", "after_p": 3, "source_url": "https://…/second.jpg", "credit_he": "צילום: אלכס קולומויסקי" }
]
```

| Поле | Обяз. | Правило |
|---|---|---|
| `file` | да | `img-<1–99>.jpg|.jpeg|.png|.webp`, файл лежит в папке статьи. Проверяется по содержимому (JPEG/PNG/WebP), **≤ 600 КБ** |
| `role` | да | `hero` — главное фото статьи, не больше одного; `inline` — фото из тела статьи |
| `after_p` | нет, желательно | Для `inline`: номер абзаца (`p` строк версии `OR`), после которого фото стоит на сайте; `0` — перед первым абзацем. Без него фото уходит в галерею под текстом |
| `source_url` | да | `https://`-адрес, откуда фото скачано |
| `credit_he` | нет | Подпись автора или агентства **как на сайте** (`צילום: …`, `רויטרס`, `AP`). Нет подписи — поле не заполняется, ничего не придумывать |
| `caption_he`, `caption_ru`, `caption_en` | нет | Подпись к фото дословно и её перевод |
| `alt_he`, `alt_ru` | нет | Короткое описание для экранного диктора |

Не больше 12 фото на статью. Поле `image` (§5.2) остаётся как было: ссылка `og:image` — запасной вариант для ленты.

**Как показываем.** Карточка ленты берёт сохранённое фото `hero`; если его нет — `og:image` по ссылке, как раньше. В Зале над таблицей: плашка источника, переключатель версий, фото `hero`, подзаголовок. В версии `OR` фото `inline` стоят **внутри таблицы между абзацами** (3.11.889): отдельной строкой на всю ширину после последней строки абзаца `after_p` (`after_p: 0` — перед первой строкой). Сервер при сборке снимка переводит `after_p` в номер строки (`after_row`). В пересказе абзацы другие, поэтому там и у фото без `after_p` — «Фото из статьи» сеткой под таблицей. У каждого фото: подпись, «Фото: {credit_he} · {издание} · источник фото ↗» (ссылка на `source_url`). Если фото не загрузилось, оно скрывается. Таблица в Зале перерисовывается (колонки, транслитерация), и фото после этого ставятся на место заново.

**Срок хранения.** Фото живут, пока статья читается (свежая и архив). При переходе в карточку (6 месяцев) и при окончательном удалении из корзины (30 дней) фото стираются. Отдаёт их `GET /api/news/images/<article_id>/<file>?v=<12 знаков хэша>`; по адресу с хэшем ответ неизменяемый (кэш на год).

### 15.3 Пределы и коды

- `article.json` ≤ **1 МБ** (было 256 КБ): оригинал на 400 строк с огласовкой и переводом больше прежнего предела.
- Новый код отказа `ORIGINAL_MISMATCH`. `IMAGE_INVALID` теперь срабатывает и на `images[]`: неверное имя или роль, два `hero`, адрес не https, нет файла, файл не JPEG/PNG/WebP. `TOO_LARGE` — фото больше 600 КБ.
- Новое предупреждение `FIDELITY_LOW:<процент>`.

### 15.4 Упаковщик

`node scripts/news/build-pack.js <папка>` ищет файлы статьи (фото, слой «в контексте (ИИ)») **сначала в подпапке с именем черновика** (`ynet-0001.draft.json` → `ynet-0001/img-1.jpg`), потом в самой папке. Так у каждой статьи может быть свой `img-1.jpg`. Упаковщик сразу проверяет размер фото и совпадение `OR` с оригиналом и печатает «оригинал совпал на N%».

### 15.5 Что не изменилось

Ключ статьи, ревизии, 72 часа свежести, архив, карточка, корзина, вход редактора, квитанция. Поле `source_text_he` в черновике по-прежнему обязательно и в архив не попадает: из него считаются отпечатки для обеих проверок. Статьи первого пакета можно перевыпустить в оригинале: тот же `canonical_url`, `revision` на 1 больше.

> - не включать: рекламу, «читайте также», подписи к фото (они идут в `images[]`), заглушки видео и встроенных постов, комментарии, кнопки соцсетей, теги, навигацию сайта;
> - кавычки и знаки — как в оригинале. Гереш — `׳` (U+05F3), гершаим — `״` (U+05F4), не ASCII `'` и `"`: в прошлом пакете צ'ילה делилось на два слова;
> - в каждой строке: `he_niqqud` (огласовка), `translit`, `translit_ru`, `ru` (точный перевод строки, близко к тексту, без сокращений), `en` — если есть в `ui_languages`; `field_meta` как в пакетах Медиатеки; слой «в контексте (ИИ)» `word-gloss-ai-layer-v1` отдельным файлом;
> - не больше 400 строк. Если статья длиннее — первые 400 строк и в `quality.warnings` строка `TRUNCATED`.
>
> **5. Заголовки.** `title_he` и `original_title_he` — заголовок статьи дословно. `title_ru`, `title_en` — перевод. `subtitle_he` — подзаголовок (כותרת משנה) дословно, `subtitle_ru` — перевод. `summary_ru` — 1–2 своих предложения «о чём» для карточки ленты.
>
> **6. Пересказ — по желанию.** Можно добавить второй версией `B1` по прежним правилам: свои слова, не больше 6 слов подряд из оригинала. `prepared.method`: `"original"` или `"original+paraphrase"`.
>
> **7. Фото** (`images[]`, до 12 на статью):
> - главное фото статьи: `role: "hero"`, одно. Фото из текста: `role: "inline"`, `after_p` — номер абзаца, после которого фото стоит на сайте (тот же номер, что `p` у строк версии «Оригинал»; `0` — перед первым абзацем). В Зале фото встанет в таблицу ровно в это место;
> - скачай самый крупный доступный вариант. Уменьши до **1600 px по длинной стороне**, сохрани в JPEG (качество около 82) или WebP, **не больше 600 КБ** (в прошлом пакете фото C14 было 3840 px). Имена `img-1.jpg`, `img-2.webp`…;
> - **обязательно `source_url`** — адрес, откуда скачано фото;
> - `credit_he` — подпись автора или агентства **как на сайте** (`צילום: …`, `רויטרס`, `AP`, `דוברות צה"ל`). Если подписи нет — оставь поле пустым, не придумывай;
> - `caption_he` — подпись к фото дословно, `caption_ru` — её перевод, `alt_ru` — 3–8 слов, что на фото;
> - не брать: рекламу и баннеры, логотипы, аватарки авторов, иконки, заглушки видео, картинки из блоков «читайте также»;
> - поле `image` заполняй как раньше: `mode: "source_link"`, адрес `og:image` и подпись. Это запасной вариант.
>
> **8. Даты.** `published_at` — с правильным поясом Израиля: зимой `+02:00`, летом `+03:00`. В 2026 году переход на зимнее время — 25 октября, поэтому сейчас `+02:00`. В прошлом пакете у Walla было `+03:00`.
>
> **9. По возможности, как раньше:** глоссарий 5–12 слов, аббревиатуры с расшифровкой, справки о людях, партиях и местах, 2–5 вопросов на понимание, `story_key` (одинаковый у статей разных изданий об одном событии), пометка тяжёлых тем `sensitive`.
>
> **10. Сборка.** `node scripts/news/build-pack.js <папка>`. Программа печатает по каждой статье «оригинал совпал на N%». Ниже 85% — проверь, не сокращён ли и не искажён ли текст. Ниже 50% — отказ `ORIGINAL_MISMATCH`. Исправь ошибки, получи `.lpnews.zip`.
>
> **11. Загрузка.** `/news-editor.html` под своим ключом редактора или `POST /api/news/packs`. Прочитай квитанцию; отклонённые статьи исправь, увеличь `revision` на 1 и загрузи снова.
>
> **12. Перевыпуск прошлых статей.** Десять статей первого пакета можно прислать заново в оригинале: тот же `canonical_url`, `revision: 2`. Сервер заменит пересказ.
>
> **Пробный пакет:** 5 статей из 3+ изданий, все с версией «Оригинал» и фото; хотя бы в одной 3+ фото в тексте, одна колонка мнений.
