## 2. Почему дизайн такой (главные факты замеров)

| Факт | Следствие в дизайне |
|---|---|
| Лимит вывода модели 65 536 ток. (архитектурный); строка таблицы ≈ 220 ток.; стена ≈ 287 строк; N=400 → MAX_TOKENS + оборванный JSON + потеря всего | Чанк-таблица ~120 сегментов/вызов; **текущий кап 400 — латентный прод-баг**, S12 его чинит |
| renderTable: 1700 строк = 347 мс, 3000 = 598 мс (CPU-троттл 6×, 380px) | Виртуализация не нужна; прогрессив = повторный `renderTable(префикс)`; byte-parity цел |
| Одновызовный ASR 75 мин: «успех» с молчаливой дырой 31 мин (warnings пусты); 2.4 ч: MAX_TOKENS (thinking делит бюджет вывода) | **Чанк-ASR окнами 15 мин** + валидация непрерывности покрытия + добор дыр |
| Range-промт «ONLY 32:00–40:00, timestamps ABSOLUTE»: точное окно, абсолютные метки, 21 с; implicit-кэш аудио-входа (90% кэшировано на повторе) | Механизм окна = range-промт по одному fileUri; `video_metadata`-клип на аудио игнорируется — NO-GO |
| Генерация ≈ 210–250 ток/с → кусок таблицы ~2–2.5 мин; окно ASR ~20–60 с | Сметы времени честные; последовательный прогон 2 ч подкаста ≈ 15–20 мин |

## 3. Архитектура и поток данных

**Сервер не меняется вообще (zero-server-growth).** Каждый кусок таблицы — обычный
сегодняшний запрос `/api/translate-table` (seg-режим, ≤400 сегментов, `he-ru-table-seg-v1`);
чанк-цикл, глобализация `segment_index`, прогрессив и ретраи живут в клиенте. Серверный
sha256-кэш по `promptId||cleanText` куска даёт возобновление бесплатно: повтор перевода
возвращает готовые куски мгновенно (`fromCache: true`) и докачивает только упавшие.

```
файл (≤3ч, ≤300МБ) → probeAudioDuration (локально, RSS-метаданным не верим)
  → СМЕТА: $ASR + $таблица + ~минуты → кнопка «Распознать (≈$X, ~Y мин)» (R16-подтверждение)
  → upload ОДИН раз (Files API, resumable) → waitActive (таймаут от размера)
  → ASR окно 1..M (range-промт, ПОСЛЕДОВАТЕЛЬНО, статус «окно k из M»)
      каждое окно: parse → retry ×1 при ASR_BAD_JSON (как сейчас)
  → mergeWindows: конкатенация, немонотонный стык → start=null (честно)
  → validateWindowCoverage: дыры >90 с → ДОБОР дыры range-промтом (×1);
      остаточная дыра → warning ASR_COVERAGE_GAP (видимый бейдж, без псевдо-сегментов)
  → превью (как сейчас) → «Использовать» → OPFS + паспорт (asr.windows[] в провенансе)
  → Студия «AI Перевод»: сегменты → куски по 120
      кусок k: renumber i→0..n-1 → POST → segment_index += base(k) → merge
      → renderTable(накопленное) → статус «кусок k из M · ≈осталось Z мин»
  → все куски готовы → тайминг buildRowTiming (без изменений) → карaоке/сохранение
```

### 4.3 `public/js/studio-import.js`
- `MAX_AUDIO_SEC = 3*3600`; `MAX_AUDIO_BYTES = 300МБ` (как есть).
- Кнопка: `«Распознать (≈$X, ~Y мин)»` из `estimateLongJob` (для >20 мин Y обязателен).
- `transcribeAudio()` → цикл окон: статус `studio.import.audioWindowProgress {k, m}`;
  retry ×1 на окно при `ASR_BAD_JSON`; после merge — добор дыр (×1 на дыру, максимум 3 добора);
  остаточные дыры → warning `ASR_COVERAGE_GAP` в паспорт + бейдж в превью.
- Паспорт `asr` расширяется: `windows: [{startSec,endSec,retries}], coverageGaps: [{fromSec,toSec}]` (R9).
- Сбой окна k после ретрая → статус-ошибка с номером окна; повторный клик «Распознать»
  продолжает с окна k (окна 1..k-1 держатся в `pendingAudio.windowResults`).

### 4.4 `public/index.html` (Студия, inline; `renderTable` НЕ трогаем)
```js
const V3_SEG_CHUNK = 120;   // сегментов на вызов (~26k out-ток, 2.4× запас до 65,536)
```
- `v3AudioSegmentsForRequest()` — снимается верхний отказ `>400`; функция отдаёт ВСЕ сегменты,
  чанк-цикл режет сам. Кап длины сегмента 2000 остаётся.
- `translateTable()` seg-ветка: если сегментов > `V3_SEG_CHUNK` → чанк-цикл:
  - смета-подтверждение (модал: строк, $, минут; `confirm` перед тратой >1 куска — R16);
  - кусок k: `segs.slice(a,b).map((s,j)=>({i:j,text:s.text}))` → POST →
    `rows.forEach(r => r.segment_index += a)` (только у целочисленных);
  - `SEG_MAPPING_LOST` куска → `delete segment_index` только его строк (сервер уже отдал их
    без индексов) — честная деградация локальна, тайминг остальных жив;
  - `SEG_COVERAGE_PARTIAL` куска → missing-индексы + `a` → агрегированный тост один раз;
  - прогрессив: `currentTableData = accum; renderTable(accum)` после каждого куска;
    статус `«кусок k из M · ≈осталось Z мин»`; кнопки сохранения/экспорта/озвучки
    заблокированы до полной готовности (существующий draft-механизм);
  - сбой куска: баннер + `«Продолжить»` → повторный запуск цикла (кэш вернёт готовые куски
    мгновенно); `TABLE_CACHE_KEY` и `v3LastGeminiMeta` пишутся ТОЛЬКО при полной таблице;
  - `v3LastGeminiMeta.chunks = [{cacheKey, fromCache, rows}]` (R9-провенанс кусков);
    `promptId: "he-ru-table-seg-v1+chunked"` в мете (кэш-неймспейс сервера не меняется).
- Guard плоского пути (микро-правка, R11): he-ru/any-he БЕЗ сегментов и `>250` строк текста →
  честная ошибка `classic.textTooLongForSingleTable` (сейчас это молчаливый 500 с потерей) —
  предложение импортировать через диалог (сегменты) или сократить. Чанкование плоского
  текста — анти-скоуп v1.

## 5. Честность (R11) — правила целиком

1. **Только сегмент-уровень.** Ничего нового: никакого word-level, никакой интерполяции.
2. **Дыры покрытия ASR.** Дыра >90 с после добора НЕ заполняется и НЕ маскируется: warning в
   паспорте + видимый бейдж («покрытие неполное: ~N мин около M:SS»). Псевдо-сегменты в текст
   не вставляются (ломали бы line-count инвариант превью).
3. **Стыки окон.** Немонотонный start на стыке → start=null (существующий validateSegments
   это уже делает); окна не перекрываются.
4. **Деградация куска локальна.** SEG_MAPPING_LOST куска k лишает индексов только строки k;
   тайминг остальных кусков живёт (прецедент — S4.1 FIX A с частичным coverage).
5. **Смета до траты, всегда** (R16): и на кнопке «Распознать», и перед мультичанк-переводом.
6. **Провенанс** (R9): окна, доборы, дыры, куски, кэш-ключи — в паспорте/мете, derived≠asserted.

## 6. Обработка ошибок

| Ситуация | Поведение |
|---|---|
| Окно ASR: BAD_JSON | retry ×1 (как сейчас); после — ошибка с номером окна, повторный клик продолжает с него |
| Окно ASR: 429/квота | существующий классификатор `GeminiError`; окна 1..k-1 сохранены в pendingAudio |
| Дыра покрытия | добор range-промтом ×1 на дыру (≤3 доборов); остаток → warning + бейдж |
| Кусок таблицы: любой сбой | баннер `tableChunkFailed {k,m}` + «Продолжить»; повтор докачивает по кэшу |
| SEG_MAPPING_LOST куска | честная локальная деградация (см. §5.4) |
| Сохранение при неполной таблице | заблокировано (draft-механизм); только полная (решение владельца) |

## 9. Риски

1. **Недетерминизм ASR внутри окна** (дыры даже на 15-мин окне — не наблюдались, но возможны)
   → coverage-валидация ловит и на окне; добор тот же механизм.
2. **Толстые free-tier ключи:** RPM 10 достаточно (≤1 вызов/2 мин последовательно), дневной
   лимит запросов free-tier может не пережить 3-часовой прогон (~25 вызовов) вместе с прочим
   использованием — ошибка квоты уже классифицируется и показывается честно.
3. **300 МБ в память браузера** (`arrayBuffer()` при загрузке): на слабых устройствах может
   упасть — байт-кап уже есть, деградация честная (существующая ошибка).
4. **Смена `V3_SEG_CHUNK` между релизами** инвалидирует серверный кэш кусков (другой нарез) —
   допустимо, отметить в комментарии константы.
5. **65 536 и 220 ток/строка — свойства текущей модели.** При смене `gemini-flash-latest`
   пересмотреть `V3_SEG_CHUNK` и сметы (комментарий-якорь у констант, как у ASR-цен).
