# S12.5 — Нарезка ЗВУКА вместо range-промта (дизайн-пакет, 2026-07-29)

**Статус:** РЕАЛИЗОВАН, живой гейт ПРОЙДЕН 2026-07-30 (см. §6.1), v3.11.265.
Остаётся owner-приёмка через UI (§8).
**Решение владельца (2026-07-29):** вариант A из развилки диагноза — резать сам звук.
**Корневая причина (закрыта диагнозом):**
`docs/research/studio-ingest-longmedia/2026-07-29/DIAGNOSIS_S12_LIVE_DEFECT_2026_07_29.md` —
`gemini-flash-latest` на глубоких офсетах одного длинного fileUri возвращает чужой контент
с подделанными in-range метками; все метко-ключёванные гейты (клип/швы/дыры/добор) слепы;
потеря 47% таймлайна прошла как успех (`coverageGaps:[]`). Три слайса (S12.2/3/4) чинили
гейты по меткам → правило «3+ фикса → вопрос к архитектуре».

**Принцип S12.5: модель не должна ИМЕТЬ ВОЗМОЖНОСТИ видеть чужой звук.** Чанк аудио =
физический диапазон; транскрипция без range-промта; абсолютное время = детерминированный
офсет чанка (наш, неподделываемый). Текст-стежок (S12.4) остаётся швом чанков.

## 1. Новый pure-модуль `public/js/mp3-slice.js` (dual-export, образец asr-transcript.js)

- `buildFrameMap(u8)` → `{offsets:[{t,byte}] (шаг ~1с), totalSec, frames, badResync}`.
  MPEG1/2/2.5 Layer III; скип ID3v2; анти-false-sync: кандидат-фрейм валиден только если
  следующий по size тоже валиден. Замер на файле владельца: 268 646 фреймов, 116.96 мин,
  0 байт resync-мусора, парс < 2с.
- `byteForTime(map, sec)` → ближайший фрейм ≤ sec.
- `sliceChunks(u8, windows)` → `[{k, startSec(факт., время фрейма), endSec, bytes:Uint8Array
  (subarray, без копий), byteFrom, byteTo}]` — границы = `AsrTranscript.asrWindows()`
  (15 мин, перекрытие 30с у k>0); последний чанк — до конца файла.
- `isSliceable(map, probedDurationSec)` → истина, если фреймов достаточно И |totalSec −
  probedDuration| ≤ 5% (защита от битых/экзотических mp3 → fallback-путь). Принимает
  ГОТОВУЮ карту (не u8): вызывающий уже распарсил файл, повторный парс 160МБ бессмыслен.
  [T1 ревью 2026-07-29: 8/8 мутаций пойманы, 13/13 юнитов, живой пин 268646/7017.69/0.]

## 2. Интеграция `studio-import.js` (transcribeAudio → два транспорта)

- **`transport: "sliced-mp3"`** (mp3 И `isSliceable`): цикл чанков — `uploadFile(chunk)` →
  `waitActive` → `transcribeAudio(plain ASR_PROMPT)` (БЕЗ range-промта) → parse → клип
  chunk-relative `[−60, chunkDur+60]` (страховка дрейфа; подделка абсолютного времени
  невозможна by construction) → сдвиг меток на `chunk.startSec` → perWindow.
  - Бисекция ASR_BAD_JSON ×2: под-нарезка БАЙТОВ чанка пополам (±15с перекрытие по frame
    map) — каждая половина = свой аплоад; тот же принцип «звук, не промт».
  - Резюм: как сейчас (windowResults), плюс аплоад-хэндлы чанков не переиспользуем
    (просто перегружаем чанк — 20МБ, дёшево).
  - Heal-добор дыры: ВЫРЕЗАННЫЙ звук дыры отдельным чанком (plain prompt, строгий клип 2с
    chunk-relative) + анти-реплей гейт (§3).
- **`transport: "ranged-file"`** (fallback: видео-файлы, не-mp3 аудио, не-sliceable mp3):
  прежний путь одного fileUri + range-промт, НО с анти-реплей гейтом окна (§3) и честной
  сводкой (§4); UI-предупреждение о меньшей надёжности длинных файлов этого формата.

## 3. Анти-реплей текст-гейт (страховка, оба транспорта; элемент варианта B)

Пере-использование принципа стежка: 6-словные нормализованные шинглы.
- Окно/чанк: доля шинглов результата, уже встречавшихся в ДРУГИХ окнах, ≥ 40% → результат
  бракуется (`windowRejectedReplay` в провенанс), диапазон уходит в ЧЕСТНУЮ дыру (не в heal
  с тем же промтом — heal при забракованном окне пропускается).
- Добор: тот же порог против ВСЕГО уже принятого материала → добор бракуется, дыра остаётся
  честной (`healRejectedReplay`).
- Порог 40% — эвристика; жи­вая речь имеет рефрены («кен, кен») ~1-3%; бракованные окна
  прогона-образца имели 60-95%. Пин порога юнитом на синтетике.
- **ШОВНОЕ ИСКЛЮЧЕНИЕ (whole-branch ревью 2026-07-29, R11).** Первая редакция гейта считала
  уликой и тот дубль, который создаём МЫ: asrWindows перекрывает соседей на 30с намеренно.
  У полного окна это ≈3%, но два живых класса окон честно ложноположительны — (1) хвостовое
  окно короче ~65с (файл длиннее кратного 15 мин на 0–60с, ≈каждый 15-й) и (2) окно,
  оборвавшее вывод сразу после шовной зоны (класс пробы §6). Живые пробы ревью: хвостовое
  окно 40/50/60с → доля 0.71/0.56/0.46 ⇒ брак, речь хвоста уничтожалась, level=bad; у (2)
  правило «не хилить забракованный диапазон» ещё и ЗАПРЕЩАЛО добор настоящей дыры в 14 мин.
  Лечение: из суждения исключается голова окна, ДОКАЗАННО совпадающая с хвостом предыдущего —
  тот же якорь, что режет шов (`AsrTranscript.replaySeamSkipWords`), без единой метки. Срез
  пословный и жёстко ограничен 80 словами, поэтому у живого окна (822–1331 слово) судится
  «всё минус 80» и реплей целого окна ловится по-прежнему; окно, где после исключения осталось
  <20 шинглов, честно уходит в «суждения нет» (null). Гейты: `S12.5-T3-h/i/k`.
- **Провенанс брака переживает РЕЗЮМ** (там же). `windowsMeta` готовых окон пересобиралась с
  нуля, поэтому после возобновления исчезали rejectedReplay/skippedRanges/bisected/clippedCount:
  сводка T4 (она считает `windowsOk` именно по этим полям) рапортовала «Чанков 8/8» о прогоне с
  подделанным окном, `rejectedRanges` был пуст, а забытый диапазон снова уходил в добор (R16).
  Теперь провенанс уезжает в резюм рядом с сегментами (`e.windowsMeta` → `deps.priorWindowsMeta`),
  а `rejectedRanges`/`ASR_WINDOW_REPLAY` восстанавливаются из него. Гейт: `S12.5-T3-j`.

## 5. Штамп версии кода + stale-tab guard

**Разведка 2026-07-29 (обязательна к учёту — наивная реализация не сработает):**
- `window.APP_VERSION` в проекте **НЕ СУЩЕСТВУЕТ**. При этом `public/js/cloud-sync.js:109`
  читает его в `source_client_version` → туда всегда уходит `undefined` (pre-existing дыра
  провенанса синка; закрывается этим же слайсом бесплатно).
- `window.__v3AppVersion` (index.html ~12526) для guard-а **бесполезен**: он заполняется
  ОТВЕТОМ СЕРВЕРА (`/api/client-config` → `j.version`), т.е. это версия сервера, а не
  загруженного в эту вкладку кода. Старая вкладка спросит сервер, получит новую версию и
  ничего не заметит.
- `/api/client-config` честен по построению (server.js `resolveAppVersion()` читает
  `const CACHE_VERSION` из `public/sw.js`, якорный регекс, фолбэк на package.json).

**Отсюда реализация:**
- Инлайн-константа в `public/index.html`: `window.APP_VERSION = "3.11.<N>"` — литерал,
  зашитый в САМ документ (единственное, что стареет вместе с вкладкой). Ставить рядом с
  ранним инлайн-скриптом флагов (~12484), ДО загрузки модулей.
- Гейт равенства `APP_VERSION` (index.html) == `CACHE_VERSION` (sw.js): дописать в
  **Suite 10 `tests/i18n.smoke.js`** — там уже живёт lock-механика `?v=`/CACHE_VERSION
  (`--write-lock`), это её естественное место, отдельный гейт плодить не нужно.
- Паспорт: `asr.codeVersion = window.APP_VERSION` (R9 — «каким кодом сделан прогон»;
  отсутствие этого штампа стоило сессии целой гипотезы H1).
- Stale-tab guard перед дорогой операцией (транскрибация): `fetch /api/client-config` →
  если `j.version !== window.APP_VERSION` → блокирующее предупреждение «Страница устарела,
  обновите вкладку» вместо прогона старым кодом. Сетевая ошибка/пустой ответ ≠ повод
  блокировать (fail-open, R11: не выдумывать факт устаревания).
