# Студия / Импорт-центр / Медиатека: жизненный цикл материала

Дата: 2026-09-12. Статус: PRODUCTION PASS — 3.11.527, runtime commit `ff41fae5`; owner-data read-only invariants подтверждены.
База: `50fad4da` / production 3.11.526. Рабочий checkout: `E:/projects/tts-material-lifecycle`.
Вручную составленный план по трём сообщениям об ошибках владельца; читать/комментировать этот файл. Проверки и команды будут добавлены по завершении. Пользовательские данные только читаются; destructive-тесты выполняются в отдельных профилях.

## Подтверждённые причины

- Медиатека восстанавливает личную ссылку из структуры как unavailable-карточку, хотя `listMediathequeMaterials` возвращает только неархивные тексты. При удалении/архивировании активная карточка превращается в технический placeholder. В живом профиле в подборке 10 ссылок, одна не имеет соответствующего текста.
- `v3LibraryDeleteText` при наличии `studio_learning_materials` подменяет удаление архивированием. Поэтому принадлежность к истории версий, а не переводчик, определяет разное поведение. «В тайне - 4» действительно имеет запись материала и не архивирован.
- «В сокрытии - 2 - madlad» существует и архивирован. Текущий Import Center направляет «Ещё действия» к общему списку задач; native-материал без import receipt не получает полноценные действия удаления/возврата.
- `texts` владеет учебным материалом через FK CASCADE; удаление текста удаляет `studio_learning_materials` и `studio_table_revisions`. Источник, дорожки и медиа могут использоваться несколькими материалами. У row versions и некоторых occurrence/event ссылок нет автоматического каскада.

## Контракт исправления

1. Личные архивные/отсутствующие тексты не отображаются в активной Медиатеке и не увеличивают её видимые счётчики. Организационные ссылки сохраняются для отмены/восстановления/переноса; это проекция, не массовая очистка данных. Недоступные публичные издания сохраняют существующее честное состояние. Возвращение во вкладку освежает локальные данные.
2. «Удалить» означает удаление выбранного учебного материала, «В архив» — отдельное обратимое действие. Предпросмотр показывает название и затрагиваемые части. Изменившийся материал требует нового предпросмотра. Общие исходники и данные других материалов не удаляются.
3. Импорт-центр показывает материал как объект с конкретными действиями: открыть, переименовать, экспортировать, архивировать/восстановить, удалить. Исходник и черновик различаются с сохранённым учебным материалом. Существующие exporters, media/revision repositories и границы публикации используются повторно.
4. Состояние слов и `review_log` не изменяются при организации/архивировании/удалении материала. Удаление тестируется только на fixtures; сохранность соседнего материала, общего источника и непустого журнала доказывается отдельно.

R4/R6: понятные действия на конкретном объекте. R11/R13/R15: сохранность, preview, транзакционный результат и обратимость архива. R3/R12: один канонический writer и устойчивые ID. R14/R16: никаких provider-вызовов, публикаций или чужих данных.

## Реализация

- `PortableLearningPackageRepository` содержит общий lifecycle writer для сохранённого текста: `updateMaterialDetails`, `previewMaterialDelete`, `deleteMaterial`. Наличие import receipt не требуется. Низкоуровневый `localDB.deleteText` и восстановление старых пакетов не переопределены.
- Предпросмотр адресован точному `text_id`, содержит название, число строк и версий, зависимости и SHA плана. Подтверждение пересчитывает план внутри SAVEPOINT. Неизвестные зависимости блокируют операцию; сбой записи откатывает изменения вместе с локальным sync intent.
- Удаляются текст, принадлежащие ему таблицы/версии/заметки, проверенные occurrence/event/derived-context ссылки и только осиротевшие row versions этого материала. Общие row versions сохраняются. `review_log` и `word_status` не изменяются.
- Источники, caption history, OPFS media и исторические import receipts сохраняются. Это удаление учебной версии, а не очистка источников. Неиспользуемый источник может появиться как черновик; экран удаления объясняет это заранее. Экспорт использует существующий архив `.lplp.zip`; ложная отмена через неполный compatibility bundle не предлагается.
- «Материалы» → поиск или фильтр «Архив» → название/«Управление материалом»: изучение, название, экспорт, архив/возврат, удаление, отдельный переход к исходнику/расшифровке. RU/EN/HE, мобильная ширина 380 px, статусы и управление фокусом.
- Библиотека направляет удаление versioned-материала в тот же предпросмотр. Ошибка lookup останавливает удаление и не допускает опасного перехода к legacy delete с неполным undo.
- Медиатека пересчитывает карточки/счётчики по живой доступной проекции и обновляет локальный список при возвращении во вкладку. Открытая форма не перерисовывается. Недоступные публичные издания продолжают отображаться честно.

## Дополнительная ошибка, обнаруженная проверкой удаления

Старое полное удаление из Истории импорта удаляло `created.tracks` в обратном лексикографическом порядке hash ID. Этот порядок не соответствует parent/child FK: при другом исходном SHA raw-дорожка удалялась раньше дочерней и SQLite откатывал операцию. Теперь удаляются листья графа; внешний дочерний track блокирует удаление. Предпросмотр также блокирует удаление источника, используемого другим материалом, binding или чужой table revision. Отдельный regression принудительно задаёт неудобный порядок и проверяет shared-source blocker.

Полный restore/open обнаружил, что `MediaHost.restoreForRows` повторно выравнивал уже проверенный паспорт immutable revision, менял `studio-exact-binding` на `aligned-offline` и терял `end` реплик. Regression сначала воспроизвёл ошибку. Узкая проверка совпадения projection revision ID/SHA и exact map теперь сохраняет исходные boundaries и ссылочную идентичность entries. Legacy и пустые/непроверенные mappings продолжают прежний путь восстановления. Изменение общее для Студии и Зала; `media-host.js?v=527` синхронизирован в обеих оболочках, SW и серверном integrity manifest.
