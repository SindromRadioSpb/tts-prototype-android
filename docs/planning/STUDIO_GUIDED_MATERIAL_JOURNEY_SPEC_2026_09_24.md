# Ведущий путь «медиа → готовый учебный материал»: спецификация

Дата: 2026-09-24. Статус: разделы 1 и 2 дизайна утверждены владельцем в чате; спецификация на ревью.
База: production 3.11.627 (`0d1517cb`).

## Зачем

Владелец прошёл цепочку «📥 Добавить материал» → «С устройства» → «Медиа на иврите → транскрипт» → ASR local → «Продолжить с черновиком» → «Собрать таблицу» → «Сохранить». Карточка «Хан Юнес» сохранилась без видео и без кнопок ▶ в колонке «Перевод», в Студии и после открытия из Библиотеки. Процесс ощущался прерывистым: неясно, на каком этапе сбой и где процесс заканчивается.

**Цель.** Программа ведёт пользователя от прикрепления медиа (локальный файл или ссылка YouTube) до открытия готового учебного материала с привязанным медиа и кнопками ▶. Ни один этап не теряет медиа молча.

**Критерий готовности.** Для локального видео с транскриптом одна главная кнопка после транскрипта доводит до финального экрана «N строк · ▶ у M · видео привязано» с кнопками «Открыть в Зале» и «Открыть в Студии». Открытый материал показывает плеер и ▶ у M строк. При любом разрыве процесс стоит на названном этапе с причиной и действием.

## Что установлено разбором (2026-09-24)

1. **Корень потери медиа** — исправлен в 3.11.627 (`0d1517cb`). Реплика субтитров «...» после нормализации слов пуста с обеих сторон. `MediaHost.revisionMatchesLines` считал пустое несовпадением, резолвер отвечал `NO_EXACT_REVISION` и сбрасывал медиа-контекст. Таблица шла плоским путём, карточка сохранялась без видео. Сигнал `window.v3MediaIntentLost` вычислялся, но никому не показывался.
2. **Ведущий процесс уже есть частично.** `LearningMaterialTask` (`public/js/learning-material-task.js`) хранит журнал этапов `imported → transcribing → transcribed → translating → table_ready → saving → saved → binding → bound → exporting → ready`. Журнал переживает перезагрузку, есть смета платного шага и возобновление. Полностью его проходит только путь YouTube.
3. **Для локального медиа этап привязки пропускается.** `binding` и `verifySaved` выполняются только при `input.youtube_source`. Если записи в `studio_text_media_bindings` нет, `preparePackage` молча упаковывает карточку как простой текст (`type:'text-card'`). Задача дошла бы до `ready` с карточкой без медиа.
4. **После транскрипта шесть кнопок, две из них главные** (`public/index.html`, `#v3ImportPreviewWrap`): «Исправить транскрипт», «Продолжить с черновиком», «Подготовить и сохранить», «Скачать OCR JSON», «Упростить…», «Закрыть». Обычный выбор («Продолжить с черновиком») выводит из процесса.
5. **О незаконченной задаче** после перезагрузки напоминает только кнопка «Задачи подготовки» (`#v3LearningTasks`).

## Раздел 1. Форма процесса

Подход A: `LearningMaterialTask` становится единственным ведущим путём для медиа-материалов. Вторая модель состояния не заводится.

```
① Медиа  ② Транскрипт  ③ Проверка  ④ Таблица  ⑤ Сохранение  ⑥ ▶ Привязка  ⑦ Готово
```

- **① Медиа, ② Транскрипт** — без изменений: выбор файла, язык, ASR (локальный или Gemini), путь YouTube.
- **После транскрипта одна главная кнопка:** «Собрать учебный материал». Она запускает задачу с этим транскриптом и его паспортом медиа. Остальные действия («Продолжить в Студии вручную», «Упростить…», «Скачать OCR JSON») уходят во второстепенный ряд. «Закрыть» остаётся.
- **③ Проверка транскрипта** — необязательный этап внутри задачи. Экран задачи предлагает «Проверить и исправить» (существующий `StudioMediaEditor`) или «Пропустить». Сохранённая правка создаёт новую ревизию транскрипта. Задача продолжает с этой ревизией и не выводит в Студию. Ревизия, на которой строится таблица, фиксируется в журнале.
- **④ Таблица** — всегда в режиме сегментов: одна реплика транскрипта даёт одну или несколько строк с `segment_index`. Смета перед платным шагом и карточка прогресса по частям — существующие.
- **⑤ Сохранение, ⑥ Привязка** — автоматически, см. 2.1.
- **⑦ Готово:** «<название> · N строк · ▶ у M · видео привязано (локальный файл | YouTube)». Кнопки «Открыть в Зале» и «Открыть в Студии». Задача закрывается только по выбору пользователя. Если ▶ есть не у всех строк, число строк без ▶ названо. Для локального файла отдельно сказано, что видео живёт в этом браузере.
- `exporting` (сборка переносимого пакета) остаётся внутренним шагом после ⑥ и на шкале не показывается. Для материала с медиа он не может деградировать в `text-card`: отсутствие привязки ловится на ⑥ раньше.

## Раздел 2. Сбои, перезагрузка, ручная Студия, ремонт

### 2.1 Доказательство медиа на каждом этапе

Одно правило: если доказать нельзя, этап не завершается, и задача стоит на нём с причиной и действием. Паспорт медиа задачи = `media_package_ref` + ревизия транскрипта + число реплик. Он берётся из `effectiveImportMeta(job)`.

| Точка | Доказательство | Отказ |
|---|---|---|
| Перед ④ | `v3ResolveMediaContext()` находит ровно одну ревизию, построчно равную тексту задачи, и это ревизия из журнала | `TASK_MEDIA_CONTEXT_LOST` с `reason` резолвера и номером первой расходящейся строки. Таблица не запускается, плоский путь для медиа-задачи запрещён |
| После ④ | каждая строка несёт целый `segment_index` в пределах числа реплик; покрытие реплик посчитано (`TableChunks.coverageForRows`) | нет индексов → `TASK_TABLE_UNSEGMENTED`; неполное покрытие не останавливает, но переносится в итог |
| ⑥ (новое для локального) | после сохранения: запись `studio_text_media_bindings` для `saved_text_id` существует; карточка переоткрывается тем же восстановлением, что в Зале (`MediaHost.restoreForRows` по сохранённым строкам), и M = число строк с таймингом > 0 | нет записи или M = 0 → `TASK_PLAYBACK_UNBOUND`, действия «Привязать заново» и «Проверить транскрипт» |

Для YouTube существующий `bindPlaybackSource` + `verifySaved` остаётся. ⑥ добавляет туда тот же подсчёт M. Итог хранится в журнале (`playback_proof: {kind, bound_rows, total_rows, missing_rows}`) и показывается на ⑦.

### 2.2 Перезагрузка и закрытие вкладки

- Журнал уже переживает перезагрузку. Оплаченные этапы повторно не оплачиваются, это действующее правило журнала и серверного кэша.
- **Новое:** при загрузке Студии, если есть задача в состоянии `running | paused | stopping` не старше 14 дней, наверху Студии появляется полоса: «Материал „<название>“ — этап ④ Таблица · <деталь> · Продолжить». У остановленной задачи в той же полосе причина словами. Полосу можно скрыть до следующей загрузки. «Задачи подготовки» остаётся полным списком.

### 2.3 Ручная Студия

- «Продолжить в Студии вручную» остаётся.
- Когда `v3MediaIntentLost` выставлен (медиа было, текст разошёлся с транскриптом), в Студии показывается постоянная полоса: «Видео не будет привязано: строка N отличается от транскрипта». Действия: «Вернуть текст транскрипта» (подставить текст ревизии) и «Продолжить без видео».
- «Сохранить карточку» при выставленном флаге требует явного выбора «Сохранить без видео» в той же полосе. Молчаливое сохранение без медиа исключено.

### 2.4 Ремонт уже сохранённых карточек («Хан Юнес»)

Действие «Привязать медиа» у сохранённого материала в Импорт-центре → «Материалы». Доступно, когда у материала есть исходный медиа-пакет, но нет привязки или M = 0.

1. **Бесплатная попытка:** строки карточки выравниваются по **диапазонам подряд идущих реплик** ревизии точным пословным совпадением (`MediaRebindCore.alignRowsToSegmentSpans`). Существующее `alignRowsToSegmentsPartialProven` ищет строку внутри одной реплики, а в «Хан Юнес» модель склеила 241 реплику в 133 строки; поправка при планировании 2026-09-24. Строка получает время своей первой реплики. Предпросмотр: «▶ получат K из N строк». Подтверждение пишет только привязку (`studio_text_media_bindings`); строки, статусы слов, заметки и `review_log` не меняются.
2. **Платная пересборка** предлагается, только если K/N < 0,8: «Пересобрать таблицу по сегментам» со сметой. Она запускает обычную задачу с ④ по ⑦ с `saved_text_id` этой карточки. Новый материал не создаётся.

### 2.5 Вне объёма

ASR, редактор транскрипта, формат карточки, Медиатека и публикация не меняются. Медиа на другом устройстве (файл только в OPFS этого браузера) вне объёма; ⑦ об этом говорит. Новых серверных эндпоинтов и миграций нет.

## Критика по ролям (до реализации)

- **R4 Премиум-UX.** Шкала из 7 этапов на 390 px не помещается в строку. Решение: на узкой ширине показывать «Этап 4 из 7 · Таблица» и полосу, полный список — по раскрытию. RTL: шкала зеркалится через logical properties. Одна главная кнопка на экране транскрипта. Второстепенные действия — ряд `btn-secondary`, не выпадающее меню, чтобы не прятать «Упростить…» глубже одного тапа.
- **R11 Do-no-harm.** Ремонт 2.4 пишет только привязку и ревизию таблицы, строки карточки не переписывает. Предпросмотр обязателен, изменившийся материал требует нового предпросмотра (тот же SHA-план, что у удаления). «Вернуть текст транскрипта» в 2.3 перезаписывает поле ввода. Если там есть ручные правки, они остаются в текущем черновике Студии и возвращаются одной отменой. Действие отдельное, не автоматическое.
- **R9/R3 Единый источник правды.** Паспорт медиа задачи — единственный. Полоса 2.3 читает существующий `v3MediaIntentLost`, второй детектор не заводится. M считается тем же `restoreForRows`, что рисует ▶ в Зале, поэтому «▶ у M» не расходится с тем, что увидит пользователь.
- **R16 Стоимость.** Новых платных вызовов нет, кроме пересборки 2.4 шаг 2 — только по явному выбору и со сметой. Бесплатное выравнивание всегда первым.
- **R13 Миграции.** Схема не меняется: `playback_proof` — поле JSON журнала задачи, привязка пишется существующим `media-package-repository`.
- **R2 Методика.** Финал «Открыть в Зале» ведёт к учебному режиму, «Открыть в Студии» — к правке. Выбор не навязывается.
- **Опровержение подхода.** Не создаёт ли единственный путь новую точку отказа? Он строится на журнале, который уже держит путь YouTube в проде. Сбой любой новой проверки останавливает этап, а не материал: ручная Студия остаётся запасным путём и теперь тоже честна (2.3).
- **Риск:** `translate()` задачи управляет глобальным состоянием Студии (`inputText`, `v3LastImportMeta`). Проверка «перед ④» обязана выполняться после того, как `translate()` выставил эти глобалы, и до `translateTable()`. Иначе резолвер читает текст предыдущего материала.

## Проверка

- Юнит: `revisionMatchesLines` (сделано), проверка контекста перед ④ (совпало / расхождение с номером строки / нет пакета), подсчёт `playback_proof`, запрет плоского пути для медиа-задачи, выравнивание 2.4 (K/N, порог 0,8), модель шкалы (7 этапов, узкая ширина).
- Браузер: одноразовый профиль, реальный короткий видеофайл с транскриптом и строкой «...», провайдер-вызовы подменены. Проход ①→⑦, перезагрузка на ④ и возобновление, расхождение текста в ручной Студии, ремонт карточки без привязки. RU/HE, светлая/тёмная тема, 390 px.
- Владелец: «Хан Юнес» через «Привязать медиа» в своём профиле; новый локальный материал через ведущий путь.
