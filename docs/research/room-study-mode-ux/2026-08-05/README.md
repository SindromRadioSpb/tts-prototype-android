# Читальный зал — учебный режим карточки текста: замеры @380px (2026-08-05)

**Что это.** Живой замер геометрии Зала при работе с медиа-материалом («карточка текста» = таблица + видео),
поднятый по жалобе владельца: служебная колонка не сжимается, чекбокса «Действие» нет, дисклеймер + футер
постоянно съедают экран. Это RAW-замер (не отчёт-решение) — питает дизайн-пакет учебного режима.

**Как получено.** Локальный `node server.js` → Playwright MCP → `/library.html` → «Мои тексты» → первый текст
(медиа-импортированный материал, паспорт есть, blob отсутствует → `fileMissing`). Все числа приведены к
**CSS-viewport 380×845** (профиль браузера имеет dpr 0.8 — окно ставилось 304×676, что даёт ровно 380 CSS px;
проверено `innerWidth`).

Медиа-режим (`.room-media-scroll` + `wrap.maxHeight`) воспроизведён теми же формулами, что `roomMediaApplyLayout`
(library-ui.js), с плашкой видео 219px = `clamp(120px, 26vh, 280px)` при vh=845.

Источник: коммит `0e8fd56a`, прод-версия 3.11.309.

## Найденные дефекты (машинно подтверждены)

1. **Служебная колонка растёт при сокращении контента.** `baseWidths=[15,20,20,21,24]` нормализуются к 100 по
   ВИДИМЫМ колонкам (`normalizeVisibleBaseWidthsTo100`, reader-core.js), поэтому при выключении «Иврит» и
   «Транслит» доля action идёт 15% → **25.4%**. Чем сильнее учащийся упрощает таблицу, тем больше места
   отъедает служебная колонка.
2. **Мёртвые грипы ресайза.** Билдер (`buildBilingualTableHtml`) эмитит `.col-resizer` — в таблице Зала
   **4 видимых грипа 10×79px**, но `table.dataset.resizeBound === null`: обработчик `onResizePointerDown`
   живёт только в `index.html`. Синтетический drag на 60px: ширины `15%|20%|20%|21%|24%` **не изменились**.
   То есть Зал рисует аффорданс, который ничего не делает (нарушение R4 «без тупиков»).
3. **Нет переключателя видимости служебной колонки.** Панель «Аа» (`buildAidsPanel`) даёт he / niqqud /
   translit / ru, но `action: true` захардкожен в `readerConfig()`.
4. **Высота окна таблицы считается при непрокрученной странице.** `roomMediaApplyLayout` берёт
   `window.innerHeight - wrap.top - 10` при scrollY=0, когда 176px шапки Зала ещё в потоке; остаток уходит в
   отрицательные числа и клампится к `Math.max(220, …)`. После того как пользователь прокрутил шапку прочь,
   освободившиеся ~176px таблице НЕ возвращаются.
5. **Дисклеймер и футер в потоке под окном таблицы.** `#readerProvNote` + `<footer class="room-footer">` —
   157px (19% экрана) постоянно видимой служебной информации во время учебного процесса.
