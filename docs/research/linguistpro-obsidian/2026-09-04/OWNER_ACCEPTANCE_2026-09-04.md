# Owner acceptance: морфологические решения и Obsidian

Дата: 2026-09-04

Целевая версия: `3.11.471`

Текущий статус: `PRODUCTION_TECHNICAL_PASS · OWNER_RECHECK_PENDING`

Первая owner-проверка `3.11.466` выявила два блокера: ложный
`identity_guarded` для Pealim `#2710` (`אֶת`) и редактор, находившийся после
82 контекстов. В `3.11.467` точный curated Pealim sense-ID корректирует ошибочный
POS старого offline-датасета без ослабления homograph guard; редактор и точный
impact находятся перед ограниченно прокручиваемым списком контекстов.

Вторая проверка выявила ложные очереди для `כָּל` и местоименной формы `לִי`,
свободный ввод POS и неудобное поле числового Pealim ID. В `3.11.468` POS —
локализованный список, поле принимает и показывает полную ссылку Pealim,
единственный кандидат предзаполняется, а словарный класс отделён от контекстной
роли. На неизменённом исходном ZIP новый технический baseline — `345 / 0 / 186`.

В `3.11.470` интерфейс переведён с технической терминологии на учебный сценарий:
причины проверки локализованы и объяснены, добавлены поиск и фильтр, подсказки
работают мышью и с клавиатуры, технические идентификаторы скрыты, а все действия
сформулированы через ожидаемый результат для пользователя.

В `3.11.471` закрыт сквозной цикл решения: подтверждённый разбор конкретного
употребления показывается в карточке слова с человеческой provenance-меткой,
оставшиеся примеры безопасной группы получают этот разбор как проверяемый
черновик, а пользователь может отметить произвольные несколько предложений.
Перед записью по-прежнему показывается точный список; небезопасные группы
остаются строго по одному примеру.

Этот протокол проверяет именно пользовательский путь владельца. Автотесты и
технический browser smoke уже выполнены, но не считаются owner acceptance.

## Безопасность проверки

1. Не очищайте основной профиль LinguistPro и не импортируйте backup с
   заменой данных в единственный рабочий профиль.
2. Для восстановления full ZIP используйте отдельный профиль браузера или
   отдельное тестовое устройство.
3. В production разрешено принять одно осмысленное решение для собственного
   текста. Batch сначала только просмотрите и отмените.
4. Сохраните обе Obsidian-выгрузки в разные файлы: до решения и после него.

## A. Версия и открытие интерфейса

1. Откройте <https://linguistpro.kolosei.com/library.html#room=mytexts>.
2. Сделайте обычное обновление. Если внизу всё ещё не `v3.11.471`, полностью
   закройте установленную PWA/вкладку, откройте снова и обновите.
3. В разделе «Мои тексты» найдите «Кфар Аза - 2 544/573».
4. Нажмите `•••` -> `⚖ Проверить морфологию`.
5. Убедитесь, что открылось окно «Слова, требующие проверки», видны счётчики
   «Нужно проверить», «Проверено», «Группы слов» и блок «Экспорт для Obsidian».
6. Наведите указатель на `?` возле каждого счётчика, затем перейдите к этим
   кнопкам клавишей Tab. В обоих случаях должно появиться понятное пояснение.
   В интерфейсе не должны встречаться `identity_guarded`, `collision`,
   `occurrence`, `cluster`, `impact`, `receipt` или `audit`.
7. Проверьте поиск по слову без огласовок и по русскому переводу, затем фильтр
   «Причина проверки». Строка «Показано групп» должна обновляться без закрытия
   окна.
8. В первой раскрытой группе редактор, варианты и кнопки решения должны быть
   видны до списка контекстов. Сам список прокручивается внутри ограниченного
   блока и больше не отодвигает редактор вниз на десятки экранов.
9. Для неизменённого исходного ZIP и профиля без решений ожидаемый технический
   baseline после исправления: `345 / 0 / 186`. Большой кластер `אֶת` из
   82 вхождений больше не должен присутствовать: конкретное вхождение в строке
   `אַתֶּם תִּרְאוּ אֶת הָאוֹפַנּוֹעִים שָׁם` проецируется как `pid:2710`,
   `lp_pos: preposition`, а не как unresolved.
10. Найдите `כָּל`: оно не должно быть в активной очереди из-за ложного
   collision. В Obsidian-проекции ожидаются `lexical_pos: noun`,
   `lp_pos: particle`, `context_role: quantifier`, Pealim 4158.
11. Если открыть группу с единственным вариантом Pealim, часть речи должна
   отображаться локализованно и выбираться из списка. Поле Pealim должно быть
   предзаполнено полной ссылкой вида `https://www.pealim.com/ru/dict/6014/`,
   рядом должна работать кнопка «Открыть в Pealim». Допустим и ручной ввод
   полной ссылки со slug, например `https://www.pealim.com/ru/dict/6014-le/`;
   приложение сохранит внутренний ID `6014`.

PASS: окно открывается без ошибки, контексты читаемы, скролл и кнопка закрытия
работают. Текущие счётчики запишите в отчёт: они зависят от уже сохранённых
решений и состава локального словаря.

## B. Базовая Obsidian-выгрузка

До изменения решения нажмите «Скачать Obsidian ZIP» и сохраните файл с
суффиксом `-before.zip`. Это создаёт локальную точку сравнения receipt.

PASS: ZIP сохраняется; внутри есть `_LinguistPro/texts/<text-id>/receipt.json`
и `resolution-audit.json`.

## C. Точный single impact и сохранение

1. Откройте любую небольшую группу, где вы уверены в разборе. Для минимального
   риска оставьте отмеченным только один пример.
2. Проверьте/исправьте лемму и часть речи. При необходимости заполните Pealim
   ID, корень, биньян и значение.
3. Нажмите «Сохранить этот разбор».
4. До записи интерфейс обязан показать «Что изменится» и
   `Будет сохранено решений: 1`. В раскрываемом блоке «Технические данные» должен
   быть ровно один идентификатор с его контекстом.
5. Нажмите «Сохранить изменения».
6. Запомните новые счётчики, закройте окно, полностью обновите страницу и снова
   откройте проверку морфологии.

PASS: очередь уменьшилась ровно на 1, «Решено» увеличилось ровно на 1, после
перезагрузки результат сохранился.

## D. Точный выбор нескольких примеров без записи

1. Откройте безопасную группу минимум с тремя примерами.
2. Отметьте первый и второй примеры, оставив третий без отметки. Строка
   «Выбрано» должна показать `2 из 3`.
3. Нажмите «Сохранить этот разбор».
4. Сравните число в строке «Будет сохранено решений» с количеством примеров в
   предварительном просмотре.
5. Нажмите «Вернуться к проверке» — в этой проверке групповое решение не
   записывайте.
6. Откройте неоднородную группу. Должно быть видно пояснение «Только один
   пример за раз»; при выборе другого предложения прежняя отметка снимается.

PASS: предварительный список содержит ровно первые два предложения; после
отмены счётчики не изменились; небезопасная группа не допускает мультивыбор.

## E. Переход в Obsidian projection и receipt

1. После single-решения снова нажмите «Скачать Obsidian ZIP» и сохраните файл
   как `-after.zip`.
2. Распакуйте `-after.zip` в отдельную тестовую папку/vault Obsidian.
3. Откройте `_LinguistPro/texts/<text-id>/receipt.json`.
4. В `resolution_transitions` найдите выбранный occurrence. Ожидается
   `from: "unresolved"`, `to: "resolved"`.
5. В `resolution-audit.json` тот же occurrence должен иметь состояние
   `resolved`; в активной очереди unresolved его уже быть не должно.
6. Откройте соответствующую lexical note и убедитесь, что применённый разбор
   виден в проекции, а исходный контекст и provenance сохранены.

PASS: before/after receipt показывает ровно один ожидаемый переход, audit и
активная очередь согласованы.

Важно: переход вычисляется между последовательными выгрузками этого текста в
том же браузерном профиле. Поэтому сначала обязателен `before.zip`, затем
решение, затем `after.zip`.

## E2. Контрольный жизненный цикл `יִשְׂרָאֵל`

Этот сценарий выполняется после production deployment 3.11.471 в основном
профиле, где для первого из четырёх употреблений уже сохранено значение
`Израиль`.

1. В карточке текста нажмите на `יִשְׂרָאֵל` в уже проверенном предложении.
   PASS: карточка показывает `Израиль`, локализованную часть речи «имя
   собственное» и метку `проверено вами`.
2. Снова откройте «Слова, требующие проверки», найдите `ישראל` поиском без
   огласовок. PASS: осталось три примера, поле «Значение» уже заполнено словом
   `Израиль`, а интерфейс объясняет, что это проверяемый черновик.
3. Отметьте первые два примера из трёх. PASS: видно `Выбрано: 2 из 3`, preview
   обещает ровно два решения и перечисляет ровно два выбранных предложения.
4. Сохраните изменения, закройте окно и откройте его снова. PASS: у `ישראל`
   остался ровно один пример.
5. Для последнего примера оставьте значение `Израиль`, нажмите «Сохранить этот
   разбор» и подтвердите preview из одного решения.
6. Закройте окно и откройте его снова. PASS: поиск `ישראל` больше не находит
   группу — все четыре точных употребления решены, ни одно соседнее слово не
   изменено.

Это намеренная запись трёх дополнительных append-only owner decisions, а не
синтетический smoke. Перед каждым подтверждением проверяется exact preview.

## F. Full/slim backup roundtrip

Автоматический executable gate уже проверяет оба внутренних режима
`exportBundle`: full и slim, remap ID при восстановлении, повторный импорт без
дубликатов и отсутствие событий другого текста.

Для ручной проверки полного архива:

1. В Studio откройте Library -> Import Center -> `Download full ZIP`.
2. Сохраните SHA-256 архива.
3. В отдельном тестовом профиле откройте Import Center -> `Restore full ZIP`.
4. Откройте тот же текст и проверку морфологии.
5. PASS: single-решение и счётчики восстановлены, текст/аудио открываются.

Slim — внутренний text-scoped контракт backup/cloud bundle, отдельной
пользовательской кнопки «slim backup» сейчас нет. Его acceptance обеспечивается
исполняемым тестом `node --test tests/lexicalResolutionBackupRoundtrip.test.js`;
не следует выдавать learning ZIP или Media Package за тот же формат.
