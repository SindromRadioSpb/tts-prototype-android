# Owner acceptance: морфологические решения и Obsidian

Дата: 2026-09-04

Целевая версия: `3.11.465`

Текущий статус: `TECHNICAL_PASS · OWNER_REPORTED_PASS_PENDING`

Этот протокол проверяет именно пользовательский путь владельца. Автотесты и
технический browser smoke уже выполнены, но не считаются owner acceptance.

## Безопасность проверки

1. Не очищайте основной профиль LinguistPro и не импортируйте backup с
   заменой данных в единственный рабочий профиль.
2. Для восстановления full ZIP используйте отдельный профиль браузера или
   отдельное тестовое устройство.
3. В production разрешено принять одно осмысленное решение для собственного
   текста. Batch сначала только просмотрите и отмените.
4. Сохраните обе Obsidian-выгрузки в разные файлы: до решения и после него.

## A. Версия и открытие интерфейса

1. Откройте <https://linguistpro.kolosei.com/library.html#room=mytexts>.
2. Сделайте обычное обновление. Если внизу всё ещё не `v3.11.465`, полностью
   закройте установленную PWA/вкладку, откройте снова и обновите.
3. В разделе «Мои тексты» найдите «Кфар Аза - 2 544/573».
4. Нажмите `•••` -> `⚖ Проверить морфологию`.
5. Убедитесь, что открылось окно «Occurrence и кластеры», видны счётчики
   «В очереди», «Решено», «Кластеры» и кнопка «Скачать Obsidian ZIP».

PASS: окно открывается без ошибки, контексты читаемы, скролл и кнопка закрытия
работают. Текущие счётчики запишите в отчёт: они зависят от уже сохранённых
решений и состава локального словаря.

## B. Базовая Obsidian-выгрузка

До изменения решения нажмите «Скачать Obsidian ZIP» и сохраните файл с
суффиксом `-before.zip`. Это создаёт локальную точку сравнения receipt.

PASS: ZIP сохраняется; внутри есть `_LinguistPro/texts/<text-id>/receipt.json`
и `resolution-audit.json`.

## C. Точный single impact и сохранение

1. Откройте любой небольшой кластер, где вы уверены в разборе. Для минимального
   риска выберите только один occurrence, не включайте batch.
2. Проверьте/исправьте лемму и часть речи. При необходимости заполните Pealim
   ID, корень, биньян и значение.
3. Нажмите «Подтвердить разбор».
4. До записи интерфейс обязан показать `Будет записано решений: 1` и ровно один
   occurrence ID с его контекстом.
5. Нажмите «Подтвердить точную запись».
6. Запомните новые счётчики, закройте окно, полностью обновите страницу и снова
   откройте проверку морфологии.

PASS: очередь уменьшилась ровно на 1, «Решено» увеличилось ровно на 1, после
перезагрузки результат сохранился.

## D. Точный batch impact без записи

1. Откройте кластер с доступным переключателем «Применить ко всему кластеру
   после просмотра всех контекстов».
2. Просмотрите все контексты; включите batch и нажмите «Подтвердить разбор».
3. Сравните число в строке impact с количеством строк occurrence-ID ниже.
4. Нажмите «Отмена» — в этой проверке batch не записывайте.
5. Откройте неоднородный/collision-кластер. Переключатель batch должен быть
   недоступен с пояснением, что разрешено только occurrence-решение.

PASS: число impact равно числу перечисленных IDs; после отмены счётчики не
изменились; для небезопасного кластера batch заблокирован fail-closed.

## E. Переход в Obsidian projection и receipt

1. После single-решения снова нажмите «Скачать Obsidian ZIP» и сохраните файл
   как `-after.zip`.
2. Распакуйте `-after.zip` в отдельную тестовую папку/vault Obsidian.
3. Откройте `_LinguistPro/texts/<text-id>/receipt.json`.
4. В `resolution_transitions` найдите выбранный occurrence. Ожидается
   `from: "unresolved"`, `to: "resolved"`.
5. В `resolution-audit.json` тот же occurrence должен иметь состояние
   `resolved`; в активной очереди unresolved его уже быть не должно.
6. Откройте соответствующую lexical note и убедитесь, что применённый разбор
   виден в проекции, а исходный контекст и provenance сохранены.

PASS: before/after receipt показывает ровно один ожидаемый переход, audit и
активная очередь согласованы.

Важно: переход вычисляется между последовательными выгрузками этого текста в
том же браузерном профиле. Поэтому сначала обязателен `before.zip`, затем
решение, затем `after.zip`.

## F. Full/slim backup roundtrip

Автоматический executable gate уже проверяет оба внутренних режима
`exportBundle`: full и slim, remap ID при восстановлении, повторный импорт без
дубликатов и отсутствие событий другого текста.

Для ручной проверки полного архива:

1. В Studio откройте Library -> Import Center -> `Download full ZIP`.
2. Сохраните SHA-256 архива.
3. В отдельном тестовом профиле откройте Import Center -> `Restore full ZIP`.
4. Откройте тот же текст и проверку морфологии.
5. PASS: single-решение и счётчики восстановлены, текст/аудио открываются.

Slim — внутренний text-scoped контракт backup/cloud bundle, отдельной
пользовательской кнопки «slim backup» сейчас нет. Его acceptance обеспечивается
исполняемым тестом `node --test tests/lexicalResolutionBackupRoundtrip.test.js`;
не следует выдавать learning ZIP или Media Package за тот же формат.
