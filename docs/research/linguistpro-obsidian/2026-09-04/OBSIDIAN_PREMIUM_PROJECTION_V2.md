# Obsidian premium projection v2

Дата: 2026-09-04

Статус: `IMPLEMENTED · AUTOMATED_GATES_PASS · PRODUCTION_PENDING · OBSIDIAN_VISUAL_ACCEPTANCE_PENDING`

## 1. Причина переработки

Проверка реального экспорта `Кфар Аза - 2 544/573` выявила не косметические,
а архитектурные дефекты первой проекции:

- `.base` зависели от положения `_LinguistPro` в корне vault и показывали ноль
  строк, если ZIP распакован во вложенную папку;
- ссылки из индексов вели только в технически названные локальные файлы;
- Pealim ID существовал в metadata, но не был представлен как понятное действие;
- контексты начинались с UUID строки и offset;
- отдельного построчного блокнота фраз не было;
- `Текст.md` был техническим контейнером двух пустых Bases, а не учебным хабом.

V2 определяет learner-facing слой отдельно от audit/roundtrip слоя.

## 2. Владелец каждого вида данных

| Данные | Канонический владелец | Представление в Obsidian |
|---|---|---|
| текст, порядок строк, переводы, аудио | LinguistPro | read-only snapshot |
| occurrence и подтверждённый морфологический разбор | LinguistPro | read-only контекст |
| лексема, Pealim identity и значение | LinguistPro | generated карточка лексемы |
| FSRS, оценки, due и review log | LinguistPro | только read-only проекция при необходимости |
| грамматические выводы, ошибки, вопросы, собственные примеры | пользователь | обычные заметки вне `_LinguistPro` |

Экспортёр пишет только `_LinguistPro`. Пользовательские заметки ссылаются на
generated-файлы или встраивают стабильные блоки фраз, но не редактируют канон.

## 3. Учебная навигация

```text
Текст.md
├── Фразы.md
│   └── Фразы/001–050.md ...
│       └── стабильный block anchor каждой строки
├── Лексика.base
│   └── локальная карточка лексемы
│       ├── значение и морфология
│       ├── примеры из текста → точная фраза
│       └── Pealim ↗
└── Очередь разбора.md / Разбор.base
    └── понятная причина → примеры → исправление в LinguistPro
```

Локальная карточка, а не Pealim, является основной ссылкой на слово. Она
работает офлайн, содержит контексты именно изучаемого текста и участвует в
графе знаний. Pealim показан рядом как явная внешняя ссылка для проверки
словарной статьи. Замена всех локальных ссылок ссылками на Pealim разрушила бы
контекст, backlinks и переносимость; отсутствие Pealim-ссылки также неприемлемо.

## 4. Переносимые Bases

V2 не фильтрует файлы по абсолютному пути внутри vault. Отбор выполняется по
типу заметки и идентификатору текста:

```yaml
filters:
  and:
    - 'note.type == "lp-lexeme"'
    - 'list(note.lp_text_ids).contains("<text-id>")'
```

Поэтому `.base` работает и в корне vault, и внутри распакованной папки. Колонка
слова использует `file.asLink(note.lemma)`, а отдельная колонка словаря —
`link(note.pealim_url, "Pealim ↗")`. Эти функции являются штатной частью
Obsidian Bases:
[синтаксис Bases](https://obsidian.md/help/bases/syntax) и
[функции Bases](https://obsidian.md/help/bases/functions).

## 5. Human-facing и audit-facing identity

Пользователь видит:

- `Фраза 17`, а не `a8b23539-...:1`;
- «не определена часть речи», а не `unknown_pos`;
- «нужно подтвердить словарное значение», а не `identity_guarded`;
- слово, значение, часть речи и действие `Pealim ↗`.

Точные `row_id`, `word_offset`, occurrence ID и candidate fingerprint нужны для
идемпотентности, receipts и обратной трассировки. Они остаются в frontmatter,
JSON/TSV и HTML-комментариях Markdown. Obsidian не показывает HTML-комментарии
в режиме чтения, но exporter может восстановить точную связь.

## 6. Блокнот фраз

Для каждого свежего экспорта генерируются все строки текста:

```text
Фразы.md
Фразы/001–050.md
Фразы/051–100.md
...
```

Каждая строка содержит по наличию:

- иврит с огласовками;
- вариант без огласовок;
- латинскую транслитерацию и русскую фонетическую запись, если они есть;
- русский перевод;
- стабильный block anchor.

Фрагмент можно встроить в личную заметку без копирования:

```markdown
![[.../Фразы/001–050#^lp-phrase-xxxxxxxx]]
```

Деление по 50 строк уменьшает тяжесть рендера и остаётся удобным для навигации.
Старый `projection.json` может восстановить только строки, встречающиеся в
occurrence evidence. Поэтому compatibility-preview старого ZIP неполон: для
проверенного snapshot он восстанавливает 539 из 545 исходных строк. Новый
экспорт включает `text.rows` и обязан дать точное фактическое число строк
выбранного текста; `544/573` в заголовке не используется как машинный счётчик.

## 7. Рекомендуемый учебный процесс

### Работа с одним текстом

1. Первичное аудирование и чтение выполняются в LinguistPro.
2. Пользователь помечает только реально мешающие пониманию слова и конструкции.
3. Неоднозначная морфология исправляется в LinguistPro на конкретных примерах.
4. После экспорта `Текст.md` становится оглавлением, а `Фразы.md` — блокнотом
   точных цитат.
5. Из фразы открывается локальная лексема; Pealim используется для внешней
   словарной проверки.
6. В личной заметке сохраняется собственный пример, ошибка, вопрос преподавателю
   или грамматическое обобщение. Generated-описание не копируется вручную.
7. Повторения и оценка знания остаются в единственном FSRS LinguistPro.

### Работа со всей библиотекой

- локальная лексема объединяет occurrences разных текстов по стабильной
  sense identity;
- личные тематические заметки ссылаются на лексемы и встраивают выбранные фразы;
- Bases дают поперечные виды: часть речи, несколько текстов, нет значения,
  требует проверки;
- недельный обзор выбирает ограниченное число повторяющихся конструкций и
  ошибок, а не превращает весь reference index в обязательный список обучения.

## 8. Масштабирование на несколько текстов

Текущий ZIP является снимком одного текста. Простое распаковывание нескольких
ZIP поверх общего `_LinguistPro/lexemes` в будущем требует merge-контракта:

- global lexeme note объединяет `lp_text_ids` и контексты;
- per-text phrase layer остаётся под `texts/<text-id>`;
- manifest определяет create/update/unchanged/conflict;
- исчезнувший occurrence не удаляет контекст другого текста;
- exporter не перезаписывает пользовательские файлы;
- tombstone применяется только к управляемому source membership.

До реализации merge/importer безопасный сценарий — отдельная папка snapshot на
текст либо полная библиотечная выгрузка одним согласованным пакетом.

## 9. Интеграция с Obsidian и агентом

ZIP остаётся обязательным переносимым транспортом. Прямой доступ агента к
Obsidian не нужен для корректности проекции. Если позднее устанавливается Local
REST API/MCP, его scope должен быть:

- read по vault;
- propose для пользовательских заметок;
- write только после preview/diff;
- запрет записи в `_LinguistPro` в обход экспортёра;
- loopback-only и секрет вне vault/repo.

Собственный плагин оправдан только для управляемого merge нескольких snapshots,
конфликтов и кнопки «предложить исправление в LinguistPro», а не для первой
рабочей версии.

## 10. Ворота приёмки v2

- `Лексика.base` и `Разбор.base` непусты в корне и во вложенной папке;
- слово открывает локальную карточку, отдельная ссылка открывает Pealim;
- у каждой лексемы показаны все её фразы из текста;
- в режиме чтения нет UUID/offset/provider codes;
- свежий экспорт содержит ровно все строки выбранного текста;
- ссылка из лексемы/очереди ведёт к правильному phrase block;
- второй экспорт того же snapshot детерминирован;
- `review_log`, FSRS и прогресс не изменяются;
- Windows Unicode paths и nested-vault проверены;
- desktop visual QA в Obsidian и owner acceptance фиксируются отдельно.

Автоматизированный контракт подтверждает генерацию и содержимое, но не заменяет
визуальную проверку на Obsidian 1.13.7. В текущем сеансе native computer-use
helper недоступен, поэтому визуальная приёмка не объявляется пройденной.
