# Карточка: варианты разбора, уточнение и имя собственное

Дата: 2026-10-21. Запрос владельца после 3.11.804, два скриншота: שֶׁפָּחַדְתָּ (строка 22) и נוֹתַר (строка 26), «Хаммам, серия 2». Основание: живой production 3.11.804, read-only Kapture, исходники release `b3ebc514`, [Pealim 867](https://www.pealim.com/ru/dict/867-lehivater/). Статус: диагностика и предложение; UI/поведение не изменялись.

## Что реализовано

`reader-morph.js:1953` (`analysisChoicesHtml`) собирает **одну** секцию редактирования выбора разбора:

1. «Варианты значения» — список `analysisCandidates`. Кнопка показывает лемму, словарный gloss и POS; Pealim — ссылка на соответствующую статью. Выбор хранит ID словарной записи, а не отдельное значение внутри неё или грамматический slot.
2. «Уточнить значение здесь» — `details`, внутри которого сейчас **только** «Имя собственное». Раскрытие само ничего не выбирает. Имя доступно как ручное исправление любого слова, не как доказанная машинная гипотеза.
3. Подсказка «При необходимости…» — статус того же редактора. `previewAnalysis` по нажатию любого кандидата меняет `aria-pressed`, подпись на «Предварительный выбор: …» и включает общую кнопку. Это ещё не запись.
4. «Использовать здесь» вызывает `saveAnalysis` → `MorphHost.confirmOccurrenceAnalysis` → append-only `lexical_resolution_events` для проверенного sentence/token anchor. Это решение об анализе конкретного вхождения; открытие редактора/предварительный выбор не оценивают знание и не создают FSRS. «Сбросить мой выбор» уже предусмотрен для сохранённого решения.

Следовательно, подсказка и кнопка не являются третьим самостоятельным смысловым блоком. Сейчас они визуально оторваны от собственного выбора. Название «Уточнить значение» обещает выбор значения/редактирование перевода, но раскрывает только исправление POS на propernoun.

## Два живых случая

| Поле | שֶׁפָּחַדְתָּ | נוֹתַר |
|---|---|---|
| Основной offline-разбор | exact, pid:1612, לפחוד, verb | exact, pid:867, להיוותר, verb/nifal |
| Основной matcher | prefix ש + PERF-2ms | PERF-3ms |
| `analysisCandidates` | **0** | **1**, pid:867, лемма להיוותר / «оставаться» |
| Производный WordGloss | «что ты боялся» | «он оставался» |
| Верхний контекстный ИИ-gloss | на скриншоте «что ты испугался» | на скриншоте/вкладке «осталось» |

Причина пустого первого списка проверена в `analysisCandidates` (`reader-morph.js:727`): индекс ищет полное написание/форму и фильтрует совпадения по полной огласованной строке. Он не использует уже доказанный основным matcher разбор prefix ש + клетка פָּחַדְתָּ. Поэтому заголовок «Варианты» остаётся над пустым контейнером, а единственный видимый выбор — «Имя собственное». Нужна согласованность производителей кандидатов, а не ручное добавление этой одной формы.

Для נוֹתַר показанная лемма словарной статьи корректна, но одна лемма недостаточна для учебного выбора формы из текста. В Pealim это прошедшее время, 3-е лицо, ед. ч., муж. род; настоящее/причастие נוֹתָר отличается огласовкой. В конкретной полностью огласованной строке нельзя показывать лишнюю грамматическую неоднозначность только из-за одинакового неогласованного `נותר`. Механический русский gloss формы, словарное значение леммы и контекстный ИИ-перевод должны иметь разные подписи. Число русских синонимов не равно числу словарных разборов.

## Дополнительный семантический дефект

`saveAnalysis` передаёт для имени `{name:true, meaning: existingAiGloss || card.meaning}`. `MorphHost.confirmOccurrenceAnalysis` сохраняет это как `manual_correction`, propernoun, без корня/binyan/Pealim ID, но с унаследованным значением. Затем `applyLexicalResolution` помечает анализ owner-confirmed. Поэтому подтверждение только класса «имя» способно превратить прежний глагольный ИИ-перевод («что ты испугался»/«осталось») в значение подтверждённого имени. Это доказано трассировкой кода; пробных сохранений в owner-профиле не выполнялось.

Подтверждение класса и подтверждение значения — отдельные утверждения. Для имени можно сохранить классификацию без придуманного/унаследованного перевода и отдельно предложить ввод имени/транслитерации; контекстный ИИ-gloss не получает статус человеческой проверки автоматически.

## Предлагаемый интерфейс

1. **Текущее понимание слова** — одна связная группа: форма из текста + её объяснение/грамматика, рядом или ниже начальная форма + словарное значение/POS + Pealim. Контекстный ИИ-gloss остаётся явно подписанным. Не дублировать ту же пару ещё раз в пустой секции вариантов.
2. **«Исправить разбор в этой строке»** — отдельное действие. В редакторе реальные варианты связаны с формой из текста и словарной статьёй. Нулевой список не создаёт заголовок «Варианты значения»; один анализ показывается как один найденный анализ; несколько — как выбор между ними.
3. Слово «разбор» соответствует нынешнему действию (словарная единица/POS). Для подтверждения конкретного грамматического чтения при нескольких slots нужен отдельно определённый и сохраняемый выбор; нынешний lexical event такого поля не содержит. Не обещать его одной перерисовкой списка.
4. В редакторе «Здесь это имя собственное» — явное действие, сохраняемое без дополнительной общей кнопки, с уведомлением «В этой строке отмечено как имя. Отменить». От открытия общего редактора получается два действия вместо трёх. Это ручная коррекция, а не универсальная рекомендация, что каждое слово может быть именем.
5. Предпросмотр и одно явное «Сохранить разбор для этой строки» оставить для сложного редактирования нескольких полей. До изменения нет неактивной бесхозной кнопки. После сохранения/при ошибке показывается однозначное состояние; отмена/повтор/закрытие не переписывают чужую карточку или прежнюю историю.

Связанные наблюдения: O-117 (структура/термины), O-118 (потерянный prefixed candidate), O-119 (подмена области подтверждённого значения). Это предложение следующего этапа, без автоматической реализации или production-выпуска.
