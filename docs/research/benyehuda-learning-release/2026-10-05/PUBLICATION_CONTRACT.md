# Контракт учебной публикации Бен-Иегуды

Это контракт кандидата, который ещё требует независимого review. Исходный формат остаётся native learning ZIP с `library/library.json`; переписывать прежние архивы не требуется. Машиночитаемая версия: [publication-contract.json](publication-contract.json).

У произведения есть четыре разные идентичности: source work ID (`corpus.byehuda_id`), сохранённый ключ ZIP (`text_key`), независимо пересчитанный canonical key и ключ конкретной publisher edition. Последний вычисляется из work ID и хеша нормализованной учебной редакции. Имя immutable body содержит префикс полного хеша тела. Эти значения не взаимозаменяемы.

Сохранённый и пересчитанный ключи вместе с прежними опубликованными ключами являются aliases только одного подтверждённого произведения. Сборщик блокирует межпроизведенческий конфликт. Клиент повторно проверяет ID в локальной metadata перед использованием alias. Для 28026 сохраняются оба исторических значения. Совпадение ключа чужого произведения не разрешает его слияние или замену.

Все пять полей чтения, порядок и ID строк, а также значение отдельной машинной огласовки сохраняются точно. Source classification остаётся отдельной от эвристической эпохи приложения. Публичная metadata проходит whitelist; raw prompts, приватные пути, служебные ledger и learner annotations не публикуются.

Карточка действительно использует ID, название, автора, жанр, язык, эпоху и число строк для каталога/фильтров. Для открытия нужны publisher key, immutable file, полный body hash, edition ID и aliases; для preview — отдельный файл и его hash. Паспорт использует measured layer counts и доказанные source/revision/rights facts. Подробные списки полей и формулы находятся в JSON-контракте.

Обычное «Читать» открывает подтверждённую существующую локальную копию и показывает её реальное число строк. Новая publisher copy появляется только после явного выбора отдельной редакции, когда уже есть подходящая прежняя копия. Холодная ссылка предлагает сохранённое продолжение без автоматической записи прогресса. Прежние user locks, notes, bookmarks, row/step progress, reviews и media остаются в прежней копии. Destructive replace, canon reconciliation и массовый reimport не используются.

Сквозные fixtures выбирают точные произведения из реальных SHA/CRC-проверенных ZIP: новый 24249, заменённый 3557, обе идентичности 28026 и отрицательное совпадение ключа чужого ID. Проверяются native import, настоящий обработчик карточки, reload, сохранность locks/notes/progress и отдельный opt-in новой редакции. Это проверка совместимости идентичностей, а не тест производительности массового импорта всего 93-work архива.

Будущий генератор должен выдавать проверяемый source ID и обе source-key идентичности, сохранять учебные строки и provenance и проходить этот контракт вместе со сквозными fixtures. Перед передачей контракта облачной сборке необходим независимый review исправленного commit. Прохождение локальных тестов ещё не означает исправленную production pipeline.
