## Scope

The approved change removes the historical Studio trainer from the user route. Studio now reads the same local FSRS projection as Reading Room and hands a due session to the canonical Room trainer through `library.html?review=due&from=studio`. No scheduler, queue, review journal, schema, corpus data, lemma canon, cloud API, or owner data was added or migrated.

## Methods

1. Read the required project canon, current planning packets, and live implementation.
2. Reconstructed the complete occurrence → lemma → source anchor → `word_status` → due query → training item → `review_log` path.
3. Captured red static tests for the legacy Studio route and missing deep-link contract before implementation.
4. Ran an isolated Playwright/OPFS fixture containing one due word from each supported source.
5. Verified open/close/refresh as read-only, one grade event, replay equality, responsive/RTL, keyboard focus, theme behavior, and Back navigation.
6. Ran the existing FSRS, memory-canon, Reader, Room, Studio, i18n, and version gates.

The isolated fixture never uses the owner's production data. Production owner-profile verification is read-only: opening and closing the first card is permitted; grading is not.

## Limitations

- A browser fixture proves the current shared data contract; it does not manufacture cards for a source the owner has never marked or learned.
- A missing source may honestly fall back to word-only evidence; it is not removed from memory.
- A completed grade creates exactly one canonical `review`/`skip` event. The pre-existing independent manual-status LWW axis may append a separate `mark` event when the user changes a manual mark; that is not a second grade and was not rewritten in this slice.
- iPhone automation is not owner-live evidence. The remaining owner-live checks are listed in the implementation packet.
