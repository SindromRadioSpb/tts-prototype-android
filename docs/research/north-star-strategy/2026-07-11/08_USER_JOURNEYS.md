# 08 — User journeys

**Status:** PROPOSAL · **Source commit:** `b426b1b7a91abcb4afb8fde7f0e34c042a9bc0d6` · **Date:** 2026-07-11

## J1 — First experience

`entry → choose “my text” or curated 90-second fragment → first sentence readable → tap one difficulty → save/grade one result → see when/where it returns`

Friction: blank-canvas choice, provider delay, terminology, consent. Avoid forced account/mentor tour. Measurable value: time-to-readable-sentence; fragment completion; first anchored evidence. Return reason: named fragment or one due action, not a streak promise.

## J2 — Studio to Reading

`paste/import → enrich with visible provenance/degraded states → preview → open in Room → read → explicit marks/taps → events → one post-reading option`

Missing handoffs: stable selection/anchor parity and simpler “done creating.” Redundancy: editing/enrichment controls must not reappear in Room. Agent continuity: offer one micro-session only when sufficient evidence exists.

## J3 — Reading to Mentor

`read → evidence gap/error → contextual “Why?” or “Practice this” → bounded task → deterministic grader → append event → projection replay → continue/next text`

Dead ends: explanation without action; practice without source sentence; LLM-only grade. Value: accepted recommendation, completed action, delayed success in context.

## J4 — Mentor to Reading

`projection detects weak construct → recommend exact fragment and reason → open at anchor → meet it naturally → retrieve → later transfer in another text`

Risk: recommendation engine overclaims a “misconception” from sparse evidence. Require confidence/abstention, curated/derived distinction and a second-context confirmation.

## J5 — Long-term learner

`weeks/months of authentic encounters → richer evidence across modalities → recommendations sharpen → hints/niqqud reduce by choice → broader texts → demonstrated independence`

Risk: optimizing due completion rather than independence. Value: lower hint dependency, higher completion/complexity, contextual transfer and productive recognition.

## Dominant loop

`Read something meaningful → resolve only what blocks understanding → save evidence in context → do one well-timed retrieval → meet/use it in a new context → choose the next meaningful text.`

## Cross-journey gates

- No dead end: every result has Continue reading, Next text, or Done.
- No silent state: marks, grades, consent and uploads are explicit.
- Preserve anchor across channels or say it is unavailable.
- Non-response is missing data, never failure/success.
- Measure handoff completion and context retention, not clicks.

## Facts / assumptions / unresolved / sources

**FACT:** many individual handoffs exist, including MA→Room and Mentor→Room. **INFERENCE:** they are not yet one validated onboarding narrative. **PROPOSAL:** instrument the five journeys before broadening scope. Sources: baseline, current UI modules, Room/mentor plans. Unresolved: funnel drop-offs and latency thresholds.
