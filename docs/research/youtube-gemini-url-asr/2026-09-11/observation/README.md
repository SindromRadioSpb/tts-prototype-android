# Наблюдение за настоящим прогоном «ссылка → учебный материал»

Дата: 2026-09-11. Ролик владельца: `https://www.youtube.com/watch?v=3DyWmEZj5ww` (11:41).
Провайдер: `gemini-flash-latest`, ключ владельца, **настоящие деньги и настоящие паузы**.

Собрано ради одного вопроса: что человек на самом деле видит и сколько ждёт. На моках всё
мгновенно, и судить о качестве экрана прогресса по ним нельзя.

## Как воспроизвести

```bash
GEMINI_API_KEY=… node scripts/premium/youtube-material-observe.cjs \
  --url=https://www.youtube.com/watch?v=<id> --out=<dir>
```
Скрипт снимает экран на каждом изменении состояния, пишет `timeline.json` и **записывает тело
провайдерских отказов** — иначе «таблица не вернулась» остаётся догадкой, а повторная проверка
стоит новых денег за тот же ответ.

## Что здесь лежит

- `timeline.json` — **главный файл**: посекундная запись состояний, меток этапов, живой строки и
  провайдерских отказов последнего прогона.
- `01-quote.png` — экран сметы до трат.
- `04-transcribing-38s.png` — момент, ради которого всё делалось: этап «идёт», причина паузы и
  обратный отсчёт повтора.
- `99-final.png` — как выглядит остановленный прогон.

Скриншоты сняты ДО перестановки диалога (цена и действие подняты над пояснениями) — порядок блоков
на них старый, состояния этапов актуальные.

## Что наблюдение показало

| Прогон | Итог | Чему научил |
|---|---|---|
| 1 | `YT_OVERLOADED` через 239 с | Этапы рисовались из снимка задачи, взятого ДО старта: 4 минуты работы выглядели как «остановлено» с пустой строкой. Живой строки не было вообще. |
| 2 | `YT_OVERLOADED` через 153 с | Повтор стал виден, но брал ТЕРМИНАЛЬНУЮ фразу ошибки и советовал нажать «Продолжить», пока прогон продолжался сам. |
| 3 | ASR **прошёл**: 193 сегмента, часы `verified` (19 из 21 якоря, медиана 0 с); таблица упала `TASK_TABLE_INCOMPLETE` | Лестница ретраев спасает прогон. Счётчик кусков показывал «2 из 2» на первом куске: телеметрия уже 1-based, а строка прибавляла единицу. |
| 4 | Все 4 попытки — HTTP 503 `"This model is currently experiencing high demand"` | Перегрузка провайдера в этот день была устойчивой. Отказ теперь записывается дословно, а не угадывается. |

Отдельно: смета обещала «обычно 5 мин» (из отгруженной модели `ASR_SEC_PER_WINDOW = 45`), а
распознавание шло **9:41**. Замеры расходятся слишком сильно (26-мин ролик распознан за 47 с в
спокойный час), чтобы честно поправить константу по двум точкам, поэтому экран теперь сам
признаётся: «идёт 9:41 · дольше обычного».
