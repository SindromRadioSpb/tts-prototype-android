## Что это за артефакт

- `measurements.json` — **единственный файл с результатами**, который следует читать. Числа, токены,
  ошибки меток. Правится только новыми прогонами, вручную не редактируется.
- `yt-probe.js`, `yt-limits.js`, `yt-oracle.js` — одноразовый спайк-харнесс, которым получены числа.
  Это **не** production-код и не гейт: при внедрении P5 из него делается штатный live-smoke.
- Сырые ответы провайдера (полные транскрипты ролика Кан 11) и скачанное медиа **в git не попадают**:
  права на вещание принадлежат правообладателю, репозиторий публичный. Они остаются во временной
  папке прогона и регенерируются командами ниже.

## Как воспроизвести

```bash
# ключ берётся из локального .env (GEMINI_API_KEY), в вывод не печатается
node yt-probe.js  full  gemini-flash-latest probe-full.json   # весь ролик одним вызовом
node yt-probe.js  clip  gemini-flash-latest probe-clip.json   # окно 600–720 с через videoMetadata
node yt-limits.js errors                                      # формы URL и коды ошибок
node yt-limits.js knobs                                       # fps / mediaResolution / повтор
# независимый оракул: наш детерминированный ffmpeg-срез → Files API → сверка абсолютных меток
yt-dlp -f bestaudio -o pilot.m4a <url> && node yt-oracle.js
```

## Ответ на вопрос владельца

**Да, Gemini делает ASR прямо по ссылке YouTube, без скачивания медиа.** Ссылка передаётся как
`parts[].file_data.file_uri`; сервер Google сам достаёт ролик. На пилоте (26 мин, иврит, Кан 11,
у ролика нет ни ручных, ни автоматических субтитров) один вызов вернул полный транскрипт.

### Качество и честность часов

Главный риск проекта — подделанные метки (уроки S12.5/S12.7: модель штампует ровный шаг вместо
чтения позиции в звуке). Здесь метки проверены **независимым оракулом**: мы сами резали скачанный
звук `ffmpeg`-ом на известных абсолютных офсетах, грузили срез как отдельный файл (модель не знает,
откуда он) и искали его текст в таймлайне YouTube-прогона.

| Проверка | Якорей | Медиана ошибки | Разброс |
|---|---|---|---|
| YouTube-прогон против нашего среза (5 окон: 180 / 780 / 1080 / 1380 / 1470 с) | 73 | 0 с | −6…+2 с |
| Прогон 1 против прогона 2 (два независимых вызова) | 210 | 0 с | −5…+1 с (P95 abs = 1 с) |
| Окно `videoMetadata` 600–720 с против полного прогона | 28 | 0 с | −6…+1 с |

Покрытие полного ролика: 327 сегментов, 7 → 1550 с при длительности 1560 с, **ни одной дыры >25 с**,
метки монотонны, 3609 слов ≈ 2.31 слова/с (нормальный темп речи). Признаков сжатия часов и тихой
потери кусков, ломавших загруженные длинные файлы, на этом ролике нет.

Оговорка (R17): оракул сверяет **текст с текстом**, а не с реальной речью на слух. Он ловит сдвиг и
пропуск, но не заменяет ручную проверку транскрипта человеком.

### Окна: режем ВХОД, а не промт

`video_metadata: {start_offset, end_offset}` работает и для YouTube-ссылки. Это структурный срез
**входа**, а не просьба в промте: 120-секундное окно стоило 10 921 видео-токен против 141 962 на
полном ролике — модель физически не получила остального звука. Метки при этом возвращаются
**абсолютные** (окно 600–720 с → `10:00…11:56`), то есть длинные ролики нарезаются без скачивания и
без риска, ради которого в S12.5 убивали range-промт как класс.

### Стоимость (R16)

`countTokens` принимает YouTube-ссылку **бесплатно** и даёт точную смету до оплаты: полный ролик =
160 928 токенов (видео 110 760 + звук 49 919). `mediaResolution` на YouTube **не влияет** ни на что,
а `fps` — влияет: при `fps: 0.2` окно 120 с стоит 5 546 токенов вместо 12 362 (**−55%**), и метки
остаются такими же честными (медиана 0 с, 22 из 23 якорей). Для ASR кадры не нужны, поэтому рабочий
режим — `fps: 0.2`: ≈46 токенов/с ⇒ **≈0.17 МТок и ориентировочно USD 0.13–0.17 на час видео**
входом плюс выход (пилот: 11.7 тыс. выходных токенов на 26 мин).

Фактические расходы этого спайка: ≈0.35 МТок входа и ≈26 тыс. токенов выхода — **порядка USD 0.3–0.45**
(оценка по стандартному прайсу, не выписка по счёту).

### Ограничения и режимы отказа

| Ограничение | Наблюдение |
|---|---|
| Приватные и unlisted ролики | не поддерживаются (официальная документация) |
| Бесплатный тариф | не более 8 часов YouTube в сутки; на платном ограничения по длине нет |
| Роликов на запрос | до 10 начиная с Gemini 2.5 |
| Форма URL | `watch?v=<id>` и `youtu.be/<id>` принимаются; **URL с лишними параметрами** (`&t=`, `&list=`) → **400** |
| Несуществующий id, не-YouTube ссылка | **400 `INVALID_ARGUMENT`** без различимой причины — UI обязан говорить честно «ссылка не принята», не угадывая |
| Перегрузка провайдера | **5 × HTTP 503 и 1 × HTTP 429 за сессию** на `generateContent`; `countTokens` не падал ни разу. Ровно это утопило прошлый пилот. Ретрай с backoff обязателен, «перегружен» ≠ «не работает» |
| Потолок одного вызова | вход ≈46 ток/с при `fps 0.2` (≈6 ч в 1 М контекста), выход ≈7.5 ток/с ⇒ стена 65 тыс. выходных токенов ≈ 2.4 ч плотной речи. Практический предел ниже: 26 мин прошли чисто, длиннее не мерено |

### Чего этот спайк НЕ доказывает

- Один ролик, один язык, одна студийная запись. Интервью с наложением речи, музыка, длинные паузы,
  часовые лекции, авто-субтитры — не мерено (план владельца просил минимум 6 роликов).
- Ролики с ограничением встраивания: ASR по ссылке может пройти, а плеер вернуть ошибку 150/153.
  Это разные механизмы: **пригодность транскрипта ≠ доступность воспроизведения**.
- Права на публикацию расшифровки/перевода. Встраивание плеера их не даёт.
- Ни одного изменения в приложении, данных владельца или production в рамках спайка не сделано.
