## Добавлено и проверено

`scripts/atlas/material_snapshot.py`: произвольные файлы без потерь, инвентарь SHA-256/bytes, проверка лишних/пропавших/изменённых файлов, запрет symlink/junction и существующей цели, копирование через временный каталог и rename. Import без `--write` ничего не записывает. Никаких вызовов БД, публикации или изменения пользовательских настроек.

На реальном снимке export → import в новый candidate → reexport: полный инвентарь совпал. Unit test проверил roundtrip, повреждение/лишний файл, отказ перезаписи и invalidation report.

Команды из корня данной рабочей копии (пути SOURCE/PACKAGE/CANDIDATE абсолютные):

```text
python scripts/atlas/material_snapshot.py export SOURCE PACKAGE
python scripts/atlas/material_snapshot.py verify PACKAGE
python scripts/atlas/material_snapshot.py import PACKAGE CANDIDATE
python scripts/atlas/material_snapshot.py import PACKAGE CANDIDATE --write
python scripts/atlas/material_snapshot.py diff SOURCE CANDIDATE
python -m unittest discover -s scripts/atlas/tests -p test_material_snapshot.py
```

Diff выдаёт changed_files и ai_requires_review для всех изменённых разделов. Обычный импорт требует соответствия runtime/context манифестам, поэтому изменение строк со старым ИИ отвергается. Для редактируемой копии используйте `prepare`: старые подсказки изменённого раздела перемещаются в `evidence/ai-requires-review`, исходный context manifest — в evidence. Активный context manifest отсутствует: штатный клиент не сможет представить этот пакет как проверенный. Это консервативная блокировка ИИ всего пакета до пересборки контекста, а не автоматическое признание подсказок актуальными. Неизменённые подсказки физически сохраняются. Исходные файлы не меняются.

```text
python scripts/atlas/material_validate.py SOURCE
python scripts/atlas/material_snapshot.py prepare EDITED_SOURCE NEW_DRAFT --baseline SOURCE
python scripts/atlas/material_snapshot.py prepare EDITED_SOURCE NEW_DRAFT --baseline SOURCE --write
```

Черновик получает собственный `edition_id=offline-a97001-<SHA256>` и `DRAFT.json`, никогда `READY.json` или регистрацию в каталоге приложения. Повторные изменения после подготовки обнаруживаются по хешу содержимого; нужно вновь выполнить prepare в новый каталог. Пользовательский прогресс не копируется и не мигрируется. Import проверяет готовый черновик по этой подписи и отсутствию устаревших активных подсказок.

Дополнение перед выпуском: изменение PDF, любого изображения/asset или файла в sources инвалидирует ИИ **всех разделов**, даже при неизменном тексте. Это консервативная политика до появления проверенной карты зависимостей страниц/рисунков. SHA-256 сравнение учитывает замену содержимого под прежним именем, добавление и удаление. Если удаление/замена нарушает ссылки или PDF provenance, prepare вообще блокируется до записи. На реальной копии заменены только байты одного PNG: все 21 ИИ-слой перемещены в evidence, байты всех разделов неизменны. Доказательство: `source-invalidation.json`. Старый ZIP сохранён как исторический; используйте поставку r2 с исправленными инструментами.

## Семантические проверки и границы

`material_validate.py` проверяет первичные ID и неявные page IDs, покрытие разделов/страниц, ссылки parent/target/formula_id/links/symbols, термины и senses, наличие изображений, координаты и перекрытия ячеек, привязку каждого раздела к имеющемуся PDF. Исторические legacy_groups и occurrence_compatibility не считаются конкурирующими первичными объектами: они сохраняются побайтно. На реальном снимке: 2301 объект, 43 явные связи, 1880 ссылок на термины, ошибок 0.

Проверены отрицательные сценарии: дублирование ID, разрыв parent, неизвестный термин, перекрытие ячеек, другой PDF, лишний файл, существующая цель, изменение после prepare. На реальном разделе s07 изменение русского текста отклонило обычный импорт, prepare исключил старый ИИ из активного набора с сохранением evidence. Dry-run не записал данные. CLI import → export вновь дал идентичные 873 файла. Откат в новый каталог совпал с исходным снимком. Результаты — `goal-verification.json`; 2 unit tests охватывают несколько отрицательных сценариев.

Транспорт сохраняет все существующие данные и файлы без проекции на ограниченный набор полей. Он не обещает восстановление отсутствующих в исходном материале распознанных ячеек из изображения, научную вычитку или обратимость исторического supplier→graph→reader компилятора. Эту потерю предотвращаем выбором полного reader snapshot как редактируемой основы и сохранением supplier/editorial/PDF отдельно. При содержательных правках search/train и контекст необходимо пересобрать; `derived_data_requires_rebuild` и `publication_allowed:false` явно фиксируют это. Черновик намеренно не монтируется в production reader.

## Пилот и откат

Предлагаемый содержательный пилот: p50 (текст), p51–52 (таблицы геометрических характеристик), p56 (пример/формулы); дополнить p159 для рисунка/скана таблицы. Внести по одной контролируемой правке в отдельную копию, выполнить validate и prepare dry-run, просмотреть changed_files, затем подготовить новую редакцию через prepare --write. Пересобрать производные search/train существующими build-search-index/build-train-bank средствами и перепроверить context контракт относительно новых строк. Проверить UI на loopback с отдельным профилем до любого предложения публикации. Не менять atlas_id внутри исходных объектов без явной карты миграции; изоляция задаётся новым namespace. Техническая мутация для проверки invalidation уже выполнена только в `goal-test-edited`, её строка явно помечена «НЕ ПУБЛИКОВАТЬ».

Откат локального эксперимента — прекратить использовать candidate и снова импортировать неизменный export в ещё один новый каталог. Этот путь выполнен фактически при reexport и проверке равенства. Production rollback не требовался и не выполнялся: указатель действующей редакции, прогресс и профиль не менялись. Переключение опубликованной редакции и миграция прогресса в объём этого результата не входят.

Финальные локальные артефакты: `goal-import`, `goal-reexport`, `goal-rollback`, `goal-test-draft-v2` в указанном архивном каталоге. Предыдущие проверки сохранены.
