# Аудит UI перед массовым релизом — 2026-09-25

**Назначение.** Этап 1 программы «LinguistPro к релизу для массового пользователя»: путь нового
пользователя без правок кода, находки по влиянию на массового пользователя (P0/P1/P2).

**Что проверено и как.**
- Живая версия `https://linguistpro.kolosei.com`, v3.11.635 (коммит `8df8660d`), чистый профиль Chromium
  (Playwright 1.60, persistent context на прогон).
- Ширины: 380×800 (touch, DPR 2) RU и HE/RTL; 1280×800 RU; тёмная тема 380 RU; `forced-colors: active` 380 RU.
- Скрипты: `lib.js` (замеры касаний и контраста), `step.js` (пошаговый путь), `batch.js` (ключевые экраны
  одной ширины), `explore.js`/`probe.js` (первичный зонд). Запуск: `NODE_PATH=<repo>/node_modules node step.js …`.
  Скриншоты сняты в PNG и сжаты в WebP (q72) в `shots/`.
- Линзы: design-critique (первое впечатление, юзабилити, иерархия, консистентность, доступность),
  ui-ux-pro-max `search.py --domain ux` (Touch Target Size: iOS 44pt / Android 48dp; для веба WCAG 2.5.8 — 24 CSS px;
  Touch Spacing ≥8px; Sticky Navigation не должна закрывать контент; Onboarding: можно пропустить), роли R2/R4/R5.

**Ограничения evidence (честно).**
- Автоматический браузер, не устройство и не скринридер. VoiceOver/TalkBack не проверялись.
- Контраст считается по цвету текста и первому непрозрачному фону. Текст на градиенте (`background-image`)
  даёт ложное «1:1»: такие случаи отбрасывались вручную по скриншоту.
- Импорт медиа в Студии (YouTube-ссылка, локальное видео с ASR) требует ключа Gemini (BYOK, платно).
  Путь не проходился. «Учебный режим с медиа» снят на общедоступном материале Медиатеки (YouTube).
  Импорт в Студии проверен текстом (бесплатный Google Translate + Dicta).
- Касания измерялись для видимых интерактивных элементов в окне. Слова таблицы — инлайн-цели;
  WCAG делает для них исключение, но в продукте это главная цель касания, поэтому они учтены.

## Сводка

За первые 60 секунд новый пользователь видит **три модальных окна подряд**. Ни одно из них не
про чтение на иврите: перенос данных с сервера, приветствие со словами IDE / offline-first / TTS / SRS
и BYOK-ключи Google Cloud. Под ними открывается **Студия** в режиме «CLASSIC MODE» с
текстом-заглушкой `שלום, זהו אבטיפוס פשוט של המערכת` («это простой прототип системы»). Читальный зал и
Медиатека, лучшие части продукта, спрятаны в плитке внутри аккордеона «Разделы и настройки».

Три поверхности (Студия, Зал, Медиатека) выглядят как **три разных продукта**. У них разные шапки,
логотипы, синие, кнопки, шрифты (Arial, Segoe UI, system-ui, Georgia, Frank Ruhl Libre) и названия
одного и того же: «Читальный зал» / «Учебный зал» / «חדר קריאה», «Сохранить слово» → «в заметках» →
«Разобрать слова» → «Повторить слова». Медиатека — самая зрелая из трёх и годится как отправная точка.

Учебный экран (решение владельца: он отдан видео и таблице) после v3.11.635 работает, **если включён
«Учебный режим»**. У нового пользователя режим выключен, и видео начинается с середины экрана
(y≈390 из 800). Таблица из 5 колонок на 380px ломает слова по буквам и показывает иврит дважды
(«Иврит» и «Огласовки»), поэтому на экране видно 2–3 строки.

Касания: на экранах чтения **90–100% видимых интерактивных элементов меньше 44px**, часть меньше 24px
(закладка 11×15, «Объяснить» 18×15, переключатели Аа 13×13).

## P0 — блокирует массового пользователя

### P0-1 · Три модальных окна подряд на первом запуске
- **Где:** `/` на первом визите, 380 и 1280. Скриншоты: `shots/01-first-run-380-ru.webp`,
  `02-onboarding-380-ru.webp`, `03-demo-click-380-ru.webp`.
- **Что:** (1) «📦 Библиотека работает на устройстве — Перенести данные с сервера / Начать с чистого листа /
  Решу позже» (`#v3Phase6*`) поверх (2) приветствия `#v3OnboardingModal`, потом (3) «Подключите свои
  API-ключи… BYOK… ключ AIza…» (`#byokOnboardingModal`). Миграционный диалог Phase 6 адресован
  пользователям 2026 года с серверной библиотекой. Новому пользователю переносить нечего.
- **Почему P0:** первое впечатление — «нужно что-то настраивать и платить». Onboarding нельзя
  пропустить одним действием. Главная кнопка приветствия «Попробовать на демо-тексте» ниже сгиба на 380px (y=798).
- **Предложение:** на первом запуске одно окно или ни одного. Phase 6 показывать только при наличии
  серверной библиотеки у этого клиента. BYOK — контекстно, при первом действии, которому нужен ключ.
  Приветствие — короткий экран «Что вы хотите: читать / учить по видео / добавить свой текст».

### P0-2 · Новый пользователь попадает в Студию, а не в чтение; навигация спрятана
- **Где:** `/`, `shots/04b-studio-home-full-380-ru.webp`, `05-studio-sections-380-ru.webp`.
- **Что:** стартовая страница — «CLASSIC MODE / IDE режим / Текст для озвучки и перевода». Путь в Зал и
  Медиатеку — плитка «Читальный зал» внутри свёрнутого аккордеона «Разделы и настройки», рядом
  11 кнопок-иконок без подписей (🌳, 🕸, MT, Anki, …). Постоянной навигации между тремя поверхностями нет.
- **Почему P0:** R2/R5 — ценность продукта в чтении и видео с таблицей. Новичок видит инструмент
  для подготовки материала с техническими словами.
- **Предложение:** единая навигация трёх разделов (нижняя панель на телефоне, верхняя на десктопе):
  Зал · Медиатека · Студия (+ Повторение). Для нового профиля стартовый раздел — Зал или Медиатека.

### P0-3 · Счётчики сервера показываются каждому пользователю как «его» лимиты
- **Где:** Студия, «Лимиты и квоты», развёрнуто на 1280 (`shots/04-studio-home-d1280.webp`).
- **Что:** чистый профиль видит «55 643 TTS символы», «411 Запросы AI», «gemini-3.8-flash · BYOK»,
  «Сегодня: 21 / 50», «Сброс квоты через…», кнопку «Открыть Google Cloud Console».
  Источник — `GET /api/usage` (`server.js:8256`): глобальные счётчики сервера, общие для всех.
  Проверено: жёсткой блокировки по `GEMINI_DAILY_LIMIT` в пути запроса нет, есть только отметка `geminiDailyLimitHit`.
- **Почему P0:** доверие и приватность (чужая активность видна как своя), ложное «21/50 — скоро
  кончится». Для BYOK общий дневной лимит бессмыслен.
- **Предложение:** убрать панель из пользовательского UI или показывать только локальные счётчики
  этого браузера. Серверные агрегаты — в диагностику владельца.

### P0-4 · Тёмная тема: заголовок Студии невидим, главная карточка остаётся белой
- **Где:** `shots/19b-dark-studio-380-ru.webp`.
- **Что:** «Текст для озвучки и перевода» #F1F5F9 на белом (1.1:1), «CLASSIC MODE» 2.56:1,
  основная карточка не переключает фон.
- **Почему P0:** в системной тёмной теме (по умолчанию у многих iPhone) первый экран выглядит сломанным.
- **Предложение:** решается токенами (Этап 2). До них — точечный фикс фона карточки.

### P0-5 · «Медиатека» в Зале — ссылка цвета браузера по умолчанию (#0000EE); в тёмной теме 1.56:1
- **Где:** шапка Зала, `07-room-shelves-380-ru-y0.webp`, `19-dark-room-380-ru.webp`, `07-room-shelves-d1280.webp`.
- **Что:** кнопка без стилей продукта: чистый синий #0000EE, рамка того же цвета. На десктопе выпадает
  из сетки (x=16 при контенте с x=80). В тёмной теме почти не читается.
- **Почему P0:** вход в Медиатеку — главный путь к видео, а он выглядит как ошибка вёрстки и не читается в тёмной теме.

### P0-6 · Шапка Зала занимает 28–54% экрана телефона в чтении без учебного режима
- **Где:** `08-reader-open-380-ru.webp`, `18-study-media-he380.webp`.
- **Что:** в открытом тексте остаются заголовок «Читальный зал» с подзаголовком, 5 иконок, «Медиатека»,
  вкладки «Доступная / Литературная / Библиотека» (≈225px), затем строка ридера и «📖 Нужен профиль слов»,
  подсказка «тап — разбор…». Таблица начинается на y≈430 из 800, видео на y≈390.
- **Почему P0:** прямое нарушение правила владельца (экран отдан видео и таблице). Учебный режим,
  который это решает, по умолчанию выключен и спрятан в «Аа».
- **Предложение:** шапка разделов не показывается внутри открытого текста на телефоне (только «назад» +
  название + ▶/🔍/Аа). «Учебный режим» — поведение по умолчанию для материалов с таблицей.

### P0-7 · Таблица из 5 колонок на 380px: слова рвутся по буквам, иврит показан дважды
- **Где:** `10-reader-study-nomedia-380-ru.webp`, `18-study-media-380-ru.webp`, `20b-forced-reader-380-ru.webp`,
  Студия `15b-studio-built-full-380-ru.webp`.
- **Что:** заголовки «Огласов|ки», «Трансли|т (SBL)», «Перево|д»; в ячейках «Здравству|йте»,
  «Очарован|ием» — перенос посреди слова. Колонки «Иврит» и «Огласовки» дублируют строку, иврит по
  1–2 слова в строке, строки по 250–450px высотой: на экране 2–3 строки текста.
- **Почему P0:** таблица — ядро учебного экрана. В таком виде она выглядит поломанной и неудобна для чтения.
- **Предложение (пересмотрено по решению владельца 2026-09-25, без изменения билдеров таблицы):**
  таблица остаётся горизонтальной таблицей на любой ширине. Строки-карточки отклонены: слушание идёт
  по 2+ колонкам параллельно, слово ищется взглядом слева направо для морфологии, строка ASR часто
  содержит много предложений, а слева и справа — два разных способа слушать (TTS в «Действии»,
  ▶︎ медиа в «Переводе»). Вместо этого:
  - наборы колонок в «Аа» (огласовка и перевод по умолчанию на телефоне; транслит и перевод;
    иврит и перевод; огласовка, транслит и перевод; одна колонка; свой набор) — на телефоне
    по умолчанию 2 колонки, ширины по-прежнему тянутся;
  - перенос только между словами, заголовки в одну строку;
  - нумерация строк в колонке «Действие»; ▶︎ медиа со временем фрагмента в последней видимой колонке;
  - кнопки 44px. Макеты — направление D в `directions/` (канвас).

### P0-8 · Видео в учебном режиме съезжает: в LTR обрезано справа, в RTL прижато к левому краю
- **Где:** `18-study-media-380-ru.webp` (x=24…384 при ширине 380), `18-study-media-he380.webp` (x=0…356).
- **Что:** у контейнера видео отступ только с одной стороны.
- **Почему P0:** видео — первое, что видит пользователь учебного экрана. Обрезанный край выглядит как брак.
- **Предложение:** симметричный gutter 16px или видео во всю ширину без отступов (как в YouTube-приложении).

### P0-9 · Касания меньше 44px на всех экранах чтения; часть меньше 24px (WCAG 2.5.8 AA)
- **Где:** замеры `targets()` на каждом шаге.

  | Экран (380) | Всего | <44px | <24px (примеры) |
  |---|---|---|---|
  | Полки Зала | 20 | 19 | ссылки футера 24px высотой |
  | Ридер | 32 | 31 | ☆ Закладка 22×21, 🤖 29×19 |
  | Учебный режим | 45 | 45 | Закладка 11×15, «Объяснить» 18×15, ▶ строки 26×26 |
  | Аа | 27 | 26 | переключатели 13×13 |
  | Карточка слова | — | статус 32×27, ? 19×19 | — |
  | Учебный с видео | 35 | 35 | ▶︎ в переводе 26×20 |
- **Что ещё:** иконки шапки Зала 38×36 с зазором 8px; «← Полки» 85×32; «Аа» 42×32.
- **Предложение:** шкала размеров касания: 44px минимум для кнопок, 32px визуально + расширение зоны до 44
  для плотных рядов (`::before` inset). Служебная колонка строки: одна кнопка ⋯ 44×44 вместо трёх иконок.

### P0-10 · Первое касание слова открывает окно согласия поверх карточки слова
- **Где:** `11-word-tap-380-ru.webp`.
- **Что:** «Уточнять значения по контексту? … отправляет предложение в облако Dicta…» появляется на первом тапе
  и перекрывает только что открытую карточку. Текст ссылается на «Подсказки чтения», а раздел теперь называется «Аа».
- **Почему P0:** первое учебное действие прерывается вопросом о приватности на техническом языке.
  Согласие нужно (R5), но его место — не поверх первого тапа.
- **Предложение:** карточка открывается сразу с офлайн-разбором. Внутри карточки — тихая строка
  «Уточнить по контексту (Dicta, облако)» с одноразовым согласием по нажатию. Исправить ссылку на «Аа».

### P0-11 · Старые вкладки не получают новую версию (O-001), подтверждено на живом
- **Где:** профиль Playwright MCP с прошлых сессий: сервер отдаёт 3.11.635, вкладка загрузила **3.11.344**
  из service worker.
- **Почему P0 для релиза:** все исправления этой программы не дойдут до уже установивших PWA.
  Это не визуальная находка, но она блокирует ценность всех визуальных релизов.
- **Уточнение (тот же день, 16:15):** тот же профиль через несколько минут сам перешёл на 3.11.635
  (кэши `v3.11.635`, `waiting=null`). Первая загрузка после долгого отсутствия отдаёт старую оболочку
  по замыслу (`staleWhileRevalidate`, обновление по тосту после safe point). Открытым остаётся O-001:
  почему у владельца две перезагрузки не помогли.
- **Предложение:** первый релиз программы (R0) — стенд обновления, диагноз O-001, исправление тоста.

### P0-12 · Студия показывает демо-заглушку «это простой прототип системы»
- **Где:** поле исходного текста, `04b-studio-home-full-380-ru.webp`.
- **Что:** значение по умолчанию `שלום, זהו אבטיפוס פשוט של המערכת` и шаг «Этап 3 из 4 — Исходный текст готов».
  Новичок, не вставивший ничего, «готов» создавать таблицу из фразы про прототип.
- **Предложение:** пустое поле с подсказкой и примерами «Вставьте текст, песню или ссылку на YouTube».
  Стадии считать от реального ввода.

## Что работает хорошо (сохранить)
- **Медиатека**: самая зрелая поверхность — чистая типографика, карточки с превью и длительностью,
  понятные вкладки, нормальные размеры шапки (`17-mediatheque-380-ru.webp`).
- **Учебный режим** после v3.11.635: при включении шапка уходит, видео и таблица занимают экран, «Конец текста» —
  хвост прокрутки и больше не перекрывает строки (`10`, `13b`).
- **Карточка слова**: ясная иерархия (слово + озвучка, перевод, корень, часть речи, действия), провенанс
  «огласовка — машинная (Dicta)» честный (R4/R11).
- **Режим forced-colors**: интерфейс не разваливается, границы и кнопки видны (`20b`).
- **RTL**: направление документа переключается, шапки и таблица зеркалятся корректно, кроме отступа видео (P0-8).
- Ретенционный путь коротко замкнут: слово → «Сохранить» → конец текста → «Повторить слова» → тренировка
  с предложением-контекстом (`14`).
