# Первый релиз поиска и выбора материалов в Зале

Основа: `origin/main` `3a4a68619c8e3483b6b1f7c68e5f6e21463f79de`, версия 3.11.729. Кандидат: 3.11.730, ветка `feat/room-discovery-release`. Это UI-релиз. Публикацию нового корпуса владелец выполняет отдельно после завершения официальной современной эпохи.

## Поведение

- На главной библиотеке появился поиск. В Бен-Иегуде поиск и режимы «Читать сейчас / Исследовать каталог» стоят до рекомендаций. Сортировка и дополнительные параметры раскрываются в фильтрах; сведения о корпусе находятся в «О корпусе и данных». Продолжение показывается только при наличии текущего материала, без второго случайного «начала».
- «Читать сейчас» ищет опубликованные учебные версии; «Исследовать каталог» сохраняет доступ ко всему каталогу и разделам. На строке материала есть название HE, автор, длина, одна причина доступности и «О материале». Проверенное RU-название показывается только при явном флаге проверки; генерации названий нет.
- Неопубликованная учебная версия имеет активный паспорт, ссылку на оригинал и отдельное действие добавления в список чтения. Обещание «перевод позже» убрано. Опубликованность, измеренная полнота, машинный перевод/редакторская помощь/человеческая проверка, аудио и локальный текст разделены. Полная доступность без сети остаётся неизвестной без проверки всех активов.
- Предпросмотр требует отдельного нажатия; показывает первые четыре строки учебного bundle. Он читает только публичные поля, не вызывает import/Reader и не пишет learner state. Допустимый payload — 128 KiB; запрос содержит Range и отдельный preview marker. SW оставляет его нативному браузерному fetch без клонирования/CacheStorage, HTTP cache выключен. При игнорировании Range поток отменяется на первом чанке, пересёкшем лимит; этот чанк может быть уже получен. Закрытие отменяет запрос, успешный cache в памяти ограничен восемью произведениями. Для больших произведений остаются паспорт и обычное полное чтение; полный body автоматически не скачивается. Автоматические поисковые snippets дополнительно ограничены тремя новыми запросами на поиск.
- `source_period` принимается только с work ID, work scope, исходной меткой, URL и снимком/версией источника. `unchecked` и `checked-absent` различаются; отсутствие данных подписано «Период по источнику неизвестен». `app era` подписана как вычисленный по автору раздел приложения. Новая официальная периодизация не выдумывается из старых buckets.
- Число групп и drilldown используют один QID projection. Текущий modern fixture: 18 исходных записей → 17 групп каталога. Это не число всех участников: исходные имена, совместные записи и coauthors сохранены. Имена без QID не объединяются по написанию. Поиск дополнен четырьмя проверенными RU aliases с Wikidata snapshot evidence; search/FTS массивы и их ordinals не менялись.

## Границы и контракты

`public/js/room-b6-core.js`: v1 history/session сохранены; URL имеет отдельную публичную projection. Любой произвольный q и автоматические recent chips остаются в хранилище вкладки. Старые origin-wide recents не читаются, не мигрируются и не удаляются; явно сохранённые пользователем поиски остаются в прежнем storage. Только `sharedSearchHash` после действия «Поделиться поиском» создаёт URL с q. Group identity остаётся локально; новые group fragments содержат только generic marker. Private/notes/rows/tags/smart/status и непроецируемые facets запрещены для share. Restore учитывает приоритет явной ссылки, Back, refresh, смену hash и public slug. Страницы нумеруются с 1; отступ пересчитывается через существующий размер 48.

`public/js/corpus-discovery-core.js`: чистая модель availability/coverage/provenance/sourcePeriod/appEra/localState; не имеет fetch, DOM или storage. `public/js/corpus-discovery-browser.js`: ограниченный сетевой preview и native dialog с Esc/focus return. `public/js/library-ui.js`: host wiring, существующие reader/import и read-list actions. `public/css/room-discovery.css`: адаптация текущей системы, включая 380 px и RTL. Новые assets и изменённые module URLs включены в SW precache/server integrity; версия shell/SW согласована. Новых аналитических каналов нет; Room referrer policy — `no-referrer`.

Поиск/паспорт не изменяют каноническую идентичность, schema, revision writers или OPFS migrations. Reader сохраняет общую горизонтальную таблицу и полный текст. Учебные подборки с уже опубликованным TTS остаются доступны через отдельную ссылку/существующую вкладку. Версия приложения не меняет версию canon или каталога и не вводит повторный импорт.

## Следующий релиз: только план

Текущий stack позволяет улучшать редакционные подборки, aliases, source-period evidence и preview sidecars без изменения learner model. Но стабильный multilingual/faceted retrieval при росте корпуса требует отдельного immutable индексного snapshot и server query API с ID/cursor, source period и count-backed coverage. Стоимость первого направления мала/средняя; второй — средняя/высокая из-за редакционной проверки, совместимости старых ссылок и миграции опубликованных редакций.

Для revision migration нужны namespace row IDs по edition, явная authority каждого поля, preflight удалений/конфликтов/audio, staged atomic commit и восстановление после сбоя/конкурентной правки. Предыдущая редакция остаётся читаемой, rollback сохраняет новые learner actions. Нельзя без проверки применять существующий `material-revision-repository.projectRows`: он очищает audio refs и удаляет отсутствующие sentences. Для публикации нужны immutable index/body/assets revision, client pin одной версии, закрытый staging, защита competing pointer updates и хранение прежних редакций. Здесь этих механизмов нет и миграции не выполнялись.

Критерии дальнейшей приёмки: выбор материала ≤30 с / ≤3 действий в пользовательских задачах, share-link correctness, доля карточек с проверенным period/provenance/полнотой, отсутствие writes при discovery, восстановление после обновления/Back, latency/count accuracy на больших индексах, доступность полного reader/TTS. Цель выбора пока не объявлена достигнутой: human task study, physical-device и assistive-technology проверки не проведены. Данные progress/notes/sync описываются по конкретному источнику; этот UI-релиз не добавляет синхронизацию read-lists, сохранённых поисков или Ben/group progress.
