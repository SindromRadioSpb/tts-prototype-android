# Караоке родного аудио «съезжает»: часы модели считают, а не измеряют

**Дата:** 2026-07-30 · **Карточка:** «Заложница Миа. Интервью» (30:05, mp3 43.3 МБ,
sha256 `094164e9…eae8b90`) · **Источник:** owner-приёмка, «строка 87 верна, с 88 всё уезжает».
**Оракул:** авто-субтитры YouTube `iw-orig` того же ролика (`y02xPRX6vCE`), пословные метки —
внешний по отношению к нашим меткам сигнал.

## 1. Симптом воспроизведён численно и совпал с описанием владельца

Сверка `audio.timing.entries` карточки с оракулом (`align-oracle.js`, выравнивание пословное,
banded-LCS; 81% слов совпали точно, 205 из 212 сегментов получили время оракула):

```
строка 88 (сегмент 87): метка  959.0   реально  960.4   ошибка  -1.4 с   ← ещё верно
строка 89 (сегмент 88): метка  964.0   реально  969.4   ошибка  -5.4 с   ← ломается здесь
строка 95 (сегмент 94): метка  993.0   реально 1002.4   ошибка  -9.3 с
строка 121(сегмент 120): метка 1123.0  реально 1154.3   ошибка -31.3 с
строка 161(сегмент 160): метка 1302.0  реально 1405.7   ошибка -103.7 с
строка 201(сегмент 200): метка 1493.0  реально 1749.8   ошибка -256.7 с
```

Ровно то, что видел владелец: строка 88 звучит **[959…964]**, а реально её речь занимает
**[960.4…969.4]** — обрывается на середине; строка 89 играет **[964…968]**, то есть кусок речи
строки 88. Дальше расхождение растёт монотонно до **4 мин 17 с**.

## 2. Гипотеза «склейка чанков таблицы» — ОТВЕРГНУТА (прямым замером)

- Таблица склеена из 2 кусков по **120 + 92** строки, а ломается строка **89** — середина
  первого куска. Шов таблицы (строка 120/121) на графике ошибки ничем не выделен.
- Соответствие «строка ↔ ASR-сегмент» **идеальное**: 212 строк, 212 сегментов, тексты совпадают
  после NFKC/снятия огласовок **212 из 212** (0 расхождений). K1/K2/K3 отработали правильно.
- `TableChunks.offsetRows` корректен; `segment_index` в этой карточке осмыслен.

Ломается не маппинг строк, а **сами метки сегментов**.

## 3. Корневая причина: часы модели внутри ASR-окна СЧИТАЮТ, а не измеряют

Файл нарезан на 3 mp3-чанка (`transport: sliced-mp3`): 0–900, 870–1800, 1770–1805.8.
Абсолютное время = наш байтовый офсет + метка модели внутри чанка. Офсет наш и неподделываем —
**ошибка целиком внутри одного чанка**.

Ошибка по окнам (тот же оракул):

| окно | сегменты | медиана \|ошибки\| | ≤2 с | размах меток / длина окна |
|---|---|---|---|---|
| 0 (0–900) | 74 | **0.6 с** | 86 % | 0.99 |
| 1 (870–1800) | 128 | **59.7 с** (макс 257 с) | 9 % | **0.71** |
| 2 (1770–1806) | 3 | 0.4 с | 67 % | 0.61 (короткий хвост) |

Механика внутри окна 1: до метки ~964 с часы идут верно, дальше локальная скорость
`d(метка)/d(реальное время)` падает — 1.04 → 0.84 → 0.74 → 0.61 → **0.50**. Модель перестала
читать позицию в звуке и начала **штамповать почти постоянный шаг**:

```
корреляция «длина текста сегмента ↔ шаг метки»   окно 0: r = 0.81   окно 1 (после 964 с): r = 0.05
средний шаг метки                                 окно 0: 11.7 с     окно 1: 4.7 с (sd 1.3)
```

То есть 930 с речи упакованы в 660 с меток. Объём ТЕКСТА при этом нормальный
(`densityRatio 0.99`) — потери речи нет, сломан только тайминг. Это тот же класс, что и корневая
причина S12.5: **координата, сообщённая моделью о себе, не является оракулом**
(`docs/research/studio-ingest-longmedia/2026-07-29/DIAGNOSIS_S12_LIVE_DEFECT_2026_07_29.md`).

## 4. Почему не поймали: детектор есть, но он косметический и не той области

`classifyCoverageGaps` нашёл разрыв 1529→1769 и честно назвал его `marks-unreliable`
(`ASR_MARKS_UNRELIABLE`, `unreliableSec: 240`). Но:

1. **Занижает область в 3.5 раза.** Помечен только хвостовой разрыв 240 с, а испорчен весь
   таймлайн от 964 с до конца окна — **836 с, 121 из 212 строк (57 % таблицы)**.
2. **Ничего не выключает.** `timingDropReason: null` — караоке строится и уверенно подсвечивает не
   ту строку. Это прямое нарушение R11 («отсутствие подсветки лучше уверенно неверной»), которое
   K1/K2 закрыли для маппинга, но не для меток.
3. **Может не сработать вовсе.** Детектор требует РАЗРЫВА (`hop > 90 с` либо хвост ≥ 180 с).
   Сжатие на 15 % в 15-минутном окне даёт хвост 135 с — под порогом; тайминг уедет на 2 мин
   молча, без единого предупреждения.

## 5. Живая проба: дефект СТОХАСТИЧЕСКИЙ, и он ловится одним числом

`probe-window1.js` — тот же прод-путь (`Mp3Slice` + `ASR_PROMPT` + Files API), тот же файл,
5 вызовов; точность каждого прогона измерена против оракула (`score-probes.js`):

| прогон | длина среза | размах меток / срез | r | медиана ошибки | ≤2 с |
|---|---|---|---|---|---|
| прод (то, что в карточке) | 937 с | **0.71** | 0.11 | **56.2 с** | 11 % |
| A — повтор прод-окна | 937 с | **0.69** | 0.37 | **55.3 с** | 17 % |
| B — тот же вызов ещё раз | 937 с | 0.97 | 0.57 | **0.58 с** | 76 % |
| C1 — срез 310 с | 310 с | 0.97 | 0.66 | 0.46 с | 89 % |
| C2 — срез 310 с | 310 с | 0.97 | 0.47 | 0.71 с | 86 % |
| C3 — срез 317 с | 317 с | 0.90 | 0.33 | 0.51 с | 69 % |

Выводы, каждый — замер, не рассуждение:

- **Это не свойство файла и не свойства промта: это лотерея.** A и B — один и тот же звук, один
  и тот же промт, одна и та же модель. A сломан (55 с), B почти идеален (0.58 с).
- **`размах меток / длина среза` разделяет сломанное и здоровое с огромным запасом**: 0.69 против
  0.90–0.97. Считается из самого ответа — без оракула, без звука, без единого лишнего вызова.
  Числа для него уже собираются (`runSpeechDensity`: `markFromSec`, `markToSec`, `windowSec`).
- **Корреляция `r` как гейт НЕ ГОДИТСЯ**: 0.37 у сломанного A против 0.33 у здорового C3.
  На полном прод-прогоне она смотрелась убедительно (0.81 против 0.05), на отдельном прогоне —
  шум. (Проверено до того, как войти в код.)
- **Повтор лечит**: тот же вызов со второго раза дал 0.58 с медианы.
- **Короткие срезы стабильно здоровы** (3 из 3), точность та же, что у удачного длинного.

## 6. Восстановить тайминг из текста НЕЛЬЗЯ — тоже замер

Прежде чем предлагать «починим офлайн, без новых вызовов», проверены все дешёвые способы
(`try-repairs.js`, `vad-retime.js`, `anchor-spacing.js`; VAD — реальный звук, энергия кадров 25 мс,
порог по шумовому полу, 403 паузы):

| способ | медиана ошибки |
|---|---|
| как сейчас (метки модели) | 56.5 с |
| пропорционально символам внутри окна | 17.5 с |
| пропорционально словам | 20.0 с |
| линейное растяжение меток модели на окно | 43.7 с |
| доверять меткам, пока они коррелируют с текстом, дальше пропорционально | 14.3 с |
| VAD + постоянный темп речи по всему файлу | 51.0 с |
| честные якоря каждые 300 с + VAD-раскладка | 9.8 с |
| честные якоря каждые 120 с + VAD-раскладка | 5.5 с |
| честные якоря каждые 60 с + VAD-раскладка | 2.4 с (p90 8.0 с) |
| честные якоря каждые 30 с + VAD-раскладка | 1.1 с (p90 4.3 с) |

Никакая раскладка по объёму текста не даёт строчной точности: паузы и переменный темп речи
доминируют. **Точное караоке требует меток, ИЗМЕРЕННЫХ по звуку, а не выведенных из текста.**
Хорошая новость из §5: измеренные метки у модели уже есть — просто не в каждом прогоне.

## 7. Что из этого следует для кода

1. **Гейт `markSpan/windowSec` + `densityRatio` — на каждый чанк, до склейки.** Текст на месте,
   а метки занимают заметно меньше окна ⇒ часы сжаты. Порог по замеру: сломано 0.69, здорово
   ≥ 0.90. Отдельно от `findCoverageGaps` — тот требует разрыва, которого может не быть.
2. **Не прошёл гейт ⇒ переделать чанк** (по замеру §5 — либо повтор, либо разрезать на ~300 с).
   Платим только когда сломалось.
3. **Не вылечилось ⇒ караоке для этого диапазона ЧЕСТНО ВЫКЛЮЧИТЬ** (`timingDropReason`), а не
   «предупредить и всё равно подсветить». Это область R11, ради которой делались K1–K3.
4. **Один процесс на всех провайдеров.** Сегодня «строка → сегмент» строится тремя разными
   способами: `segment_index` (seg-режим Gemini), `source_line_index` (премиум K2),
   выравнивание по тексту (K3, сохранённые карточки). Первые два требуют строгого 1:1
   «строка = сегмент» и зависят от поля конкретного провайдера; третий не требует ничего от
   провайдера, работает 1:N и несёт собственный оракул. Кандидат на единственную опору — K3;
   индексы провайдера остаются перекрёстной проверкой, а не источником истины.

## Как воспроизвести

```bash
# оракул: пословные субтитры того же ролика (в репозиторий не кладём — тянутся за секунду)
yt-dlp --skip-download --write-auto-subs --sub-langs iw-orig --sub-format json3 \
       -f sb0 --ignore-no-formats-error -o "mia.%(ext)s" \
       "https://www.youtube.com/watch?v=y02xPRX6vCE"

node align-oracle.js      # карточка ↔ оракул: кривая ошибки (нужен экспорт карточки, см. README)
node try-repairs.js       # офлайн-стратегии починки по тексту
ffmpeg -i <mp3> -ac 1 -ar 16000 -f s16le mia.raw
node vad-retime.js        # VAD по реальному звуку
node anchor-spacing.js    # какой шаг честных якорей нужен для строчной точности
node probe-window1.js     # ЖИВЫЕ вызовы Gemini (тратит ключ, ~$0.10 за 5 вызовов)
node score-probes.js      # точность каждого живого прогона против оракула
```
