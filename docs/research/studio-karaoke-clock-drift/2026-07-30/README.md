# studio-karaoke-clock-drift · 2026-07-30

**Что это.** Разбор дефекта «караоke родного аудио уезжает» на карточке владельца
«Заложница Миа. Интервью» и замеры, на которых строится решение.
**Читать:** [`FINDINGS.md`](FINDINGS.md) — весь диагноз с числами. Остальное — воспроизводимость.

**Источник кода:** ветка `main`, commit `3c23a1db` (прод-версия карточки — `3.11.268`).

## Входы, которых здесь НЕТ (и почему)

- **mp3 владельца** (43 МБ) — личный/чужой контент, в репозиторий не кладём. Скрипты берут его по
  пути в `Downloads`; sha256 в `FINDINGS.md` §1 фиксирует, какой именно файл замерялся.
- **`mia.raw`** (58 МБ PCM) — производное от mp3, делается одной командой ffmpeg (см. `FINDINGS.md`).
- **`mia.iw-orig.json3`** (293 КБ, авто-субтитры YouTube) — внешний оракул, тянется одной командой
  `yt-dlp` (см. `FINDINGS.md`); не наш контент, поэтому не коммитим.
- **экспорт карточки** `text-card-заложница-миа-интервью.json` — личный текст владельца.
- **тексты сегментов в `probe-results.json`** заменены плейсхолдерами `w0 w1 …`: это транскрипт
  чужого вещания, публиковать его мы не вправе. Всё, на чём стоит вердикт детектора (метки и
  ЧИСЛО слов на сегмент), сохранено дословно, поэтому `verify-detector.js` воспроизводится
  как есть; `score-probes.js` (сверка с субтитрами) требует настоящих текстов — перезапустите
  `probe-window1.js` (5 вызовов, ≈$0.10).

Скрипты ожидают эти файлы рядом с собой (или по абсолютным путям, прописанным сверху каждого
скрипта). Ничего из них редактировать не нужно — это измерительный стенд, а не рабочие материалы.

**Вылеченная карточка** (`text-card-заложница-миа-интервью-healed.json`) — личный текст
владельца, поэтому лежит рядом с оригиналом в `Downloads`, а не в репозитории. Регенерируется
`node heal-card.js`. Что именно решено на основе этих замеров — канон
`docs/planning/STUDIO_ASR_CLOCK_COMPRESSION_S12_7_2026_07_30.md`.

## Стоимость живой пробы

`probe-window1.js` сделал 5 вызовов Gemini (2 × ~937 с + 3 × ~310 с аудио) ≈ **$0.10**
по ключу `GEMINI_API_KEY` из `.env`. Прогон резюмируемый: результаты лежат в `probe-results.json`,
повторный запуск ничего не перезапрашивает.
