# Восстановление production после повторной доставки завершённого деплоя

Дата: 2026-10-22. Исходный commit приложения: `bf4af1b324b5344dfbf840f3ababb587d33a8eee`, версия `3.11.805`. Статус: production восстановлен, защитный hotfix Coolify установлен и проверен.

## Причина и доказательства

- До восстановления `/healthz` возвращал HTTP 503, тело `no available server`. В Docker отсутствовал контейнер приложения; прежний образ и том данных сохранились. Остальные сервисы работали, диск имел 7,3 ГБ свободного места. OOM в доступном журнале ядра за двое суток не найден.
- Деплой Coolify `pnvz0lgzc1f8z3kj65fc29pp` (queue row 2886) стартовал 2026-10-20 23:49:24 UTC и успешно закончился в 23:52:53 UTC.
- 2026-10-21 23:49:26–27 UTC повторно доставленная `ApplicationDeploymentJob` завершилась `MaxAttemptsExceededException`. Redis `retry_after=86400`, job `tries=1`; интервал согласуется с повторной доставкой через сутки.
- Сохранённые строки этого деплоя прямо содержат `Deployment failed: ... attempted too many times` и `Deployment failed. Removing the new version of your application.` Журнал Docker фиксирует остановку контейнера в ту же секунду. Запись деплоя осталась `finished`.
- В Coolify 4.1.1 `failed()` продолжал удаление контейнера после `failDeployment()`, хотя переход статуса завершённого деплоя уже был отклонён. Это подтверждённая причина удаления работающего приложения. Почему исходная доставка не была окончательно подтверждена очереди, доступные данные не устанавливают.

## Исправление

1. Приложение восстановлено командой `docker compose up -d --no-build --pull never` из конфигурации последнего деплоя. Использованы существующий образ и прежний том; сборки, смены версии, очистки данных или восстановления старого backup не было.
2. В `App\Jobs\ApplicationDeploymentJob::failed()` перед любыми побочными эффектами добавлены `refresh()` записи и немедленный выход при статусе `FINISHED`. Обработка действительно незавершённых/ошибочных деплоев сохранена.
3. PHP синтаксис проверен. Реальный вызов `failed(new MaxAttemptsExceededException(...))` для завершённой записи 2886 прошёл: статус и SHA-256 логов не изменились, контейнер остался running с тем же ID и нулём рестартов. Тест не создавал учебных событий или записей owner-профиля.
4. Horizon завершён штатной командой `horizon:terminate` и автоматически поднят менеджером процессов; последующая проверка подтвердила `Horizon is running`. Очередь high: pending/reserved/delayed = 0/0/0.
5. На хосте сохранены исходник, исправленный файл и идемпотентный startup hook в `/opt/linguistpro-ops/coolify-finished-deployment-guard-20261022/`. В поддерживаемом `docker-compose.custom.yml` Coolify добавлено подключение hook в `/etc/entrypoint.d/40-finished-deployment-guard.sh` для будущего пересоздания контейнера. Текущий контейнер исправлен непосредственно; пересоздание панели для проверки mount не выполнялось.
6. Hook проверен в отдельном одноразовом контейнере того же образа без сети, секретов и томов приложения: первое применение установило защиту, второе подтвердило идемпотентность; PHP lint прошёл. Объединённая compose-конфигурация прошла `config --quiet`.

Защита ограничена точным SHA-256 исходника Coolify: original `5e19df3a633b397f4c2ad56e9404d54e85476c19ae24b3114032e4ac641cc8b9`, patched `5528c174724e5d96b38b186d2fce729f5bbfe12567abc8f9965e965f83aa9815`. Для незнакомого исходника hook пишет предупреждение и ничего не переписывает. Обновление Coolify требует проверки upstream-исправления или адаптации защиты; см. O-120.

## Production acceptance

- Три запроса без кэша 2026-10-22 18:55:38 UTC: HTTP 200, `ok=true`, `db.ready=true`, `migrations.ready=true`, uptime 277 секунд.
- `/api/client-config`: HTTP 200, версия `3.11.805`.
- `/api/mediatheque`: HTTP 200, revision 215, 78 материалов, 17 категорий, 34 подборки.
- В настоящем Chrome через Kapture загрузились общедоступные карточки медиатеки, включая подборку «Хаммам» с пятью материалами. Учебные статусы, отзывы и прогресс диагностикой не менялись.
- После обновления вкладки Coolify доступны `Redeploy`, `Restart`, `Stop`; runtime приложения восстановлен.
- Диск: health сообщает 81% и `disk_warn=true`. Это существующий риск O-055, а не доказанная причина текущей остановки. Очистка в этой сессии не выполнялась.

Откат только hotfix: убрать custom mount, вернуть сохранённый original PHP-файл и штатно перезапустить Horizon. Рабочий контейнер LinguistPro и том данных при этом не трогать. Откат возвращает подтверждённую уязвимость к повторному failure callback.
