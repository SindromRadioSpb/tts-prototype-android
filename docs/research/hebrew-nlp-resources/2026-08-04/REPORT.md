Оси оценки владельца: **УЦ** учебная ценность · **Ц** целесообразность · **П** приоритетность · **А** актуальность (1–5).

## 0. TL;DR — главные выводы

1. **L4-выбор инструментов в целом подтверждён, но с критической оговоркой:** у MADLAD-400-10B
   **нет ни одного опубликованного he→ru замера** — превосходство текущего выбора над
   880-МБ **CPU**-моделью OPUS-MT heb-sla (опубл. chrF 0.503, CC-BY) не доказано. Никуд
   (DictaBERT-menaked) — без локальных конкурентов. Для S6-alignment рабочие пути —
   stable-ts (наш же Whisper) и WhisperX; MFA — тупик. **Следствие: L4 обязан начинаться
   с локального бенчмарка** (уже в духе R10 и L0-прецедента), и CPU-путь перевода может
   освободить эксклюзивный GPU-слот целиком.
2. **Shironet-корпус (15K песен) хостить нельзя** — CC BY-SA датасета не лицензирует сами
   тексты (license laundering; Shironet легален только потому, что платит ACUM за просмотры).
   Легальные пути к песням: user-import (уже работает, 0 кода) + snippet-каталог («цитата» §19)
   + дешёвый PD-песенный слой поверх уже имеющегося корпуса (Рахель/Бялик/Черниховский).
3. **Каталоги дают немедленные quick wins для КАЧЕСТВА, а не только фичи:** человеческий
   UD/IAHLT-голд для tap-морфологии (закрывает нашу же R11-дыру «Dicta-silver судит Dicta»),
   standing ASR-голд ivrit.ai для S12-гейтов, частотные базы для SRS/читабельности,
   suffixed-verbs голд для литературного корпуса.
4. **Самые сильные новые направления** (не в roadmap): письмо с GEC-петлёй и картой ошибок
   **именно русскоязычных** (HELEECS RU-подкорпус), QA-генерация с независимым span-оракулом
   (dictabert-heq), частотная лестница читабельности поверх нашей FSRS-модели знаний,
   произношение/shadowing (через CTC-alignment, не MFA).
5. **Системная лакуна: he↔ru.** В национальных каталогах нет ни одного he↔ru параллельного
   корпуса/MT-модели — наша пара уникальна и обслуживается только «внешними» ресурсами
   (OPUS/NLLB/MADLAD, OpenSubtitles he-ru, word2word). Это и риск (нет готового голда),
   и моат (никто в экосистеме эту пару не обслуживает).

устраняет весь класс подделанных меток S12.5/S12.7 (тот же урок: LLM-координаты ≠ оракул).

**Расхождение агентов (зафиксировано честно):** агент E предлагал произношение через «MFA
Hebrew pretrained»; агент B проверил официальный индекс mfa-models — иврита там **нет**
(источник E — Medium-гайд). Направление «произношение» остаётся жизнеспособным, но на
WhisperX/CTC-alignment, не на MFA.

## 3. Кейс Shironet и песенный слой

Полный разбор: `raw/agent-c-shironet.md`.

- Датасет идентифицирован (Kaggle, 2022, 4.1 МБ CSV, не обновлялся). Формат — «мешок слов»
  (words list, без пунктуации и, вероятно, без строк) — **даже технически не годится для
  чтения** без пере-скрейпа.
- **Право:** CC BY-SA компилятора не лицензирует тексты (у скрейпера нет прав). Публичный
  хостинг полных текстов — не defensible даже некоммерчески (§19 факторы 3–4; ACUM).
  Личное изучение владельцем — defensible («private study» прямо в §19).
- **Оценки владельческих осей:** Shironet-как-корпус: УЦ 5 / Ц 1 / П 2 / А 5.
  Альтернатива «user-import + snippet-каталог»: УЦ 5 / Ц 4 / П 4 / А 5.
  Альтернатива «PD-песенный слой» (наш же корпус + Zemereshet как источник метаданных,
  не файлов): УЦ 3 / Ц 5 / П 4 / А 3.
- **Рекомендация синтеза:** песни — да, корпус-скрейп — нет. Путь: (1) тег «песня» + караоке
  от пользовательского аудио для PD-поэзии уже в Зале; (2) discovery-каталог современных
  песен со сниппетами-цитатами и ссылкой на Shironet, полный текст — только user-import.

## 5. Новые направления (агент E, топ-10 → синтез-топ-4 + watch)

Полный список: `raw/agent-e-greenfield.md`.

**Синтез-топ (сильные и осуществимые):**
1. **Письменная продукция (GEC-петля)** — УЦ 5/Ц 4/П 5/А 4. HELEECS с **RU-L1 подкорпусом**
   (research-access по запросу) + Hspell-детерминированный слой + LLM-классификация по
   эмпирической таксономии ошибок русскоязычных → error-profile → целевые FSRS-карточки.
   Закрывает целую SLA-модальность (output). R11: do-no-harm гейт обязателен.
2. **QA-генерация с независимым оракулом** — УЦ 5/Ц 5/П 4/А 4. LLM генерирует вопросы,
   dictabert-heq (0.2B, CC-BY) обязан извлечь ответ из текста — галлюцинированные вопросы
   отбрасываются by construction. Первый честный грейдер listening comprehension поверх
   караоке. Идеальное совпадение с R17.
3. **Частотная лестница читабельности** — УЦ 5/Ц 5/П 4/А 3. Lexical coverage любого текста
   против **персональной** FSRS-модели знаний (review_log!) — рекомендер «текст с покрытием
   95–98%». Детерминированная математика, 0 LLM-затрат (R16). Синергия с частотными базами
   из §4 (строка 3).
4. **Произношение/shadowing** — УЦ 5/Ц 3/П 4/А 5. Первый шаг к speaking-измерению, которого
   у продукта нет. Техпуть скорректирован: CTC-alignment (WhisperX/stable-ts), не MFA.
   Калибровочный порог против несправедливых оценок обязателен.

**Watch (ценно, но позже/по триггеру):** he-ru фразовый слой из OpenSubtitles (правовая
выжимка примеров, не редистрибуция); аллюзии/слои языка (Dicta Citation Finder — условия
API уточнить); кореференция «кто этот הוא» (IAHLT); словесные игры из due-слов (канал D1
в review_log с первого дня); DictaLM-3.0-24B-W4A16 как локальный LLM-кандидат (сначала
VRAM-замер); Hebrew LLM Leaderboard как основа выбора моделей per-задача.

**Отдельно — академическая кооперация (УЦ 3/Ц 4/П 2/А 5):** opt-in анонимизированный поток
ошибок RU-L1 ученика — вклад в HELEECS-линию и легитимный партнёрский канал для дипломной
работы владельца (OSF-преregistration уже есть). R15-инварианты (согласие, TTL, экспорт).

## 6. Моменты, которые владелец не обговаривал (страт+опер)

1. **«Некоммерческий» ≠ «свободный»:** NC-статус открывает CC-NC/research-ресурсы, но не
   лечит (а) чужой копирайт в scraped-данных, (б) copyleft (AGPL Hspell/wordlists нельзя
   бандлить в PWA — только server/audit-side), (в) custom ToU (NLI, JPress, Zemereshet),
   (г) различие «личное использование» vs «публичный прод-хостинг». В плане введён
   лицензионный чек-лист per-resource.
2. **Портфельная дисциплина:** master-plan 2026-07-25 прямо говорит «новые корпуса сейчас
   не добавлять; портфель перегружен» (§5.3), и evidence-долг + N=1 никуда не делись.
   Исследование НЕ отменяет это — оно даёт меню. Всё, что не quick-win внутри существующих
   эпиков, требует явного owner-решения о приоритете (см. план, D-решения).
3. **R10 measure-before-code повсюду:** каждый кандидат на замену/добавление модели получает
   в плане обязательный локальный бенчмарк с числовым гейтом до продуктизации.
4. **Бюджеты:** PWA офлайн-бандл (частоты/векторы — квантовать до единиц МБ, как
   Pealim-словарь), прод-диск 74% + открытый WAL-вопрос (новые корпуса — на том, не в git),
   VRAM-бюджет сайдкара (эксклюзивный слот; CPU-модели предпочтительнее GPU при равном
   качестве).
5. **Staleness/каденция:** каталоги живые (и местами битые) — в план заложен квартальный
   re-scan + пиннинг версий моделей (как ASR-пин) + фиксация лицензий на момент скачивания.
6. **he↔ru лакуна как моат:** экосистема пары не обслуживает; всё he↔ru — наша собственная
   добавленная стоимость. Это усиливает аргумент за собственный FLORES+in-domain голд-набор
   he↔ru (переиспользуемый для любых будущих MT/LLM-кандидатов).
7. **R17-заземление агентов:** HeQ/HebNLI дают внешние голды для грейдеров — «кто учит, не
   сертифицирует» получает измеримую основу.

## 8. Аддендум (follow-up 2026-08-04): HebArabNlpProject + систематический HF-свип

Два вопроса владельца после первого раунда: (1) полезна ли HF-организация
HebArabNlpProject; (2) не рискуем ли мы, ограничившись каталогами. Ответы —
двумя дополнительными агентами (raw: `agent-f-hebarabnlp-org.md`, `agent-g-hf-sweep.md`).

### 8.1 HebArabNlpProject — да, полезна (точечно)

Организация оказалась **HF-лицом самой национальной программы** (MAFAT/DDR&D + IAHLT;
среди участников — Shaltiel Shmidman из Dicta). 11 моделей + 17 датасетов; всё арабское
и Hebatron (31.6B — не влезает в 8GB и проигрывает Gemini на их же бенче) — мимо. Ценное:

- **shoshan** (MIT, 07.2026) — лемматизатор, который **не может выдумать лемму** by
  construction (выбор из банка 117.6K + ограниченный edit-script): 0.0% выдуманных форм
  против 12.3% у DictaBERT-lex на незнакомых словах; 92.4% OOD-точность. Это наш
  R1/R11-инвариант, машинно-энфорснутый → кандидат в **независимый оракул lemma-canon**
  (и возможный апгрейд лемматизации). Обязателен R10-аудит на литературном регистре
  Ben-Yehuda до внедрения (shoshan-data даёт паттерн харнесса).
- **AlephBench** (CC BY 4.0) — воспроизводимый ивритский LLM-бенчмарк (11 задач, 11 432
  промпта, замороженные выходы): независимо подтверждает наш облачный выбор
  (gemini-2.5-flash #1 = 88.8 > DictaLM-3.0-24B 85.2) и даёт готовый харнесс для любых
  будущих переоценок модели.
- **asmachta + abstractive-qa-llm-eval** (MIT / CC BY-SA) — grounded-QA грейдеры со
  строковой сверкой span-ов **без judge-модели** + намеренно безответные вопросы —
  turnkey-актив для R17-направления (QA-оракул, F2 плана).
- **Semantic-Retrieval победители** — ценна **рецептура, не веса** (у весов нет LICENSE):
  fine-tuned bge-m3 → bge-reranker two-stage даёт 97% качества ансамбля (nDCG@20 0.6525
  vs 0.6736) — измеренный рецепт для нашего направления семантического поиска.

Ядро стека не задето: ивритских ASR/wav2vec2, NER и чего-либо he↔ru в организации нет.

### 8.2 HF-свип — вопрос владельца был оправдан: каталоги отстают

Систематический срез (API-фильтры + именные поиски; заметка: `?language=he` HF-API
молча игнорирует — перепроверено `?filter=he`). Материальные дельты:

- **MT (меняет кандидат-лист L4.0a):** tencent **Hy-MT2-1.8B** (Apache-2.0, 05.2026,
  WMT-линия Hunyuan) — иврит И русский в официальном списке 33 языков; **первая маленькая
  открытая модель с претензией на прямой he↔ru**; влезает в 3070 с запасом. Плюс
  HPLT he↔en v2.0 (CPU-базлайн), тест-сеты **FLORES+** (поддерживаемый преемник
  FLORES-200) и **wmt24pp** (человеческие пост-редакции en→he_IL), reference-free
  метрика CometKiwi-DA.
- **Nikud (усиливает L4.0b):** TigreGotico/hebrew_diacritized_text — **5.3M огласованных
  предложений** (CC BY 4.0) — крупнейший открытый nikud-корпус; **dicta-onnx** (MIT) —
  ONNX-путь деплоя menaked без Python/torch; проект **renikud** (автор phonikud) — watchlist.
- **Гейты (усиливает Wave Q):** **microsoft/VibeVoice-ASR** (MIT, 694K скачиваний,
  60-минутное аудио одним проходом со спикерами и таймстемпами, иврит в списке) —
  независимая вторая ASR-гипотеза для кросс-чека чанкованного Whisper-пайплайна;
  **MMS forced aligner** (CC BY-NC → только gate-side) — независимый audio↔text
  тайминг-оракул, ровно паттерн «валидируй LLM-координаты независимым сигналом» из
  S12.5/S12.7; **SaT** (MIT) — сегментационный оракул.
- **TTS (обновляет L6-watch):** **Chatterbox Multilingual** (MIT, 2.5M скачиваний, иврит

### 8.3 Ответ на стратегический вопрос владельца

Ограничиться каталогами было бы ошибкой — свип это доказал (Hy-MT2, VibeVoice, 5.3M
nikud-корпус, Chatterbox — всё мимо каталогов). Но и «бесконечного исследования» не
нужно: решётка плана (бенчи L4.0 с числовыми гейтами, волны Q/F, лицензионный чек-лист,
квартальный re-scan) принимает новые находки дельтами. Свип закрыл главный временной
риск; дальше — плановая каденция: **квартальный re-scan = каталоги NNLP-IL + HF-срез +
Hebrew LLM Leaderboard + AlephBench** (теперь четыре источника вместо двух).
