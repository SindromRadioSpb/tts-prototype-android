# Новые направления программы LinguistPro из израильского Hebrew-NLP ландшафта
Дата ресёрча: 2026-08-04. Источники: NNLP-IL Hebrew-Resources, resources.nnlp-il.mafat.ai, IAHLT, Dicta, ivrit.ai, HF. Шкалы 1–5: **УЦ** учебная ценность · **Ц** целесообразность · **П** приоритетность · **А** актуальность ресурса.

---

## 1. Письменная продукция: мини-GEC-петля + карта ошибок русскоязычных

**Ресурсы:**
- **HELEECS — Hebrew Learner Essay Corpus** (LREC 2022): эссе изучающих иврит с аннотацией ошибок и target-hypotheses, **включая отдельный подкорпус L1=русский** — [paper](https://aclanthology.org/2022.lrec-1.598.pdf), [обзор методологии](https://cris.iucc.ac.il/en/publications/analyzing-learner-language-the-case-of-the-hebrew-learner-essay-c-2). Доступ: research-use по запросу у авторов.
- **Hspell** — свободный спелчекер/морфоанализатор — http://hspell.ivrix.org.il/ (GPL-семейство; + [HspellPy](https://github.com/eranroz/HspellPy/)).
- **«Штей шекель»** — вики-проект грамматических правок (готовые пары «ошибка→исправление», CC BY-SA) — [страница проекта](https://he.wikipedia.org/wiki/%D7%95%D7%99%D7%A7%D7%99%D7%A4%D7%93%D7%99%D7%94:%D7%AA%D7%97%D7%96%D7%95%D7%A7%D7%94/%D7%A9%D7%AA%D7%99_%D7%A9%D7%A7%D7%9C).

**Что получает ученик:** режим «Напиши сам»: после чтения/квиза пользователь пишет 1–3 предложения с due-словами; Hspell ловит орфографию офлайн, LLM-проверка (BYOK) классифицирует грамматические ошибки **по эмпирической таксономии ошибок именно русскоязычных** из HELEECS (предлоги, согласование рода, смешение биньянов), а не «вообще ошибок». Ошибки падают в личный error-profile и конвертируются в целевые FSRS-карточки. Продукт сейчас тренирует только рецепцию + reverse/dictate; свободная продукция — незакрытая модальность SLA (R2: output hypothesis).

**Почему сейчас:** MultiGEC-2025 покрыла 12 языков — **иврита там нет** ([shared task](https://spraakbanken.github.io/multigec-2025/)); HELEECS — фактически единственный аннотированный ресурс, и его RU-подкорпус будто создан под этот продукт.

**УЦ 5 · Ц 4 · П 5 · А 4.** Риск: HELEECS — по запросу, а LLM-корректор без детерминированного гейта (Hspell + таксономия) может «исправлять» верное — нужен R11-инвариант do-no-harm.

## 2. Генерация вопросов + честная оценка понимания прочитанного/услышанного

**Ресурсы:**
- **HeQ** — 30 147 вопросов SQuAD-формата (Википедия + Geektime), NNLP-IL — https://github.com/NNLP-IL/Hebrew-Question-Answering-Dataset (открытый).
- **dictabert-heq** — готовая экстрактивная QA-модель — https://huggingface.co/dicta-il/dictabert-heq (CC BY 4.0).
- **ParaShoot** — ещё 3K QA-пар — https://github.com/omrikeren/ParaShoot.

**Что получает ученик:** к любому импортированному тексту/ASR-транскрипту автогенерируются вопросы на понимание (LLM), но **каждый вопрос проходит независимый оракул**: dictabert-heq должен извлечь ответ из текста — неотвечаемые/галлюцинированные вопросы отбрасываются by construction (точно в духе R17 «кто учит — не сертифицирует» и урока про независимые оракулы). Для аудио — это первый настоящий грейдер listening comprehension: прослушал сегмент караоке → 2 вопроса → ответ свободным текстом → сверка span-оракулом.

**Почему сейчас:** вся инфраструктура (импорт, караоке, квиз-движок, D1-грейды) уже есть; не хватало ровно ивритской QA-модели-валидатора — она существует и маленькая (0.2B, влезает в локальный сайдкар).

**УЦ 5 · Ц 5 · П 4 · А 4.** Риск: экстрактивный оракул валидирует только фактоидные вопросы — инференционные вопросы останутся без независимой проверки (честно маркировать).

## 3. Частотно-обоснованная лестница читабельности: «какой текст мне сейчас по зубам»

**Ресурсы:**
- **The Word-Frequency Database for Printed Hebrew** — 554 270 типов / 620M токенов из 914 газетных выпусков — https://github.com/eranroz/BotMisparim (открытый GitHub).
- **wordfreq** (иврит включён) — https://pypi.org/project/wordfreq/ (MIT/Apache).
- **UD Hebrew IAHLTwiki / IAHLT-HTB** для синтаксической сложности — https://github.com/UniversalDependencies/UD_Hebrew-IAHLTwiki.

**Что получает ученик:** офлайн-скоринг всех ~26K работ Зала и любого импортированного текста: lexical coverage против **персональной** модели знаний (review_log уже хранит истину о памяти каждого слова!) + частотный профиль + длина клауз. Рекомендер «следующий текст с покрытием 95–98%» — золотой стандарт extensive-reading исследований (R2/R8). Сейчас scaffolding адаптивен внутри текста, но выбор текста — ручной; это закрывает главный тупик «26 тысяч работ — с чего начать».

**Почему сейчас:** уникальное преимущество продукта — точная модель знаний ученика уже существует (FSRS + lemma-canon); coverage-расчёт — чистая детерминированная математика без LLM (R16: нулевая стоимость).

**УЦ 5 · Ц 5 · П 4 · А 3.** Риск: газетные частоты 1990–2000-х смещены против литературного корпуса Зала — нужна калибровка по самому корпусу Ben-Yehuda.

## 4. Произношение и shadowing: форс-алайнмент + GOP-скоринг

**Ресурсы:**
- **MFA Hebrew acoustic model + словарь** (Montreal Forced Aligner, pretrained, CC BY 4.0) — https://mfa-models.readthedocs.io/en/latest/, [гайд по ивриту](https://mim-armand.medium.com/montreal-forced-alignment-hebrew-de7bd4180d6a).
- **ivrit-ai/crowd-recital** — краудсорсные начитки Википедии с посентенсными таймстемпами (эталонное «прочитанное вслух») — https://huggingface.co/datasets/ivrit-ai/crowd-recital ([ivrit.ai license](https://www.ivrit.ai/en/the-license/), разрешает research+commercial).
- Уже стоящий в сайдкаре Whisper (ivrit-ai tuned) как второй сигнал.

**Что получает ученик:** режим shadowing в караоке: сегмент звучит (TTS/оригинал) → пользователь повторяет в микрофон → MFA выравнивает по фонемам → Goodness-of-Pronunciation по каждой фонеме + слову; проблемные для русскоязычных контрасты (ה/א/ע, ר, редукция гласных) подсвечиваются и попадают в error-profile. Продукт сейчас вообще не слышит ученика — это целое отсутствующее измерение (speaking), при том что ASR-стек локально уже развёрнут.

**Почему сейчас:** ivrit.ai в 2025 выложил >20k часов и обновлённые модели; MFA-модель иврита готова; GPU-сайдкар — точка встраивания без затрат на облако.

**УЦ 5 · Ц 3 · П 4 · А 5.** Риск: GOP на MFA чувствителен к качеству микрофона/акустики — без калибровочного порога легко скатиться в несправедливые оценки (анти-цель для мотивации).

## 5. Разговорный регистр: he↔ru параллельные субтитры как «фразовый слой»

**Ресурсы:**
- **OPUS OpenSubtitles v2018, пара he-ru** — выровненные предложения кино/ТВ-субтитров — https://opus.nlpl.eu/legacy/OpenSubtitles-v2018.php (свободно для research; сами субтитры — серая зона авторского права).
- **The HUJI Corpus of Spoken Hebrew** — естественная спонтанная речь с транскриптами — https://huji-corpus.com/.
- **IsraParlTweet** — 294.5M токенов Кнессет+твиты, регистр публичной полемики — https://github.com/guymorlan/IsraParlTweet.

**Что получает ученик:** для каждого изучаемого слова — кнопка «как это говорят»: 3–5 живых разговорных примеров из субтитров **с готовым русским переводом** (пара he-ru выровнена — перевод не надо генерировать и не надо верифицировать LLM-ом), с пометой регистра (разговорное/сленг/формальное). Весь контент продукта сейчас — литературный/новостной; разрыв «выучил из Бялика — не понял в маколете» реален, и параллельность именно с русским уникально дёшево его закрывает.

**Почему сейчас:** he-ru выравнивание уже сделано в OPUS (не надо строить); фильтрация мусора субтитров — детерминированный офлайн-пайплайн.

**УЦ 4 · Ц 4 · П 4 · А 3.** Риск: качество выравнивания OpenSubtitles шумное + правовой статус субтитров требует «выжимку примеров», а не редистрибуцию корпуса.

## 6. NER + граф знаний над Залом: карточки персон и мест в чтении

**Ресурсы:**
- **NEMO-Corpus / NEMO2** — NE-аннотации ивритского трибанка + нейромодели — https://github.com/OnlpLab/NEMO-Corpus, https://github.com/OnlpLab/NEMO.
- **HebSpacy** — пайплайн с 16 типами сущностей — https://github.com/8400TheHealthNetwork/HebSpacy (MIT).
- **KIMA — исторический газеттир иврита**: 27 239 мест, 94 650 вариантов написания, с координатами — http://data.geo-kima.org/.

**Что получает ученик:** тап по имени/топониму в Зале → карточка «кто это/где это»: KIMA даёт исторические варианты написания мест (критично для дореволюционной орфографии корпуса Ben-Yehuda) + мини-карта; сквозной индекс «этот персонаж встречался в трёх рассказах». Расширяет уже существующий моат «тап-морфология» на **сущностный** слой — то, чего нет ни у Pealim, ни у Reverso.

**Почему сейчас:** пайплайн бейка корпуса уже гоняет Dicta-морфологию по работам — NER-прогон встраивается в тот же конвейер; KIMA решает главную боль (вариативность исторических написаний) готовыми alternate-формами.

**УЦ 4 · Ц 4 · П 3 · А 4.** Риск: NER-модели тренированы на новостях/Кнессете — на литературе XIX века precision просядет; нужен R10-замер до кода.

## 7. Диахронная глубина: карточки аллюзий и исторических слоёв языка

**Ресурсы:**
- **Dicta Citation Finder** — находит точные и приблизительные цитаты из Танаха/Талмуда в произвольном тексте — [обзор инструментов Dicta](https://www.eurojewishstudies.org/digital-forum-showcase-reports/dicta-the-israel-center-for-text-analysis/), https://dicta.org.il.
- **Sefaria-Export** — 3000 лет еврейских текстов с переводами, пер-текстовые открытые лицензии — https://github.com/Sefaria/Sefaria-Export/.
- **BEREL** (Dicta, раввинистический иврит) — https://huggingface.co/dicta-il (BEREL-seg, pre-BEREL); **ETCBC BHSA / Text-Fabric** — полная морфология Танаха — https://annotation.github.io/text-fabric/tf/ (CC BY-NC).

**Что получает ученик:** литературный канон Зала (Бялик, Агнон, Мендele) насыщен библейско-талмудическими аллюзиями, которые для русскоязычного невидимы. Тап по фразе → «это цитата из Йешаяу 40:3» + огласованный стих + перевод из Sefaria; бейдж слоя языка на слове («мишнаитское», «библейское») объясняет, почему слово не находится в современном словаре. Провенанс-этика продукта (derived≠asserted, R9) идеально ложится на цитатные карточки.

**Почему сейчас:** это единственный ландшафт в мире, где инструменты интертекстуальности иврита существуют production-grade (Dicta) — и продукт уже интегрирован с Dicta-стеком.

**УЦ 4 · Ц 3 · П 3 · А 5.** Риск: условия программного использования Citation Finder не опубликованы явно — нужен контакт с Dicta (у проекта уже есть рабочие отношения с их API).

## 8. Кореференция как учебный аид: «кто этот הוא?»

**Ресурсы:**
- **IAHLT coref** — открытые кореференс-данные для иврита — https://github.com/IAHLT/coref + тулкит https://github.com/IAHLT/iahlt_coref_he (условия IAHLT, открыто).
- Свежий бенчмарк: [«Beyond Word Boundaries: A Hebrew Coreference Benchmark…» (2026)](https://arxiv.org/pdf/2604.17108) — задача активно жива.

**Что получает ученик:** в Зале тап по местоимению/суффиксальной форме → подсветка цепочки антецедентов («הוא = ר' יהודה из первого абзаца»). Для иврита это острее, чем для европейских языков: кореференция прячется в **клитиках** (ראיתיו), которые продукт уже сегментирует Dicta-стемом. Побочный выигрыш: клоз-квизы перестают резать местоимения с неоднозначным референтом (повышение качества существующей модальности).

**Почему сейчас:** IAHLT выложила и данные, и тулкит; бенчмарк-2026 показывает зрелость задачи именно для морфологически сложного текста.

**УЦ 4 · Ц 3 · П 3 · А 5.** Риск: качество кореференс-моделей на литературном (не новостном) тексте не измерено — обязательный R10-аудит на выборке Зала до продуктизации.

## 9. Генератор словесных игр: кроссворды, шорэш-паззлы, никуд-Wordle

**Ресурсы:**
- **hebrew_wordlists** (извлечены из Hspell) — https://github.com/eyaler/hebrew_wordlists (Hspell-происхождение → GPL-семейство, проверить при бандлинге).
- **Word-Frequency Database** — https://github.com/eranroz/BotMisparim (частоты для калибровки сложности).
- Собственный офлайн-словарь парадигм продукта (9 279 парадигм) как источник клеток «спрягите корень».

**Что получает ученик:** ежедневная мини-игра из **его собственных due-слов**: кроссворд с определениями-глоссами, «собери 4 слова одного корня», Wordle с никудом. Полностью офлайн-генерация (R16: ноль LLM-затрат), низкострессовый retrieval-канал поверх FSRS — разгружает монотонность квизов, а score = обычный review-грейд в review_log.

**Почему сейчас:** все данные уже на устройстве; генератор кроссвордов на 5-буквенной сетке — задача выходного дня; частотная БД даёт честную шкалу сложности.

**УЦ 3 · Ц 5 · П 3 · А 4.** Риск: игровая модальность без channel-aware грейда (D1) может загрязнить FSRS-статистику — маркировать канал в review_log с первого дня.

## 10. Внешнее бенчмарк-заземление + научная кооперация

**Ресурсы:**
- **Hebrew LLM Leaderboard** (DDR&D/NNLP-IL + Dicta + Webiks): задачи включают **никуд, перевод, суммаризацию** — https://huggingface.co/spaces/hebrew-llm-leaderboard/leaderboard, [анонс](https://huggingface.co/blog/leaderboard-hebrew).
- **DictaLM 3.0 24B** — суверенная ивритская LLM, включая quantized-варианты — [paper](https://arxiv.org/pdf/2602.02104), https://huggingface.co/dicta-il.

**Что получает ученик (опосредованно):** (а) выбор модели под каждую LLM-задачу продукта (перевод таблиц, никуд, QG) делается по опубликованным ивритским метрикам, а не «Gemini потому что привычно» — прямой R16/R11-выигрыш; (б) DictaLM-3.0-24B-W4A16 — кандидат в локальный GPU-сайдкар как офлайн-фолбэк LLM-функций; (в) канал в NNLP-IL/HELEECS-группу: анонимизированный (R15, opt-in) поток ошибок русскоязычного ученика — вклад в единственный в мире RU-L1 ивритский learner-ресурс и легитимный академический партнёр для дипломной линии владельца.

**Почему сейчас:** лидерборд активен, DictaLM 3.0 вышла (2026) — впервые есть ивритская модель уровня, сопоставимого с облачными, в открытых весах.

**УЦ 3 · Ц 4 · П 2 · А 5.** Риск: 24B даже в W4A16 может не влезть в текущий GPU-бюджет сайдкара — сначала замер, потом обещания.

## Соблазнительно, но слабо (пропустить)

1. **Детский/YA graded-контент из открытых корпусов** — современная детская литература на иврите под копирайтом; открытого корпуса нет, а детский раздел Ben-Yehuda уже в Зале — новый ресурс ничего не добавляет.
2. **Караоке-обучение по песням Широнета** ([Kaggle, 15K песен](https://www.kaggle.com/datasets/guybarash/hebrew-songs-lyrics)) — учебно заманчиво, но лирика целиком под копирайтом; скрейпнутый датасет нельзя ни шипить, ни показывать.
3. **Распознавание рукописного ввода для тренировки письма от руки** ([HebHTR](https://github.com/Lotemn102/HebHTR)) — одиночный студенческий проект без бенчмарка точности; риск несправедливого грейда выше пользы.
4. **Семантические карты слов через Hebrew WordNet** ([MILA](http://www.mila.cs.technion.ac.il/resources_lexicons_wordnet.html)) — сайт MILA «temporarily down» длительно, ресурс 2000-х, покрытие устарело; связи корней продукт уже даёт лучше через собственный словарь.
5. **Упрощение новостей до «лёгкого иврита»** — открытого ивритского корпуса упрощения не существует (проверено: только Newsela-EN и SAMER-AR аналоги); «лёгкие» газеты (Yanshuf и пр.) коммерческие. LLM-упрощение без параллельного корпуса = неверифицируемый выход против R11. Частично закрывается направлением №3 (подбор текста по уровню вместо переписывания текста).
