# יוֹפִי: разбор, альтернативы и объект статуса

2026-10-20. Follow-up владельца после 3.11.800. Проверены открытая production-карта через Kapture,
runtime engine и код `32204e7c`; диагностика без нажатия подтверждения имени/статусов/сохранения.
Это анализ и предлагаемые требования, не реализованное исправление.

## Подтверждённые факты

Четвёртая строка `בְּסֵדֶר, יוֹפִי.`, word offset 1. AI gloss собственного вхождения: «отлично».
Источник огласовки поля: OpenAI assistant, указан в архиве.

В локальном runtime dataset уже есть обе записи Pealim:

| ID | Часть речи | Значение | Данные форм |
|---|---|---|---|
| 5856 | noun | красота | ячейки, в том числе `יֹפִי` |
| 5857 | adverb | отлично! замечательно! | cells пустой, запись и значение присутствуют |

Публичные первоисточники: [5856](https://www.pealim.com/ru/dict/5856-yofi/), [5857](https://www.pealim.com/ru/dict/5857-yofi/).
Наличие обоих вариантов подтверждено в браузере; технической необходимости переходить на сайт, чтобы вообще увидеть их, нет.

Воспроизведение через ReaderMorph:

- `resolveOffline(engine, 'יופי', 'יוֹפִי')` → guessed / meaning-fallback, «красота», без ID и POS;
- `resolveCore` с локальным Dicta → label=dicta, lemma=יפי, pos=noun, meaning пусто, alts=[];
- Dicta-лексикон написания имеет amb=true, altN=8: это свёртка текстов устройства, не независимый вердикт по данному месту;
- для формы `יֹפִי` получается exact / noun / 5856 / «красота», без альтернатив: варианты написания меняют путь, а совпадение формы не доказывает однозначность значения;
- fallback Dicta очищает alts и meaning; заголовочная метка осталась вне свёрнутого блока разбора;
- PealimFunctionLinks.lookup('יופי','noun',...) возвращает adverb/5857 как POS-mismatched fallback;
- resolveWordLight получает внутренне противоречивую карту: pos=noun, pealim_id=5857, meaning пусто. По ambiguous ссылка в UI понижается до поиска;
- lemmaKey остаётся `dl:יפי#noun`, поскольку label=dicta приоритетно использует dictaKey. То же подтверждено с точным sentence place/offset 1.

На момент проверки сохранённой отметки по этому ключу нет. Кнопки статуса доступны.
При нажатии статус будет записан для этой лексической сущности, не для gloss «отлично» и не только для текущего вхождения.
onStatusSet → MorphHost.markWordStatus → local-db.setWordStatus; отметка журналируется как kind=mark,
а уровни l1–l4 могут дать первоначальный FSRS seed, если расписания ещё нет. Это не оценка ответа grade.
Сама строка значения не является ключом знания; выбранные словарные записи одного написания должны различаться.

Кнопка «Это имя здесь» появляется для любого неподтверждённого AI occurrence с sentence_id и callback;
проверки, что именно имя здесь является релевантной гипотезой, нет. Это общее действие коррекции,
но его видимость рядом с «отлично» выглядит как рекомендация. На скриншоте первый шаг раскрыт владельцем;
диагностика не нажимала окончательное подтверждение.

## Требуемое поведение — предложение

1. **Каждое утверждение имеет область и источник.** В заголовке слово; в блоке «В этой строке» контекстный перевод и статус проверки. Источник огласовки относится к огласовке. Метка Dicta располагается внутри конкретного анализа с его леммой/POS, не над всей картой.
2. **Кандидаты сохраняются.** Показать обе локальные статьи с POS, значением, источником и прямой ссылкой. Отсутствие таблицы форм у наречия не означает отсутствия статьи. Различия יוֹפִי/יֹפִי не должны скрывать реальные варианты; нормализация ограничена подтверждённой орфографической эквивалентностью и не сливает омографы.
3. **Согласованный объект анализа.** Нельзя сочетать noun из Dicta с ID наречия Pealim. Источник/лемма/POS/значение/ID/таблица должны принадлежать одному кандидату. Общий спорный Dicta-лексикон не выдаётся за проверку контекста предложения.
4. **Общая коррекция чтения.** «Уточнить значение здесь» открывает кандидаты и отдельный вариант «Имя собственное». Выбор значения сохраняет anchored occurrence decision существующим каноническим путём. AI gloss не превращается автоматически в подтверждённую POS или owner decision.
5. **Явный объект знания.** Перед статусами показывать, например, «Мой статус: יוֹפִי — отлично! замечательно! · наречие». Статус относится к выбранной лексической записи на всех поверхностях; существительное «красота» — отдельная запись. Пока конфликт не разрешён, не разрешать молча оценивать другую сущность под видимым AI gloss; дать выбор на месте. Значения внутри одной статьи — отдельная продуктовая задача, текущий lemma-key не является sense-ID.
6. **Сохранение истории.** Выбор чтения не переносит молча старые mark/review/FSRS. Новое корректное чтение использует собственную идентичность; старые события сохранены, возможное связывание/перенос требует отдельного обоснованного решения. Правка gloss не равна отметке знания и не равна разрешению морфологической неоднозначности.

## Приёмка предлагаемого исправления

- Исходный יוֹפִי и вариант יֹפִי: оба кандидата видны, нет ложной однозначности; слова без cells участвуют в выборе.
- Выбор 5857: едины POS, значение, ссылка и объект статуса; выбор 5856 даёт самостоятельный объект.
- Повторное открытие, plain/niqqud колонка, Studio/Room/«Мой словарь», экспорт/импорт и отложенный Dicta согласованы.
- Само открытие/просмотр кандидатов не пишет статус, lexical decision, grade или FSRS.
- Статус/повтор пишется каноническим путём только для явно указанного объекта; старые события не переписываются.
- Проверены имя שאול, неизвестное слово, несколько одноимённых статей и 380 px/RTL; проверки не ограничены единственным יוֹפִי.

Связанные наблюдения: O-111–O-114. Предыдущая приёмка 3.11.800 подтверждает архивные источники и gloss,
но не доказывает полноту морфологической идентичности/выбора для каждого из 2193 слов.
