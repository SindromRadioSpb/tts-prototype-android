# S12 «Длинные медиа» — замеры до кода (R10 measure-before-code)

**Дата:** 2026-07-28 · **Слайс:** W2-S12 (chunked-таблица, снятие капа 20 минут)
**Канон-контекст:** `docs/planning/STUDIO_INGEST_MULTIMODAL_DECISION_PACKET_2026_07_25.md` §4 п.8
**Статус файлов:** результаты замеров = raw (не редактировать); README = итоговый отчёт.

Все LLM-вызовы — реальный ключ Gemini (`gemini-flash-latest`, как в проде), Node-скрипты в этой папке.
Аудио-материал: реальные иврит-подкасты («עושים טכנולוגיה», Spreaker CDN, публичный RSS);
файлы MP3 НЕ коммитятся (см. скрипт `m3-long-asr.js` — URL внутри).

## Главные выводы

1. **Стена одного вызова `/api/translate-table` — подтверждена и замерена: ~287 строк.**
   `outputTokenLimit` модели = 65 536 (архитектурный, поднять нельзя), реальный расход
   ≈ **205–220 выходных токенов на строку таблицы** (иврит + огласовки очень токеноёмки).
   N=400 сегментов → `finishReason: MAX_TOKENS`, JSON оборван на строке ~287, parse-fail,
   **потеря всей работы после 270 с ожидания**. Значит **текущий кап 400 сегментов УЖЕ за
   стеной** — 30-минутные субтитры (~400+ строк после слияния) падают сегодня, это латентный
   прод-баг, а не только «потолок для двухчасовых подкастов». S5a-тест на 267 строках прошёл
   на 84% лимита — на волоске.
2. **Безопасный кусок: 120–150 сегментов** (≈26–33k выходных токенов, ~2× запас до лимита).
   Скорость генерации ≈ 210–250 ток/с → **~2–2.5 мин на кусок**.
3. **renderTable виртуализация НЕ нужна; сам renderTable можно не трогать.**
   Полная перерисовка на троттлинге CPU 6× (аппроксимация телефона), viewport 380×844:
   1700 строк ≈ 350 мс, 3000 строк ≈ 600 мс. Прогрессив = повторный вызов
   `renderTable(накопленный префикс)` после каждого куска: худший кадр 350–600 мс раз в
   ~2 минуты — приемлемо, byte-parity гейт `smoke:reader-parity` не задевается вообще.
4. **ASR одним вызовом на длинных файлах — НЕЧЕСТЕН и упирается в ту же стену. Чанковать
   надо и ASR (окна ~10–20 мин), не только таблицу.** Два замера:
   - *75 мин, «успех»:* один вызов, 139 с, 360 сегментов, JSON цел, `timingOk: true`,
     warnings пусты — а модель **молча выбросила ~31 минуту середины** (скачок тайминга
     31:46 → 63:00 между соседними сегментами). Без проверки покрытия это ушло бы
     пользователю как честный транскрипт — R11-нарушение, невидимое всем существующим
     валидаторам (они проверяют монотонность, не непрерывность).
   - *~2.4 ч (склейка двух эпизодов, 215 МБ):* `finishReason: MAX_TOKENS` — candidates
     29 161 + **thinking 36 371 = 65 532 ≈ лимит 65 536** (мысле-токены делят бюджет вывода
     с ответом!), JSON оборван на 73-й минуте, вся работа потеряна, 287 с впустую.
   Клиентский таймаут ASR 180 с (`gemini-files.js`) при окнах ~15 мин остаётся достаточным.
5. **Плотность строк уточнена:** реальный подкаст-монолог ≈ **4.8 сегм/мин** (в каноне было
   ~8 — то была короткая запись); субтитры после слияния ≈ 11–14 строк/мин (TED-фикстура 218
   строк / 19 мин). Для смет: 2 ч подкаста ≈ 550–950 строк; 2 ч субтитров ≈ 1400–1700 строк.

## M1 — профиль renderTable (`m1-rendertable-profile.js`)

Локальный сервер + Playwright Chromium headless, CDP CPU throttle 6×, viewport 380×844.
Строки синтетические (иврит + полные огласовки + транслит + русский, worst-case длины).

| Строк | Полная отрисовка (settled) | DOM-узлов | Прогрессив по 150: total | худший кусок |
|------:|---------------------------:|----------:|-------------------------:|-------------:|
|  400  | 147 мс | 3 620 | 755 мс | 511 мс |
|  800  | 184 мс | 7 220 | 718 мс | 183 мс |
| 1700  | 347 мс | 15 320 | 2 551 мс | 352 мс |
| 3000  | 598 мс | 27 020 | 6 432 мс | 599 мс |

«Прогрессив total» — сумма ВСЕХ перерисовок префиксами; в реальности они размазаны по
минутам прихода кусков. Худший единичный кадр — то, что почувствует палец.

## M3 — длинный ASR (`m3-long-asr.js`)

Реальный подкаст, Files API resumable upload из Node (тот же протокол, что `gemini-files.js`).

- **75 мин (108 МБ):** upload 12 с, ACTIVE мгновенно, ASR **139 с**, STOP, 360 сегментов,
  360/360 валидных стартов, `timingOk: true`. Вход 70 882 аудио-токена, выход 20 100
  (+16 697 thinking). Стоимость ≈ $0.16. **Дефект: молчаливая дыра покрытия 31:46 → 63:00**
  (~31 мин контента отсутствует; warnings пусты). Плотность там, где покрыто: ~7–12 с/сегмент.
  Первый прогон той же фазы дал `ASR_BAD_JSON` (недетерминизм на длинном выводе; частично
  скомпрометирован UTF-8-багом самого замер-скрипта) — прод-повтор «1 retry» остаётся нужным.
- **~2.4 ч склейка (215 МБ):** upload 21 с, ACTIVE мгновенно, 287 с генерации →
  **MAX_TOKENS, оборванный JSON, потеря всего** (вход 140 945 аудио-токенов; выход
  29 161 + thinking 36 371 = впритык к 65 536). Одновызовный ASR для длинных файлов невозможен.
- **range-промт на пропавшем окне 32:00–40:00 — механизм чанк-ASR ПОДТВЕРЖДЁН:** «transcribe
  ONLY 32:00–40:00 … timestamps ABSOLUTE» → 21 с, 35 сегментов, firstStart=1920 (ровно 32:00),
  lastStart=2386, метки абсолютные, контент из дыры восстановлен. Вход почти весь из
  implicit-кэша (63 743 из 70 882 аудио-токенов) → повторные вызовы по одному fileUri дёшевы.
- **clip-проба `video_metadata.start/end_offset` на аудио — НЕ РАБОТАЕТ:** оффсеты
  проигнорированы, модель транскрибировала файл с 0:00 (вход 71 131 ток. = весь файл).
  Попутно этот прогон дал ещё одно свидетельство ненадёжности одновызовного ASR: 427
  сегментов, покрытие только до 47:35 из 74:48 при `finishReason: STOP`.
- Сырые транскрипты (`m3-raw-*.txt`) НЕ коммитятся: контент подкастов не наш (репо готовится
  к публичности), числа сняты в этот README; повторить — `node m3-long-asr.js <фаза>`.
- Попутно: implicit-кэширование Gemini работает и для АУДИО-входа (повторный вызов по тому же
  fileUri: 63 799 из 70 882 аудио-токенов закэшированы) — повторные/диапазонные вызовы по
  одному файлу дешевле по входу.

## Численная модель для смет (R16)

- Таблица: **~220 out-ток/строка** × $2.50/M → **~$0.055 на 100 строк**; вход ~35 ток/сегм × $0.30/M — копейки.
- ASR: вход ≈ 945 аудио-ток/мин × $1.00/M; выход (с thinking) ≈ 490 ток/мин × $2.50/M → **~$0.13/час аудио**... (уточнено: 75-мин прогон = $0.16 → **~$0.13/ч вход + выход ≈ $0.13/ч** → итого ≈ $0.13–0.16/час).
- Ориентиры полного цикла: **2 ч подкаста ≈ $0.30 (ASR) + $0.35–0.55 (таблица) ≈ $0.7–0.9**;
  **2 ч субтитров ≈ $0.8–0.95** (только таблица). Время: первые строки через ~2 мин после
  старта таблицы, полная таблица 2-часовых субтитров последовательно ≈ 25–30 мин.
