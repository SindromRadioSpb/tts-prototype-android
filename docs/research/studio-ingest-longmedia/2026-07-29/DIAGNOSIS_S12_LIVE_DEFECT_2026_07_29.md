# Диагноз живого брака S12.x — прогон владельца 117-мин аудио (2026-07-29)

**Что это:** результат диагностической сессии по браку, пережившему три фикс-слайса
(S12.2/S12.3/S12.4). Анализ структуры бракованного транскрипта владельца против
исходных YouTube-субтитров того же видео. Только числа и методика — личный контент
(семейное интервью) в репо не попадает.

**Как получено:** шингл-матчинг (4 нормализованных слова) строк транскрипта к
тайм-меченым субтитрам источника → карта «позиция в транскрипте → минута источника».
Скрипты: сессионный scratchpad (`dup-structure.js`, `replay-runs.js`, `trajectory.js`,
`segments-map.js`) — одноразовые, воспроизводятся по описанию ниже. Исходные артефакты —
локально у владельца (Downloads + scratchpad сессии 86f17baf). Код на момент анализа:
прод v3.11.264, ветка main 3e179954.

**Статус:** диагноз ЗАКРЫТ (артефакты + live-провенанс вкладки, §6–§8). H1/H3 отвергнуты,
корневая причина установлена (§7).

## 2. Ключевые факты

- **«Обрыв на 66-й минуте» — иллюзия.** Реальное покрытие: 0→53:23 и 65:14→73:24
  (максимальный единичный матч ~82 мин). Хвост 76–117 мин отсутствует ПОЛНОСТЬЮ.
  Итоговая потеря таймлайна ≈47%. Последним ЧИТАЕТСЯ реплей сцены ~65:50 — отсюда
  впечатление обрыва.
- **~38% строк транскрипта — перемещённые реплеи** уже транскрибированного материала
  (дубль-шинглы 11.8–22.2% в зависимости от K; 67 дословных строк-дублей, 61 из них
  на расстоянии >100 строк). Пары дублей отстоят на >1000 слов (1171 из 1239) —
  это НЕ шовные дубли (шовная зона = 30с ≈ 75 слов).
- **Копии расходятся текстуально** после дословного начала (пример: вопрос интервьюера
  дословно, продолжение разными формулировками) ⇒ это ДВЕ НЕЗАВИСИМЫЕ транскрипции
  одной речи, а не копипаст/петля генерации.
- **Реплей 35:39–39:37 (17 строк) вставлен ровно после граничного сегмента дыры
  53:23** — сигнатура heal-добора (`insertAt` = граница дыры). Гигантский реплей-блок
  835–1316 начинается сразу после последнего реального сегмента 73:24 — сигнатура
  добора хвостовой дыры.
- **Дубль ×2 шириной ~3 мин на шве 30:00** (29:54–32:51) — шире и зоны перекрытия
  30с (S12.4), и клип-допуска ±2с (S12.3): метки этого дубля были «легальными» для
  своих окон.
- Хвост транскрипта кончается ЦЕЛЫМ предложением (не обрыв на полуслове) — стена
  out-токенов одного вызова непохожа.

## 3. Механизм (реконструкция)

1. Окна 1–4 отработали в основном честно; окно 4 оборвалось на 53:23 (≈ середина
   второй половины бисекции?), окно 5 стартовало с 65:14 (потеря 60:00–65:14),
   окна 6–8 (75–117 мин) не дали ничего размеченного своим диапазоном.
2. Образовались честные дыры (53–65, 73→конец) → **heal-добор** запрашивал их range-промтом.
3. **Модель на добор-диапазон возвращала ЧУЖОЙ контент со штампами внутри дыры**
   («легально врущие метки» — тот же класс, что убил S12.3, но теперь в доборе).
   Строгий клип ±2с по штампам это пропускает: штампы-то в диапазоне.
4. После вставки повторный `findCoverageGaps` видит дыры «закрытыми» фейковыми
   штампами → ни `ASR_COVERAGE_GAP`, ни предупреждения → прогон выглядит успехом.

**Системный вывод (важнее конкретного бага): все гейты покрытия конвейера — клип,
поиск дыр, добор, merge — используют метки самой модели как оракул. Подделанная
(«легальная») метка обходит их все разом. Метка ≠ доказательство; доказательством
работает только ТЕКСТ (принцип S12.4-шва), но сейчас он применяется только к шовной
зоне ±30с, а не к телу окна/добора.**

## 4. Что артефакт НЕ различает → нужен провенанс вкладки

Ни одна версия (256–264) не защищена от «чужого контента с легальными штампами»
внутри тела окна — поэтому артефакт совместим и с H1 (стейл-вкладка ≤261), и с
H2/H3 (свежий 264, модель обходит честный промт / деградация пиковых часов).
Различитель — снипет в консоли РАБОЧЕЙ вкладки владельца (см. решение-пакет сессии):
`AsrTranscript.ASR_WINDOW_OVERLAP_SEC` (=30 только в 264), `stitchWindowSegments`
(только 264), `ASR_WINDOW_SEC` (=900 с 256), плюс полный дамп
`v3LastImportMeta.audio.asr` (windows/seams/coverageGaps/healedGaps/skippedRanges).

## 5. Следствия для фиксов (кандидаты — решение по провенансу)

Независимо от исхода H1/H2/H3 артефакт уже доказывает четыре дефекта класса R11:
1. Heal-добор доверяет штампам модели → нужен текстовый анти-реплей гейт добора
   (добор, текстуально дублирующий уже транскрибированное ГДЕ УГОДНО в прогоне, — брак
   добора, дыра остаётся честной).
2. Тот же анти-реплей гейт нужен телу окна (не только шовной зоне).
3. Паспорт прогона без штампа версии кода — слепота «каким кодом сделан прогон» (R9).
4. Итог прогона не показывает сводку «окон N, дыры мм:сс–мм:сс, добор X» перед
   «Использовать» — потеря 47% выглядела успехом.

## 7. Корневая причина (закрыто)

**`gemini-flash-latest` не выдерживает range-скоупинг на длинном файле: чем глубже офсет,
тем чаще вызов возвращает контент ЧУЖОГО диапазона, причём с правдоподобными метками
«внутри своего» диапазона (подделка).** Глубинная корреляция по этому прогону:
w1–w3 (0–45 мин) — почти честно (перехлёсты с честными метками, клип справился);
w4–w5 (45–75) — частичное усечение (real 44:59–53:23 и 65:14–73:24); w6–w8 (75–117) —
контента своего диапазона НЕТ ВООБЩЕ, только реплеи ранних минут с in-range-штампами.

Все гейты целостности конвейера — клип, noAnchor-резы, `findCoverageGaps`, строгий клип
добора — ключуются на этих метках, поэтому подделанный контент проходит их все и
МАСКИРУЕТ реальные потери. Промт «TIMESTAMPS ARE ABSOLUTE AND HONEST» (S12.4) подделку
не останавливает. Текст-якорь (единственный не-метковый механизм) на реальных данных
срабатывает редко (1/7) и защищает только шовную зону ±30с.

**Резолюция гипотез: H1 (stale tab) — ОТВЕРГНУТА** (код вкладки v3.11.264, прогон
17:14–17:49 в этой же инстанции). **H3 (деградация пиковых часов) — ОТВЕРГНУТА**
(0 ошибок, 65–118с/вызов). **H2 — ПОДТВЕРЖДЕНА и углублена**: дефект не в шве, а в самом
контракте «один fileUri + range-промт»; шов — вторичная жертва (нечего якорить, когда
одна из сторон — чужой контент).

Три фикс-слайса (S12.2/3/4) не могли пройти: каждый чинил очередной гейт ПО МЕТКАМ,
а корневая причина — метки не являются доказательством. Архитектурный вывод по правилу
«3+ фикса → вопрос к архитектуре».

## 8. Развилка фиксов (решение владельца)

- **A (рекомендация): резать сам ЗВУК, а не промт.** Клиент режет mp3 по границам фреймов
  на чанки ~15 мин (+перекрытие 30с), каждый чанк — ОТДЕЛЬНЫЙ аплоад в Files API,
  транскрипция БЕЗ range-промта (модель физически не видит чужого звука → класс подмены
  умирает по построению); метки чанк-относительные → абсолютные детерминированным офсетом;
  существующий текст-стежок остаётся на швах; добор дыры — тоже вырезанным куском звука.
  Цена по токенам та же (тот же суммарный звук ×1.03 перекрытий), +N-1 аплоадов.
- **B: оставить range-промт, обвесить текстовыми гейтами** (глобальный анти-реплей: окно/добор
  с высоким текстовым совпадением с чужим материалом = брак → честная дыра; независимая
  сводка). Дешевле, но покрытие остаётся недоказуемым, а модель ненадёжна глубже ~60 мин.
- **C: сменить модель для длинного ASR** (pro-класс) — дороже в разы, тот же непроверенный
  контракт range-промта.

В любом варианте: R9-штамп версии кода в паспорт; честная сводка прогона перед
«Использовать» (окна/дыры/добор + предупреждение при потере); анти-реплей гейт добора как
страховка. Правило слайса: живой прогон на реальном длинном аудио (шинглы <3%, все корзины
покрытия >0) — обязательный гейт закрытия.
