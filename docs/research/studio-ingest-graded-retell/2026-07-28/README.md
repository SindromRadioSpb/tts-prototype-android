## Матрица M1: 3 текста × 3 способа задать уровень

Тексты: `ted` — TED-транскрипт иврит, устный регистр, 2 227 слов (фикстура
`scripts/premium/fixtures/captions/ted-hebrew-manual.vtt`); `literary` — «חצי-נחמה»
Ахад ха-Ама, 1 743 слова (работа 10 корпуса); `article` — «קח־ותן», публицистика 1920-х,
680 слов (работа 11774).

Варианты промта: `cefr` — метка «רמה A2–B1 (CEFR)»; `list` — явный список разрешённых
слов (top-1200 частотных) + до 15 новых с NEW-декларацией; `freq` — «только частотная
лексика (~1500 слов), ≤5% редких».

Модели: `ted×cefr` — прод-модель `gemini-flash-latest` (= gemini-3.6-flash); остальные
ячейки — `gemini-3-flash-preview` (дневная free-tier квота прод-модели 20 req/day
исчерпалась; 2.5-flash для новых ключей закрыт — «no longer available to new users»).

**Выводы M1:**
1. **R1-риск низкий**: 0 выдуманных форм на ~150 вручную размеченных предложениях
   (включая литературный иврит XIX века и устную речь). Гейт всё равно нужен
   (смоук: OOV-кандидаты через офлайн-резолвер + ручная выборка), но это страховка,
   не главный риск.
2. **Явный список лемм в промте НЕ работает как механизм**: модель соблюдает его на
   60–75%, платит ×8–10 thinking-токенов, декларация новых слов машинно ненадёжна,
   и появляются искажения смысла. Данные-driven уровень «только твои известные леммы»
   генерацией не обеспечивается.
3. **Метка уровня (cefr) и частотное ограничение (freq) работают** — чистый иврит,
   верный смысл, дёшево. freq — чуть проще лексика, cefr — чуть богаче покрытие деталей.
4. **Компрессию промт-долей не удержать**: просили ⅓, получили 6–22%. Длину надо
   задавать числом предложений/слов — подтверждено длинным пробником (см. ниже).
5. Caveat метрики: «top-1500 корпус-частот» — прокси по архаичному корпусу Бен-Йехуды;
   современные слова пересказов (טכנולוגיה, אוניברסיטה…) в нём занижены. Продуктовая
   мера — известность по личному `word_status`, не корпус-частоты. Сравнение МЕЖДУ
   вариантами валидно (одна линейка).

## Длинный вход (s11-long-probe.js)

Псевдо-транскрипт 48 514 токенов (12 корпусных работ, ~18К слов) → один вызов
`gemini-3-flash-preview`, промт с числовым контролем «60–80 предложений»:
- finish=STOP, wall 25.7 с, выход **71 строка** (в запрошенном диапазоне), thinking 3.1К;
- выборочная проверка: покрыты начало/середина/конец входа, выдуманных форм в выборке нет;
- стоимость по прайсу flash ($0.30/M in, $2.50/M out): вход $0.0146 + выход+thinking
  $0.0120 ≈ **$0.027 за пересказ масштаба 3-часового подкаста**. Часовой подкаст
  (~20К ток. входа) ≈ **$0.01–0.015**.

**Вывод:** чанк-пересказ v1 не нужен — вход до ~50К токенов (≈3 ч аудио-транскрипта)
держится одним вызовом; стоимость ничтожна рядом с ASR (~$0.25+/час). Смета в UI —
паттерн лейбла кнопки (как аудио-импорт), confirm-модал не обязателен.

## Coverage-движок (s11-cov-speed.js)

`agent/access/textCoverageResolver.calculate` (Node): загрузка словаря 1.67 с (разово),
далее 22 820 токенов за **51 мс** (~450К ток/с). Скорость не ограничение ни в Node,
ни (по порядку величины) в браузере.
