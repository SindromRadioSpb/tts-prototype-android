# Атлас P3: выпуск A, поиск S1–S3

Дата: 2026-11-02. Ветка `feat/atlas-search-voice`, основание `origin/main` = `99930cdc`; план импортирован из `01bec5dd`.
Статус: реализовано и проверено локально; публикация на проде не выполнялась. Это отчёт в точке остановки A из handoff.

Реализованы общий модуль сборки/поиска, индекс всей книги, нормализация иврита через CorpusFTS и приставки на запросе, русский Snowball, транслит, ключи обозначений с регистром и единиц. Выдача разбита по типам объектов; карточки терминов показывают огласовку, транслит, полный перевод и страницы. Есть переход и подсветка объекта/ячейки, поиск в текущем разделе, отдельное состояние недоступности индекса, возврат к запросу и восстановление истории/адреса. Фрагмент из 6 ивритских слов включает страницы по терминам и текстовому покрытию с переходами к формулам.

Коммиты: S1 — `ec5fc6ac`; S2 — `dd8a6685`; S3 и оптимизация — `2152a44f`. Дополнение сохранения количества результатов и Escape — последующий коммит этой ветки.

## Интерфейс

Применён `frontend-design`. Направление — предметный указатель учебного пособия внутри существующего ридера. Система сохранена: Segoe UI/системный шрифт для интерфейса, Arial/Noto Sans Hebrew для иврита; основные цвета `#FFFFFF`, `#0F172A`, `#475569`, `#0F6F74`, `#EEF2F7`, выделение `#FFEFA8`, с существующими тёмными токенами. Новый визуальный акцент — разделители групп и страницы, а не декоративные карточки. Выравнивание по началу строки, зеркало в HE, одна колонка на телефоне.

```

    [стр. 131] [стр. 134] ...
Обозначения / Формулы / Текст / Таблицы / Рисунки
```

## Качество и размеры

- Независимый эталон: 90 запросов; ожидаемые ref взяты из канонических ссылок терминов, таблиц обозначений и примеров книги, до оценки выдачи. В JSON указан источник каждой записи. Отдельно просмотрены 33 скана страниц; это проверка источников эталона, не приёмка всех страниц книги.
- 80 точных запросов: recall@5 = 100%, MRR = 0.981667. 10 фрагментов: recall@5 = 100%, MRR = 1. Промахов нет. Включены приставки, словоформы, транслит, `σ_Lc`/`sigma_Lc`, `τ_S`, `d₁`, `n_гзира`, единицы, аббревиатуры и опечатки стр. 7/289/485.
- Основной `search.json`: 1 281 296 байт; 7 614 объектов, 33 706 ключей. Неизвестных команд и записей без ref — 0.
- Первый поиск получает также подписи/координаты ячеек: 1 144 649 байт. Итого обычная загрузка ≈ 2.43 МБ. Только для фразы в кавычках нужен дополнительный словарный файл полного текста — 1 082 798 байт. HTTP-сжатие не требуется. Каждый файл меньше 1.5 МБ.
- Полный текст не обрезается для поиска фразы. Основной файл хранит словарь/ссылки; списки совпадений декодируются лениво. Три файла вместе с index.json и SHA-256 разделов образуют один комплект данных.
- Последний замер с параллельными проверками: разбор Node 47.44 мс, запрос p95 1.65 мс, самый долгий фрагмент 26.76 мс. Изолированный Chromium с CPU ×4: разбор и подготовка основного файла 73–100 мс; это эмуляция, не замер физического телефона.

Численные результаты: [search-eval.json](search-eval.json), [search-build.json](search-build.json), [index-performance.json](index-performance.json).

## Отклонения от первоначальной схемы

1. Для полных фраз и метаданных нужны два дополнительных файла; один файл с усечёнными текстами давал неверный поиск. Их хэши находятся в основном индексе, хэш основного индекса — в index.json. Загрузка проверяет согласованность и показывает недоступность при расхождении.
2. `room-b6-core.js` минимально расширен только для anchor атласа: первоначальная предпосылка плана о сохранении дополнительных полей не соответствовала sanitizer. Проверены чистый контракт и реальный browser Back/reload. Для других корпусов поля не сохраняются. `server.js` меняет только версию integrity-key этого модуля; версии ключей в SW и импорте синхронны.
3. Выдача фрагмента дополняет покрытие словарных терминов покрытием исходного текста. Это позволяет находить страницу условия со склонёнными словами, которых нет отдельной леммой в регистре.

## Перед публикацией

Handoff требует остановки после локально проверенного A. Нужны отдельно разрешённая запись комплекта данных на прод-том, резервная копия и проверка диска, выбранная актуальная версия выпуска (CACHE_VERSION/APP_VERSION и shell), затем один deploy и живая анонимная проверка. Номера модулей и integrity подготовлены в ветке; номер приложения для деплоя не занят заранее. Данные копировать комплектом, до кода, с проверкой хэшей.

Озвучка — следующий выпуск B. Требование владельца: только иврит; русский голос и режим HE→RU исключены. Права публикации/скачивания и профиль как у Материаловедения уже разрешены; повторно спрашивать D1/D2 не нужно. V1–V3, инвентаризация и пакет 40 формул ещё не реализованы. TTS-вызовов и расходов не было.
