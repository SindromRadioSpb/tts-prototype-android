# Atlas 97001 RC3.2 — отдельный корпус

Дата: 2026-11-07. Основание: пакет владельца `atlas97001-full-native-rc3-scoped-20261107.zip`, базовый commit `cec374dec254d5213dcf21170c1042f9d2f93478`. Пользователь разрешил публикацию после проверок и выбрал новый корпус вместо замены первоначальной редакции.

Статус на этом этапе: локальная приёмка пройдена; резервирование и production-проверки выполняются. Плановая версия приложения — **3.11.875**, версия поставщика — `3.11.874-atlas97001-rc3.2`.

## Сосуществование и данные

- Первоначальный корпус `atlas:a97001` сохраняет revision `50253381cb255822678b07e0ed41a608a3a701a661527eb796837b2f3ee64edc`, manifest SHA `085d33fddbd04a1eaaa4a9e625273591683cdcf9ff19d0b16899d503132ada7a`, прежние URL, исходные файлы, учебные ключи и действующий экспорт. Его данные не пересобираются и не перезаписываются.
- Новый корпус — `atlas:a97001rc32`, отдельная карточка «Инженерный атлас 97001 · RC3.2». Сырой источник поставщика остаётся в immutable namespace `atlas-editions/a97001/cea369d48494fcf58e78e0567fb82477abe7bb21ba02112707c3d7ba31fc4fd7` с manifest SHA `0211488a36ef6a03c6f277c6c913fb18165ab19430d13a4e623c95fc640ba332`.
- После проверки исходных байтов клиент проецирует служебные ID в `a97001rc32`. Исходный ID сохраняется в `source_id`; исходный `atlas_id` — в `source_atlas_id`. Содержание языковых полей не изменяется. Ссылки на картинки сразу указывают на закреплённую редакцию поставщика. Это адаптация идентичности приложения, а не исправление исходного текста.
- SRS нового корпуса использует `at1:a97001rc32:…`, места — `atlas-block-v1:a97001rc32:…`. Новая история поиска мест хранится в `room.atlas.find.v1.a97001rc32`, недействительные вопросы — в `room.atlas.find.stale.v1.a97001rc32`. Старые ключи не мигрируют, не очищаются и не наследуются. Особенно исключено вытеснение старых 500 ответов новым корпусом.
- Личные термины и ступени уже различаются по atlas ID; общий словарь приложения остаётся общим. Выкладка не меняет словарные статусы. Автоматического переноса старого знания в изменённый смысл нет.
- Исходный AI context остаётся привязан к старой редакции. Новый корпус отвергает загрузку AI context до сетевого запроса. Сертификация всех строк, научных утверждений, огласовок или переводов не заявляется.

## Изменения runtime

Проверены все 16 файлов исходного patch и новые build/test-файлы. Patch без конфликтов проходит `git apply --check` на точном базовом commit. Его переключение единственного PIN было заменено двумя клиентами с разными corpus ID. Добавлены карточка и переводы RU/EN/HE, согласованы shell/SW/module URLs, сохранён первоначальный PIN. Внесены проверки granular eligibility, таблиц с частями/подписями, MathML, точных областей термина и удержания старых оценок из пакета. Недопущенные значения символов и единиц также исключены из scoped-редакции.

Проекция ID требует проверки поисковых связей по исходному манифесту: повторная сериализация проекции даёт другой SHA. Исходные файлы по-прежнему полностью проверяются до проекции, затем `checkLink` проверяет равенство межфайловой ссылки хешу из того же манифеста. Отрицательные тесты повреждённых байтов и неправильных хешей проходят; ослабления проверки целостности нет.

## Исправление экспорта первоначального прогресса

До выкладки реальный экспорт отказал с `ATLAS_PROGRESS_SCHEMA`. Read-only диагностика через существующий выделенный snapshot RPC (без SQL из консоли, открытия профиля на диске или замены worker) установила, что валидатор не разрешал поле `confidence`, которое штатно пишет reading-tap writer. Также тест воспроизвёл отказ законной структурной ссылки `…:structure:<sha256>`. Валидатор теперь принимает только перечисленные provenance labels из ReaderMorph и точный структурный суффикс. Произвольные строки, объекты, вложенные секреты и чужие источники продолжают отклоняться. 20 schema/capture/snapshot тестов пройдены.

Для исходного снимка до релиза исправленный экспортёр временно смонтирован в разрешённой вкладке приложения, с тем же guarded read-only RPC. Глобальный экспортёр не заменялся; временный блок удалён. Файл сохранён владельцем и независимо проверен. В действующую БД импорт не выполнялся; данные не нормализовались и не отбрасывались ради зелёной проверки. Исправление самого экспортёра включено в релиз 875.

## Production и откат

Развёртывание допускается только после согласованного backup и capacity gate. Установить исключительно новый revision атомарным rename после полной проверки; сохранить старые atlas/atlas-editions/context/source packages, все пользовательские данные и резервные копии. Синтетическую БД не переносить.

Откат — возврат runtime на предыдущий рабочий образ/commit без восстановления старой learner-БД и без удаления какого-либо namespace. Новый corpus исчезнет из старого каталога, но его данные и учебные ключи сохранятся для повторного включения. Уже открытым вкладкам RC3.2 после возврата старого runtime может потребоваться перезагрузка: прежний сервер не знает расширенный набор файлов нового manifest. Первоначальный корпус продолжает использовать прежний revision. Полное восстановление volume из backup — аварийная процедура, а не обычный откат этого добавления.

Production-версия, фактические проверки сохранности, backup checksum и результат выкладки будут добавлены после завершения.
