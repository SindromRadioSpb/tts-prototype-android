## Найденный и исправленный дефект

На живом 3.11.838 результат находился и подсвечивался, но таймер goToPage через 500 мс прокручивал к началу страницы. В 390 px после ожидания 1.8 s верх найденной строки был на y=2459 / 1134 / 2231 px для σ_Lc / об/мин / N/mm при высоте окна 900 px.

Исправление `64e5c0e7` (3.11.839): выравнивание и его отложенный повтор привязаны к найденному объекту/ячейке; повтор отменяется для отсоединённого DOM. Локально те же строки остались на y≈185 px. В browser smoke добавлена проверка видимости после таймера на RU/HE 390 px. Исходные доказательства: scroll-before.json и scroll-local-fixed.json.

## PWA и проверка владельцем

Первый тест 837→838 перезагрузил страницу до завершения активации service worker и истёк по timeout; это не использовано как подтверждение обновления. Свежий изолированный PWA-контекст 838 прошёл загрузку и повторную перезагрузку без pageerror. Контрольный сценарий обновления выполнен отдельно: в анонимном контексте воспроизведён кэш коммита 3.11.839, затем отключено воспроизведение и через реальную кнопку приложения «Обновить» выполнен переход на немодифицированный живой 3.11.840. Итог — footer 3.11.840, controller активен, выдача 50 результатов, pageerror 0. Это контролируемое воспроизведение старого кэша, не профиль владельца. Свежая PWA 840 также получила activated worker и precache 840 (289 ключей). Прямые промежуточные сценарии во время rollout, закончившиеся timeout, не считаются доказательством успешного обновления.
