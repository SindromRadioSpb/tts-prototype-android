# Редактор разбора в строке: реализация и проверки

Дата: 2026-10-21. База `b3ebc514` / 3.11.804, кандидат 3.11.805. [Утверждённый контракт](../../../planning/MORPH_ANALYSIS_EDITOR_2026_10_21.md). Статус: выпущено в 3.11.805, CI и production acceptance прошли; [итоговый отчёт](RELEASE.md).

## Результат

- Общая карточка Зала/Студии показывает «Разбор в этой строке»: подписанный контекстный gloss, источник, словарную форму и значение, форму из текста, производный перевод и грамматику. Данные не спрятаны в свёрнутом словарном разделе. Машинный gloss не получает статус человеческой проверки.
- Отдельный раскрываемый редактор называется «Исправить разбор в этой строке». При нуле кандидатов нет пустого заголовка, при одном — «Найденный разбор», при нескольких — «Варианты разбора». Кандидат показывает текущее написание/форму и связанную словарную запись с Pealim. Сохраняется статья/POS, не отдельный sense/slot.
- Кнопка сохранения появляется после предварительного выбора словарной статьи. «Здесь это имя собственное» сразу сохраняет классификацию без старого перевода. «Отменить» работает после повторного открытия, восстанавливает прежний разбор или исходное машинное чтение, добавляя событие и сохраняя старые записи. Устаревшая отмена отклоняется.
- При отсутствии целого словарного совпадения кандидаты повторно используют существующие огласованные proclitic splits и `WordGloss.matchCell` с грамматическими ограничениями. שֶׁפָּחַדְתָּ получает pid1612; נוֹתַר сохраняет единственный pid867 / PERF-3ms. Целое совпадение имеет приоритет. Не принимаются произвольное снятие буквы, неверная огласовка приставки или предлог перед личным глаголом.
- Сохраняются source/candidate anchors, запрет повторной записи при двойном клике, проверка актуальной карточки перед append и перед перерисовкой. Ошибка записи допускает повтор. События записи получают монотонный timestamp относительно прежнего решения данного вхождения, включая действия в одну миллисекунду.
- Текст, review_log, word_status, FSRS и старые lexical events не мигрируются. Локальные сценарии используют одноразовые OPFS/серверные каталоги. Платные провайдеры не вызывались.

## Устранение гонки release gate

PR16 CI `39515566644` прошёл целиком (6m37s); merge `783dd512` имеет идентичное дерево приложения. Main CI `39516365906` обнаружил гонку старого API smoke: после HTTP 200 от `/healthz` он немедленно вызвал `/api/library/export`, пока временная SQLite БД ещё имела `ready:false`, и получил 503 `DB_NOT_AVAILABLE`. Прежнее ожидание проверяло только HTTP status.

Исправлен тестовый стенд: состояние health должно подтверждать одновременно `ok`, `db.ready` и `migrations.ready`. Ограниченный poll не скрывает ошибки экспортного API и не меняет серверное поведение. Добавлены проверки последовательности liveness → DB → migrations и отказа при истечении срока. Локально: 5/5 проверок helper и API smoke pass. Исправление вошло через PR17 / `bf4af1b3`, финальный main CI прошёл; версия клиентских assets остаётся 3.11.805.
