## Источники и результат подготовки

- Оригинал: https://benyehuda.org/read/34190. Его частичная огласовка `הבוֹקר הטהוֹרים.` не задаёт произношение всей строки.
- Опубликованная редакция: https://linguistpro.kolosei.com/data/benyehuda/works/34190.json, 437 строк. SHA-256 исходных байтов: `80fd43b0ea0005d9997c80bbc360c995865d1e9305d2ea11c2b3acc5a6287a3a`. Удалённый файл на томе проверен перед релизом; исходник не перезаписывался.
- `build-learning-niqqud.js` снимает исходные знаки, отдаёт Dicta 23 связных фрагмента, возвращает огласовку на исходные буквы через `fillMatres`. Границы фрагментов ограничены размером и окончаниями предложений; это не восстановление исторической абзацной разметки.
- Все 437 ID/порядок/исходные буквы и пунктуация сохранены. 2 928 из 2 953 ивритских токенов получили согласованный по буквам ответ с гласными; 25 остались без дополнения (главы א/ב/ג, имена, сокращения, междометия и слитное исходное `בביתהכנסת`). Они не заменены догадками. Это не оценка лингвистической точности 99,15 %.
- 327 строк отличаются от прежней огласовки. Строка 06: `הַבּוֹקֶר הַטְּהוֹרִים.` → `Haboker hatehorim.` / `habbôqer haṭṭəhôrîm.` / `хабокэр хатэхорим.`. Проверена в настоящем читателе для трёх профилей.
- Машинный результат не вычитан полностью. Применённый provider/model: `dicta-cloud` / `dicta-nakdan-cloud-v1` (версия адаптера, не утверждение о точной версии весов). 25 токенов и контекстные чтения имён требуют дальнейшей редакторской проверки. Правила невозможной огласовки дают один сигнал на конструкции с приставкой перед цитатой; они не являются независимым доказательством языковой корректности.

Перед первым paint читатель проверяет hash слоя, source work ID, число/порядок/совокупный hash исходных строк, затем прежнюю огласовку каждой строки. При 503/offline/hash mismatch читатель показывает источник; timeout запроса ограничен 1,8 с, успешный слой кэшируется, ошибка может повториться при следующем открытии. Полноценный offline/PWA сценарий отдельно не заявляется.

В Студию и native ZIP по-прежнему передаётся сохранённая редакция, а не эта временная проекция. Подключение учебного слоя к этим поверхностям и экспорту — отдельное расширение после пилота; оно не должно незаметно менять source/provenance.

## Полный учебный слой — исполнение goal

Основание: явное поручение владельца 2026-10-06 довести решение до зрелой реализации, включая Студию и стабильную заранее подготовленную транслитерацию. Предыдущие разделы фиксируют выпущенный пилот; ниже описан релиз 3.11.734. Исходная ветка: `501b4835` (origin/main), checkout `.tmp/benyehuda-partial-niqqud`. Статус: полный учебный слой опубликован и production-проверен в `6bb292da8bece67bb8edace7c1b2d3c2e32ac364`; техническая реализация goal завершена. Полная ручная языковая вычитка остаётся отдельной очередью O-079.

Инвентаризация точных публичных байтов каталога 8: 1 421 ready work, 106 375 строк, 954 225 ивритских слов длиной от двух букв, 108 366 562 байта исходников. Для 251 работы показатели исходных гласных недостаточны. Эти показатели служат отбору неполной огласовки, а не измеряют языковую точность. Исходные буквы, пунктуация, ID и сами опубликованные bodies не меняются.

Подготовка сохраняет полноценную исходную огласовку; частичные строки дополняются моделью в связных фрагментах, затем знаки проецируются на точные исходные буквы. Provider answers, конфигурация, hashes и ledger хранятся в игнорируемом durable `data/benyehuda-learning-niqqud/corpus-v8` основного checkout. Используются бесплатный Dicta cloud и уже установленная локальная `dictabert-large-char-menaked@2025-03`; после HTTP 503 batch прекращает новые облачные запросы, допускает возобновление из кэша. `--local-fallback --cloud-first` повторно использует ранее сохранённые ответы обоих провайдеров и запрашивает cloud только для отсутствующих. Платные переводы и другие поля не пересчитываются.

Итоговый builder `source-preserving-context-v3` сохраняет полноценные исходные слова и внутри частичных строк. В 64752 рядом с `תש"י` сохраняются `לֹאמַר` и `וָחֹרֶף`, вместо машинной замены на `לֵאמֹר` / `וְחֵרֶף`. Пересборка всего корпуса использовала только cache: 0 новых запросов. Provider cache context v2 остаётся прежним, поскольку входы модели не изменились; версия проекции независима от ключа raw ответов. Неизменившиеся pointed strings повторно используют профили только из byte-verified assets того же исходника, compiler и profile versions.

Каждая учебная редакция получает SHA-256 и immutable filename. Все три профиля компилируются заранее каноническим движком с явными версиями. При чтении проверяются слой, источник и версия профиля. На устройстве проверенные данные хранятся в отдельном CacheStorage, переживающем обновление service worker; в памяти удерживаются только четыре работы. При недоступности нового слоя явно показывается исходная огласовка. Открытие книги не вызывает модель. Ручные огласовка/транслит/блокировки имеют приоритет, соседние непоправленные строки сохраняют учебный слой.

Общий MaterialOpen готовит read model для Зала и обоих режимов Студии. DOCX, Anki sentence export и sentence SRS читают ту же проекцию. Raw backup сохраняет канонические строки и переносимый производный слой отдельно; восстановление закрепляет exact pin и работает без сетевой загрузки слоя. «Сохранить как новый» сохраняет исходные строки и отдельную frozen origin, не превращая личную копию в карточку корпуса. Просмотр/сравнение не перезаписывают SQL-источник, notes, bookmarks, progress или review_log.

Слова, которым не удалось безопасно сопоставить гласные, остаются в исходной форме и отмечаются знаком ⁕ в строке. Контекстные чтения имён и омографов остаются машинными, без обещания полной редакторской вычитки. Правила plausibility имеют положительный guard на проверенных Pealim forms, учитывают конечные כ/פ и не склеивают слова через кавычки/дефисы; это дополнительная диагностика, не независимый семантический эталон модели.

### Повторяемая подготовка и следующая публикация

1. Сделать frozen dry-run нового каталога штатным publisher; сохранить точные `corpus-index-vN.json` и source bodies.

4. Выполнить `--out <durable-directory> --finalize --revision <next-revision> --manifest public/js/benyehuda-learning-niqqud-manifest.js`. До готовности каждой работы manifest не публикуется. Финализация компилирует три профиля из готовых знаков без запросов модели; проверяет все fingerprints и записывает `release/files.json`, `quality.json`, manifest и immutable layers.
5. Разместить новые source bodies при обычной публикации новых произведений, затем учебные assets. Для существующего каталога bodies не перекладываются. `python3 scripts/premium/install-learning-niqqud.py --release <staged-release> --corpus <volume-data/benyehuda>` проверяет каждый опубликованный исходник и каждый новый слой до первой записи. 6. `publish-corpus-batch.js --apply` после revision 2 требует полного manifest, совпадающего с hash/version frozen каталога, и правильного pin для каждой ready work. При новом каталоге включать manifest в allowlist вместе с обычными catalog/shell/module/SW changes.
