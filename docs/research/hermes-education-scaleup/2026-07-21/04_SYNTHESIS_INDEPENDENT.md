# 04 — Независимый синтез: как масштабно поднять образовательный процесс LinguistPro ↔ Hermes

Дата: 2026-07-21 · Автор: Claude · Основа: 00 (базлайн по живому коду) + 01 (SLA-доказательность, ~25 источников) + 02 (конкуренты, ~25 продуктов) + 03 (MCP/энейблеры, ~35 инструментов). Написан ДО чтения параллельного исследования (сверка — файл 05).

## Цель (уровень «постановщика целей»)

Максимизировать **реальное владение ивритом** — удержание лексики, перенос в понимание живого контента, производство (речь+письмо) — при сохранении доктрин честности (W0, «кто учит — не сертифицирует», провенанс). Не «больше фич», а замыкание недостающих учебных петель: сейчас связка блестяще делает ввод (чтение+морфология) и повторение (FSRS), но **не имеет ни одной петли производства** (речь, письмо) и не использует главный доказанный AI-эффект — разговорную практику (g≈0.53–0.61).

## Портфель программ (инструменты + практики + данные)

### P1 · ГОЛОС — крупнейший гэп и главная ставка
Единственный гэп, который одновременно: топ-1 у конкурентов (02), топ-1 по evidence (01: разговорная практика, снижение тревожности), и полностью отсутствует в связке (00).
- **Этап A (недели): асинхронная речевая петля.** Голосовое сообщение → **ivrit.ai** ASR (открытые Whisper-файнтюны SOTA для иврита; self-host + MCP-обёртка) → Hermes ведёт разговор по протоколу recasts-в-потоке + отложенный explicit-разбор 3–5 повторных ошибок (01-§2, d=0.7–0.8) → ответ текстом+TTS. Инструменты: MCP-сервер ASR [M]; практика: скилл «Голосовая беседа» с протоколом коррекции; данные: темы из личных текстов + due-слова (01-§1).
- **Этап B (месяцы): произносительный скоринг.** Готового для иврита НЕ существует (03: Azure/Speechace не покрывают) — самосбор ASR-alignment + **Phonikud** (G2P с ударением). Это ниша: ни один конкурент не делает (02). [L]
- **Этап C: realtime-голос.** Gemini Live поддерживает иврит, но вне MCP-транспорта — отдельный клиент, после A/B.

### P2 · ПИСЬМО — вторая отсутствующая петля производства
- Практика: цикл **«черновик → focused WCF (2–3 категории ошибок) → обязательная ревизия»** (01-§4 HIGH; ChatGPT-фидбек ≈ учительскому). Скилл-уровень, доступен сегодня.
- Инструмент LinguistPro (W1): **propose_track_word** — агент предлагает слова из ошибок письма в трекинг SRS, владелец подтверждает (паттерн propose-then-confirm уже жив). Данные: produced-output хранить класс-C с собственным consent (или не хранить — только разбор в чате; решение владельца).
- Иврит-гардрейл: проверку орфографии/никуда агент сверяет через Dicta (не генерирует сам).

### P3 · Разговорные сессии на личном материале — доступно сегодня, усилить протоколом
Evidence-топ-1 (01-§1) реализуем текстом уже сейчас: сессии на темах из песен владельца с вплетением due-слов (гэп #4 из 02: у конкурентов это премиум-фича, у нас — natural fit: агент ВИДИТ словарь и тексты). Требуется только скилл-протокол: тема из текста → negotiated interaction → recasts → пост-сессионный разбор → handoff на реальное повторение.

### P4 · i+1 по расчёту покрытия, а не «на глаз»
01-§3 HIGH: подбор контента с 95–98% покрытием известных слов. Внутри уже есть corpus-vocab + scaffold-advisor (S2 «Следующий для тебя») — но агент к ним слеп, и для ЛИЧНЫХ песен покрытие не считается. Инструмент LinguistPro (read): **get_reading_recommendations / get_text_coverage** (покрытие текста известными словами из word_status) → скиллы P3/P5 выбирают материал по числу, не интуиции.

### P5 · Песенный контур — уникальный моат владельца, углубить данными
- **LRCLIB** (бесплатные синхронизированные LRC): due-слово → строка песни → таймстамп; narrow listening цепочками одного исполнителя с preview 5–8 слов (01-§8 dose-dependent). [S]
- **Spotify MCP**: плейлист как учебный план; **YouTube-transcript MCP**: клипы/подкасты. [S]
- **Dicta Nakdan API** (недоиспользованный эндпоинт уже-знакомого Dicta): автоникуд новых текстов песен. [S/M]
- Инструмент LinguistPro (W1): **propose_import_text** — агент нашёл текст песни → предлагает импорт в Библиотеку → владелец подтверждает → текст попадает в полный конвейер (морфология, TTS, SRS). Сегодня агент может только «посоветовать словами» — разрыв конвейера.
- ⚠ Shironet — без API, скрейпинг юридически чувствителен (ACUM): легальный путь LRCLIB/Musixmatch.

### P6 · SRL-коучинг недельного цикла — самый недооценённый множитель
01-§5: мета Chen 2022 **g=1.32** (крупнейший эффект всего исследования) — цели процесса, выбранные учеником + implementation intentions + регулярный обзор фактов. У агента есть все данные (progress_delta, brief), нет только: **goal-store** (LinguistPro: цель недели как класс-A запись; scope goal.read + propose_goal W1) и скилла «Недельная ретроспектива» (вс: факты → что сработало → цель следующей недели → якорь-намерение «после утреннего кофе — 10 минут повторения»).

### P7 · Обогащение retrieval и глоссы — дешёвые проценты поверх FSRS
- Скилл-уровень: после fail в разборе — elaboration; recall-форматы «употреби в своём предложении» (01-§6: evaluation — главный драйвер ILH). Расписание НЕ трогается (W0).
- LinguistPro-фича: **MC-глоссы** целевых слов в Зале (01-§5: ×1.7 к выучиванию, MC-формат лучший) — поверх существующей морфологии-на-тап.

### P8 · Знаниевая обвязка агента — подключить сразу
- **Sefaria MCP** (hosted, официальный) — словари Klein/Jastrow + интертексты песен (ивритская песня цитирует Танах постоянно — глубина, которой нет ни у одного конкурента). [S — минуты]
- **kaikki.org wiktextract** (52 МБ JSONL иврита) + **wordfreq**/субтитровые частотники — офлайн-lookup и приоритизация на диске Hermes. [S/M]

### P9 · Гардрейлы качества агента — обязательная пара к росту роли
01-§7: слабейшие места LLM-тьюторов — обнаружение ошибок и дозировка подсказки; сикофантия; галлюцинации семитской морфологии. Меры: (а) **морфо-grounding инструментом**: новый read-инструмент **get_word_morphology** (парадигма из офлайн-Pealim/Dicta) — агент ОБЯЗАН сверять утверждения о формах, не генерировать; (б) scaffolding-first в скилл-политике (намёк раньше ответа); (в) анти-сикофантия в политике; (г) грейд остаётся детерминированным (уже доктрина). Анти-паттерны из 01 — в скилл-политику явным списком.

### P10 · Аудио/видео-иммерсия — асинхронно, юзер-side
Language Reactor (работает с ивритом) — рекомендация владельцу, не интеграция; YouTube-transcript MCP покрывает агентскую часть (подкасты Кан, Streetwise Hebrew). Транскрипция своего аудио — через P1-ASR.

## Данные, которых не хватает (сводно)
1. Покрытие текстов известными словами (P4) — расчётный слой над word_status.
2. Goal-store недельных целей (P6) — класс A.
3. Произведённая продукция ученика (P2) — класс C, отдельный consent, опционально.
4. Частотники/wiktextract/LRC — внешние, на диск Hermes (S).
5. (Уже есть с 2026-07-19: exposure-провенанс — фундамент честности всего роста роли агента.)

## Секвенирование (по соотношению эффект/стоимость)
- **Горизонт 1 (дни, без кода LinguistPro):** Sefaria MCP + YouTube-transcript MCP + LRCLIB; датасеты (kaikki, wordfreq) на диск Hermes; 4 новых скилла-протокола: «Разговорная сессия» (P3), «Письмо с WCF» (P2-практика), «Недельная ретроспектива» (P6-практика), обновление политики гардрейлами (P9).
- **Горизонт 2 (недели, малый код):** LinguistPro-инструменты get_word_morphology (P9), get_text_coverage (P4), propose_import_text + propose_track_word + propose_goal (W1-семейство); Dicta Nakdan; Spotify MCP; ivrit.ai ASR MCP → асинхронная голосовая петля (P1-A).
- **Горизонт 3 (месяцы):** speech-scoring самосбор (P1-B), realtime voice (P1-C), MC-глоссы в Зале (P7), S4-заметки агенту, этап-2 взвешивания по накопленному провенансу.

## Мера успеха (не XP)
Lapse-rate после интервалов; % покрытия при чтении нового; минуты произведённой речи/письма в неделю; регулярность (дней с занятием/нед; 01: частота сессий — ключевой модератор SRL-эффекта). Всё выводимо из review_log/study_day + новых петель.
