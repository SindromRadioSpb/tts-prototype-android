## A. Снятые излишние рамки

1. **«Создай один документационный commit»** → разрешены 2–3 staged docs-only коммита.
   Причина: пакет ~34 файла; одна длинная сессия без промежуточной фиксации — риск потери работы.
   Все коммиты остаются документационными, сообщение-конвенция промта сохраняется.
2. **«Каждый prompt самодостаточен» (буквально)** → самодостаточность = точные пути обязательных
   к чтению файлов пакета + краткая сводка инвариантов в каждом промте. Полное дублирование канона
   в 20 файлов создало бы 20 расходящихся копий истины — анти-паттерн; Codex читает файлы репо
   в начале сессии, это и есть самодостаточность в git-контексте.
3. **Исчерпывающие per-item чеклисты каждого документа** → трактуются как coverage-гайд, не как
   обязательные подразделы. Дубли консолидируются (06 ↔ H1-промты ссылаются, не копируют).
   Критерий качества — «Codex не должен угадывать», а не «каждый пункт чеклиста заполнен».
4. **Оценки стоимости для 20/100 пользователей** → даются порядком величин с пометкой SPECULATIVE:
   продукт single-tenant (один владелец), мульти-тенантные цифры — экстраполяция, не обязательство.
5. **Фиксированная нарезка H1.0–H1.8** → рекомендованная; допускается пере-секвенирование по
   фактическим зависимостям при сохранении порядка «политика → скиллы → интеграции → closure».
