# iPhone + Chrome: local-media qualification kit

Статус: **эксперимент для владельца, не готовая функция LinguistPro**.
Физический iPhone пока не проверен. Windows/Chromium не заменяют этот гейт.
Команды ниже — тестовая настройка, НЕ предлагаемый премиальный интерфейс.

## Что нужно согласовать и установить

Нужна однократная установка бесплатного приложения
[a-Shell mini](https://apps.apple.com/us/app/a-shell-mini/id1543537943).
Chrome остаётся основным браузером. Компьютер, платный API, прокси, VPN,
аккаунт YouTube и новый сервер не нужны этому тесту. Обычный интернет,
свободная память телефона и электричество всё равно расходуются.
Установка приложения на телефоне — действие владельца, агент её не выполнял.

1. Сохранить `linguistpro-iphone-probe.zip` в «Файлы» на iPhone и распаковать.
2. Открыть a-Shell mini. Выполнить `pickFolder` и выбрать распакованный каталог
   `LinguistPro-iPhone-probe`. Подтвердить доступ только к этому каталогу.
   `ls` должен показать `run.py`, `OWNER_README.md`, `acquisition_service`.
   Если после выбора каталог не сменился, остановиться и сообщить версию a-Shell:
   у автора есть [сообщение об изменении pickFolder](https://github.com/holzschu/a-shell/issues/1020).
3. Выполнить установку закреплённых зависимостей только внутрь этого каталога:

```sh
python3 run.py --install-runtime
```

Создаётся `runtime-v1`; системный Python/другие пакеты не обновляются. Скачиваются
только три закреплённых pure-Python wheel с PyPI, проверяются SHA-256. При
повторном запуске существующий `runtime-v1` не перезаписывается. Не следует
обходить ошибку установки командами `pip install -U` или удалением чужих файлов.

## Сначала — способность устройства выполнять код

```sh
python3 run.py --preflight
```

Ожидается `NATIVE_PREFLIGHT_PASS`: реальное вычисление в Apple WebKit плюс
создание, проверка ffprobe и faststart-remux односекундного AAC-файла. Тестовая
секунда создаётся во временном каталоге и автоматически удаляется. Это ещё
не скачивание YouTube и не подтверждение работы Chrome.

Если ошибка/зависание — сохранить видимый код/этап, остановить проверку и
сообщить его. Не переустанавливать приложение и не менять сетевые настройки.
Закреплённый сторонний WebKit-плагин использует внутренний API yt-dlp;
совместимость с текущим a-Shell mini должна быть подтверждена этим тестом.

## Затем — реальный файл с YouTube

Выбрать публичный ролик, на сохранение которого есть право. Наличие ролика
в открытом доступе само по себе не является разрешением. Значения `--rights`:
`owned` — ваш материал, `permission` — разрешение правообладателя,
`public-domain` — общественное достояние. Не выбирать основание автоматически.
Ниже `VIDEO_ID_11` — заменяемый идентификатор ролика из 11 символов (не полный URL).

```sh
python3 run.py --download --video-id VIDEO_ID_11 --kind audio --rights permission
python3 run.py --download --video-id VIDEO_ID_11 --kind video --quality 360 --rights permission
```

Оставаться в a-Shell mini до завершения. Полноценное фоновое скачивание,
переживание блокировки экрана и возобновление после выгрузки приложения **не
обещаны**. Лимиты: 3 часа длительности, 300 MiB итогового файла; нет плейлистов,
приватного/DRM-контента, cookies и обхода входа. Проверка времени 30 минут
кооперативная на событиях загрузки, не гарантированный kill зависшего WebKit.

Результат в `results/<job_id>/`: `verified.m4a` либо `verified.mp4` и
`report.json`. Успех этого этапа называется `LOCAL_BYTES_VERIFIED`: реальный
H.264/AAC, длительность, разрешение, размер и SHA-256, а не метаданные источника.
Итоговый файл и промежуточный файл намеренно остаются в этой папке; при неудаче
могут остаться частичные файлы и `failure.json`. Удалять только выбранную
тестовую папку через «Файлы» после проверки; автоматической очистки результатов нет.

## Возврат именно в Chrome и импорт

Отдельное действие, после завершения скачивания. Подставить напечатанный
`job_id` (32 строчных шестнадцатеричных символа):

```sh
python3 run.py --return-chrome JOB_ID
```

`REQUESTED` означает лишь отправленный запрос. Владелец должен увидеть Chrome,
домен `linguistpro.kolosei.com` и обычную сессию LinguistPro. Chrome может открыть
новую вкладку. Фрагмент `#lp-local-probe=...` содержит только случайный ID;
продукт пока **не обрабатывает** его и не получает файл автоматически.

В Chrome: «Добавить материал» → «С устройства» → выбрать `verified.*` через
«Файлы». Проверить длительность, начало/середину/конец, звук и видео. Не запускать
облачную расшифровку для проверки бесплатного скачивания: у ASR отдельная стоимость.
Не удалять исходную тестовую папку до подтверждения сохранности файла в LinguistPro.

Прислать: модель iPhone, версии iOS/Chrome/a-Shell mini, `report.json` (без самого
медиа) и что фактически получилось с возвратом, выбором файла, воспроизведением
и повторным открытием. Отчёт содержит ID источника, поэтому перед пересылкой его
следует просмотреть. Нет ключей/подписанных потоковых ссылок/имени устройства.

## Граница результата

Переход **из Chrome в помощник** через `ashellmini:` подтверждён пока исходниками
приложения, но не тестом этого комплекта. Здесь помощник запускается вручную.
Пять исходных шагов «По ссылке → варианты → скачать → смотреть/слушать/ASR/экспорт»
ещё не реализованы локально end-to-end. После успешного теста нужны отдельные
доработки запуска из Chrome, возврата метаданных, связи задания с выбранным
файлом и восстановления после iOS suspension. Нельзя публиковать кнопку как
готовую функцию до этих гейтов и owner-acceptance.

Сборка: `python scripts/premium/build-iphone-media-probe.py`.
`package-manifest.json` содержит исходный commit и SHA-256 всех входных файлов.
В ZIP используются существующие planner/backend/byte-verifier без ручного форка.
