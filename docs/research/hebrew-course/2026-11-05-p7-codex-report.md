# P7 — синхронизация курса и возвращение к уроку

Дата: 2026-11-05. Ветка: `feat/course-sync`. База: `origin/main` (`119f784e`) с влитой `origin/feat/course-audio` (`689c41f7`). Статус: реализация на ветке, production-выпуск ожидает отдельного «да» владельца.

## Что сделано

- Попытки получили случайный суффикс ID, ввод в доказательстве ограничен 300 символами. `mergeProgress` объединяет попытки по ID, остальные поля по детерминированным правилам; `progressDigest` считает FNV-1a канонического JSON.
- `course_progress` хранится в том же согласованном хранилище, что и `state_bundle`, с лимитом 2 МБ, проверкой ключа и схемы. Новый GET/PUT API требует текущего `cloud_texts` consent; PUT требует CSRF и выполняет атомарный compare-and-swap. Устаревшая база даёт 409 с текущим содержимым.
- Клиент загружает, сливает, сначала сохраняет локально, затем отправляет. На 409 сливает и повторяет один раз. Доступны статусы в списке и уроке. Синхронизация запускается при открытии курса, через 5 секунд после попытки, после восстановления сети и при скрытии вкладки. При смене пользователя экземпляр прекращает работу.
- `dueReturns` выводит урок через сутки после переноса, после нового варианта — через 3 дня; неудачный перенос возвращается сразу. У transfer-задания допустимы валидируемые `variants`. Кнопка открывает новый вариант или честно предлагает повтор урока, если вариантов нет.

## Решения при неоднозначности

- `Progress.reader` хранит позицию и черновики устройства. Клиент не отправляет его в облако и сохраняет локально при слиянии. На сервере остаётся только учебное доказательство.
- Конфликт 409 реализован условным SQL UPDATE/INSERT. Обычный `artifacts/put` не принимает `course_progress`, иначе он обходил бы проверку версии.
- При неудаче в варианте следующий вход открывает тот же вариант, пока он не принят.
- Независимая проверка нашла два Important случая, устранённых до передачи: два ридера одного устройства сохраняют объединение попыток перед записью; GET/PUT требуют `X-LP-User`, совпадающий с авторизованной сессией, поэтому кэш прежнего `me()` не переносит чужой прогресс при смене аккаунта в другой вкладке.
- Выпуск P7 отложен до «да» владельца. Браузерный smoke использовал два контекста одного disposable owner; отдельный аккаунт проверен изоляцией репозитория, анонимный API — 401. Owner-live ПК/телефон после выпуска остаётся владельцу.
