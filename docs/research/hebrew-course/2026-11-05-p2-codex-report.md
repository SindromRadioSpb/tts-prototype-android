## Решения при неоднозначности плана

- «Первая попытка» определяется отпечатком независимо от канала. Поэтому cards → write_he на том же отпечатке не даёт самостоятельности; положительный пример использует новый вариант. Это соответствует Global Constraints, хотя комментарий к примеру теста допускает другое прочтение.
- FNV-1a вычисляется по UTF-8 канонического JSON; undefined-поля опускаются по правилам JSON. Нулевое время учитывается наличием ключа, а не истинностью значения. Дубликаты определяются последней попыткой того же задания, равными вводом/каналом и интервалом 0 ≤ delta < 1000 мс; откат часов не считается дублем.
- Attempt дополнен `baseFp` и неизменяемым `taskSnapshot` для различения правки определения и нового варианта, сохранения исторических достижений. При `record(..., {via: "ai"})` сохраняется явная пометка; канал ai сам по себе независимым доказательством не является.
- Миграция сравнивает базовый отпечаток, а не вариант последней попытки: новый вариант не объявляется правкой задания. Старые `seen` сохраняются; возврат прежнего содержания не делает знакомое задание новым. Тот же номер версии возвращает независимую копию без изменений значений.
- Для частично пройденного набора transfer-заданий выбран `not_started`; последний неуспешный ответ на любой transfer даёт `needs_review`. Урок без transfer — `not_started`.
- Счётчики считают единицу лексикона вместе с её формами один раз. Для слотов учитываются требуемые значения, а не все альтернативы; для confirm — card, для replacement — next/prev. Введённые единицы урока учитываются по прямому правилу плана.
- `openAid` не сохраняет at: в заданной схеме Aids поля времени нет; попытка хранит снимок текущей помощи. Помощь не сбрасывается после ответа.
- Повреждённые/чужие данные проверяются по структуре, courseId, каналам, вердиктам и вложенному снимку; исходная строка остаётся на месте и копируется под corrupt-ключ. При неудаче резервного копирования последующая запись блокируется как unavailable, чтобы не затереть единственную копию. Ошибки доступа к getter localStorage тоже перехватываются. Новых зависимостей нет.

## Границы проверки

Тесты автоматические Node, со своим поддельным storage. UI, физические устройства, настоящий браузерный quota/приватный режим и production не проверялись; модули ещё не подключены к страницам. Синхронизация и FSRS остаются P7. Никакие пользовательские данные, чужие локальные файлы или диски не очищались.

Исторический itemStatus сохраняет результат после изменения model или удаления задания внутри сохранённого урока (есть тест). Но соответствие старых попыток единицам использует переданные текущие `slots`/`introduces`: исходный интерфейс record не получает урок. Изменение этих отображений или исключение целого урока из переданного списка не позволяет восстановить прежнюю лексическую привязку; полноценный архив версий урока этим этапом не реализован. AI-пометка обозначает происхождение, не доказывает точность внешней оценки.
