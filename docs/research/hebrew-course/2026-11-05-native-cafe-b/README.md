## Что подготовлено

- `B000-foundations`: 14 входных лемм, явная женская форма רוצה, 7 заданий,
  14 экранов. `preknown: []`: знакомство и освоение не объявляются автоматически.

  работают через существующий нативный ридер, а не через новый отдельный сайт.

## Узкие изменения движка

1. `task.evidenceLexIds` и переопределение варианта ограничивают лексическое
   доказательство конкретным заданием. Один ответ больше не приписывает пилоту
   производство всех восьми новых слов. Пустой список допустим.
2. `flow.steps[].metLexIds` отмечает встречу только после показа соответствующего
   шага. Переход к началу B001 не означает, что ученик видел все предпосылки и слова.
3. `spec.requestOnly` включает консервативный фильтр для просьб, кратких ответов
   и исправлений. «Я не хочу…», «нет…», «есть…», «что это…» больше не принимаются
   как нужный заказ только потому, что совпали слоты. Неясный ответ идёт на
   самопроверку, а не получает ложное успешное доказательство.

Все расширения опциональны. Старые ID и отпечатки без полей сохранены; прежнее
поведение legacy-урока не мигрируется и не переписывается.

## Воспроизведение

```sh
npm ci --cache .tmp/npm-cache --no-audit --no-fund
node scripts/course/course-cafe-b-gates.cjs
node scripts/course/validate-course.cjs content/course/ulpan-cafe-b-pilot --json
node scripts/course/build-course-data.cjs content/course/ulpan-cafe-b-pilot <fresh-output-directory>
node scripts/course/course-cafe-b-smoke.cjs
```

Для штатного Chromium допускается `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`.
Smoke создаёт отдельную БД и браузерный контекст, блокирует внешние origin,
проверяет оба модуля и неизменность sentinel-прогресса старого курса. `--serve`
поднимает только локальную тестовую копию для ручной проверки. Не запускать
проверки на профиле владельца или production-хранилище.

Для разрешённого managed preview используйте сохранённый
`managed-preview-start.cjs.txt`: отдельный DATA_DIR и TTS disabled. Это тестовый
сервер, не публикация. Точный URL берётся из результата `sites-preview start`;
старый результат URL не является гарантией работающего preview.

### Повторная проверка при старом service worker

Если браузер продолжает показывать закэшированный HTML без новых модулей,
не считать это проверкой текущих исходников. В этой среде запуск отдельного
Chromium через Playwright завершился sandbox-ошибкой `socket() Operation not
permitted`; запрет не обходился. Поддерживаемый managed preview работоспособен.
Для него сохранён отдельный **только тестовый** вариант:

```sh
mkdir -p .tmp/cafe-b-managed-preview
cp docs/research/hebrew-course/2026-11-05-native-cafe-b/managed-preview-resume-start.cjs.txt .tmp/cafe-b-managed-preview/start.cjs
cp docs/research/hebrew-course/2026-11-05-native-cafe-b/managed-preview-fresh-assets.cjs.txt .tmp/cafe-b-managed-preview/qa-assets.cjs
printf '%s\n' '{"private":true,"scripts":{"dev":"node start.cjs"}}' > .tmp/cafe-b-managed-preview/package.json
sites-preview start "$PWD/.tmp/cafe-b-managed-preview"
```

К точному origin из результата CLI добавляется путь, указанный `prefix`/`tag`
в тестовом wrapper, затем `/library.html#room=course%3Aulpan-cafe-b-pilot`.
`/manifest.json` на том же префиксе показывает **хеши исходников**, не
преобразованных HTTP-ответов. Wrapper префиксует пути HTML-ресурсов, импортов
модулей и course-data, не меняет логику приложения или cache keys релиза.
При новой редакции кода нужно новое значение `tag` и перезапуск preview.
По окончании: `sites-preview stop`. Это не production/физическая приёмка.
