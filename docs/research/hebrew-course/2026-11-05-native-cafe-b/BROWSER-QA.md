# Реальный browser QA нативного кафе B

Это исходная проверка до расширения повторов. Актуальная повторная проверка
исправлений O-145/O-146 и R00: [resume-browser/RESULTS.md](resume-browser/RESULTS.md).

Дата: 2026-11-05. Основа: `d3ad49e427482a9f87bc51d6b0b12684ce8d452c`, ветка `pilot/cafe-b`, локальный незакоммиченный патч.
Evidence: настоящий управляемый Chromium/Linux, нативный `public/library.html`, одноразовый сервер и новая анонимная локальная история.
Статус: проверенный ниже browser scope пройден; это **не полный release gate, не физическая мобильная или owner-приёмка**.

## Главный результат

Штатный `sites-preview` сделал локальную копию доступной cloud browser. Ранее зафиксированная невозможность открыть интерфейс не является текущим блокером для этой конфигурации.

- Все **72 экрана**: B000 (14) и B001 (58), фактически загружены на **380×497 CSS px / RTL (he)** и на **320×426 CSS px / LTR (ru)**.
- На обеих ширинах `documentElement.scrollWidth === clientWidth` на каждом экране. Неготовых `data-course-play` элементов нет.
- Desktop проверен на 1165×759 CSS px: подготовительные карточки, задания, сцена и перевод.
- B000 пройден последовательно до конца с выполнением всех семи заданий. Итог: «Пройден с опорой».
- B001: проверены все экраны и ключевые виды взаимодействия, перечисленные ниже. **Все 45 заданий последовательно не решались**, завершение B001 не заявляется.
- После просмотра последнего экрана при невыполненных заданиях B001 остался «В процессе», а не «пройден».
- В 180 захваченных warning/error-сообщениях были только сообщения browser-extension `Error sending browser metadata to extension`. Сообщений приложения среди них не найдено. Это ограниченный console capture, не отдельный сетевой аудит.

## Что сделано в интерфейсе

### Подготовка B000

1. Открыт курс через нативный Зал: оба урока доступны, исходный прогресс равен нулю.
2. Последовательно просмотрены опоры, различия наличия/желания, сцена и все диагностические задания.
3. На задании `B-E01-2` неверный выбор дал «Попробуйте ещё» и оставил «Дальше» выключенной. Верный выбор дал «Смысл передан», переход разблокировался.
4. Русский ответ на `B-E01-1` сначала получил «Проверка недоступна для этого варианта». Явная «Сверить с образцом» дала самопроверку с опорой, а не самостоятельное доказательство.
5. На `B-E01-3f` черновик `אני לא רוֹצָה מים` сохранён до отправки; после reload он восстановился. Подсказка и образец открылись. Образец содержит женскую форму.
6. Все оставшиеся подготовительные самопроверки выполнены; последний экран предупреждает, что окончание экранов не является освоением.

### B001: ответы и виды заданий

- `B-E03-2`: `אני לא רוצה קפה` **не принят автоматически**, «Дальше» выключена. `אפשר תה, בבקשה?` отклонён: нужен кофе, а не чай. `אפשר קפה, בבקשה?` принят. После прежних ошибок доказательство осталось «с опорой; первая попытка: нет».
- `B-E03-3`: корректная просьба чая с первой попытки, без помощи: «самостоятельно; первая попытка: да». На главной курса число «Отвечаете сами» стало 1, не 8.
- `B-E05-2`: маленький кофе с молоком отклонён при требовании большого. Два нажатия подсказки показали общий текст, после второго кнопка выключилась. Исправленный большой кофе принят с отметкой помощи.
- `B-E05-1`: собрана фраза из всех шести плиток, принята; доказательство обозначено каналом «карточки» и «с опорой».
- `B-E05-4`: правильный заказ «маленький кофе с молоком, без сахара» введён и принят обычным click на 380px RTL.
- `B-E07-3`: на 320px неверное исправление `לא, קטן, בבקשה.` отклонено; `לא, גדול, בבקשה.` принято.
- Встроенная клавиатура открылась; «Буква алеф» добавила א, «Удалить предыдущий символ» восстановила исходную строку; закрытие сработало.
- Tab от поля ответа перевёл фокус на кнопку клавиатуры. Полная screen-reader/assistive-technology проверка не проводилась.
- На сцене B001 перевод первой реплики показан и снова скрыт. Иврит, знаки вопроса и огласовки визуально проверены на сцене и в ответах.

### Сохранение и навигация

- Reload сохранил неподанный черновик B000, принятый выбор B000, текст и результат B001.
- «К урокам» → browser Back → browser Forward → Back вернули соответствующие экраны. После асинхронного открытия ответ остался доступен.
- Повторный вход в B001 из списка возобновил последнюю позицию.
- После просмотра всех экранов и reload список показал: введено 22, узнаёте 0, отвечаете сами 1, применили после перерыва 0; B000 с опорой, B001 в процессе.
- Переключение ru → he установило `html lang="he" dir="rtl"`. Содержимое задания осталось авторским русским, интерфейс стал ивритским. Обратное переключение тоже работает.
- Смена языка возвращает в список курса; позиция, ответ, подсказки и результат восстанавливаются при повторном открытии урока. Это UX-наблюдение O-145, не потеря данных.
- Существующий legacy-прогресс `ulpan` не подменялся sentinel-данными в этом browser run. Его byte-for-byte изоляцию следует подтверждать отдельными автоматическими тестами, не этим отчётом.

## Среда, безопасность и воспроизведение

Рабочий код не менялся. Пилот и legacy bundle собраны в свежий DATA_DIR, БД также новая. Окружение очищено через `smokeServerEnv`, загрузка `.env` отключена в тестовом процессе, `TTS_ENABLED=false`. Production, аккаунт/данные владельца, ключи, оплачиваемый синтез, push и deploy не использовались.

Запуск: поддерживаемый daemon `sites-preview`, не отдельный вручную поднятый listener. Временный wrapper сохранён без изменения как [managed-preview-start.cjs.txt](managed-preview-start.cjs.txt). Из корня этой рабочей копии:

```sh
mkdir -p .tmp/cafe-b-managed-preview
cp docs/research/hebrew-course/2026-11-05-native-cafe-b/managed-preview-start.cjs.txt .tmp/cafe-b-managed-preview/start.cjs
printf '%s\n' '{"private":true,"scripts":{"dev":"node start.cjs"}}' > .tmp/cafe-b-managed-preview/package.json
sites-preview start "$PWD/.tmp/cafe-b-managed-preview"
```

Открывать **точный URL, возвращённый CLI**, затем `/library.html#room=course%3Aulpan-cafe-b-pilot`. В этом запуске daemon вернул `http://127.0.0.1:4173/`. Preview остановлен через `sites-preview stop` после проверки.

DevTools/device emulation были явно запрещены политикой Chromium. Запрет не обходился. Узкие размеры получены обычным изменением размера окна через оконный менеджер и штатным browser zoom: 150% для 380×497, 175% для 320×426. Размеры измерены из DOM; desktop снова проверен на 100%.

На разведочном, неприёмочном размере 293×189 CSS px при zoom 400% click «Проверить» вместо проверки раскрыл верхний breadcrumb. Из-за крайне низкой высоты и фиксированных панелей это **не evidence физического телефона**; окончательные проверки 380×497 и 320×426 сработали. Связанное открытое O-142 не закрывается этим прогоном.

## Ограничения и незакрытые вопросы

- Физические Android/iPhone, WebKit, touch keyboard, устойчивость на реальном телефоне и owner-профиль не проверены.
- Отдельные повторные/прерванные сценарии проверены, но не все 52 задания со всеми возможными ответами.
- Повтор одинакового click «Проверить» при разведочной сверхнизкой высоте не доказывает корректную дедупликацию: в тот момент попадание ушло в breadcrumb. Дедупликацию подтверждают отдельные unit/DOM тесты.
- Аудио, ASR, произношение, независимая языковая и ученическая приёмка не выполнялись.
- Облачная синхронизация, API-приватность и неизменность старого `review_log` не проверялись в этом UI-сеансе.
- У заданий пилота нет конкретных `hints`; два клика показывают одну общую фразу. Зафиксировано как O-146.
- Браузерная работоспособность текста не снимает остальные release gates из основного README.
