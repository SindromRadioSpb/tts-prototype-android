Generated by:

```
node scripts/premium/train-queue-shots.js
```

The script starts the app on an isolated port, seeds ten due words into a throwaway OPFS
profile, enters the review through the canonical Studio→Room deep-link
(`?review=due&from=studio`) rather than by poking internals, captures each viewport, and fails
if the page ever scrolls horizontally or emits a page error. These are browser-emulation
screenshots, not physical-device evidence.

**These screenshots earned their place.** The first run showed
`В этой сессии: 10 (повторение 0, новых 10)` for ten words that all had a live interval and
`reps: 2`. `getDueWithSource` returns the schedule as `srs` while the selection engine reads
`_srs`, so every word bucketed as new: the weakness quota, the known refresh and the review
budget were all silently no-ops and the session was capped by `newPerDay` instead. No static
gate could see it — the unit tests build their fixtures with `_srs` already set. Suite 7b of
`smoke:train-queue` now pins the real row shape.
