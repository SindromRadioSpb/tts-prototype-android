# Читальный зал — «Учебный режим» карточки текста (дизайн)

**Дата:** 2026-08-05 · **Поверхность:** Читальный зал (`public/library.html`, `public/js/library-ui.js`)
**Статус:** OWNER-APPROVED (решения D1–D5 ниже) · **Замеры:** `docs/research/room-study-mode-ux/2026-08-05/`
**Роли-линзы:** R4 (премиум-UX mobile-first @380px, без тупиков), R2 (методика: удержание внимания),
R8 (graded reading), R11 (do-no-harm к parity-залоченному билдеру), R5 (планка продукта).

## 1. Проблема (измерено, а не предположено)

Живой прогон @380×845 CSS px на медиа-материале из «Моих текстов» (`node server.js` + Playwright,
коммит `0e8fd56a`, прод 3.11.309). Полные числа и кадры — в research-папке.

**Вертикаль.** Из 845px экрана таблице достаётся **220px (26%), одна видимая строка**:

| Слой | px |
|---|---|
| шапка Зала | 176 |
| `.reader-bar` (sticky) | 96 |
| `#readerTip` | 58 |
| `#roomMediaBar` + видео | 292 |
| **окно таблицы** | **220** |
| `#readerProvNote` | 17 |
| `#roomFooter` | 140 |

**Горизонталь.** В учебной конфигурации владельца (видимы Огласовки + Перевод) служебная колонка
занимает **85px из 337 = 25.4%**. Причина: `normalizeVisibleBaseWidthsTo100` (reader-core.js)
нормализует базы `[15,20,20,21,24]` **по видимым** колонкам, поэтому доля `action` растёт
15% → 25.4% ровно тогда, когда учащийся упрощает таблицу. Дефект тем сильнее, чем ближе
конфигурация к учебному идеалу «две колонки».

**Три сопутствующих дефекта, вскрытых замером:**

1. **Мёртвый аффорданс.** Билдер эмитит `.col-resizer`; в Зале это **4 видимых грипа 10×79px**, но
   `table.dataset.resizeBound === null` — обработчик живёт только в `index.html`. Синтетический drag
   на 60px: ширины `15%|20%|20%|21%|24%` не изменились. Зал рисует ручку, которая ничего не делает.
2. **Высота окна таблицы считается при непрокрученной странице.** `roomMediaApplyLayout` берёт
   `innerHeight - wrap.top - 10` при `scrollY = 0`, когда 176px шапки ещё в потоке; остаток уходит
   в минус и клампится `Math.max(220, …)`. После прокрутки шапки прочь эти 176px таблице **не
   возвращаются никогда**.
3. **Дисклеймер и футер — 157px (19% экрана) постоянной служебной информации** прямо под окном таблицы.

## 2. Решения владельца

| № | Решение |
|---|---|
| **D1** | Направление **B** — «Учебный режим» одним переключателем, **с пользовательской настройкой колонок**: комбинации выбирает учащийся. |
| **D2** | Новых кнопок в `.reader-bar` **не добавляем**. Единственная точка входа — существующая раскрывающаяся панель по кнопке **«Аа»**. |
| **D3** | Служебная колонка — **три положения**: Полная / Рельс / Скрыта. |
| **D4** | Дефолт при первом включении режима — **Рельс**. |
| **D5** | Режим включается **только вручную**. Никакого автовключения для медиа-материалов. |

Ширины колонок регулируются **живым drag'ом** — мышью на ПК и пальцем на айфоне одним и тем же
кодом (Pointer Events; `.col-resizer` уже несёт `touch-action: none`).

## 3. Дизайн

### 3.1 Панель «Аа» — новый первый блок

Панель (`#readerAids`, строится `buildAidsPanel`) получает блок **над** существующим «Иврит».
Порядок и содержимое остального не меняются.

```
┌──────────────────────────────────────────────┐
│ 🎬 Учебный режим                     [ ○—● ] │
│    Экран отдаётся видео и таблице            │
│                                              │
│ Служебная колонка: [Полная][Рельс][Скрыта]   │
│ Ширины: тяните ‖ между заголовками  [↺ Сброс]│
└──────────────────────────────────────────────┘
```

* «Служебная колонка» — сегментированный переключатель из трёх кнопок (`role="radiogroup"`),
  активная помечена `aria-checked`.
* Видимость **содержательных** колонок (Иврит / Огласовка / Транслит / Перевод) уже управляется
  существующими элементами этой же панели и **не дублируется**: пользователь и сегодня собирает
  любую комбинацию. Единственная колонка без переключателя — служебная; её и добавляем (D1/D3).
* «↺ Сброс» возвращает ширины к базовым `[15,20,20,21,24]` и не трогает видимость колонок.
* Подсказка про drag — одна строка `.reader-aids-hint`, без картинок.

### 3.2 Учебный режим

Переключатель ставит/снимает `body.room-study`.

**Скрывается** (`display: none`): `header.room-header`, `#readerTip`, `#readerCovChip`, `#roomFooter`.

**Раскладка:** `#roomReader` становится `position: fixed; inset: 0; display: flex; flex-direction: column`.
Порядок потока: `.reader-bar` (не растёт) → `#roomMediaBar` (не растёт) → `#roomReaderTable`
(`flex: 1 1 auto; overflow-y: auto`).

> **Арифметика высоты в режиме не нужна вовсе.** `roomMediaApplyLayout` при `body.room-study`
> не устанавливает `wrap.style.maxHeight` — высоту даёт flex. Это и есть починка дефекта №2:
> считать больше нечего.
>
> **Но класс `.room-media-scroll` обязан остаться.** По нему `roomMediaFollowRange` решает, какой
> скроллер двигать (собственное окно таблицы против окна страницы). Снять класс, оставив окно
> скроллирующимся, — значит увести авто-слежение караоке в ветку страничного скролла и сломать
> «активная строка — вторая». Ранний выход касается **только** `maxHeight`, не класса. В учебном
> режиме класс ставится ВСЕГДА (в том числе для материалов без медиа — окно таблицы там тоже
> собственный скроллер).

**Липкая шапка таблицы:** в режиме таблица скроллится в своём окне, поэтому
`#roomReader #proTable thead th { top: 0 }` (а не `var(--room-thead-top)`). Без этого правила
шапка уезжает вниз на высоту бара и оставляет пустую полосу — воспроизведено в прототипе.

**Вне режима** поведение не меняется: страничный скролл + существующий медиа-режим окна.
Дефект №2 вне режима чинится отдельно: высота пересчитывается на `scroll`/`resize`/`orientationchange`
(throttle через rAF), а не единожды при открытии.

**Замер прототипа @380×845:** окно таблицы **220 → 489px (26% → 58% экрана)**, видимых строк **1 → 5**.

### 3.3 Служебная колонка — три положения

| Положение | Ширина | Содержимое | Как достигается |
|---|---|---|---|
| Полная | доля из `baseWidths` (сейчас 85px / 25.4%) | ▶ 🤖 ☆ крупно | текущее поведение |
| **Рельс** (дефолт режима) | **34px** | ▶ 🤖 ☆ — все на месте | post-render пересчёт долей + компактный CSS |
| Скрыта | 0 | ▶ ☆ 🤖 — оверлеем на активной строке | `visibleColumns.action = false` в `readerConfig()` |

**Рельс — почему все действия остаются.** Замер живого DOM: содержимое ячейки занимает 57px при
колонке 85px, а `.row-tts-btn` и сегодня имеет `visibility: hidden; opacity: 0` на неактивных
строках (появляется на активной/наведённой). Значит 34px хватает: ▶ 26×26, 🤖 и ☆ по ~18px.
Ничего не прячем и не переносим — сжимаем пустоту.

Замер после перехода на рельс: «Огласовки» 114 → **141px**, «Перевод» 137 → **169px** (+23%).

**Скрыта — оверлей без новых жестов.** Группа `[▶ ☆ 🤖]` показывается **только на активной строке**
(`.smk-row-active` / `.row-playing`), абсолютом у **левого** края строки — там, где стояла служебная
колонка (порядок колонок в таблице LTR: `action` первым, независимо от RTL-содержимого ячеек;
подтверждено кадрами). Оверлей поверх текста, полупрозрачная подложка. Активной строка становится
уже существующими путями: караоке ведёт её сам, а тап по строке = перемотка медиа на эту строку.
Новых жестов не вводим — это принципиально: тап по слову занят морфологией, долгий тап по слову —
статусом, тап по «Переводу» — озвучкой, тап по пустому месту строки — перемоткой.

### 3.4 Ширины — живой drag (ПК + айфон)

Движок ресайза Студии (`onResizePointerDown/Move/Up`, `applyLinkedResize`, `applyColgroupWidthsToDom`,
`index.html` ~37490–37610) переносится в `public/js/reader-core.js` как:

* чистая `applyLinkedResize(visibleColumns, baseWidths, leftKey, rightKey, startLeft, startRight, delta)`
  (Node-тестируемая, рядом с уже живущими там `normalizeVisibleBaseWidthsTo100` /
  `enforceMinWidthsWithLocalAdjust` / `RESIZE_MIN_COL_PERCENT`);
* тонкая `attachColumnResize(mount, opts)` — делегат `pointerdown` на таблице, `setPointerCapture`,
  запись в `<col>`, `onCommit(baseWidths)` для персиста.

`index.html` **не трогаем** — Студия продолжает жить на своей копии (Stage 2 объединит их отдельно).

Под палец:

* хит-зона грипа **24px** вместо 10px при `@media (pointer: coarse)` и в учебном режиме;
* видимый маркер вместо волосяной линии 2px/18% (в учебном режиме);
* **двойной тап по грипу — сброс пары колонок** к базам;
* `touch-action: none` уже есть в `reader-core.css:368` — прокрутка окна во время drag'а не перехватывается.

### 3.5 Дисклеймер

`#readerProvNote` перемещается **внутрь** `#roomReaderTable`, после `<table>` — то есть в конец
скроллируемого окна. Виден, когда доскроллили до конца материала, а не постоянно.

> **Ловушка:** `rerenderReader()` делает `mount.innerHTML = …` и сотрёт перенесённый узел.
> Перенос обязан выполняться **после каждого рендера**, тем же паттерном, что `roomMediaRefresh()`
> и инъекция закладок/🤖.

## 5. Ловушки, подтверждённые прототипом

1. **Ширину `<col>` нельзя задать из CSS.** Билдер пишет инлайновый `style="width:25.4237%"`.
   В прототипе правило `col[data-col="action"] { width: 34px !important }` **проиграло**:
   `getComputedStyle(col).width` остался 87.48px. Ширины назначаются **в JS после рендера**,
   и — во избежание остатка при `table-layout: fixed` — **все колонки в процентах**:
   `railPct = 34 / tableWidth * 100`, остальным — `(base_i / Σbase) * (100 − railPct)`.
   Проверено: даёт ровно `action:34px · niqqud:141px · ru:169px` при таблице 345px.
2. **Sticky-шапка.** Без `thead th { top: 0 }` в режиме шапка съезжает на высоту бара и оставляет
   пустую полосу над первой строкой (видно на `proto-study-mode-rail-380.png`, исправлено в `-v2`).
3. **Перерисовка стирает post-render.** Ширины рельса, перенос дисклеймера и оверлей обязаны
   переустанавливаться после каждого `rerenderReader()`.
4. **Смена набора колонок в панели** («Иврит» / «Огласовка» / «Транслит» / «Перевод») перенормирует
   базы — пересчёт рельса обязан идти **после** нормализации, иначе доля `action` снова уплывёт.
5. **Тап-seek не должен ловить drag.** Делегат tap-seek фильтрует `button, a, .rm-w, select, input`,
   а грип — `div`. Спасает то, что грип живёт в `<thead>`, у которого нет `tr[data-row-idx]`;
   тем не менее обработчик ресайза обязан звать `stopPropagation()` на `pointerdown`.
6. **Полоса «следования» караоке меряется по окну браузера.** `_karaokeRowFollowable` считает
   центральную полосу от `window.innerHeight`, но в учебном режиме прокручивается окно таблицы,
   а не страница. Полосу считать от активного скроллера (`mount.clientHeight` + его `top`), когда
   скроллером является `#roomReaderTable`. Иначе «уступи ручному скроллу / вернись» срабатывает
   не там, где смотрит человек.
7. **`wireKaraokeScrollPause` слушает `window`.** События `wheel`/`touchmove` всплывают до `window`
   и из вложенного скроллера, так что пауза при ручной прокрутке продолжает работать — менять
   не нужно, но при правке §6 обязана остаться рабочей (покрыть гейтом).

## 6. Гейты и приёмка

**Гейты:**

* `npm run smoke:room-media` — медиа-плеер Зала не сломан (караоке, tap-seek, состояния).
* `npm run smoke:reader-parity` — билдер таблицы не тронут.
* `npm run smoke:i18n` — 3 локали, без дублей ключей.
* `npm run test:api-smoke` — общий страж.
* Скриншот @380px перед `git add` (канон CLAUDE.md).

**Новый гейт** `smoke:room-study` (Node, чистые функции + DOM-инварианты):

1. `applyLinkedResize` — сумма видимых баз остаётся 100 ± 1e-6; ни одна не уходит ниже
   `RESIZE_MIN_COL_PERCENT`; drag влево и вправо симметричны.
2. Пересчёт рельса: при любом наборе видимых колонок `action` даёт 34px ± 1px при заданной
   ширине таблицы, а сумма всех долей = 100%.
3. **Анти-регресс основного дефекта:** при выключении «Иврит» и «Транслит» доля `action`
   **не растёт** (сегодня 15% → 25.4%).
4. Три положения служебной колонки: в каждом ▶/☆/🤖 достижимы (в «Скрыта» — на активной строке).
   Тупиков нет.

**Приёмка владельцем** — на живом айфоне: включить режим в «Аа», убедиться, что (а) видео и таблица
занимают экран, (б) служебная колонка узкая, (в) ширина колонок тянется пальцем, (г) дисклеймер и
футер не мешают во время учёбы.
