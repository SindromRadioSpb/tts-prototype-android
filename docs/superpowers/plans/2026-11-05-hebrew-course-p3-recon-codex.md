# Задание для Codex: разведка кода перед планом P3 (урок в Зале)

Цель: Claude пишет план P3 по вашему отчёту, не перечитывая код Зала сам. Код **не менять**. Результат — только отчёт.

Работать от свежего `origin/main` (`git fetch origin`), можно прямо в основной папке на `main` или в `.worktrees/p3-recon`.

Отчёт: `docs/research/hebrew-course/2026-11-05-p3-recon.md`. Пушить в main с `[skip cd]` (коммит только с этим файлом). Для каждого пункта — файл и строки (`path:line`), имена функций, короткая выдержка кода и ответ на вопрос. Где ответа нет, так и написать.

1. **Корпус атласа в Зале как образец.** Как корпус `atlas:` регистрируется и открывается в `public/js/library-ui.js`: `renderAtlasCorpus`, `corpusSwitcherBar`, адрес `#room=atlas:…`, восстановление позиции, выход из Зала (`leaveRoom`). Что нужно сделать, чтобы добавить `course:ulpan`; список всех мест, где проверяется префикс `atlas:`.
2. **Данные с тома.** Маршрут `/data/atlas` в `server.js`, кэширование, `DATA_DIR`; как данные атласа попадают на том при выпуске (скрипты, ручная заливка).
3. **Подключение скриптов и версии.** Где подключаются `atlas-*.js` в `public/library.html`, список в `public/sw.js`; где `CACHE_VERSION`, `APP_VERSION`, `?v=`; какой тест проверяет lockstep.
4. **Строки Зала для текста урока.** Как атлас переиспользует строку Зала: касание слова → морфологическая карточка (`attachReaderMorph`, `ReaderMorph opts.cardTop`, `atlas-words.js`), ▶ у строки (TTS ряда, `audio_asset_key`), настройки `room.heOn/niqqudMode/translitOn/ruMode`. Можно ли отдать модулю строку `{niqqud, plain, ru}` без записи в БД материалов.
5. **Хранение и синхронизация прогресса.** Где Зал хранит прогресс чтения и статусы слов (локальная БД / OPFS / сервер), как работает синхронизация (`docs/` по sync-hardening, модули клиента), есть ли общий механизм, через который курс мог бы сохранять свой `Progress` (JSON на пользователя).
6. **FSRS и review_log.** Где ключи повторения (`at1:` атласа), как исключаются из тренировки Зала; что нужно, чтобы курс завёл свой ключ.
7. **Роль owner.** Как атлас показывает элементы только владельцу (`lib/atlasReview.js`, `requireUser`, проверка роли на клиенте).
8. **Движок «Миров».** Можно ли смонтировать сцену `world-engine.js` / `story.json` внутри блока Зала, а не на весь экран: API, размеры, пауза, уменьшение движения, очистка.
9. **Ивритская экранная клавиатура.** Есть ли уже в проекте (поиск по `keyboard`, `virtual`, `hebrew-keys`); если нет — где UI-правила для новых панелей (`docs/architecture/AGENT_UI_GUIDE.md`).
10. **Браузерные проверки.** Какой smoke-скрипт атласа (`scripts/atlas/atlas-browser-smoke.cjs`) взять за образец для урока и как его запускать локально.

Готово, когда отчёт запушен в main. Приёмку и план P3 делает Claude.
